# 新治理运行原则

## 1. 核心判断

QuantPilot 的治理重心从法条型治理转向拓扑型治理:

```text
开发正确性 =
  结构定位正确性
  x 模块边界清晰度
  x 当前游标准确性
  x 局部不变量绑定度
  x 触发式流程升级
```

这并不表示 General Policy、超级规范化或诱错循环失效。它表示这些高能级工具不应日常常驻，而应在边界、升级、发布和异常时发挥作用。

## 2. 六层分工

| 层级 | 日常角色 | 主要载体 |
| --- | --- | --- |
| 实体定位层 | 回答在哪里、属于谁、能改什么 | 总游标、全量树、模块树、用户功能切面树 |
| 局部不变量层 | 把 GP 铁律投影到模块和边 | local invariants、policy refs |
| 开发模式层 | 判定推进、重构或切面打磨 | QPCursor mode stack |
| 触发式流程层 | 高风险变化时升级流程 | 治理热度、超级规范化通道 |
| 发布证明层 | 证明版本可收口 | closeout gates、evidence |
| 异常诱错层 | 在未知风险升高时主动找错 | 自由维度诱错循环 |

## 3. 旧治理隔离原则

旧治理继续保持当前权威。本目录只做旁路孵化，不做默认替换。

禁止事项:

1. 禁止在本目录试运行阶段修改旧治理文件来迎合新治理。
2. 禁止把旧治理入口改指向本目录。
3. 禁止把新治理未验证的规则写成默认强制规则。
4. 禁止让代理用本目录绕过既有门禁。

允许事项:

1. 允许从旧治理读取事实和规则。
2. 允许在本目录记录新治理对旧治理的重新定位。
3. 允许用试运行任务验证 QPCursor、热度触发和局部不变量。
4. 允许在 closeout 后形成 promote 建议。

## 4. 一句话原则

全量树和模块树负责让开发不迷路；GP 负责让开发不越界；超级规范化负责在高风险变化时升级流程；诱错循环负责在未知风险升高时主动找错。
