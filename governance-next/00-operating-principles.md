# 新治理运行原则

## 1. 核心判断

QuantPilot 的治理重心从法条型治理转向拓扑型治理:

```text
开发正确性 =
  结构定位正确性
  x 模块边界清晰度
  x 当前游标准确性
  x 局部不变量绑定度
  x 触发式流程升级
```

General Policy、超级规范化和诱错循环仍然有效，但它们不再日常常驻。它们应在边界、升级、发布和异常时发挥作用。

## 2. 六层分工

| 层级 | 日常角色 | 主要载体 |
| --- | --- | --- |
| 实体定位层 | 回答在哪里、属于谁、能改什么 | QPCursor、全量树、模块树、用户功能切面树 |
| 局部不变量层 | 把 GP 铁律投影到模块和边 | local invariants、policy refs |
| 开发模式层 | 判定推进、重构或切面打磨 | QPCursor mode stack |
| 触发式流程层 | 高风险变化时升级流程 | 治理热度、超级规范化通道 |
| 发布证明层 | 证明版本可收口 | closeout gates、evidence |
| 异常诱错层 | 在未知风险升高时主动找错 | 自由维度诱错循环 |

## 3. 旧治理归档原则

旧治理不再保持默认权威。本目录成为默认治理入口，旧 `markdown/00-matrix-governance/` 作为兼容档案、历史索引和门禁素材库保留。

禁止事项:

1. 禁止把旧三矩阵重新声明为默认权威入口。
2. 禁止用旧递归协议覆盖 QPCursor 的 allowed workset、stop_if 和 evidence。
3. 禁止为了减少文档工作删除旧治理文件、旧里程碑或旧全量树记录。
4. 禁止让代理用旧治理绕过新治理的治理热度、局部不变量和 closeout evidence。

允许事项:

1. 允许从旧治理读取事实、历史规则和迁移来源。
2. 允许保留旧门禁脚本，作为兼容门禁继续运行。
3. 允许在新治理尚未完全机器化的区域引用旧模块树和旧递归游标。
4. 允许通过新治理文件记录对旧治理的重新定位、降重和替代路线。

## 4. 权威冲突规则

当新旧治理结论冲突时，按以下顺序裁决:

1. 用户当前明确指令。
2. `governance-next/05-authoritative-operating-model.md`。
3. `governance-next/01-qpcursor-protocol.md`。
4. `governance-next/02-governance-heat-trigger.md`。
5. `governance-next/03-local-invariants.md`。
6. 旧三矩阵和旧递归协议的兼容解释。

旧治理可以补事实，不能改结论。

## 5. 一句话原则

QPCursor 负责让开发不迷路；全量树和模块树负责让结构可查；局部不变量负责让开发不越界；治理热度负责只在需要时升档；证据门禁负责让交付可接管。
