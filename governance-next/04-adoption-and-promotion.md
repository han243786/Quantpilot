# 旁路接入与替换条件

本文件定义新治理如何在不破坏旧治理的前提下进入 QuantPilot。

## 1. 接入阶段

### Phase 0: 隔离建档

目标: 建立 `governance-next/`，不改旧治理。

完成条件:

1. 新目录存在。
2. 新目录说明自身不是默认权威。
3. 旧治理文件没有被移动、删除或改写。

### Phase 1: 只读试判

目标: 用新治理判断任务热度和游标结构，但不改变执行流程。

完成条件:

1. 至少 3 个历史任务能被映射到 G0-G5。
2. 至少 3 个历史任务能生成 QPCursor 草案。
3. 发现的冲突只记录，不要求旧治理修改。

### Phase 2: 旁路执行

目标: 对明确声明试用的新任务启用 QPCursor。

完成条件:

1. 代理能按游标接管。
2. 修改范围没有越过 allowed workset。
3. stop_if 能阻止范围外扩张。
4. evidence 能支撑下一代理继续。

### Phase 3: 双轨对照

目标: 新治理和旧治理同时运行，比较返工率、接管成本、门禁遗漏和文档漂移。

完成条件:

1. 新治理不增加架构错误。
2. 新治理不提高返工率。
3. 新治理能减少上下文依赖。
4. 新治理能更早发现模块边界问题。

### Phase 4: promote 提案

目标: 形成替换旧治理入口的正式提案。

promote 前必须输出:

1. 试运行任务清单。
2. QPCursor 接管证据。
3. 治理热度判定证据。
4. 新旧治理冲突清单。
5. 迁移方案。
6. 回退方案。

## 2. promote 禁止条件

出现以下任一情况，不允许替换旧治理:

1. 新治理导致旧门禁被绕过。
2. 新治理不能解释 G3-G5 高风险任务。
3. QPCursor 无法让新代理接管。
4. 全量树或模块树出现漂移。
5. 旧治理冲突没有明确处理方案。
6. 没有回退路径。

## 3. 回退原则

试运行阶段任何冲突默认回退到旧治理。

```text
旧治理 = 当前权威
新治理 = 旁路试运行
promote = 需要证据的显式动作
```
