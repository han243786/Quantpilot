# 治理热度与触发矩阵

新治理采用热度触发，不让高成本治理工具日常常驻。

## 1. 热度等级

| 等级 | 名称 | 典型任务 | 启用治理 |
| --- | --- | --- | --- |
| G0 | 叶子级低热度 | 单文件、无接口、无 capability、无持久化、安全或运行时语义变化 | QPCursor、全量树路径、模块树叶子、局部测试 |
| G1 | 模块级中低热度 | 模块内部结构调整、拆 helper、移动私有方法、局部重构 | 模块树、公私方法声明、局部回归、全量树同步 |
| G2 | 模块边界热度 | 新增 public 方法、改变父子关系、新增文件、重命名模块、跨两个以上模块 | 全量树、模块树、接口冻结、受影响模块回归、必要时进入 RM |
| G3 | 能力热度 | 新增用户入口、新增功能、能力扩展、supported/deferred/unsupported 状态变化 | 功能演进登记、capability 真源通道、支持矩阵、回归保护矩阵 |
| G4 | 架构热度 | QS 语义、Core IR、runtime、Risk Plane、ExecutionMachine、交易模式、持久化 schema、安全边界 | MAJOR/MINOR 演化通道、阶段化开发、兼容桥、拒绝路径、架构级回归 |
| G5 | 发布或未知风险热度 | 版本 closeout、多代理并行、无法解释退化、返工率上升、架构错误重现 | 完整 closeout、自由维度诱错、发布前检查、GP 合规矩阵、元流水线自审计 |

## 2. 默认策略

低热度任务不启动完整超级规范化，不启动自由维度诱错循环。

高热度任务不允许只靠局部判断推进，必须显式进入对应通道。

## 3. 触发规则

### G0 不启用

以下内容默认不启用:

1. 完整超级规范化。
2. 自由维度诱错。
3. 功能演进登记。
4. MAJOR/MINOR 演化通道。

### G2 触发

命中以下任一条件，至少进入 G2:

1. 新增文件。
2. 移动文件。
3. 改变 public surface。
4. 改变模块父子关系。
5. 改变模块调用边。
6. 跨两个以上模块。

### G3 触发

命中以下任一条件，至少进入 G3:

1. 新增用户可见入口。
2. 新增或扩展能力。
3. 改变 capability 来源、状态或展示。
4. 改变 supported、experimental、deferred、unsupported 的用户侧含义。
5. 前端入口需要以后端 capability 为真源。

### G4 触发

命中以下任一条件，至少进入 G4:

1. 改变 QS 语义。
2. 改变 Core IR。
3. 改变 runtime 状态机。
4. 改变 Risk Plane。
5. 改变 ExecutionMachine。
6. 改变交易模式、凭证、安全边界或持久化 schema。

### G5 触发

命中以下任一条件，进入 G5:

1. 架构错误出现 1 次。
2. 代码返工率连续两个周期高于 15%。
3. 出现跨切面回归。
4. 出现难以定位的 bug。
5. 出现 capability、文档、UI 状态漂移。
6. 出现安全、凭证、资金、持久化相关改动。
7. 进入 MAJOR/MINOR closeout。
8. 新代理接管失败。
9. 模块树出现未登记边。
10. 全量树校验失败或长期未同步。

## 4. 原则

治理热度只能升档，不能因为代码量少、测试暂时通过或只是文档变更而降档。
