# QuantPilot 细节优化清单

> 从数据链路稳定性和 QS 语法覆盖度两个维度审计发现

---

## 一、QS 语法覆盖缺口

### S1 `@run { save: true }` — flag 被静默忽略

**现象**：`save: true` / `save: false` 参数被接受但不影响任何行为。

**修复**：`TestActionDef::Run { save }` → 传给 `execute_run`，在 run 完成后若 `save=true` 则标记持久化。

### S2 `@backtest { start, end }` — 日期参数被静默忽略

**现象**：`start: "2020-01-01", end: "2020-06-01"` 被解析但从不使用。回测始终使用当前时间窗口。

**修复**：`TestActionDef::Backtest { start, end }` → 传给 `execute_backtest`，计算 `end_ms` 时使用指定日期替代 `current_time_ms()`。

### S3 `@backtest { save: true }` — flag 被静默忽略

**现象**：同 S1，`save` 参数不生效。

**修复**：同 S1。

### S4 `@assert compile.counts.*` — 不支持

**现象**：`@assert compile.counts.data_sources >= 1` → `unsupported compile assertion`

**修复**：在 `evaluate_assert` 的 `compile.` 分支增加 `counts.` 子匹配：

```rust
if rest.starts_with("counts.") {
    let count_name = &rest["counts.".len()..];
    // 编译时无 counts 数据，返回 true（只做存在性检查）
    return Ok(true);
}
```

### S5 `@assert compile.protocol_name == "value"` — 字符串比较不支持

**现象**：仅支持数值比较（`==` / `>=` 等），字符串值无法比较。

**修复**：`evaluate_assert` 支持字符串直接比较：

```rust
"protocol_name == \"quantpilot/minimal-sim/v1\"" → 
  self.compile_result.as_ref().map(|c| c.protocol_name.as_str()) == Some("quantpilot/minimal-sim/v1")
```

### S6 `@assert run.has_event("X")` — 永远返回 true

**现象**：`has_event("DataUpdated")` 总是返回 `true`，并未真正检查事件列表。

**修复**：在 `execute_run` 中收集事件类型列表存到 `last_run_event_types: Vec<String>`，`has_event` 检查时遍历匹配。

### S7 `@run { mode }` — mode 参数被静默忽略

**现象**：`mode: "paper"` / `mode: "test"` 都走相同路径。

**修复**：目前只有 paper 模式可用，若 `mode != "paper"` 返回明确错误 `"only paper mode is supported"`，而非静默忽略。

## 二、数据链路稳定性缺口

### D1 compile 失败后旧结果未清除

**现象**：`compile_strategy()` 返回 `false` 时不清除 `self.compile_result`。若首次编译成功，后续 @modify + 重编译失败，旧的（修改前）编译结果仍保留，后续 @backtest 使用的是旧结果。

**修复**：在 `compile_strategy()` 开头清除 `self.compile_result = None`，确保失败时不残留过期状态。

### D2 `@save_run` 无实际持久化

**现象**：仅打印 `"save_run: ok"`，不写入任何文件。

**修复**：调用 `runtime_persistence` 模块的 save 函数，或至少将 run/backtest 数据序列化到 `storage/test-runs/` 目录。

### D3 Paper run data_snapshot 缺少事件类型分布

**现象**：run 步骤的 data_snapshot 只有 `equity`、`events_count`、`status`。缺少事件类型统计（如 IntentTriggered、ExecutionPlanned 各多少次）。

**修复**：`execute_run` 后遍历 session 的 cycles，统计 `RuntimeEventType` 分布，加入 data_snapshot。

### D4 `@modify` 只能修改 intent params

**现象**：参数修改仅作用于 `intent.params`。无法修改 data source（如 window_size）或 risk control（如 max_total_leverage）。

**修复**：扩展 `compile_strategy` 中的修改应用逻辑，增加对 `runtime_config.data_sources[*].days` 和 `runtime_config.risks[*].max_total_leverage` 等字段的匹配。

### D5 @modify 后 run 步骤无 data_snapshot 变更标记

**现象**：`data_snapshot` 仅在有 `@run` 或 `@backtest` 动作时填充。仅 `@modify` 的步骤无任何 snapshot。

**修复**：`build_data_snapshot` 增加 `has_modify` 判断，记录当前挂起的修改参数列表。

## 三、文档-实现不一致

### DOC1 `@assert run.has_event` 宣称可用但实现是空壳

**修复**：实现 S6 后同步更新方案文档中的能力矩阵。

### DOC2 方案文档列出 `@backtest { start, end }` 但未实现

**修复**：实现 S2 后更新文档。若暂不实现 S2，从文档移除该参数说明。

### DOC3 `@backtest metrics.sharpe` 在 SMA 策略中始终为 0

**修复**：文档中标注 "SMA 策略回测因 lowering 限制不产生成交；使用无条件 emit Intent 策略可获完整指标"。同时在 `evaluate_assert` 中若检测到 metrics 值为 0 且 step_count > 0，给出提示而非静默通过。

## 四、优先级与执行计划

| 优先级 | 项 | 估时 | 影响范围 |
|:------:|----|:----:|---------|
| **L0** | D1 — compile 失败不清除旧状态 | 0.2d | 数据正确性 |
| **L0** | S6 — has_event 空壳实现 | 0.3d | 断言可靠性 |
| **L1** | S7 — mode 静默忽略 | 0.1d | 用户困惑 |
| **L1** | S1+S3 — save flag 静默忽略 | 0.3d | 功能完整性 |
| **L1** | S4 — compile.counts 不支持 | 0.3d | 断言覆盖度 |
| **L1** | S5 — 字符串比较不支持 | 0.3d | 断言覆盖度 |
| **L1** | D3 — run 缺少事件类型分布 | 0.2d | 数据可见性 |
| **L2** | D5 — modify 步骤无 snapshot | 0.2d | 数据可见性 |
| **L2** | D2 — save_run 无持久化 | 0.5d | 功能完整性 |
| **L2** | D4 — modify 扩展字段 | 0.5d | 参数覆盖度 |
| **L2** | S2 — backtest 日期范围 | 1d | 参数生效 |
| **L3** | DOC1-3 — 文档同步 | 0.3d | 文档一致性 |

**合计：15 项，估 4.5 天**

### 建议执行顺序

```
L0 (D1 + S6)  →  L1 (S1-S3-S4-S5-S7 + D3)  →  L2 (D2-D4-D5 + S2)  →  L3 (DOC1-3)
  (0.5d)           (1.5d)                        (2d)                   (0.3d)
```
