## P0 — QS 路径成交（阻塞性）

> **目标**：.qs 文件中的 `@backtest` 能产生产生实际成交（非 0 fills）

### 现状根因

```
QS emit Intent("BUY") → lowering → IntentKind::LongTermBuy
    → agent/risk/execution 链 ≠ graph double_ma 链
    → 信号特征不同 → deterministic_mock 下 0 fills

Graph minimal_runtime_request.json → builtin.intent.double_ma
    → SMA crossover 信号 → agent → risk → execution
    → 5 fills ✓
```

### P0.1.1 调查两条路径的 Intent 信号差异

**目标**：抓取两条路径产生的 `IntentSignal`、`AgentDecision`、`RiskDecision` 样本，定位分歧点。

| 步骤 | 操作 | 输出 |
|------|------|------|
| 1 | 在 `execute_backtest_request` 中加 debug 日志，打印 IntentTriggered 事件的 payload | 信号强度/频率/方向统计 |
| 2 | 在 TestRunner `execute_backtest` 中加同样日志 | 同上 |
| 3 | 对比两者差异，确定是信号数量不同还是信号类型不同 | 差异报告 |

**文件**：`src/runtime_api.rs`（加 debug）、`src/test_runner.rs`（加 debug）

### P0.1.2 让 TestRunner 走 graph API 编译路径

**方案 A（推荐）**：TestRunner 内部调用 `map_frontend_runtime_config` + `compile_runtime_protocol_config`，复用与 `POST /api/runtime/compile` 完全一致的管线。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/test_runner.rs` | `compile_strategy()` 产出 `RuntimeProtocolCoreConfig` 后，额外调用 `frontend_runtime_config_from_core_with_template`（需设为 `pub(super)` 或提取到公共模块） |
| 2 | 同上 | 用得到的 `FrontendRuntimeConfig` 调用 `map_frontend_runtime_config` → `compile_runtime_protocol_config` |
| 3 | 同上 | `execute_backtest` / `execute_run` 使用新编译结果 |
| 4 | `src/compile_api.rs` | 将 `frontend_runtime_config_from_core_with_template` 改为 `pub(super)` |

**方案 B**：TestRunner 直接 HTTP 调用 `POST /api/quantscript/formal/compile` + `POST /api/runtime/backtest`（需在 Rust 中引入 HTTP client）。

> 选方案 A。

### P0.1.3 验收

curl -X POST http://127.0.0.1:3000/api/test/scenario/run \
  -d '{"source": "...QS策略 + @backtest..."}'
# → total_fills > 0, net_profit != 0
```

**验收标准**：
- `scenario_01_btc_dual_ma.qs` 回测步骤 `total_fills > 0`

## P1 — 指标 + 断言增强

### P1.1 Sharpe / Turnover / Fee 指标计算

> 当前 `BacktestSummary` 中 `turnover_ratio`/`average_trade_notional`/`fee_drag_ratio` 在 `run_backtest()` 阶段硬编码为 0，需从 sessions 数据实时计算。

#### P1.1.1 在 TestRunner 内实现指标计算

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/test_runner.rs:execute_backtest()` | 遍历 `sessions[].fill_reports`，累加 `total_filled_notional`、`total_fees` |
| 2 | 同上 | 计算 `turnover_ratio = total_filled_notional / initial_equity` |
| 3 | 同上 | 使用 `equity_curve` 数据计算简易 Sharpe：`mean(daily_return) / std(daily_return) * sqrt(252)` |
| 4 | 同上 | 加入 `last_backtest_metrics` |

#### P1.1.2 验收

```
backtest: steps=200, fills=5
  sharpe: -1.23
  turnover: 0.05
  fee_drag: 0.02%
  max_drawdown: 0.10%
```

### P1.2 跨指标比较断言

> `@assert backtest.metrics.initial_equity == backtest.metrics.final_equity`

#### P1.2.1 实现

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `quantscript/src/test_plan.rs` | 新增 `AssertExpr { left: AssertRef, op: CompareOp, right: AssertRef }`，`AssertRef` 为 `Metric(String)` 或 `Literal(f64)` |
| 2 | `quantscript/src/script.rs` | parser 支持 `@assert a.b.c == d.e.f` 跨指标语法 |
| 3 | `src/test_runner.rs:evaluate_assert()` | 匹配 `AssertExpr` 结构，从 `last_backtest_metrics` 取两侧值比较 |

#### P1.2.2 验收

```
@assert backtest.metrics.net_profit > backtest.metrics.total_fees_paid
→ passed
```

### P1.3 浮点容差

> `@assert backtest.metrics.total_return_pct == 0.0(0.01)`

#### P1.3.1 实现

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/test_runner.rs:evaluate_assert()` | `==` 比较时检测字面量后的 `(tolerance)` 后缀 |
| 2 | 同上 | 使用 `(a - b).abs() < tolerance` 替代 `f64::EPSILON` |

```

→ passed (within 1bp tolerance)
