## M0 — 致命修复（0.5 天）

### M0-1 空 source 返回 400 而非 200

**文件**：`src/api_test_scenario.rs`

```rust
// run_test_scenario 函数开头添加：
if request.source.trim().is_empty() {
    return Err((
        axum::http::StatusCode::BAD_REQUEST,
        "source is empty — provide a valid quantscript strategy with @test directives".to_string(),
    ));
}
```

**验收**：`POST /api/test/scenario/run` with `{"source": ""}` → `400 Bad Request`

### M0-2 `@modify` 实际生效而非仅日志

**根因**：当前 `execute_step` 中 `TestActionDef::Modify` 只记录日志，未修改编译产物。Q  S 源码是文本，重编译总是使用原始文本。

**方案**：在 `@modify` 后，下次 `@compile` 使用修改后的参数重新 lowering。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/test_runner.rs` | 新增 `pending_modifications: Vec<(String, String, f64)>` 字段 |
| 2 | 同上 | `TestActionDef::Modify` → push 到 `pending_modifications` |
| 3 | 同上 | `compile_strategy()` 检查 `pending_modifications`，若有则修改 `RuntimeProtocolCoreConfig` 中对应 intent 的 params 后再编译 |
| 4 | 同上 | 编译成功后清空 `pending_modifications` |

**验收**：
```
@modify { node: "dual_ma", param: "fast_period", value: 5 }
@compile              → compilable == true
@backtest             → fills 与修改前不同（参数变化反映到结果中）
```

## M1 — 输入校验（1.5 天）

### M1-1 无效 backtest source 返回明确错误

**文件**：`src/test_runner.rs:execute_step()`

```rust
TestActionDef::Backtest { source, ... } => {

            source
        ));
    }
    // ...
}
```

**验收**：`@backtest { source: "nonexistent" }` → step failed: "unsupported backtest source: 'nonexistent'"

### M1-2 畸形 cover 数组解析校验

**文件**：`quantscript/src/script.rs:parse_test_fields()`

在 list 类型字段解析后加校验：
```rust
// 从 fields 提取 cover 列表后
if cover_str.contains('"') && cover_str.matches('"').count() % 2 != 0 {
    // 引号不成对，格式错误
}
```

更简洁的方案：将 `cover` 字段的解析从简单字符串拆分改为 mini JSON 解析：
```rust
let cover: Vec<String> = serde_json::from_str(&format!("[{}]", raw_cover))
    .unwrap_or_default();
```

**验收**：`cover: ["A" "B"]` → cover 解析为空列表或报错，而非单字符串 `A" "B`

### M1-3 0s duration 运行拒绝或警告

**文件**：`src/test_runner.rs:execute_step()`

```rust
TestActionDef::Run { duration_secs, .. } => {
    if *duration_secs == 0 {
        return Err("run duration must be > 0".to_string());
    }
    // ...
}
```

**验收**：`@run { mode: "paper", duration: 0s }` → step failed: "run duration must be > 0"

### M1-4 step name 长度限制

**文件**：`quantscript/src/script.rs:parse_step_block()`

```rust
const MAX_STEP_NAME_LEN: usize = 500;

let name = line.split('"').nth(1).unwrap_or("unnamed").to_string();
if name.len() > MAX_STEP_NAME_LEN {
    // Truncate with warning
```

**验收**：10KB step name → 截断到 500 字符或返回错误

### M1-5 负 seed 文档化处理

**文件**：`quantscript/src/test_plan.rs` + `src/test_runner.rs`

种子字段已是 `u64` 类型，Rust 的类型系统在 JSON 反序列化阶段会自动拒绝负数。需要做的是：
- 在 `run-scenario.js` 工具中添加 seed 范围提示
- 在 TestRunner 注释中说明 seed 为 `u64`，不接受负数

**验收**：文档明确 seed 范围 `[0, 2^64-1]`

### M2-1 `@test` 无 `@step` 时友好报错

**文件**：`quantscript/src/script.rs:parse_test_block()`

```rust
    }
}
```

**验收**：`@test { name: "x" }` without `@step` → 400 "test scenario 'x' has no @step directives"

### M2-2 无效 @assert 前缀清晰报错

**文件**：`src/test_runner.rs:evaluate_assert()`

```rust

    "unknown assertion: '{}'. Supported prefixes: compile., run., backtest.metrics.",
```

**验收**：`@assert invalid.thing` → step failed: "unknown assertion: 'invalid.thing'. Supported prefixes: compile., run., backtest.metrics."

### M3-4 `run-all-scenarios.sh` → `run-all-scenarios.js` 跨平台

**文件**：新建 `tools/run-all-scenarios.js`

```js
#!/usr/bin/env node
// Cross-platform scenario runner
const { execSync, spawn } = require("child_process");
const path = require("path");
const fs = require("fs");

const ROOT = path.resolve(__dirname, "..");
const SCENARIO_DIR = path.join(ROOT, "tests", "scenarios");

function log(msg) { console.log(`[${new Date().toISOString().slice(11,19)}] ${msg}`); }

async function main() {
  log("Starting backend...");
  const backend = spawn(path.join(ROOT, "target", "debug", "quantpilot.exe"), [], {
    env: { ...process.env, QUANTPILOT_PORT: "3000", QUANTPILOT_DEV: "true", QUANTPILOT_API_KEY: "" },
    stdio: "pipe"
  });
  
  // Wait for backend
  await new Promise(r => setTimeout(r, 3000));
  
  log("Running scenarios...");
  const files = fs.readdirSync(SCENARIO_DIR).filter(f => f.endsWith(".qs") && f.startsWith("scenario_"));
  let passed = 0, failed = 0;
  
  for (const f of files) {
    try {
      execSync(`node "${path.join(ROOT, "tools", "run-scenario.js")}" "${path.join(SCENARIO_DIR, f)}"`, { stdio: "inherit" });
      passed++;
    } catch { failed++; }
  }
  
  log(`Done: ${passed} passed, ${failed} failed`);
  backend.kill();
  process.exit(failed > 0 ? 1 : 0);
}

main();
```

**验收**：`node tools/run-all-scenarios.js` 在任何 OS 上正确运行
