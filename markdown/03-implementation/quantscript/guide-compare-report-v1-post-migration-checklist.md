# Compare Report V1 后迁移检查清单

本文档定义了 `V1` 后迁移计划，用于将当前双重的比较/报告响应面合并为一个权威的外部报告真实数据。

当前 `V1` 合约仍保留两者：

- `report_narrative`
- `compare_report`

在 `V1` 阶段收口期间，这种双重形态仍然是有意的，因为：

- 它保留了已落地的响应合约
- 它避免了在冻结工作仍然活跃时进行后期 API 破坏
- 它让 `compare_report` 在成为唯一对外报告真实数据之前成长更丰富的模块化报告视图

此检查清单的存在是为了防止临时或过早删除。

## 当前真实数据边界

在 `V1` 结束时，按如下方式处理比较/报告真实数据层：

- 内部比较真实数据来自共享的比较块加上共享的比较/报告包构建器
- `compare_report` 是更强的长期外部报告形态
- `report_narrative` 在 `V1` 期间仍然是稳定的兼容性投影

不要在 `V1` 阶段收口期间删除 `report_narrative`。

## 迁移目标

在 `V1` 阶段收口之后，迁移到以下目标状态：

- `compare_report` 成为比较/报告消费者的唯一权威外部报告模块
- `report_narrative` 首先被标记为已弃用，然后可移除
- 测试和文档停止将两个字段视为同等的顶层真实数据

## 任何移除前的先决条件

仅在所有以下条件满足后才开始移除阶段：

1. `V1` 冻结检查清单已满足。
2. `compare_report` 完全覆盖保留的 `V1` 比较/报告需求：
   - 假设
   - 指标
   - 交易台账
   - 权益曲线
   - 概览/标题/亮点
3. 没有活跃文档仍将 `report_narrative` 作为首选的长期报告真实数据。
4. API 消费者已：
   - 迁移到 `compare_report`，或
   - 接受了一个弃用窗口。

## 迁移步骤

### 步骤 1. 文档重新措辞

在任何响应形态删除之前：

- 重新措辞文档，使 `compare_report` 被描述为规范的外部报告视图
- 将 `report_narrative` 重新措辞为为过渡保留的兼容性层
- 移除将两者呈现为同等长期输出的措辞

### 步骤 2. 测试重新措辞

在删除任何字段之前：

- 修改比较 API 测试，使：
  - `compare_report` 是主要断言报告真实数据
  - `report_narrative` 仅检查兼容性存在性和基本一致性
- 在意图仅为"相同报告真实数据，不同外部包装"时，停止为两种形态复制完整的预期 JSON

### 步骤 3. 弃用窗口

在文档和测试对齐后：

- 在一个明确的过渡窗口期内保留 `report_narrative`
- 在文档中将其标记为已弃用
- 避免仅向 `report_narrative` 添加新能力

### 步骤 4. 移除

在过渡窗口之后：

- 从比较响应中移除 `report_narrative`
- 如果其专用构建器不再服务任何内部目的，则删除它
- 仅当共享的比较/报告包仍为 `compare_report` 提供输入时才保留它

### 步骤 5. 最终清理

移除后：

- 删除仅兼容性测试
- 删除仅兼容性文档措辞
- 使 `compare_report` 成为路线图和队列文档中唯一的命名比较/报告真实数据

## 删除优先级

当此迁移重新开启时，按以下顺序删除：

1. 将两个字段视为同等长期真实数据的测试措辞
2. 将两个字段视为同等长期真实数据的文档措辞
3. `report_narrative` 兼容性断言
4. `report_narrative` 响应字段
5. 任何现在未使用的兼容性构建器或辅助函数

## V1 期间不得移除

以下操作在 `V1` 阶段收口期间明确禁止：

- 移除 `report_narrative`
- 重命名 `compare_report`
- 以破坏性方式更改比较响应形态
- 在冻结清理期间强制客户端切换

## 成功条件

仅在以下条件满足时，才将 `V1` 后迁移视为完成：

1. `compare_report` 是唯一文档化的外部报告真实数据。
2. 比较 API 仅暴露一个权威报告模块。
3. 没有为 `report_narrative` 留下的仅兼容性测试。
4. 队列和路线图文档不再描述双重的报告真实数据。
