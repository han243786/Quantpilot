# 运行时工件保留与保存门禁

本文档记录了验证、测试运行、模拟和回测工件的存储安全优化。

## 问题

在开发期间，每次可用性检查或验证测试都可能在 `storage` 下创建新文件夹，尤其是在运行时和回测路径下。重复检查会产生密集的 `storage/test-*` 或回测工件目录，累积的事件日志、台账、曲线和清单会迅速消耗大量存储空间。

这是一个存储安全风险。验证应证明策略能否运行；它不应自动成为持久化工件。

## 目标规则

默认情况下，验证和测试执行是瞬态的。

工件仅在显式保存操作后才进入 `storage`。

这适用于：

- 编译验证检查
- 策略可用性测试
- 模拟冒烟运行
- 回测预览运行
- 参数验证运行
- 前端和后端开发测试

面向用户的规则应简单：

1. 运行验证或测试。
2. 检查结果。
3. 如果结果应成为持久历史的一部分，点击保存。
4. 如果瞬态结果应从当前会话中移除，点击丢弃。
5. 仅保存路径将工件文件夹写入 `storage`。

## 存储层级

### 瞬态层

瞬态工件仅用于即时 UI 反馈。

必需行为：

- 不要写入 `storage/graphs`、`storage/runs`、`storage/backtests` 或 `storage/experiments`
- 小记录优先使用内存
- 大型回测预览溢出到 `.quantpilot-tmp/runtime-artifacts/backtests` 而非持久历史文件夹
- 为瞬态根附加 TTL 和配额
- 在服务器启动、成功提升后、显式丢弃后以及 TTL 过期后清理瞬态文件
- 将瞬态工件从策略中心计数和历史列表中排除
- 允许手动丢弃而无需触及持久历史

### 持久层

持久化工件是持久的项目记录。

必需行为：

- 仅在显式保存后写入
- 对已保存的图、运行、回测、实验和审计记录使用现有的 `storage` 子树
- 保留已保存工件的回放兼容性
- 在策略中心历史面板中仅列出已保存的工件
- 在瞬态工件被提升时记录审计元数据

### 证据报告层

证据报告记录是持久化的元数据。它们链接到源运行/回测证据、序列范围、治理标识、生成策略和导出的工件元数据。它们不复制原始日志。

必需行为：

- 报告存储下的报告 JSON 记录是受保护的持久元数据
- 报告导出负载从报告元数据推导，可以重新生成
- 紧凑证据仍是受治理源证据的投影，而非独立保留的缓存
- 瞬态报告生成输出可在清理 TTL 后删除
- 清理可移除名称以 `report-generation-tmp-` 或 `report-generation-partial-` 为前缀的内容
- 清理不得删除已保存的报告 JSON 记录、已保存的运行、已保存的回测或已保存的实验

## 后端计划

1. 添加工件持久化范围。

   建议值：

   - `transient`（瞬态）
   - `saved`（已保存）

   范围应由运行、回测和实验创建流程携带。

2. 使测试和验证端点默认为 `transient`。

   当前在测试期间调用持久化写入的后端函数默认不应调用：

   - `persist_run_record`
   - `persist_backtest_record`
   - `persist_backtest_artifacts`
   - `persist_experiment_record`

3. 添加提升路径。

   瞬态结果应通过专用的保存操作而非原始测试操作来提升。

   端点形态：

   - `POST /api/runtime/runs/:run_id/save`
   - `POST /api/runtime/backtests/:backtest_id/save`
   - `POST /api/runtime/experiments/:experiment_id/save`

   提升将现有瞬态记录复制或重建到正常的持久存储布局中。

4. 添加显式丢弃路径。

   未保存的工件可通过专用的删除操作丢弃：

   - `DELETE /api/runtime/runs/:run_id`
   - `DELETE /api/runtime/backtests/:backtest_id`
   - `DELETE /api/runtime/experiments/:experiment_id`

   这些端点必须拒绝已持久化的工件，因为已保存的历史不属于瞬态清理路径。

5. 保持持久化写入原子性。

   回测提升应首先写入临时兄弟目录，然后重命名为 `storage/backtests/:backtest_id`。这防止半写入的工件文件夹进入历史。

6. 为大型预览添加瞬态溢出。

   小规模回测预览保持在内存中。一旦预览记录超过配置阈值，它将被写入瞬态根作为完整的工件包加最小瞬态元数据。正常的详情、回放、保存和丢弃路径必须从相同的抽象加载，因此 UI 不需要第二套运行时模型。

7. 添加清理。

   服务器应清理瞬态或提升工件：

   - 启动时
   - 成功提升后
   - 显式丢弃后
   - TTL 过期后

   证据报告清理更窄：它仅移除瞬态报告生成输出，并保持持久化报告记录完整。

8. 添加配额。

   运行时临时存储应有护栏：

   - 最大瞬态工件数量
   - 最大瞬态字节数
   - 最大存在时间
   - 当清理无法回收空间时发出警告

## 前端计划

1. 重命名测试操作，使其围绕意图而非持久化。

   验证或测试的按钮不应暗示保存。建议标签：

   - `验证`
   - `试运行`
   - `预览回测`

2. 在成功的瞬态结果后添加显式保存和丢弃操作。

   建议标签：

   - `保存本次结果`
   - `保存为回测记录`
   - `保存到历史`
   - `丢弃临时结果`

3. 显示工件状态。

   结果面板应区分：

   - `临时结果`
   - `已保存`
   - `已丢弃`

4. 保持策略中心整洁。

   策略中心计数器、历史面板和比较队列应忽略瞬态工件，直到它们被保存。

5. 保护比较流程。

   比较队列仅应接受已保存的回测，或者必须清晰提示用户在添加之前保存瞬态回测。

## 测试框架计划

开发和 CI 测试不得写入共享的 `storage/test-*` 路径。

必需的更改：

- 将硬编码的 `storage/test-graphs`、`storage/test-runs` 和 `storage/test-backtests` 替换为每个测试的临时目录
- 确保临时目录在每个测试后移除
- 添加回归测试，如果后端测试在真实的 `storage` 根下创建新条目则失败
- 保持 fixture 小巧且确定性

## 迁移计划

1. 保持现有已保存工件可读。
2. 停止在产品视图中列出 `storage/test-*` 文件夹。
3. 提供过时开发工件的清理命令。
4. 不要自动删除用户已保存的工件。
5. 在移除前记录清理输出，以便用户可以审查将要删除的内容。

## 验收标准

- 重复运行验证不会在 `storage` 下创建新文件夹。
- 重复运行预览回测不会增长持久历史。
- 大型未保存的预览回测仅溢出到瞬态根。
- 未保存测试后，策略中心计数保持不变。
- 已保存的瞬态结果在持久历史中恰好出现一次。
- 未保存的瞬态结果可从当前会话中显式丢弃。
- 丢弃持久化工件被拒绝，不会删除已保存的历史。
- 比较页面仅可消费已保存的回测，或要求在比较前保存。
- 后端测试使用隔离的临时目录并在执行后清理。
- UI 措辞更改后，UTF-8 和面向用户文本检查仍为绿色。

## 已实现范围

当前实现保持现有的运行时模型，仅收窄持久化边界。

已实现：

- `POST /api/runtime/test-run` 现在仅创建内存运行记录。
- `POST /api/runtime/backtest` 现在创建瞬态回测预览。
- 小型回测预览保持在内存中。
- 大型回测预览在超过配置溢出阈值后溢出到 `.quantpilot-tmp/runtime-artifacts/backtests`。
- 瞬态溢出根有 24 小时 TTL 清理路径，最多 32 个瞬态目录，512 MB 总配额，以及 256 MB 单工件配额。
- 瞬态溢出清理在服务器启动时、溢出写入前、显式丢弃后以及成功保存提升后运行。
- `POST /api/runtime/experiments/backtest-sweep` 将扫掠记录保持在内存中，并让大型变种回测使用相同的瞬态溢出路径。
- `POST /api/runtime/runs/:run_id/save` 将当前运行提升到 `storage/runs`。
- `POST /api/runtime/backtests/:backtest_id/save` 将当前回测提升到 `storage/backtests/:backtest_id`，无论它仍在内存中还是已溢出到瞬态根。
- `POST /api/runtime/experiments/:experiment_id/save` 将扫掠记录及其变种回测提升到正常的持久存储。
- `DELETE /api/runtime/runs/:run_id` 显式丢弃未保存的内存模拟运行。
- `DELETE /api/runtime/backtests/:backtest_id` 显式丢弃未保存的内存或溢出回测预览。
- `DELETE /api/runtime/experiments/:experiment_id` 显式丢弃未保存的内存扫掠记录及其未保存的变种回测。
- 丢弃端点以冲突响应拒绝已持久化的工件，因此已保存的历史无法通过瞬态清理路径移除。
- 回测提升现在写入兄弟 `.saving-*` 目录，验证完成的工件包，然后重命名为 `storage/backtests/:backtest_id`。
- 重新保存现有回测首先将旧包移动到兄弟 `.replacing-*` 备份，并在最终重命名失败时恢复它。
- 运行时历史列表跳过 `.saving-*` 和 `.replacing-*` 工作目录，因此半写入的包永远不会进入产品历史。
- 回测提升工作目录现在有 24 小时 TTL 清理路径。清理在服务器启动时和每次回测工件提升前运行。
- 提升工作目录在保存前进行配额检查。当前护栏拒绝超过 32 个提升工作目录、超过 512 MB 总提升工作数据或超过 256 MB 的单提升包。
- 运行时历史和策略中心计数仅继续读取已保存的工件。
- 仅当当前模拟或回测已完成但仍为瞬态时，事件面板才暴露 `保存本次结果` 和 `丢弃临时结果`。
- 后端 API 测试不再使用硬编码的 `storage/test-*` 目录。

在此切片中未实现：

- 无

## 非目标

- 不要引入第二套运行时模型。
- 不要更改成功验证的含义。
- 不要移除已保存工件的现有回放或历史兼容性。
- 不要自动删除用户已保存的工件。
