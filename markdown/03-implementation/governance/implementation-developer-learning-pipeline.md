# 开发者学习流水线契约

> 生效目标: v4.0.0 | 第一服务对象: 项目 owner | 目的: 让项目和开发者共同进步

---

## 目标

开发者学习流水线用于在项目推进中持续解释项目结构、文件关系、调用链、状态流、底层原理和测试保护。它不是普通教程，而是一条可循环、可迁移、可验证的学习元流水线。

第一版服务项目 owner。面向所有协作者的版本必须在 owner 多轮体验后再抽象设计。

## 存储边界

仓库内保存:

- 本契约。
- 可迁移学习方法。
- 学习模板。
- 大版本 closeout 检查规则。

本地保存:

- 个人学习记录放入 `markdown/learning/`。
- `markdown/learning/` 默认不进入版本控制。
- 个人学习记录不推 GitHub。

若个人学习内容需要沉淀为公共知识，必须先整理为正式文档，再放入仓库内规范目录。

## 零假设解释协议

学习模式下，解释必须遵守零假设原则:

- 不假设 owner 懂 Rust、React、Tauri、QS、运行时、构建、测试或部署。
- 第一次出现的术语必须解释。
- 不能只说“调用 API”，必须说明 API 是什么、为什么调用、输入输出是什么。
- 不能只说“状态更新”，必须说明状态在哪里、谁改、什么时候持久化。
- 不能只说“测试覆盖”，必须说明测试防止哪类坏事。
- 每个复杂模块都要给出“你只要记住”的核心句。

## 三种读取模式

| 模式 | 触发 | 范围 | 输出 |
|------|------|------|------|
| 快速地图模式 | “快速地图”“先看项目骨架” | 目录、配置、入口、测试、文档索引 | 项目骨架、入口、风险点 |
| 主题追踪模式 | “学习: 主题”“追踪: 功能” | 围绕主题读取相关文件 | 调用链、状态流、副作用、测试保护 |
| 全量学习模式 | “全量学习模式”“显式 UTF-8 全量读取项目” | 源码和文档全量读取，排除依赖、生成物、密钥、本地学习记录 | 项目地图、模块关系、学习优先级 |

全量学习模式必须由用户明确触发。

默认排除:

```text
.env
密钥文件
证书
本地数据库
node_modules
target
dist
build
.git
运行态缓存
markdown/learning/
```

## 学习循环

每次学习循环按以下顺序执行:

1. 选定主题。
2. 从零解释主题。
3. 定位相关文件。
4. 追踪入口到结果的调用链。
5. 解释数据流、状态流、副作用和持久化。
6. 说明测试保护和现有风险。
7. 列出 owner 必须掌握的关键点。
8. owner 用自己的话复述。
9. 纠偏并补充解释。
10. 用户明确要求时写入学习记录。

## 写入规则

默认不写入 `markdown/learning/`。

只有用户明确说出以下类似指令时，才能生成个人学习记录:

```text
记录本轮学习
生成学习记录
归档本轮学习
写入学习档案
```

建议文件名:

```text
markdown/learning/YYYY-MM-DD-topic.md
```

建议结构:

```markdown
# 本轮学习记录: 主题

## 我问了什么

## 系统从零解释

## 涉及文件或机制

## 我需要记住的关键点

## 我自己的复述

## 纠偏记录

## 后续待学
```

## 大版本 closeout 接入

学习流水线不进入每次强制门禁。

大版本 closeout 必须检查:

```text
本版本是否引入了需要项目 owner 学习的新核心机制？
```

若答案为“是”，closeout 必须记录:

- 是否已有零假设解释材料。
- 是否标注涉及文件和调用链。
- 是否说明状态、数据流、副作用和测试保护。
- 是否记录到本地 `markdown/learning/` 或正式元流水线文档。
- 是否需要 owner 复述/校准。

若答案为“否”，记录:

```text
本版本无新增 owner 必学核心机制。
```

## 可迁移原则

本流水线可迁移到任意项目。迁移时保留以下核心方法:

- 先识别入口。
- 再识别模块边界。
- 再识别数据流。
- 再识别状态流。
- 再识别副作用。
- 再识别测试保护。
- 最后把技术细节翻译成项目 owner 能指挥的判断语言。

## 防过期规则

正式学习文档应标注:

```text
based_on_commit
last_verified
covered_files
staleness_rule
```

当 `covered_files` 变化时，学习解释需要复核。
