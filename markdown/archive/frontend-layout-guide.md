# Frontend Layout Guide (Archived, Normalized)

This file replaces a legacy frontend layout draft that is no longer the active UI
spec.

## Historical Role

- Early layout planning for strategy, backtest, and compare pages
- Background material only
- Not part of the active implementation baseline

## Retained Conclusions

- Page responsibilities should stay separated between strategy list, strategy
  workspace, backtest detail, and compare views.
- Dense operational content belongs in structured panels and summaries instead of
  uncontrolled single-page sprawl.
- Diagnostics, runs, logs, and comparison outputs should stay subordinate to the
  current task context.
- UI structure should support truthful capability boundaries instead of exposing
  speculative product surface.
