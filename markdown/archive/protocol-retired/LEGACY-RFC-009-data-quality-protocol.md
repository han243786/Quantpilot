# Legacy RFC-009 Data Quality Protocol

数据质量协议定义系统如何描述数据是否可信、是否完整以及是否适合继续流向上层模块。量化系统中很多问题并不是因为接口失败，而是因为看似成功返回的数据其实存在延迟、缺失、重复、字段漂移或数值异常。本协议要求这些问题被显式记录，而不是默默吞掉。

数据质量至少要覆盖来源可达性、响应完整性、记录唯一性、时间新鲜度、字段合法性和范围异常。质量信息既可以作为单条记录的附属描述，也可以作为批次级别的汇总说明。对于能够自动修正的问题，应记录修正行为；对于不能自动修正的问题，应向上层暴露风险等级和具体原因。这里的设计理念是，质量语义不能在系统成型之后再补，因为一旦上层已经开始依赖不透明的数据输入，再回过头补可信性约束，代价会很高。数据规范模块从一开始就把质量问题保留在输出结构里，是为了让后续所有模块都能在明面上处理不确定性。

本协议让数据规范模块不只是抓取和转换，还承担进入系统前的第一道可信性判断。后续的回测结果解释、策略行为分析和审计追踪都需要依赖这一层质量语义。
