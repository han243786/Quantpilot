## 目标

### S0-1 ✅: `summarize_equity_curve` 接入 `compute_backtest_metrics`

**问题**: v1.0.7 回测记录触发 artifact rebuild 时，`summarize_equity_curve` 不调用 `compute_backtest_metrics`，导致所有分组指标（夏普/索提诺/盈亏比等）变为零值。

**方案**: 在 `backtest_artifacts.rs` 的 `build_metrics_artifact()` 中，`summarize_equity_curve` 调用后追加 `compute_backtest_metrics(&mut summary, &sessions, &equity_curve, &benchmark_curve)`。

**验收**:
```bash
cargo test --test api_backtest load_v1_0_7_backtest  # 旧回测加载后新指标非零
```

**状态**: v1.1.0 closeout 中已修复。

### S0-2 ✅: LatencyModel 接入 FillEngine

**问题**: `LatencyModel::Normal/PerExchange` 定义在 `slippage.rs` 中，`delay_ms()` 方法从未被调用。`pseudo_random_normal()` 实现也是错误的（产生均匀分布而非正态分布）。

**方案**:
1. ~~重写 `pseudo_random_normal()` 为 Box-Muller 变换~~ → `build_fill_report` 已在 v1.1.0 接入 LatencyModel
2. 补全 `build_fill_report_from_open` 的延迟调用（v1.1.1 修复）
3. 删除 `FastBacktestSandbox::latency_assumption_ms` 遗留字段，改为 `set_execution_assumptions`
4. `runtime_api.rs` 调用点同步迁移

**验收**:
```bash
cargo test fill_engine  # 10/10 通过
cargo check --workspace  # 通过
```

**状态**: v1.1.1 已修复。

## P2 — 下个版本 ✅

### P2-1 `compute_daily_returns` 重命名为 `compute_step_returns`

**问题**: 函数名暗示日收益率，实际计算的是 equity_curve 步间收益率（可以是小时/日/周）。
**方案**: 重命名函数 + 添加文档注释说明单位取决于 equity_curve 的时间间隔。
**文件**: `qrpc_runtime/src/backtest_metrics.rs`

### P2-2 零 PnL 交易连胜/连亏计数修复

**问题**: `pnl == 0.0` 被归类为亏损并打断连胜。
**方案**: `is_win = pnl > 0.0` 改为三态判断: `Some(true)` for >0, `Some(false)` for <0, `None` for ==0（不打断当前连胜）
**文件**: `qrpc_runtime/src/backtest_metrics.rs`

### P2-3 benchmark equity zip 对齐加固

**问题**: `compute_benchmark_equity` 依赖 `timeline.providers` 与 `initial_prices` 的 zip 对齐，若 provider 顺序变化则断裂。
**方案**: 改用 `data_id` 键匹配而非位置索引。
**文件**: `qrpc_runtime/src/sandbox/mod.rs`

### P2-4 `period_returns` 空序列化优化

**问题**: 空的 `benchmark_equity_curve` 和 `period_returns` 始终序列化为 `[]`。
**方案**: 添加 `#[serde(skip_serializing_if = "Vec::is_empty")]` 到两个字段。
**文件**: `qrpc_core/src/lib.rs`

### P2-5 VaR/CVaR 最小样本量提升

**问题**: n<20 时 VaR 退化为单一最差日收益率。
**方案**: 最小样本量从 5 提升到 20，不足时返回 `(0.0, 0.0)` 并在前端显示 "-"。
**文件**: `qrpc_runtime/src/backtest_metrics.rs`

### P2-6 偏度/峰度最小样本量提升

**问题**: n=3 时峰度公式除零。
**方案**: 最小样本量提升到 12，不足时返回 `(0.0, 0.0)`。
**文件**: `qrpc_runtime/src/backtest_metrics.rs`

### P2-7 空 `benchmark_equity_curve` 前端跳过渲染

**问题**: 无基准时 `EquityOverlayChart` 仍渲染灰色虚线（值为 0）。
**方案**: `benchA` 为空时跳过 `benchmark` dataKey，或传 `null` 给 `connectNulls`。
**文件**: `frontend/src/pages/BacktestComparePage.jsx`

### P2-8 320px 窄屏指标卡片溢出

**问题**: 5 列 Hero 指标卡片在 320px 宽度溢出。
**方案**: `account-metric-grid` 在小屏使用 `grid-template-columns: repeat(auto-fill, minmax(140px, 1fr))`。
**文件**: `frontend/src/pages/backtest-analysis.css`

## 决策纪录

### 决策 1: LatencyModel 替代 latency_assumption_ms

**选项**:
- A: LatencyModel::Fixed 替代 `latency_assumption_ms`，移除旧字段
- B: 保留 `latency_assumption_ms` 作为 LatencyModel::Fixed 的别名

**选择**: A

**理由**: GP §5.4 禁止绕过统一路径。保留两个延迟设置入口会导致用户困惑（哪个生效？）。直接迁移，向前兼容通过 serde default 保证。

### 决策 2: corrupted JSON 降级策略

**选项**:
- A: 任一文件损坏即拒绝全部加载（当前行为）
- B: 尽力加载可用文件，如 metrics.json 损坏则显示默认指标

**选择**: B

**理由**: GP §1.2 跨三层验证要求优雅降级而非硬失败。metadata 文件损坏应允许用户查看可用的部分数据，UI 中标记"部分数据不可用"。
