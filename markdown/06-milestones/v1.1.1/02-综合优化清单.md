## S0 — 阻断发布

### S0-1 旧回测 artifact rebuild 丢失新指标

**严重度**: 阻断
**诱错角色**: 7 (API 调用者)
**策略**: GP §1.2 (跨三层验证), GP §5.2 (禁止静默忽略)
**问题**: `summarize_equity_curve` 不调用 `compute_backtest_metrics`，v1.0.7 回测记录 rebuild 后所有 v1.1.0 分组指标为零。
**方案**:
1. 读取 `backtest_artifacts.rs` `build_metrics_artifact()` 函数
2. 在 `summarize_equity_curve` 调用后追加 `compute_backtest_metrics(&mut summary, &sessions, &equity_curve.points, &benchmark_equity_curve)`
3. 若无 sessions 可用，至少从 equity_curve 计算 drawdown/risk_adjusted 指标
**验收**:
```bash
cargo test --test api_backtest v1_0_7_artifact_rebuild_preserves_metrics
cargo test backtest_artifacts summarize_equity_curve_includes_v1_1_0_metrics
```

### S0-2 LatencyModel 死代码激活

**严重度**: 阻断
**诱错角色**: 5 (运维者), 6 (安全研究者)
**策略**: GP §5.3 (禁止 stub), GP §5.1 (禁止硬编码)
**问题**: `LatencyModel::Normal/PerExchange` 定义但从未调用；`pseudo_random_normal` 实现错误（均匀分布）。
**方案**:
1. `slippage.rs`: `pseudo_random_normal` 改为 Box-Muller 变换
2. `slippage.rs`: 补全 `delay_ms()` 文档
3. `fill_engine.rs`: `build_fill_report` 和 `build_fill_report_from_open` 调用 `assumptions.latency.delay_ms(exchange, seed)`
4. `sandbox/mod.rs`: 移除 `latency_assumption_ms` 字段，`with_execution_assumptions` 中通过 LatencyModel::Fixed 替代
5. 反向兼容: 旧 `set_latency_assumption_ms` 方法标记 deprecated，内部转为 LatencyModel::Fixed
**验收**:
```bash
cargo test slippage::tests::box_muller_normal
cargo test fill_engine::tests::latency_model_offsets_fill_time
cargo test sandbox::tests::latency_model_integration
```

## P1 — 发布前必须

### P1-1 `compute_fill_price` NaN 守卫

**严重度**: 高
**诱错角色**: 6 (安全研究者)
**策略**: GP §5.1 (禁止硬编码), NaN 传播到 portfolio 导致整条权益曲线崩溃
**问题**: 腐败的市场数据 (NaN price/bid/ask) 通过 `compute_fill_price` → `apply_fill_to_portfolio` 传播，使 `cash_balance` 变为 NaN。
**方案**:
1. `slippage.rs` `compute_fill_price` 函数体开头添加:
   ```rust
   if !market.price.is_finite() {
       return order.reference_price;
   }
   ```
2. `fill_engine.rs` `to_extended` 中添加 NaN 检查
**验收**:
```bash
cargo test slippage::tests::nan_price_falls_back_to_reference
cargo test fill_engine::tests::nan_market_data_does_not_corrupt_portfolio
```

### P1-2 跨标的 dead code 移除 + 多策略缩放修复

**严重度**: 高
**诱错角色**: 4 (插件开发者), 5 (运维者)
**策略**: GP §5.2 (禁止静默忽略)
**问题**: `max_correlated_long_exposure` 读取后未使用；多策略迭代时重复缩放已缩放值。
**方案**:
1. `qrpc_core_ir/src/lib.rs`: 移除 `RiskPolicy::max_correlated_long_exposure` 字段
2. `risk_checker.rs:apply_cross_symbol_constraints`: 操作前克隆原始 decisions 快照
3. 所有 construction site 中移除 `max_correlated_long_exposure` 字段
**验收**:
```bash
cargo test risk_checker::tests::cross_symbol_multi_policy_scale_preserved
cargo check --workspace  # 确认字段移除无残留
```

### P1-3 `storage/cache/historical/` 生命周期注册

**严重度**: 高
**诱错角色**: 5 (运维者)
**策略**: GP §7.1 (三级分类), GP §7.2 (全局配额)
**问题**: `storage/cache/historical/` 未在 `storage_lifecycle.rs` 中注册，无配额控制、无启动清理。过期缓存文件永久积累。
**方案**:
1. `storage_lifecycle.rs`: 添加 `"cache" => StorageLifecycle::Temporary`（7 天 TTL，DEV 下 1 天）
2. `data_module.rs`: `persist_historical_cache` 调用 `ensure_storage_quota`
3. `data_module.rs`: 启动时扫描 `storage/cache/historical/`，删除超过 TTL 的文件
**验收**:
```bash
cargo test storage_lifecycle::tests::cache_directory_has_lifecycle
cargo test data_module::tests::historical_cache_respects_ttl
```

### P1-4 回测 JSON 损坏时优雅降级

**严重度**: 高
**诱错角色**: 10 (系统管理员)
**策略**: GP §1.2 (跨三层验证)
**问题**: 7 个强制文件任一损坏导致整条记录返回 500，无降级路径。
**方案**:
1. `load_backtest_record_from_directory`: 改为 `if let Ok` 按文件加载
2. `manifest.json` 损坏 → 拒绝加载（最小必要信息）
3. `metrics.json` 损坏 → summary 使用 Default
4. `trade_ledger.json` 损坏 → 空台账
5. `equity_curve.json` 损坏 → 空曲线
6. `event_log.json` 损坏 → 空事件列表
7. 返回的 response 中添加 `degraded: true` 标记
**验收**:
```bash
cargo test backtest_artifacts::tests::partial_record_load_with_corrupted_metrics
cargo test api_backtest::tests::degraded_record_returns_200_with_flag
```

### P1-5 `.saving-` 临时目录 TTL 缩短

**严重度**: 高
**诱错角色**: 10 (系统管理员)
**策略**: GP §7.1 (三级分类), §7.5 (DEV 激进清理)
**问题**: `PROMOTION_WORK_DIR_TTL_MS` = 24h，DEV 模式也是 24h。崩溃后 `.saving-` 孤儿目录残留一整天。
**方案**:
1. `PROMOTION_WORK_DIR_TTL_MS`: 24h → 1h
2. DEV 模式: 1h → 5min
3. 启动清理显式检查和删除 `.saving-` 前缀目录
**验收**:
```bash
cargo test storage_lifecycle::tests::saving_dir_ttl_reduced
cargo test storage_lifecycle::tests::saving_dir_dev_mode_5min_ttl
```

### P1-6 负夏普视觉区分

**严重度**: 中
**诱错角色**: 8 (前端用户)
**策略**: GP §8.1 (配色饱和度限制)
**问题**: `sharpeColor()` 对负夏普返回 `var(--ad-text)`（中性灰），与不可用值相同。
**方案**: `sharpeColor()` 增加 `if (value < 0) return "var(--ad-error)"`
**验收**:


## P2 — 两个里程碑内

### P2-1 函数重命名 `compute_daily_returns` → `compute_step_returns`

**严重度**: 中
**诱错角色**: 9 (数据分析师)
**问题**: 函数计算 equity_curve 步间收益而非日历日收益，名称误导。用于年化波动率计算时对非日线数据产生错误。
**方案**: 重命名并添加 `/// 返回 equity_curve 连续点间的收益率。若 equity_curve 不是日频，调用方应处理时间间隔。`
**验收**: `cargo test backtest_metrics`

### P2-2 零 PnL 连胜/连亏修复

**严重度**: 低
**诱错角色**: 9 (数据分析师)
**问题**: `pnl == 0.0` 归类为亏损并打断连胜。
**方案**: 三态判断: `Some(true)` for pnl > 0, `Some(false)` for pnl < 0, continue for pnl == 0。
**验收**: `cargo test backtest_metrics zero_pnl_streak`

### P2-3 benchmark equity zip 对齐加固

**严重度**: 低
**诱错角色**: 9 (数据分析师)
**问题**: `compute_benchmark_equity` 依赖 provider 与 initial_price 的位置对齐。
**方案**: 改用 `data_id` HashMap 匹配。
**验收**: `cargo test sandbox benchmark_equity_alignment`

### P2-4 空序列化优化

**严重度**: 低
**诱错角色**: 5 (运维者)
**问题**: 空 `benchmark_equity_curve` / `period_returns` 始终序列化为 `[]`。
**方案**: 添加 `#[serde(skip_serializing_if = "Vec::is_empty")]`
**验收**: 检查空回测 JSON 中无 `"benchmark_equity_curve":[]`

### P2-5 VaR/CVaR 最小样本量 → 20

**严重度**: 低
**诱错角色**: 7 (API 调用者), 9 (数据分析师)
**问题**: n<20 时 VaR/CVaR 退化为单一最差日。
**方案**: 最小样本量 `5 → 20`，不足时返回 `(0.0, 0.0)`，前端显示 "-"。
**验收**: `cargo test backtest_metrics var_cvar_min_samples`

### P2-6 偏度/峰度最小样本量 → 12

**严重度**: 低
**诱错角色**: 9 (数据分析师)
**问题**: n=3 时峰度公式除零。
**方案**: 最小样本量 `3 → 12`，不足时返回 `(0.0, 0.0)`。
**验收**: `cargo test backtest_metrics skewness_min_samples`

### P2-7 空基准 EquityOverlayChart 跳过渲染

**严重度**: 低
**诱错角色**: 8 (前端用户)
**问题**: 无基准时灰色虚线与 Y=0 重合。
**方案**: `benchA.length === 0` 时跳过 `benchmark` Line。
**验收**: `npm run build && npm run test`

### P2-8 320px 窄屏指标卡片溢出

**严重度**: 低
**诱错角色**: 8 (前端用户)
**问题**: 5 列 Hero 卡片在 320px 溢出。
**方案**: `grid-template-columns: repeat(auto-fit, minmax(140px, 1fr))`
**验收**: `npm run build`
