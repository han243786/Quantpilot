# v3.4.0 综合优化清单

> 版本: MINOR | 基准: v3.3.0 closeout | 来源: 遗留项 + 诱错审计

---

## P1 高优 (2 项)

### P1-1: 执行端前端 i18n 模块

**严重度**: P1
**来源**: v3.3.0诱错 F-1
**策略**: GP §2.5 (前端字符串 t() 包裹)
**问题**: 执行端所有 UI 字符串硬编码中文，无法国际化。ExecutorTopBar/OrderPanel/AssetPanel/KlineChart/StrategyGraphPanel 均未使用 t()
**方案**:
1. 创建 `frontend-executor/src/i18n/index.js` — 轻量 i18n 模块 (zh-CN + en-US)
2. 在 `main.jsx` 包裹 `<I18nProvider>`
3. 逐组件替换硬编码字符串为 `t("...")`
4. ExecutorTopBar: "运行中"/"异常"/"待机"/"紧急停止"
5. OrderPanel: orderStatusText() 硬编码
6. AssetPanel: "资产"/"总权益"/"现金余额"/"持仓"
7. KlineChart: 加载态文字
8. ExecutorApp: "等待策略部署"/"确认紧急停止"等
**验收**: `grep -r '["\x{201c}][\x{4e00}-\x{9fff}]' frontend-executor/src/components/` 返回0

### P1-2: React.memo 剩余包裹

**严重度**: P1
**来源**: v3.3.0诱错 F-2
**策略**: 性能优化
**问题**: OrderPanel/AssetPanel/StrategyGraphPanel 未包裹 React.memo，父组件 3s 轮询导致无条件重渲染
**方案**:
1. OrderPanel: `export default memo(function OrderPanel({ strategyId }) {...})`
2. AssetPanel: 同上
3. StrategyGraphPanel: 同上 (strategyId 替代 strategy 对象 — 与 KlineChart 同模式)
**验收**: Chrome React Profiler: 3s 轮询时仅 ExecutorApp 重渲染，子组件不变

## P2 中优 (4 项)

### P2-1: api_guard Phase 5 HMAC 验证激活

**严重度**: P2
**来源**: GP §5.3 (禁止 stub)
**策略**: GP §2.7 (实时执行安全边界)
**问题**: `verify_request_signature()` 未激活，api_guard_middleware 为透传
**方案**:
1. 在 `api_guard_middleware` 中读取请求头 `X-Executor-Signature` + `X-Executor-Timestamp`
2. 调用 `verify_request_signature(body, sig, ts)`
3. 失败返回 401 Unauthorized
4. health 端点跳过验证
**验收**: 无签名请求→401; 正确签名→通过; 过期时间戳→400

### P2-2: 告警 resolve_condition 自动恢复

**严重度**: P2
**来源**: GP §9.3 (告警引擎)
**策略**: GP §9.3 (每条告警规则必须有恢复条件)
**问题**: AlertRule 缺少 `resolve_condition` 字段，告警仅能手动 ack
**方案**:
1. 在 `AlertRule` 结构体添加 `resolve_condition: Option<String>`
2. 修改 `trigger_alert_check`: 对已触发的告警评估 resolve_condition
3. 条件满足→自动 `Resolved`
4. 10条默认规则补充恢复条件表达式
**验收**: 模拟 data_freshness 恢复→告警自动 Resolved

### P2-3: 刷新令牌轮换

**严重度**: P2
**来源**: GP §2.8 (用户认证安全)
**策略**: 安全最佳实践
**问题**: JWT refresh token 无轮换检测，旧 token 可无限刷新
**方案**:
1. 刷新时生成新 refresh token → 废弃旧 token
2. 检测到旧 token 被重放→撤销所有该用户的 token
3. 存储已废弃 token 的哈希 (24h TTL)
**验收**: 旧 refresh token 重复使用→401 + 全部 token 撤销

### P2-4: 文件头版本号批量更新

**严重度**: P2
**来源**: v3.3.0诱错 I-2
**策略**: 文档一致性
**问题**: 20+ 文件头注释写 v3.0.0，代码已是 v3.4.0
**方案**: 批量替换 `/// v3.0.0:` → `/// v3.4.0:` (20个文件)
**验收**: `grep -r "v3\.0\.0" src-executor/ frontend-executor/src/ --include="*.rs" --include="*.jsx" | grep -v "S0修复\|v3.0.1\|v3.0.2\|v3.2\|v3.3"` 返回0
