# v4.6.0 规划方案 — v4 LiveActual 模式 + OKX 实盘

> 版本类型: MINOR | 基准: v4.5.0 | 终稿确认: 2026-05-25
> 来源: v4.0.0 Phase 6/7 自然延伸 + v4.2.0 执行端集成基础 + 四种运行时模式中 LiveActual 的 v4 路径

---

## 目标

v4.6.0 把 v4 状态机运行时从"纯模拟"扩展到"真实下单"。当前 v4 runtime 只支持 PaperSimulated (本地模拟成交)。本版本接入 OKX testnet 真实订单路径，启用 `LiveActual` 模式。

1. **v4 LiveActual runtime** — v4 策略在 LiveActual 模式下通过 Risk Plane → ExecutionMachine → OKX REST 真实下单
2. **ProviderNative 能力验证** — ExecutionMachine 在 LiveActual 模式下只接受 `provider_native` 能力，拒绝 `runtime_simulated`
3. **v4 实盘监控** — 执行端前端实时展示 v4 LiveActual 订单/成交/持仓/风控状态

核心变化:

- `V4PaperSimulatedRuntime` 扩展为支持多模式的 `V4Runtime`，`LiveActual` 变体接入 OKX REST
- Risk Plane 在 LiveActual 模式下强制执行 `risk_precheck → risk_order_check → risk_postcheck`
- 真实订单路径有完整拦截测试

## 非目标

- 不在 v4.6.0 支持 LiveSimulated (Live 账户 + 本地模拟，流向 v4.7.0+)
- 不改变 v3.7.1 OKX 实盘路径
- 不接入新交易所 (仍为 OKX testnet)
- 不开放无 Risk Plane 的真实下单

## W1 — v4 LiveActual runtime (3 天)

### W1-1 Runtime 模式分发

**文件**: `qrpc_runtime/src/v4_runtime.rs`

**方案**: `V4PaperSimulatedRuntime` 重构为 `V4Runtime`，根据 `RuntimeTradingMode` 分发：
- `PaperSimulated` → 现有路径 (本地撮合)
- `LiveActual` → OKX REST 下单 + Risk Plane 强制

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `qrpc_runtime/src/v4_runtime.rs` | `V4PaperSimulatedRuntime` → `V4Runtime`，内部分发 |
| 2 | 同上 | `new_for_mode(LiveActual)` 构造器 |

**约束**: GP §1.9 (Risk Plane 不可绕过)
**验收**: 创建 v4 LiveActual runtime → `venue_adapter_boundary.provider_order_submission_allowed = true`

### W1-2 Risk Plane LiveActual 强制执行

**方案**: LiveActual 模式下：
- `risk_plane.required = true` 不可覆盖
- `evaluate_risk_plane_for_execution()` 拒绝任何未经 Risk Plane 批准的 Execution 事件
- `emergency_halt` 信号 → 立即取消全部挂单 + 禁止新单

**验收**: Risk Plane 拒绝 → ExecutionMachine 不发送订单 → 事件日志记录 `risk_plane_rejected`

### W1-3 OKX REST 订单提交

**文件**: `qrpc_runtime/src/v4_runtime.rs`, `src-executor/okx_rest.rs`

**方案**: LiveActual ExecutionMachine 调用 OKX REST API 提交真实订单。复用执行端 `okx_rest.rs` 的签名逻辑。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `qrpc_runtime/src/v4_runtime.rs` | ExecutionMachine LiveActual 变体 → `submit_provider_order()` |
| 2 | 同上 | Provider 响应 → `order_acknowledged` / `order_rejected` 事件 |
| 3 | 同上 | 成交回报 → `order_filled` / `fee_charged` / `portfolio_changed` 事件 |

**约束**: GP §2.7 (实时执行安全: HMAC-SHA256, 速率限制, 错误清洗)
**验收**: v4 LiveActual 策略 → OKX testnet 产生真实订单 → testnet 可查询

### W1-4 ProviderNative 能力门禁

**方案**: `evaluate_execution_capabilities_for_execution()` 在 LiveActual 模式下：
- 只接受 `CapabilitySupportSource::ProviderNative` 的能力
- `RuntimeSimulated` → `ModeRejected`
- 拒绝原因写入事件日志和 v4 evidence

**约束**: GP §1.10 (Execution 能力来源显式标记)
**验收**: v4 LiveActual 策略声明 `limit` 能力 → OKX 原生支持的 `limit` 通过 → `trailing_stop` (仅 runtime_simulated) → ModeRejected

## W2 — 实盘监控与安全 (1.5 天)

### W2-1 执行端 v4 LiveActual 监控

**文件**: `frontend-executor/src/components/V4EvidencePanel.jsx`

**方案**: 扩展执行端 v4 证据面板，LiveActual 模式展示：
- 真实订单状态 (acknowledged/filled/rejected)
- Provider order ID (交易所订单 ID)
- Risk Plane 实时决策流
- `real_order_path_unlocked` 状态指示灯

**验收**: v4 LiveActual 运行 → 执行端面板显示 OKX order ID + 实时成交

### W2-2 拦截测试

**方案**: 新增 Rust 测试，验证以下场景被正确拦截：
- 无 Risk Plane 的 graph → LiveActual 模式拒绝启动
- Risk Plane 拒绝 → 订单不发送
- `emergency_halt` → 挂单全部取消
- `runtime_simulated` 能力 → LiveActual 模式拒绝

**验收**: 全部拦截测试通过

## 兼容性与迁移

- v4.6.0 不改变 v3.7.1 OKX 实盘路径；v4 LiveActual 仅通过 v4 runtime mode 独立进入。
- LiveActual 必须保留 Risk Plane required 与 ProviderNative capability gate；缺少任一条件时 fail-closed。
- OKX testnet 真下单依赖外部凭证与网络环境，允许在 closeout 中作为延后 E2E，但不得解除真实下单安全门禁。
