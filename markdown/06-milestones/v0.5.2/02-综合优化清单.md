## S0 — 测试套件修复（1.5 天）

### S0-1 后端集成测试编译修复

**严重度**: 🔴 阻断 | **来源**: v0.5.1 回归 | **策略**: §5.5 端到端验证

**问题**:

`cargo test --workspace` 编译失败 (65 错误)。根因是 `tests/common/mod.rs` 使用 `include!("../../src/main.rs")` 将 `main.rs` 嵌入 `tests::common::backend` 模块。当 `src/` 中文件使用 `crate::credential_vault::CredentialVault` (`test_runner.rs:3`) 等跨模块引用时, `crate::` 在集成测试上下文中解析失败。

受影响的引用链:
- `src/test_runner.rs:3` — `use crate::credential_vault::CredentialVault`
- `src/alert_engine.rs:301,366,367` — `crate::storage_lifecycle::*`
- `src/app_runtime_helpers.rs:52,56` — `crate::credential_vault::CredentialVault`, `crate::safe_log::*`
- `src/safe_log.rs:64` — `crate::app_runtime_helpers::*`
- `src/chaos_experiment.rs:234,235` — `crate::storage_lifecycle::*`

**方案**:

两种可行方案 (推荐方案 A):

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **A** | `lib.rs` 通过 `pub use` 导出 `credential_vault`, `storage_lifecycle`, `safe_log`, `app_runtime_helpers` 等模块, `src/` 文件改用 `quantpilot::*` 引用 | 不改测试基础设施; 最小改动 | 增加公共 API 面 |
| **B** | 重构 `tests/common/mod.rs` 的 `include!()` 模式, 改为编译 `quantpilot` 为 lib crate, 集成测试通过 `use quantpilot::*` 引用 | 从根本上解决 include 脆弱性 | 改动大, 需要将 `main.rs` 逻辑提取到 `lib.rs` |

**推荐步骤 (方案 A)**:

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/lib.rs` | 添加 `pub mod credential_vault;` `pub mod storage_lifecycle;` `pub mod safe_log;` `pub use app_runtime_helpers::*;` |
| 2 | `src/test_runner.rs:3` | `use crate::credential_vault::CredentialVault` → `use quantpilot::credential_vault::CredentialVault` (如为 bin-only 则保留 crate::) |
| 3 | 全部 `src/*.rs` | 确保所有被 tests/ 引用的模块可以通过 `crate::` 或 `quantpilot::` 解析 |
| 4 | `tests/common/mod.rs` | 如需要, 在 `backend` 模块中添加 `use quantpilot::*;` |
| 5 | 全部 | `cargo test --workspace` 验证 |

**验收**:
- `cargo test --workspace` 编译通过
- 所有集成测试运行通过 (或跳过 — 不要求通过, 但要求编译)
- `grep -rn "crate::credential_vault\|crate::storage_lifecycle\|crate::safe_log\|crate::app_runtime_helpers" tests/` 返回 0
