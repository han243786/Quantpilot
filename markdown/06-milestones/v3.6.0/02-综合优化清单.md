### U3: 长操作添加阶段进度反馈

**严重度**: P1
**来源**: UX诱错 §操作反馈
**问题**: 编译/回测/部署仅有"X中..."按钮文字，无进度条或阶段指示
**方案**:

| 操作 | 实现 |
|------|------|
| 编译 | 按钮旁显示阶段文字: `compiling... → 语法分析中... → 类型推导中... → 代码生成中...`。利用后端返回的诊断阶段信息 |
| 回测 | 后端 `run_backtest` 每 bar 返回进度 → 前端 progress bar `[████░░░░] 45% (225/500 bars)` |
| 部署 | 三步文字: `部署中 ①编译中 → ②打包中 → ③发送中` |

**验收**: 点击编译 → 按钮旁出现阶段文字变化(≥2种不同文字)

### U4: 状态标签全平台统一

**严重度**: P1
**来源**: UX诱错 §一致性
**问题**: 主前端和执行端对同一状态使用不同标签
**方案**: 统一映射表

| 状态 | 主前端(旧) | 执行端(旧) | 统一 |
|------|-----------|-----------|------|
| idle | 空闲 | 待机 | → "空闲" |
| running | 运行中 | 运行中 | → "运行中" |
| error | 错误 | 异常 | → "错误" |
| stopped | 已停止 | (无) | → "已停止" |

修改: `runtimeStatus.js` 和 `ExecutorTopBar.jsx` 同步到此表
**验收**: `grep -r "待机\|异常" frontend-executor/src/ --include="*.jsx"` 返回0

### U5: 模板库首次默认展开

**严重度**: P1
**来源**: UX诱错 §可发现性
**问题**: 模板库默认折叠, 新用户难以发现
**方案**: `StrategyHubTemplateLibrarySection.jsx` 的 `isExpanded` 初始值: 检查 `localStorage` 有无访问记录 → 无记录则 `true`, 有记录则用用户偏好
**验收**: 清除 localStorage → 打开策略中心 → 模板库已展开

## P2 — 体验不佳 (5项)

### U6: 错误码和HTTP状态码人文化

**严重度**: P2
**来源**: UX诱错 §错误信息
**问题**: `QS0501`/HTTP `404`/`500` 直接显示
**方案**:
1. `errorText.js:humanizeErrorText` 追加错误码映射: `QS0501`→"数据不足", `QS0403`→"除零错误"
2. HTTP 状态码 → 语义: `404`→"请求的资源不存在", `500`→"服务器内部错误"
3. `runtimeApproval.js:8` 使用 `humanizeErrorText` 包装

**验收**: 触发编译错误 → UI 不显示 `QS0xxx` 裸码, 显示中文描述

### U7: 全局通知系统

**严重度**: P2
**来源**: UX诱错 §操作反馈
**问题**: 通知分散在各组件, 无中心化 toast
**方案**:
1. 创建 `frontend/src/components/Toast.jsx`: 接收 `{ type, message, id }`
2. 创建 `frontend/src/hooks/useToast.js`: `const toast = useToast(); toast.success("保存成功")`
3. App.jsx 顶部渲染 `<ToastContainer />`
4. 现有 `setNotice`/`actionMsg` 逐步迁移到 toast

**验收**: 从任意组件调用 `toast.error("失败")` → 全局右上角出现红色toast

### U8: 后端自动恢复轮询

**严重度**: P2
**来源**: UX诱错 §错误恢复
**问题**: 后端恢复后前端不自动重连
**方案**: `graphStore.js` 添加心跳:
```js
if (capabilityStatus !== "ready") {
  setInterval(() => refreshCapabilities(), 30_000);
}
```
**验收**: 关闭后端→前端降级→重启后端→30s内自动恢复 "ready"

### U9: SSE 无限重连 + 浏览器 online 事件联动

**严重度**: P2
**来源**: UX诱错 §错误恢复
**问题**: SSE 最多5次重试后放弃, 不响应浏览器 online 事件
**方案**:
1. `graphStoreRuntimeTransport.js`: 移除5次上限, 最大间隔60s
2. 监听 `window.addEventListener("online", ...)` → 立即触发重连

**验收**: 断网→重连网→SSE自动恢复(不限次数)

### U10: 部署后策略管理UI

**严重度**: P2
**来源**: UX诱错 §连贯性
**问题**: 部署后无已部署策略面板
**方案**: `ExecutorApp.jsx` 空状态区域 → 显示已部署策略卡片列表(复用已有 `GET /strategies` 数据)。每卡片: 策略名 + 状态点 + start/stop 按钮
**验收**: 部署策略→执行端显示策略卡片(含启动按钮)
