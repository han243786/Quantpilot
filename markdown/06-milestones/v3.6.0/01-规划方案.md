# v3.6.0 规划方案 — 用户体验全量优化

> 版本类型: MINOR | 基准: v3.5.0 | 来源: UX诱错审计 (路由/连贯性/困惑点)
> 目标: 用户首次使用即能独立完成完整策略生命周期, 无需猜测或查阅文档

---

## 目标

- 消除 UI 中的编译器术语泄漏 (Strategy IR/Core IR/QS/lowering)
- 所有空状态附带下一步操作指引
- 长操作(编译/回测/部署)添加进度反馈
- 主前端与执行端状态标签/颜色统一
- 后端恢复后前端自动重连

## 非目标

- 不新增功能
- 不改变后端 API
- 不修改协议定义

## 方案

### P1 — 用户困惑 (5项)

| # | 问题 | 方案 |
|---|------|------|
| U1 | Strategy IR/Core IR/QS/lowering 术语暴露 | 替换: "Strategy IR"→"策略中间表示", "Core IR"→"核心中间表示", "QS"→"策略脚本", "lowering"→"代码转换"。左侧导航"QS"→"QuantScript" |
| U2 | 空状态缺操作指引 | 每个"暂无数据"追加引导句: 诊断面板→"点击编译按钮生成诊断", 审批面板→"运行模拟后AI提案自动生成", 事件流→"调整筛选条件或启动模拟" |
| U3 | 编译/回测/部署无进度 | 编译: 按钮旁添加阶段文字("语法分析中...→类型推导中...→代码生成中...")。回测: 后端已有 per-bar 进度, 前端用 progress bar 展示。部署: 三步文字("编译中→打包中→发送中") |
| U4 | 状态标签不一致 | 统一为: idle="空闲", running="运行中", error="错误", stopped="已停止"。同步主前端和执行端 |
| U5 | 模板库默认折叠 | 首次访问(`localStorage` 无记录)默认展开; 后续记住用户偏好 |

### P2 — 体验不佳 (5项)

| # | 问题 | 方案 |
|---|------|------|
| U6 | 错误码暴露 (QS0501/HTTP 状态码) | 在 `humanizeErrorText` 中追加错误码→中文映射; HTTP 状态码替换为语义描述(404→"请求的资源不存在") |
| U7 | 通知系统分散 | 实现全局 toast 栏: 成功(绿)/错误(红)/信息(蓝), 3秒自动消失, 错误持久。所有组件通过 `useNotification()` hook 触发 |
| U8 | 后端恢复不自动重连 | 在 `graphStore.js` 添加 30s 心跳轮询: `capabilityStatus !== "ready"` → 每30s调 `refreshCapabilities()` |
| U9 | SSE 最多5次重试后放弃 | 改为无限重试, 最大间隔60s。连接浏览器 `online` 事件, 恢复上线后立即重连 |
| U10 | 部署后无策略管理 UI | 执行端 `ExecutorApp.jsx` 的"等待策略部署"空状态改为"已部署策略"列表(复用已有 `/strategies` 端点数据)。添加基础的 start/stop 按钮 |

### P3 — 建议 (2项)

| # | 问题 | 方案 |
|---|------|------|
| U11 | 部署文案不一致 | 统一为"部署到执行器" |
| U12 | 中文 locale 含英文术语 | `zh-CN.js` 中的 "Core IR 工件"→"核心中间表示工件"; "Strategy IR"→"策略中间表示" |

## 验收

| # | 验收项 | 标准 |
|---|--------|------|
| 1 | 术语清零 | `grep -r "Strategy IR\|Core IR" frontend/src/components/ frontend/src/pages/ --include="*.jsx"` 返回0 (仅注释/变量名除外) |
| 2 | 空状态有指引 | 每个"暂无"消息旁有"请..."引导句, 抽查5处 |
| 3 | 编译有进度 | 编译按钮旁显示≥2个阶段文字变化 |
| 4 | 状态标签统一 | 主前端和执行端 idle/running/error/stopped 标签一致 |
| 5 | 模板默认展开 | 清除 localStorage → 打开策略中心 → 模板库已展开 |
| 6 | 后端恢复 | 关闭后端→前端显示降级→重启后端→30s内自动恢复 |
| 7 | SSE无限重连 | 断开网络→SSE断→恢复网络→自动重连(不限于5次) |
| 8 | 编译+测试 | `cargo check --workspace && cargo test --bin executor ≥12` |
| 9 | 前端构建 | `npx vite build ×2` 成功 |
