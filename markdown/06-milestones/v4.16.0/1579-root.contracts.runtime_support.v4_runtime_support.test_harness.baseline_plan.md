## Frozen Test Surface

The movement must preserve:

- all sample Core IR and compatibility graph builders;
- all venue capability matrix fixtures;
- nested observation graph fixture;
- all 32 v4 runtime tests and assertions;
- test data literals and expected event names;
- test ordering assumptions where present.

Expected test discovery path change:

- from `v4_runtime::tests::*`
- to `v4_runtime::test_harness::*`

This path rename is acceptable because the test module owner changes, but the test functions and assertions must remain equivalent.

## Hard Boundaries

The next movement must not change:

- production v4 runtime behavior;
- public v4 DTOs or constants;
- constructor, replay, transition, risk/execution gate, or simulated execution code;
- test assertions, event payload expectations, or fixture semantics;
- live execution, plugin runtime, ops compatibility, metrics, QuantScript, plugin metadata, executor, backend, frontend, or release-transition optimization.

Stop before code movement if moving the tests requires:

1. changing any production runtime code beyond the test module declaration;
2. editing test assertions or fixture semantics;
3. splitting the test file into multiple children in the same step;
4. changing public API, runtime mode behavior, event schemas, or persistence owners.
