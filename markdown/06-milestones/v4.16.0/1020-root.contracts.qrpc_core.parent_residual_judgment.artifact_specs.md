## Selection Rationale

`artifact_specs` is selected because it is the next contiguous schema-bearing region after runtime protocol config:

- it owns `ArtifactDigestAlgorithm`, `ArtifactDigest`, and `canonical_json_sha256_digest`;
- it owns `RunModeSpec`, `BacktestReplaySource`, and `StrategyArtifactSourceKind`;
- it owns `DatasetSpec` and `DatasetSpec::from`;
- it owns `ExecutionAssumptionSpec`, `ExecutionAssumptionValueSource`, `ExecutionAssumptionSourceSummary`, and `ExecutionAssumptionSpec::from`;
- it owns `MarketDataSnapshotSpec` and `MarketDataSnapshotSpec::from_runtime_protocol`;
- it owns `RunSpec`, `RunSpecRuntimeProtocolInput`, and `RunSpec::from_runtime_protocol`;
- it owns `BacktestSpec` and `BacktestSpec::new`;
- it owns `StrategyArtifact`, `CoreIrArtifact`, `CompileArtifact`, and `CompileArtifactBundle`;
- it can move before runtime IO because runtime IO DTOs begin after the artifact bundle region and consume artifact specs only through normal public names.

## Same-Parent Parallel Judgment

`same_parent_parallel_children` remains inactive for this selection.

Artifact specs contain public protocol/schema surfaces plus canonical digest behavior. A serial extraction protects digest determinism, schema field order expectations, and crate-root facade stability before runtime IO contracts move.
