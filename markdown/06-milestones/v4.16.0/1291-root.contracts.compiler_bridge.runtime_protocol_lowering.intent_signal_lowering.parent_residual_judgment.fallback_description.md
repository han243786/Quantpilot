## Selection Rationale

`fallback_description` is selected next because it is the largest remaining cohesive behavior pocket in `qrpc_compiler/src/runtime_protocol_lowering/intent_signal_lowering.rs`:

- it owns `describe_runtime_intent_condition`;
- it owns raw fallback text for MA/SMA, LongTermSell, RSI, MACD, Momentum, ZScore, and QuoteObserve intents;
- it owns spread-observe fallback formatting and uses parent-owned decode helpers through the parent boundary;
- it is separate from structured condition construction, which is already closed under `condition_lowering`;
- it is separate from intent-kind mapping, which is a small queued residual;
- moving it behind one parent-mediated call can reduce the parent file without changing public APIs or Core IR output.

## Same-Parent Parallel Judgment

`same_parent_parallel_children` remains inactive for this selection.

`fallback_description` and `intent_kind_mapping` are same-parent residuals, but they differ in behavior shape: fallback description is text/reporting fallback logic, while intent-kind mapping is a small enum conversion. The faster safe path is to finish the larger fallback child first, then reassess whether the remaining mapping is worth a separate physical split or should close with the parent facade.
