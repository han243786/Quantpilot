Freeze the formal QuantScript syntax and public AST/type/HIR DTO surface before any code movement.

## Equivalence Requirements

Future movement must preserve:

- formal QS syntax acceptance and rejection behavior;
- parser error message shape where surfaced by tests or API callers;
- AST enum/struct names and public field shapes;
- test block and step block parsing;
- type annotation parsing behavior;
- HIR DTO type names, field names, and clone/debug/serde-free Rust shape;
- crate-level public re-exports from `quantscript::*`;
- downstream imports in `src/lib.rs`, `src/test_runner.rs`, `src/compile_diagnostics.rs`, backend graph conversion, and integration tests.

## Forbidden In This Child

Do not move or change:

- legacy config compatibility parser and deprecated entrypoints in `quantscript/src/lib.rs`;
- typed resolution logic in `resolve.rs`;
- diagnostics and analysis logic in `analysis.rs` or `diagnostics.rs`;
- normalization/evaluation logic in `evaluator.rs`;
- lowering logic under `quantscript/src/lowering/*`;
- v4 static audit or handoff logic;
- test-plan extraction behavior;
- backend, runtime, executor, frontend, plugin metadata, or release-transition behavior.

## Expected Movement Shape

If BE-002FX-02 performs extraction, it should be a facade-only structural move:

- preserve `quantscript::*` public imports;
- keep parent-mediated exports through `quantscript/src/lib.rs`;
- avoid changing downstream caller paths;
- avoid child-to-child shortcuts from parser to resolve/lowering;
- keep file-level modules stable unless the actual move proves a clean parent facade can reduce coupling without increasing governance cost.

If the implementation inspection shows the current `script.rs` + `types.rs` + `hir.rs` split is already the optimal physical boundary, BE-002FX-02 may become a no-code structural closeout proposal instead of forcing a cosmetic move.
