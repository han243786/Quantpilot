## Baseline Decision

Freeze `intent_collection_orchestration` for actual extraction.

The next Rust movement may create a child module under `quantscript/src/lowering/intents/` and move only the statement traversal and top-level `infer_intents` orchestration. `intents_from_condition` must remain parent-owned in this wave because it already contains specialized MA crossover construction and condition-to-builder dispatch logic.

## Approved Movement Scope

Move only:

- implementation body behind `infer_intents`
- `collect_intents_from_stmts`

The parent facade `infer_intents` may remain in `intents.rs` and delegate to the child.

## Parent-Owned Exclusions

Do not move in this step:

- `intents_from_condition`
- `single_indicator_intent`
- `spread_intent_from_condition`
- `moving_average_ratio_intent`
- `legacy_intent_from_emit`
- `merge_intent`
- `emit_action`
- `emit_instrument`
- `invert_condition`
- relation/id helper bodies
- data-source canonicalization and inferred agent params
- spread operand DTOs, decoding, parsing, and params helpers

## Boundary Contract

| Field | Rule |
| --- | --- |
| Parent input | `FunctionDecl`, `BindingEnv`, and `DataSourceConfig` slice |
| Child output | ordered `Vec<IntentConfig>` or `anyhow::Error` |
| Child visibility | `pub(super)` implementation entry only |

| Child calls back to parent | Only for parent-owned `intents_from_condition`, `legacy_intent_from_emit`, `merge_intent`, `emit_action`, `invert_condition`, and error constants as needed |
