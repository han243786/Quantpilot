# v4.16.0 root.contracts.qrpc_core.runtime_io_contract.execution_io baseline plan

> Batch: BE-001SH-01
> Node: `root.contracts.qrpc_core.runtime_io_contract.execution_io`
> Parent: `root.contracts.qrpc_core.runtime_io_contract`

---

## Summary

`execution_io` freezes the simulated execution DTO family before physical extraction.

This baseline may only prepare the next extraction of:

- `SimOrder`
- `ExecutionPlan`
- `FillReport`
- `OpenOrder`
- `FillResult`

## White Box Boundary

| Item | Owner | Input | Output | Side effects |
| --- | --- | --- | --- | --- |
| `SimOrder` | `execution_io` | strategy/risk execution intent | simulated order schema | none |
| `ExecutionPlan` | `execution_io` | risk decision id plus simulated orders | execution plan schema | none |
| `FillReport` | `execution_io` | simulated fill result data | fill report schema | none |
| `OpenOrder` | `execution_io` | unfilled simulated order state | open order schema | none |
| `FillResult` | `execution_io` | plan status, fills, open orders, runtime events | execution result schema | none |

`RuntimeEvent` remains parent-owned until `runtime_output` is selected. `FillResult.events` must keep using the parent-mediated `RuntimeEvent` type.

## Equivalence Baseline

The next extraction must preserve:

- `SimOrder`: `order_id`, `exchange`, `symbol`, `side`, `order_type`, `quantity`, `limit_price`, `time_in_force`, `allow_partial`, `reference_price`, `slippage_bps`, `fee_bps`, and `strategy_tag`.
- `ExecutionPlan`: `plan_id`, `source_risk_decision_id`, `orders`, `created_at_ms`, and `trace_id`.
- `FillReport`: fill id, plan id, exchange/symbol/side, filled quantity, fill price, fee, timestamp, status, and trace id.
- `OpenOrder`: order/plan identity, instrument, side/type/TIF, remaining/reserved quantity and cash, optional limit, reference price, default slippage/fee, timestamps, and trace id.
- `FillResult`: `plan_id`, `status`, `fills`, `open_orders`, and `events`.
- Existing `Serialize` / `Deserialize` derives and serde default attributes.
- Existing crate-root and parent facade exports through `qrpc_core/src/lib.rs` and `qrpc_core/src/runtime_io_contract.rs`.

## Extraction Plan

BE-001SH-02 may:

- create `qrpc_core/src/runtime_io_contract/execution_io.rs`;
- add `mod execution_io;` and `pub use execution_io::*;` to the runtime IO parent;
- move only `SimOrder`, `ExecutionPlan`, `FillReport`, `OpenOrder`, and `FillResult`;
- import primitive execution types from the qrpc-core crate facade;
- import `RuntimeEvent` through the parent facade.

BE-001SH-02 must not:

- move `Position`, `ExchangeExposure`, `PortfolioState`, `RuntimeEvent`, `RuntimeCycleOutput`, `SessionOutput`, or backtest output DTOs;
- widen public surface beyond the existing parent re-export;
- add sibling horizontal links;
- change downstream backend/runtime/compiler/executor behavior;
- introduce release-transition optimization.

## Same-Parent Parallel Judgment

`same_parent_parallel_children` remains inactive for this leaf.

Reason: `FillResult` references parent-owned `RuntimeEvent`, and later `portfolio_state` / `runtime_output` residuals consume execution DTOs through the parent facade. Serial extraction keeps the parent-child communication proof simple.
