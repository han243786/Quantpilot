## Decision

Freeze `market_trigger_flow` as a precision child movement candidate.

The next movement may extract market price update trigger behavior while keeping fill ledger/accounting, snapshot projection, validation helper families, and tests parent-owned.

## Allowed Movement

The actual extraction may add `qrpc_runtime/src/v4_runtime/simulated_execution_engine/market_trigger_flow.rs` and move only these methods from `qrpc_runtime/src/v4_simulated_execution.rs`:

| Method | Visibility after move | Reason |
| --- | --- | --- |
| `update_market_price` | `pub(in crate::v4_runtime)` | Existing `event_replay_orchestration` and runtime adapter callers invoke the market update entrypoint from the v4 runtime module tree. |
| `check_order_triggers` | private or `pub(super)` if required by compiler | Conditional order trigger sweep for accepted orders. |
| `update_trailing_stop` | private | Trailing stop trigger adjustment before conditional evaluation. |
| `request_from_order` | private | Converts resting order state into an execution request for trigger/fill handoff. |

The movement must preserve:

- market price insertion key and position market value update;
- expiry-before-trigger ordering;
- limit marketability trigger behavior;
- trailing stop peak/trough update semantics;
- conditional order triggered event payload;
- conversion from triggered conditional order to resting limit order when not marketable;
- handoff to parent-owned `fill_existing_order`;
- final portfolio changed event payload.

## Frozen Parent-Owned Surface

The next movement must leave the following outside `market_trigger_flow`:

- `submit_order`;
- `fill_existing_order`;
- `validate_position_action`;
- `pre_execution_rejection_reason`;
- `non_executable_resting_reason`;
- `apply_fill_to_ledger`;
- `record_asset_point`, `asset_point`, `snapshot`, and `microstructure_metrics`;
- validation, capability, parse, token, and payload helper families;
- v4 tests.

`fill_existing_order` may be called by the moved trigger flow through the simulated execution parent boundary, but it must not move into this child.

## Local Invariants

| Invariant | Requirement |

1. moving `fill_existing_order` or `apply_fill_to_ledger`;
2. changing event names, event order, payload shapes, order status values, or order id sequencing;
3. adding direct sibling calls between trigger, fill, lifecycle, snapshot, or validation children;
4. changing tests instead of preserving behavior;
5. changing runtime mode, persistence owner, route/schema, or public API.
