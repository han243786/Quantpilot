## Summary

`root.contracts.core_ir.v4_contracts.runtime_mode_contract` freezes the equivalence baseline for extracting the
runtime trading mode contract family from `qrpc_core_ir/src/v4.rs`.

Frozen public surface:

- `RuntimeTradingMode`
- `RuntimeModeContract`
- `RuntimeTradingModeSpec`
- `RuntimeAccountDomain`
- `RuntimeSettlementAuthority`
- `RuntimeExecutionEventSource`
- `RuntimeExecutionEventKind`
- `V4_RUNTIME_EXECUTION_EVENTS`
- `v4_runtime_execution_events`
- `default_v4_runtime_mode_contract`
- `RuntimeModeContract::validate_static_contract`
- `RuntimeModeContract::mode_spec`
- `RuntimeModeContract::settlement_authority_for`

Frozen default behavior:

- required modes remain PaperActual, PaperSimulated, LiveActual, and LiveSimulated
- each mode keeps its account domain, settlement authority, execution event source, provider/local fill flags,
  account-context flag, risk-plane requirement, and default execution events
- default runtime execution events remain order acknowledged, order rejected, partial fill, fill, fee, and portfolio change

Frozen validation behavior:

- schema version, duplicate mode, missing mode, per-field mismatch, missing risk plane, and missing execution event
  error strings remain unchanged
- `mode_spec` and `settlement_authority_for` lookup behavior remains unchanged

Allowed extraction:

- add `mod runtime_mode_contract;` to `qrpc_core_ir/src/v4.rs`
- re-export the child through `pub use runtime_mode_contract::*;`
- create `qrpc_core_ir/src/v4/runtime_mode_contract.rs`
- move the runtime mode DTOs/enums/constants, runtime default constructor, validation impl, lookup helpers,
  `validate_runtime_mode_spec`, `default_runtime_mode_contract_version`, `default_runtime_mode_specs`,
  `expected_runtime_mode_spec`, and `default_runtime_execution_events`
- move `required_runtime_trading_modes` into the child as an internal v4-visible helper because parent plugin
  governance validation still uses it

Forbidden movement:

- `VenueCapabilityMatrix`, `VenueCapability`, `ExecutionCapabilityKind`, and venue validation
- QS type system, plugin governance, version manifest, reproducibility, complexity budget, capability reports,
  bridge builders, tests, machine contract, machine graph contract, and QS profile
