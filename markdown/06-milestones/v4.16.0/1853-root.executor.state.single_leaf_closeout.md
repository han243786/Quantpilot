## Why No Further Split

- The child sits inside the target terminal size range.
- Health, mode, and params routes share executor state ownership and audit
  mutation behavior.
- Splitting mode and params would increase route-registration and audit-helper
  coordination without improving parent modularity.
- Existing state storage, audit log, API guard, and credential files remain
  separate physical support modules.

## Preserved Boundaries

- Public API unchanged.
- Route paths and response shapes unchanged.
- Parent `main.rs` keeps process startup and route registration.
- Runner, migration, websocket, OKX REST, and strategy lifecycle handlers remain
  outside this leaf.
- No release-transition link was introduced.
