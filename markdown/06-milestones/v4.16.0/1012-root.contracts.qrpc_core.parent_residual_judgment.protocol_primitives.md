## Selection Rationale

`protocol_primitives` is selected because it is the next contiguous low-coupling region in `qrpc_core/src/lib.rs`:

- it owns qrpc-core version constants such as `RUN_SPEC_V1_VERSION` and `EVENT_ENVELOPE_PROTO_VERSION`;
- it owns primitive exchange, symbol, market, data, intent, signal, decision, order, execution, risk reason, source status, and source health enums;
- it owns `Symbol::parse`, `Symbol::as_str`, serde behavior for `Symbol`, and display behavior for `OrderSide`;
- it owns primitive defaults such as `RiskDecisionMode::default` and `SourceHealth::default`;
- it can be extracted before runtime config, artifact specs, runtime IO, and RFC execution contracts because those later families depend on the primitives as parent-provided public surfaces.

## Same-Parent Parallel Judgment

`same_parent_parallel_children` remains inactive for this selection.

The queued `runtime_protocol_config`, `artifact_specs`, `runtime_io_contract`, and `rfc_execution_contracts` all depend on these primitive surfaces. A serial primitive extraction keeps the parent facade stable before heavier schema-bearing children move.

## Hard Boundaries

The next `protocol_primitives` baseline must not:

- change version strings, serde names, symbol parsing behavior, display behavior, default values, enum variants, public exports, tests, or digest behavior;
- move runtime protocol config structs, artifact specs, runtime IO DTOs, RFC execution contracts, or tests;
- change closed error/proto/plugin/strategy IR contracts;
- change `qrpc_core_ir`, `qrpc_compiler`, `qrpc_runtime`, `quantscript`, backend, executor, frontend, physical `plugins/*`, or release transition.
