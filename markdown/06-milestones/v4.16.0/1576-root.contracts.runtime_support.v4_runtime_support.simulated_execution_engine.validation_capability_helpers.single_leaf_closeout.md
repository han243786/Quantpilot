## Stop-Split Rationale

`validation_capability_helpers` has a single owner: the simulated execution admission and helper contract used by the parent and same-parent children through parent re-exports. Its size is intentionally terminal: large enough to avoid micro-child churn, small enough to remain reviewable as one helper owner.

Rejected finer splits:

| Candidate | Decision | Reason |
| --- | --- | --- |
| position action validation child | Reject | The checks are admission logic and share request/action semantics with the other validation helpers. |
| capability derivation child | Reject | Capability derivation is part of the same order admission contract and would add another parent re-export surface. |
| conditional order helper child | Reject | Conditional classification, trigger direction, execution conversion, and marketability checks are small and cohere around order execution eligibility. |
| fill price helper child | Reject | Fill price math is a tiny helper consumed by the same simulated admission/fill path. |
