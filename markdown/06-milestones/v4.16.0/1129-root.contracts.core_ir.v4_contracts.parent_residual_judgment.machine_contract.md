## Selection Rationale

`machine_contract` is selected because it is the next contiguous and high-value v4 contract family:

- it owns machine-level taxonomy and DTOs before graph-level orchestration;
- it owns `V4MachineContract::validate_static_contract`, the local invariant gate for states, groups, transitions, memory fields, and child machine nesting;
- it is referenced by later graph, profile, bridge, runtime, and tests, so extracting it early reduces the residual parent surface;
- it is larger than the just-closed DTO leaf, so the next baseline must freeze schema and validation behavior before movement.
