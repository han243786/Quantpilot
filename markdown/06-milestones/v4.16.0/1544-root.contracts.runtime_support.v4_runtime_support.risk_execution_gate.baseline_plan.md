## Scope

`root.contracts.runtime_support.v4_runtime_support.risk_execution_gate` freezes the v4 runtime risk-plane and execution-capability gate behavior before movement.

Current physical owner:

- `qrpc_runtime/src/v4_runtime.rs`

Planned child direction:

- introduce `qrpc_runtime/src/v4_runtime/risk_execution_gate.rs`;
- move only risk-plane decision evaluation/recording and execution-capability decision evaluation/recording;
- expose gate methods to sibling transition/simulated-execution owners through parent-mediated `pub(super)` methods.

## Owned Surface

The child may own:

- `V4PaperSimulatedRuntime::evaluate_risk_plane_for_execution`
- `V4PaperSimulatedRuntime::record_risk_plane_decision`
- `V4PaperSimulatedRuntime::evaluate_execution_capabilities_for_execution`
- `V4PaperSimulatedRuntime::record_execution_decision`
- `V4PaperSimulatedRuntime::validate_single_execution_capability`

Visibility expectation:

- all moved methods must be `pub(super)` because the closed machine transition child and parent-owned simulated execution hooks call them.

Owned behavior:

- Risk Plane required/source/origin/event-source/payload/priority/status checks;
- risk-plane approved/rejected decision recording;
- execution capability policy missing/empty/not-declared/unsupported/mode-rejected evaluation;
- execution accepted/rejected decision recording;
- single execution capability mode validation for amend/cancel-replace paths.

## Explicitly Out Of Scope

- public v4 type surface;
- graph symbol expansion;
- constructor/mode gate behavior;
- replay/input orchestration;
- machine transition mechanics;
- `apply_runtime_simulated_execution_for_transition`;
- simulated order request construction;

- simulated execution order/fill engine internals;
- snapshots and v4 tests.

## Leaf Split Decision Gate

This child should be evaluated after extraction.

Expected decision:

`stop_split_after_extraction: likely`

Reason:

- Risk-plane and execution-capability gates are both admission gates for execution transitions.
- Splitting risk gate from execution gate would create two small high-risk leaves that must always be traversed together by transition execution.
- Simulated order/fill behavior remains a separate child, so this gate leaf is not expected to exceed terminal range.
