## Scope

This baseline freezes built-in data-module live HTTP transport behavior before extraction.

Current owner file:

- `qrpc_runtime/src/data_module.rs`

Planned child module:

- data-module child module named `http_transport`

## Allowed Movement

The next extraction may move only:

- `PingProbe`
- `BuiltinDataModule::probe_ping` as a parent method delegating to child transport or as an equivalent child function taking a parent-owned `reqwest::Client`
- `BuiltinDataModule::fetch_okx` as a parent method delegating to child transport or as an equivalent child function taking a parent-owned `reqwest::Client`
- `BuiltinDataModule::fetch_json` as a parent method delegating to child transport or as an equivalent child function taking a parent-owned `reqwest::Client`
- `block_on_http`
- `FALLBACK_RT`
- `fetch_json_via_powershell`

The parent may add:

- `mod http_transport;`
- imports for `PingProbe`;
- parent-owned re-exports for `block_on_http` and `fetch_json_via_powershell` so existing historical-cache calls continue to go through `data_module` parent mediation;
- thin wrapper methods on `BuiltinDataModule` if that keeps call sites stable.

## Boundaries To Preserve

| Boundary | Requirement |
| --- | --- |
| Client ownership | `BuiltinDataModule.client` remains parent-owned; the child receives a reference or clone and does not own provider lifecycle. |
| Ping disabled path | `source.ping_enabled == false` must still return the disabled/default probe without calling HTTP. |
| Ping probe | Ping endpoint selection, elapsed latency capture, endpoint recording, and formatted error capture must remain equivalent. |
| OKX live fetch | Kline/Quote endpoint selection, parser dispatch, normalization helper usage, elapsed latency, and healthy diagnostics must remain equivalent. |
| JSON fetch | Reqwest request, 429 retry loop, exponential delay, status categorization, `error_for_status`, JSON parsing, and context strings must remain behaviorally equivalent. |
| Windows fallback | Windows PowerShell fallback must keep escaped endpoint handling, UTF-8 output encoding, timeout, JSON compression depth, stderr/stdout error projection, and JSON parsing. |
| Runtime bridge | `block_on_http` must keep the existing Tokio-current-runtime path and fallback runtime behavior. |
| Parent facade | `fetch_and_normalize`, breaker decisions, stale cache fallback, request-interval cache, and mock fallback remain parent-owned orchestration. |
| Historical cache mediation | `historical_cache` must continue to import transport helpers through the `data_module` parent; no direct sibling-to-sibling dependency is allowed. |

## Exclusions

The next extraction must not move:

- request-interval cache (`CachedSnapshot`, `rate_limited_snapshot`, `cached_snapshot`, `store_cache`, `cache_ttl_ms`);
- `BuiltinDataModule.cache` or `BuiltinDataModule.breaker`;
- circuit-breaker decision logic inside `fetch_and_normalize`;
- mock generation or mock fallback construction;
- historical cache persistence/fetch orchestration;
- exchange endpoint/parser ownership in `exchange_surface`;
- normalization implementation;
- quality diagnostics;
- data-module tests.

## Risk Notes

This is a medium-risk leaf because it touches async runtime bridging, HTTP retry behavior, Windows fallback, and diagnostics. The extraction should prefer thin parent wrappers and child free functions over moving parent state. If the implementation exposes more coupling than expected, keep the coupled owner in the parent and move only the verified transport primitives.

## Leaf Granularity Note

After extraction, `terminal_leaf_control_v2` must evaluate the created transport child file before any deeper split. A deeper split into ping, OKX fetch, JSON fetch, and runtime bridge is not approved by this baseline.
