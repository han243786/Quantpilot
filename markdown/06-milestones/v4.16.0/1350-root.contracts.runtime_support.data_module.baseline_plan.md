## White-Box Responsibilities

This child owns runtime data acquisition and normalization:

- convert Core IR data bindings into runtime data source configs
- collect data through `BuiltinDataModule`
- apply request interval cache and stale cache fallback
- probe source health and emit fetch diagnostics
- normalize quote and kline snapshots
- build data quality snapshots, flags, health, previews, and summaries
- build OKX and Binance endpoints and parse exchange payloads
- generate deterministic mock data for fallback and backtest support
- load and persist historical kline cache
- preserve data-module unit tests

## First Child Selection Preview

The next parent residual judgment should select `contracts.runtime_support.data_module.source_mapping`.

Reason:

- source mapping is small, cohesive, and upstream of collection
- it has clear inputs and outputs: Core IR data bindings in, `DataSourceConfig` values out
- it includes only source-hint parsers and keeps provider/network behavior untouched
- it is a low-risk first split for validating the new data-module child tree

## Leaf Split Decision Gate

The baseline requires continued splitting:

- `public_surface_owned`: the data module exposes provider and helper surfaces consumed by runtime coordinator, sandbox, and tests.
- `size_or_behavior_pressure`: acquisition, source mapping, diagnostics, HTTP, exchange parsing, mock data, cache, and tests are different behavior families.
- `independent_failure_modes`: external payload parsing, fallback cache, source quality, mock generation, and Core IR mapping can fail independently.
- `parent_child_communication_kept`: child modules must communicate through the `data_module` parent, not sibling shortcuts.
- `release_transition_guard`: no horizontal child connection is proposed because the developer has not declared release transition.

Stop rules do not apply at this parent baseline.
