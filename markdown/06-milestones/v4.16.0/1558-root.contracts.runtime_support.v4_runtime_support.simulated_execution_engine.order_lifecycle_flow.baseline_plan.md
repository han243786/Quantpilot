## Decision

Freeze `order_lifecycle_flow` as a precision child movement candidate.

The next movement may add an order lifecycle child module and move only order-book lifecycle helpers out of the parent implementation include. The parent keeps the cross-domain orchestration methods that still span validation, fills, ledger mutation, market triggers, snapshots, and runtime adapter calls.

## Allowed Movement

The actual extraction may move these methods from `qrpc_runtime/src/v4_simulated_execution.rs` into the order lifecycle child:

| Method | Visibility after move | Reason |
| --- | --- | --- |
| `submit_oco_bracket` | `pub(super)` or private if only called from moved code | OCO parent/leg order lifecycle registration |
| `amend_order` | `pub(super)` | Runtime adapter calls cancel-replace amend directly |
| `reject_order` | `pub(super)` | Runtime adapter and parent orchestration need rejection events |
| `expire_orders` | `pub(super)` | Market update orchestration calls expiry before trigger sweep |
| `trim_history` | `pub(super)` | Shared retention policy for order lifecycle changes |
| `cancel_oco_siblings` | `pub(super)` | Fill completion needs lifecycle sibling cancellation through parent-visible method |
| `reject_existing_order` | `pub(super)` | Amend, trigger, and future fill flows share existing-order rejection |
| `accepted_order` | `pub(super)` | Parent submit flow and OCO registration share order construction |

The movement must preserve event payloads, order status transitions, order sequencing, rejection count behavior, OCO group semantics, amend revision increments, expiry semantics, history trimming, and portfolio changed event emission.

## Frozen Parent-Owned Surface

The next movement must leave the following in the parent include:

- `submit_order`, because it currently spans validation, order lifecycle, immediate fill construction, ledger mutation, event emission, and snapshot projection;
- `update_market_price`, `check_order_triggers`, `update_trailing_stop`, and conditional order helper calls;
- `fill_existing_order` and all fill/ledger/accounting mutation helpers;
- `record_asset_point`, `asset_point`, `snapshot`, and `microstructure_metrics`;
- validation, capability, parse, token, and payload helper families.

## Local Invariants

| Invariant | Requirement |
| --- | --- |
| API freeze | No public API, route, event schema, persistence owner, or runtime mode change |
| Parent mediation | Runtime adapter and trigger/fill flows call only parent-visible order lifecycle methods |
| No sibling direct link | Future trigger, fill, snapshot, and validation children must not directly call private order lifecycle internals |
| Trading semantics | Accepted/rejected/amended/expired/canceled order statuses and event payloads remain byte-shape compatible |
| Release guard | No release-transition optimization, caching shortcut, or hot-path horizontal connection |

1. moving `submit_order` wholesale;
2. moving fill construction or ledger mutation;
3. changing event names, payload shapes, order status values, or order id sequencing;
4. adding direct sibling calls between lifecycle, trigger, fill, snapshot, or validation children;
5. changing tests instead of preserving behavior.
