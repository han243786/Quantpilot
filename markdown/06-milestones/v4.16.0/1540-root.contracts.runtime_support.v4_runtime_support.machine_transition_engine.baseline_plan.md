## Scope

`root.contracts.runtime_support.v4_runtime_support.machine_transition_engine` freezes the v4 runtime machine transition mechanics before movement.

Current physical owner:

- `qrpc_runtime/src/v4_runtime.rs`

Planned child direction:

- introduce `qrpc_runtime/src/v4_runtime/machine_transition_engine.rs`;
- move transition selection, preflight, state/memory update, emitted-event payload construction, and transition matching helpers;
- keep risk/execution gate and simulated execution internals parent-owned.

## Owned Surface

The child may own:

- `V4PaperSimulatedRuntime::process_event`
- `V4PaperSimulatedRuntime::transition_candidate_for_machine`
- `V4PaperSimulatedRuntime::machine_transition_preflight`
- `V4PaperSimulatedRuntime::payload_for_emitted_event`
- `MachineTransitionPreflight`
- `matching_transition`

Visibility expectation:

- `process_event` must become `pub(super)` because the closed `event_replay_orchestration` child drains the event queue and calls it through `run_until_idle`.

Owned behavior:

- validate candidate transition guard and memory-write preflight;
- choose parent/child machine transition candidates;
- sort candidates by priority and stable id;
- apply state transitions and memory writes;
- update soft-silent/recovering machine status on accepted events;
- record transition-applied control events;
- construct payloads for emitted machine events.

## Explicitly Out Of Scope

This leaf must not move:

- public v4 type surface;
- graph symbol expansion;
- constructor/mode gate behavior;
- replay/input orchestration;
- event payload schema validation;
- shared event construction helpers;
- `machine_spec` and `find_machine_spec`, because non-transition public runtime methods still use them;
- risk-plane decision evaluation and recording;
- execution-capability decision evaluation and recording;
- simulated execution order/fill application;
- v4 tests.

## Coupling Notes

`process_event` currently calls risk/execution gate and simulated execution hooks. Those calls may remain in the moved method, but the hook implementations stay parent-owned until their own residual judgments. This preserves behavior while avoiding a giant mixed extraction.

## Leaf Split Decision Gate

This child should be evaluated after extraction.

Expected decision:

`stop_split_after_extraction: likely`

Reason:

- Splitting transition candidate selection from state/memory application would create sequencing risk.
- Splitting emitted-event payload construction would create a tiny helper leaf still tightly coupled to transition emission.
- Gate and simulated execution internals are already excluded and will receive their own residual judgments.
