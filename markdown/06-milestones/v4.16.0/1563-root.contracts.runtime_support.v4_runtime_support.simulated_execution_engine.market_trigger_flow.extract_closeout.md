## Decision

Extract `market_trigger_flow` as a dedicated simulated execution child.

The extraction moved market price update and conditional trigger behavior out of the parent include while preserving trigger ordering, event payloads, trailing-stop semantics, resting-limit behavior, fill handoff, and final portfolio changed event emission.

## Code Movement

| Path | Change |
| --- | --- |
| `qrpc_runtime/src/v4_runtime/simulated_execution_engine.rs` | Adds `mod market_trigger_flow;` before existing child modules. |
| `qrpc_runtime/src/v4_runtime/simulated_execution_engine/market_trigger_flow.rs` | New child module owning market-trigger helper methods. |
| `qrpc_runtime/src/v4_simulated_execution.rs` | Removes the moved trigger helper implementations and keeps fill/accounting, validation, snapshot metrics, and tests outside this child. |

Moved helper methods:

| Method | Final visibility | Reason |
| --- | --- | --- |
| `update_market_price` | `pub(in crate::v4_runtime)` | Existing event replay orchestration and runtime adapter callers invoke the market update entrypoint from the v4 runtime module tree. |
| `check_order_triggers` | private | Trigger sweep is internal to the market update flow. |
| `update_trailing_stop` | private | Trailing stop adjustment is internal to trigger evaluation. |
| `request_from_order` | private | Resting order to execution request conversion is internal to trigger/fill handoff. |

## Preserved Parent-Owned Surface

The following stayed outside `market_trigger_flow`:

- `submit_order`;
- `fill_existing_order`;
- `validate_position_action`;
- `pre_execution_rejection_reason`;
- `non_executable_resting_reason`;
- `apply_fill_to_ledger`;
- `record_asset_point`, `asset_point`, `snapshot`, and `microstructure_metrics`;
- validation, capability, parse, token, and payload helper families;
- v4 tests.

`market_trigger_flow` calls parent-owned `fill_existing_order` through the same simulated execution state owner. It does not own fill ledger mutation.

## Boundary Notes

The extraction keeps parent-mediated communication:

- expiry remains delegated through `order_lifecycle_flow.expire_orders`;
- fill execution remains delegated to parent-owned `fill_existing_order`;
- snapshot projection and asset point recording remain parent-owned;
- no direct sibling bypass was introduced.

No release-transition optimization, hot-path sibling horizontal connection, route/schema change, persistence owner change, runtime mode change, or test rewrite was introduced.
