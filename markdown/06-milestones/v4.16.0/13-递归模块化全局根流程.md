# v4.16.0 递归模块化全局根流程

> 版本类型: MINOR architecture / governance。
> 基准: `07-顶层大模块统计.md`、`12-system十叶模块等价基线.md`。
> 执行档位: 重型。
> 判定: 将“顶层模块 -> 叶子抽离 -> 叶子整理 -> 是否继续细分 -> 递归处理 -> 全局根收束”固化为后续全量模块树的通用流程。

---

## 目标

本文件把后续模块化工作固定为递归流程:

```text
全局根 root
  -> 分顶层模块
  -> 选择一个顶层模块
  -> 做叶子抽离
  -> 整理这些叶子
  -> 判断叶子是否值得拆得更细
      -> 值得: 把该叶子当成新的局部顶层模块，重复同一流程
      -> 不值得: 标记该叶子完成
  -> 全部叶子完成后，标记该顶层模块完成
  -> 按同一规范处理其他顶层模块
  -> 六大顶层模块都完成后，收束到全局根和全量模块树
```

这不是一次性全量抽离，也不是无限细分。它是一个可停止、可验证、可递归的模块化算法。

## 递归状态机

| 状态 | 输入 | 输出 | 通过条件 |
| --- | --- | --- | --- |
| R0 顶层模块确认 | 全局根、顶层候选 | 顶层模块清单 | 顶层 owner 和真实范围清楚 |
| R1 叶子划分 | 单个顶层模块 | L2 叶子清单 | 每个叶子都有 owner、真实文件和边界说明 |
| R2 叶子抽离 | 单个叶子 | 候选模块、兼容桥、回退点 | 单叶单批，不跨父域 |
| R3 叶子整理 | 已抽离或已登记叶子 | 等价基线、public/内部实现分类、未迁移边界 | 能证明功能与之前一致 |
| R4 细分价值判断 | 已整理叶子 | 继续细分 / 停止细分 | 有明确 owner 和独立等价证据才继续拆 |
| R5 局部递归 | 值得细分的叶子 | 新的局部顶层模块 | 仿照 R0-R4 重复处理 |
| R6 顶层完成 | 顶层所有叶子 | 顶层模块完成记录 | 所有叶子完成或明确停止细分 |
| R7 全局根收束 | 六大顶层完成记录 | 全量模块树完成 | 全局根能解释所有 active 模块和边界 |

## 细分价值判定

叶子只有满足下列条件之一，才值得继续拆得更细:

| 值得细分的信号 | 说明 |
| --- | --- |
| 独立 owner | 叶子内部存在两个以上稳定 owner，且父子通信可以清楚表达 |
| 独立 public 入口 | 子叶有独立 public 入口或明确兼容入口 |
| 独立状态/锁/持久化 | 子叶拥有不同状态、锁顺序、事务或持久化责任 |
| 独立验证证据 | 子叶能单独用测试、契约、artifact 或人工清单证明等价 |
| 独立发布/构建边界 | 子叶对应单独构建、CI、交付、schema 或配置边界 |
| 长期演进频率不同 | 子叶变化频率明显不同，放在一起会制造冲突 |

满足下列情况时，不值得继续拆:

| 不值得细分的信号 | 说明 |
| --- | --- |
| 只是文件夹好看 | 没有独立 owner，只是目录美化 |
| 只是 helper 分组 | 内部 helper 没有 public/兼容入口和独立验证 |
| 只是 generated asset | 生成资产没有独立行为 owner |
| 会增加横向通信 | 拆开后需要绕过父模块互相调用 |
| 需要整理或重构才能解释完成 | 当前仍不进入整理/重构 |

## 顶层模块完成判定

一个顶层模块只有同时满足以下条件，才能视为处理完成:

1. 顶层模块的叶子清单已固定或明确暂缓。
2. 每个叶子都有 public 入口、关键内部实现、保留外部边界和等价证据。
3. 每个叶子都完成抽离、完成登记，或明确不值得继续拆。
4. 值得细分的叶子已经按同一递归流程处理完毕。
5. 没有未解释的横向连接、owner 冲突、新旧入口冲突或测试缺口扩大。
6. closeout 写明“抽离完成”还是“整理/重构仍未启动”。

---

## 全局根完成判定

六大顶层模块全部完成后，才能宣告全局根完成:

| 全局根条件 | 要求 |
| --- | --- |
| 六大顶层齐全 | `system`、`backend`、`frontend`、`executor`、`contracts`、`docs` 都有完成记录 |
| 全量模块树齐全 | 模块树能定位每个 active 模块、叶子、真实文件和 public 入口 |
| 全量树齐全 | 全量树能覆盖所有 active 文件和治理索引 |
| 父子通信闭环 | 叶子只能经父模块或明确 adapter 通信 |
| 停止条件可解释 | 每个叶子为什么停止细分都能被审查 |
| 无发布态偷渡 | 未经开发者明确声明，不引入发布态横向连接 |

## 当前应用到 system

`system` 现在处于 R3/R4 之间:

1. R0 顶层模块确认已完成: `root.system` 是六大顶层之一。
2. R1 叶子划分已完成: 3 层、10 个叶子。
3. R2 叶子抽离已部分完成: S2 `system.entry.backend_process` 已完成。
4. R3 叶子整理已启动: `12-system十叶模块等价基线.md` 已铺好。
5. R4 细分价值判断待逐叶执行: S1/S4/S10 可低风险 closeout，S6/S9 需暂停，S5 暂不细分。

因此下一步不是全量抽离，也不是立刻 L3 细分，而是按 `12-system十叶模块等价基线.md` 做单叶 closeout。

---

## 禁止事项

- 不一次性推进一个顶层模块的全部叶子抽离。
- 不在叶子等价基线未完成前继续拆 L3。
- 不把整理、重构、旧实现退役混入抽离批次。
- 不把配置样例、generated schema、构建脚本误判为 runtime 行为真源。
- 不让 AI 主动提出发布版本过渡或横向连接。

---

## 验收标准

1. 递归模块化流程进入 v4.16 里程碑索引。
2. 顶层模块、叶子抽离、叶子整理、细分价值判断、顶层完成、全局根收束都有明确状态。
3. `system` 的下一步能自然落到单叶 closeout。
4. 后续 `backend`、`frontend`、`executor`、`contracts`、`docs` 能复用同一流程。
5. 治理门禁能发现本流程文档缺失。
