## Summary

This baseline freezes the `static_contract_bundle` extraction boundary before Rust code movement.

Frozen public surface:

- `V4StaticContractBundle`
- `impl Default for V4StaticContractBundle`
- `V4StaticContractBundle::validate_static_contract`
- `default_static_contract_bundle_version`

Frozen fields:

- `schema_version`
- `version_manifest`
- `qs_profile`
- `type_system`
- `runtime_modes`
- `plugin_governance`
- `reproducibility`
- `complexity_budget`
- `learning_pipeline`
- `machine_graphs`
- `venue_matrices`
- `plugin_manifests`
- `metadata`

Frozen validation behavior:

- schema version must equal `V4_STATIC_CONTRACT_BUNDLE_VERSION`
- delegated validation order remains version manifest, QS profile, type system, runtime modes, plugin governance, reproducibility, complexity budget, learning pipeline
- empty `machine_graphs` still reports `static contract bundle must include at least one machine graph`
- empty `venue_matrices` still reports `static contract bundle must include at least one venue matrix`
- each graph validates static contract and graph-derived complexity metrics
- each venue matrix validates first-wave capability rules
- each plugin manifest validates against plugin governance, type system, and runtime modes

Allowed BE-001VW-02 movement:

- add `qrpc_core_ir/src/v4/static_contract_bundle.rs`
- add `mod static_contract_bundle;`
- add `pub use static_contract_bundle::*;`
- move only the bundle DTO, default impl, static validation method, and static bundle version default helper

Forbidden movement:

- `V4CompileTimeCapabilityRequest`, `V4CompileTimeCapabilityReport`, report entry/status/diagnostic DTOs, and report validation
- `V4StaticContractBundle::build_compile_time_capability_report` and its private report-entry builders
- capability diagnostic helpers
- compatibility bridge DTOs, bridge builders, bridge validators, tests, and sample builders
- already extracted sibling contract implementations

Equivalence proof target:
