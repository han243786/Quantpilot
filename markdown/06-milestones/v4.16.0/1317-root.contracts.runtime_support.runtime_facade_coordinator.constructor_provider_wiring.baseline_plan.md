## Physical Scope

This child freezes the constructor and provider-injection surface currently located near the start of `qrpc_runtime/src/runtime_facade_coordinator.rs`.

Owned public constructor APIs:

- `RuntimeCoordinator::from_core_ir`
- `RuntimeCoordinator::new`
- `RuntimeCoordinator::with_modules_from_core_ir`
- `RuntimeCoordinator::with_modules`
- `RuntimeCoordinator::with_data_module_from_core_ir`
- `RuntimeCoordinator::with_data_module`
- `RuntimeCoordinator::with_intent_module_from_core_ir`
- `RuntimeCoordinator::with_intent_module`
- `RuntimeCoordinator::with_agent_module_from_core_ir`
- `RuntimeCoordinator::with_agent_module`
- `RuntimeCoordinator::with_risk_checker_from_core_ir`
- `RuntimeCoordinator::with_risk_checker`
- `RuntimeCoordinator::with_execution_module_from_core_ir`
- `RuntimeCoordinator::with_execution_module`
- `RuntimeCoordinator::with_module_providers_from_core_ir`
- `RuntimeCoordinator::with_module_providers`

Owned initialization behavior:

- translate `CompiledRuntimeProtocol` into `CoreStrategyIr` constructor entry points
- install builtin data, intent, agent, risk, and execution providers
- wrap injected execution modules in `Arc<Mutex<dyn ExecutionModuleProvider>>`
- derive the initial cash balance from `core_ir.execution.params.initial_cash_balance`
- create the initial `PortfolioState`
- initialize `RuntimeState`
- initialize `ConfigTracker`
- initialize `MergeCoordinator`
- set default `RiskDecisionMode::Normal`
- start with no pending module config, no risk monitor, and no stopped risk state

## Exclusions

This child does not own:

- the `RuntimeCoordinator` struct definition
- `ConfigGenerationEntry`
- `impl Debug for RuntimeCoordinator`
- session and cycle orchestration
- execution submission and market data entry points
- runtime state and config accessors
- module config swap and apply behavior
- config generation history mutation after construction
- portfolio projection helpers
- merge record inspection
- coordinator tests except constructor or provider override tests if moved later

## Leaf Split Decision Gate

`continue_split: false` for this child after extraction unless closeout finds a concrete reason to continue.

Reasons:

- the constructor/provider API group is cohesive and shallow
- all functions participate in the same object construction responsibility
- splitting builtin-provider shortcuts from provider-object injection would add coordination overhead without a clear independent owner
- public API preservation is more important than micro-layering this cluster
