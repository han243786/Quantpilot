## Summary

This baseline freezes the RFC-001 data request contract family before extraction from `qrpc_core/src/rfc_execution_contracts.rs`.

The next implementation step may move only the data request taxonomy and DTO surface into a private child module under the RFC execution parent. Public names must remain available through the RFC execution parent facade and the qrpc-core crate root facade.

## Frozen Surface

The selected child owns:

- `MarketScope`;
- `PrimaryDataType`;
- `SourceType`;
- `Timeframe`;
- `TimeRange`;
- `RoundingMode`;
- `PrecisionPolicy`;
- `UsageTag`;
- `DataRequest`.

## Equivalence Baseline

| Surface | Frozen behavior |
| --- | --- |
| Market scope taxonomy | `MarketScope` keeps `Spot`, `Margin`, `Perpetual`, `Futures`, `Options`, `Index`, and `Composite`. |
| Primary data taxonomy | `PrimaryDataType` keeps `FactPrice` and `KlineRange`. |
| Source taxonomy | `SourceType` keeps spot, perpetual, futures, index, and aggregated variants unchanged. |
| Timeframe taxonomy | `Timeframe` keeps tick, sub-second, second, minute, hour, day, and week variants unchanged. |
| Time range DTO | `TimeRange` keeps `start_ms` and `end_ms`. |
| Precision policy DTO | `PrecisionPolicy` keeps `price_scale`, `quantity_scale`, and `rounding_mode`. |
| Usage taxonomy | `UsageTag` keeps live, intent, simulation, backtest, and diagnostics variants unchanged. |
| Data request DTO | `DataRequest` keeps request id, instrument, taxonomy fields, optional timeframe/lookback/range, precision, usage, priority, realtime flag, and requested timestamp. |
| Derives and serde | All current `Debug`, `Clone`, `Serialize`, `Deserialize`, and `PartialEq` derives remain unchanged. |
| Public facade | Existing public names remain available through `qrpc_core::*`. |

## Planned Extraction Shape

BE-001SS-02 may:

- create `qrpc_core/src/rfc_execution_contracts/data_request.rs`;
- add `mod data_request;` and `pub use data_request::*;` to `qrpc_core/src/rfc_execution_contracts.rs`;
- move only the frozen surface listed above;

- leave allocation, order, feedback, and handoff contracts in the parent file.
