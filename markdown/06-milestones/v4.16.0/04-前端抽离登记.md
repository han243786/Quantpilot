# v4.16.0 前端抽离登记

> 职责: 为前端抽离批次建立候选清单、父模块坐标、组件/状态边界、兼容桥和 UI 行为对照方式。
> 范围: React 工作区、策略中心、运行面板、能力投影、页面级状态。
> 非目标: 不重做视觉体系，不重排产品入口，不借抽离做 UX 重构。

---

## 登记规则

1. 每个候选只能围绕一个页面、组件簇、store 切片或能力投影展开。
2. 抽离阶段不改变用户入口、布局语义、文案边界和 supported/unsupported 声明。
3. 新候选组件或 store 适配层必须由父页面或父 store 调用。
4. E2E 只作为历史证据，不作为本阶段必须整理对象。
5. 缺少稳定 E2E 时，优先补组件测试、projection 测试或契约测试作为替代证据。
6. 采用 system 经验回填口径: 页面/父 store 入口、兼容入口、关键内部实现和保留外部边界分开登记。

## 候选细节

### F1 strategy workspace 壳层

| 字段 | 内容 |
| --- | --- |
| 目标 | 把工作区页面壳、动作入口和状态注入边界登记为可抽离候选 |
| 关键 public 方法 | `StrategyWorkspacePage`、`useGraphStore`、workspace action helpers |
| 关键内部实现 | 同父页面/父 store 下的 action bundle、panel adapter、projection helper，需验证后再归位 |
| 保留外部边界 | 用户入口、路由、布局语义、主题、文案、supported/unsupported 声明 |
| 输入/输出 | strategy id、graph store、capability context -> workspace shell、actions、panels |
| 兼容桥 | 旧页面继续渲染，候选壳只做包装或局部委托 |
| 回退点 | 原 `StrategyWorkspacePage` 和 store 调用不删除 |
| 等价证据 | `StrategyWorkspacePage.codeMode.test.jsx`、store action 单测、人工截图核查 |
| 替代证据 | 当 E2E 延后时，使用页面组件测试、store action 单测和人工截图核查替代 |
| 决策点 | D2 接口粒度、D9 后端/前端先后顺序、D11 E2E 延后影响 |

### F2 runtime panels 投影层

| 字段 | 内容 |
| --- | --- |
| 目标 | 抽出运行面板的 projection 和证据展示边界，不改变事件语义 |
| 关键 public 方法 | `EventStreamPanel`、`RuntimeDiagnosticsPanel`、`buildRuntimeDiagnosticsProjection`、`buildRuntimeTimelineItemsFromEvents` |
| 输入/输出 | runtime events、diagnostics、selected node -> event UI、timeline、diagnostics view |
| 兼容桥 | 原面板继续拥有渲染入口，候选 projection 先并存 |
| 回退点 | 原 utils 和组件仍可直接使用 |
| 等价证据 | `EventStreamPanel.layout.test.jsx`、`RuntimeDiagnosticsPanel.test.jsx`、`runtimeTimeline.test.js` |
| 替代证据 | 当端到端事件路径不稳定时，使用 projection 单测和面板组件测试替代 |
| 决策点 | D5 等价证据、D10 测试废弃边界 |

### F3 strategy hub 目录/检查器

| 字段 | 内容 |
| --- | --- |
| 目标 | 抽出策略中心 roster、inspector、recent activity 的模型投影层 |
| 关键 public 方法 | `StrategyHubPage`、`projectStrategyHubRosterRows`、`projectStrategyHubInspectorOverview` |
| 输入/输出 | hub model、selected strategy、runtime history -> roster rows、inspector overview、activity panels |
| 兼容桥 | 原页面入口保留，候选 model/projection 由 section 调用 |
| 回退点 | 原 page/section/projection 文件不删除 |
| 等价证据 | `StrategyHubPage.test.jsx`、`StrategyHubRosterTableSection.test.jsx`、projection 单测 |
| 替代证据 | 当视觉快照延后时，使用 hub 页面测试、roster 表格测试和 projection 单测替代 |
| 决策点 | D2 接口粒度、D11 E2E 延后影响 |

### F4 capability projection 边界

| 字段 | 内容 |
| --- | --- |
| 目标 | 把 capability snapshot 到 UI action 的投影边界作为抽离优先候选 |

### F5 graph store runtime/compile 切片

| 字段 | 内容 |
| --- | --- |
| 目标 | 把 runtime actions、compile actions 和 protocol flow 登记为父 store 下的候选 action bundle |

| 决策点 | D2 接口粒度、D3 状态归属、D11 E2E 延后影响 |

## 暂停条件

出现以下任一情况，停止实现并回到方案讨论:

1. 候选会改变页面布局、主题、导航或文案语义。
2. 候选绕过父页面或 `useGraphStore` 直接横向调用其他模块状态。
3. 候选将 unsupported 能力显示成 supported。
4. 候选缺少组件测试、projection 测试或人工 UI 对照。
5. 候选需要同时修改多个页面主入口。
6. 候选无法区分页面/父 store public 入口、关键内部实现和必须保留的 UI/能力外部边界。
