# v4.16.0 规划方案: 模块化抽离第一波

> 版本类型: MINOR architecture / governance。
> 基准: v4.15.0 三矩阵完全接管。
> 执行档位: 重型。
> 主轴: 只启动十万行级重大工程的“抽离控制面”；“整理”和“重构”进入后续方案，不在本里程碑实现。

---

## 目标

v4.16.0 的目标是把模块化改造从治理设想推进到可执行的第一步: 抽离控制。

抽离的定义是: 在不改变现有行为、不删除旧实现、不切换主入口的前提下，把目标功能建立为可独立登记、可并存、可回归验证的模块化候选版本。

这波模块化改造按十万行级重大工程看待。v4.16.0 不承诺一次性完成十万行代码迁移，也不创建单个巨型重构变更；它只负责建立抽离动作的治理入口、分片规则、决策暂停点和首批候选登记方式。

本里程碑完成后，项目应具备以下能力:

1. 每个抽离目标都能指向明确的父模块、模块树节点、真实文件、关键 public 方法和回归保护。
2. 抽离主线拆为后端抽离和前端抽离，分别登记父模块、兼容桥、状态边界和验证证据。
3. 新旧实现可以并存，入口选择、兼容桥和回退点可审查。
4. E2E 整理延后，不把当前 E2E 体系修复作为 v4.16 抽离前置条件。
5. 现有测试程序进入测试资产汰换视角，允许后续大规模废弃，但废弃前必须登记替代证据或明确风险窗口。
6. 需要设计取舍的地方会被标记为决策点，并在实现前与开发者讨论。
7. 抽离完成后只证明“功能已可被搬出并隔离验证”，不宣称整理完成，也不宣称旧路径已退役。

## 十万行级重大工程保护栏

| 保护栏 | 规则 |
| --- | --- |
| 单批次边界 | 每个落地批次只允许围绕一个父模块、一个兼容桥或一条等价验证链展开 |
| 禁止巨型 PR | 不允许把跨域抽离、整理、重构、旧实现删除混在一个变更中 |
| 决策先行 | 首个抽离目标、批次粒度、状态归属和兼容桥方向必须先讨论后执行 |
| 旧行为冻结 | 抽离阶段默认不改变运行行为、用户入口、能力声明和支持矩阵 |
| 证据密度 | 每个抽离批次必须有能证明行为不变的测试、artifact、事件序列或人工核查清单；旧测试废弃时必须有替代证据登记 |
| 回退路径 | 每个抽离批次必须能回到旧入口或旧实现，不得形成不可逆中间态 |
| 规模透明 | 预计大范围移动、生成、重命名或删除时，必须在提案中声明影响文件数和预估行级规模 |

十万行级工程不新增第四档。它仍属于重型档，但必须叠加本节保护栏。

## 抽离主线分流

v4.16.0 将抽离分成两条主线，避免后端状态迁移和前端界面拆分互相缠绕。

| 主线 | 范围 | 当前目标 | 禁止事项 |
| --- | --- | --- | --- |
| 后端抽离 | Rust 后端、运行时、编译链、存储、安全、执行端交互边界 | 先建立父模块接口、状态归属、兼容桥和等价证据 | 不切换主 API，不删除旧 handler，不迁移执行端真实状态所有权 |
| 前端抽离 | React 工作区、策略中心、运行面板、能力投影、页面级状态 | 先建立页面/组件候选模块、store 适配层和 UI 行为对照 | 不重做视觉体系，不重排产品入口，不借抽离做 UX 重构 |
| E2E 整理 | Playwright 场景、视觉快照、端到端 mock、历史测试程序 | 延后到后续测试汰换方案 | 不在 v4.16 用 E2E 整理阻断抽离控制面落地 |

## 测试资产汰换声明

后续测试程序会发生大规模废弃和替换，因此 v4.16 不把当前测试程序视为长期稳定资产。

| 项 | 规则 |
| --- | --- |
| 当前 E2E | 记录现状和失败类别，整理延后，不作为本里程碑必须修复项 |
| 旧测试程序 | 可以进入废弃候选，但不能静默删除 |
| 替代证据 | 每个被废弃的关键测试都要登记替代证据: 单测、集成测试、契约测试、artifact 对比、事件序列或人工验收 |
| 风险窗口 | 暂时没有替代证据时，必须写清风险窗口和不阻断理由 |
| 抽离验证 | 优先使用小型、稳定、靠近模块边界的等价性测试，不依赖庞大 E2E 套件证明一切 |

## 抽离状态机

所有抽离工作必须按以下状态推进:

1. 候选盘点: 列出目标功能、现有入口、调用方、状态和测试。
2. 批次切片: 将十万行级工程拆成可验证小批次，避免跨父模块混合推进。
3. 决策暂停: 若存在目标顺序、接口粒度、状态归属、兼容桥方向或批次规模争议，先与开发者讨论。
4. 抽离壳建立: 新建模块化候选壳或适配层，不改变旧行为。
5. 白箱登记: 同步模块树，登记输入、输出、关键 public 方法、父级通信规则和回归保护。
6. 并存验证: 通过旧入口调用、适配器调用或对照测试证明行为一致。
7. 抽离 closeout: 记录仍需整理/重构的缺口，不把缺口伪装成完成。

## 工作线

| 工作线 | 优先级 | 内容 | 验收 |
| --- | :--: | --- | --- |
| W0 抽离候选盘点 | P0 | 盘点可抽离目标、父模块、现有入口、状态归属和测试锚点 | 形成候选清单，首个目标不由 AI 单方面决定 |
| W1 决策点登记 | P0 | 标记目标顺序、接口粒度、状态归属、兼容桥方向、旧实现保留方式 | 每个决策点都有“需讨论”或“已决策”状态 |
| W2 后端抽离切片 | P0 | 将后端抽离拆成父模块级、兼容桥级或验证链级批次 | 任一批次都能独立验证、独立回退 |
| W3 前端抽离切片 | P0 | 将前端抽离拆成页面、组件、store 或能力投影批次 | 不借抽离重做 UX 或产品入口 |
| W4 抽离边界模板 | P0 | 为目标模块写输入、输出、public 方法、父子通信和回退点 | 模块树能审查该模块是否可插拔 |
| W5 新旧并存方案 | P0 | 设计旧实现、候选模块和适配器的并存方式 | 旧路径可回退，新路径可单独验证 |
| W6 等价性验证 | P0 | 定义对照测试、快照、事件序列或 artifact 对比方式 | 抽离不改变行为有证据 |
| W7 E2E 整理延后 | P0 | 记录当前 E2E 只作为历史证据和风险来源 | 不把 E2E 整理塞进抽离里程碑 |
| W8 测试资产汰换登记 | P0 | 为将被大规模废弃的测试程序建立废弃候选和替代证据登记 | 旧测试不能静默消失 |
| W9 closeout 口径 | P1 | 抽离完成后只宣告“已抽离”，不宣告“已整理/已重构” | 后续整理、重构进入独立里程碑 |

## 必须讨论的决策点

遇到以下情况时，AI 辅助流程必须暂停推进实现，先给出方案并与开发者讨论:

| 决策点 | 触发条件 | 讨论内容 |
| --- | --- | --- |
| D1 首个抽离目标 | 多个候选都可启动 | 先抽低风险边界，还是先抽核心交易状态机 |
| D2 接口粒度 | public 方法可能过粗或过细 | 以父模块接口为准，还是先保留兼容包装 |
| D3 状态归属 | 状态可能留在旧模块或迁入新模块 | 哪一侧拥有状态，哪一侧只做投影 |
| D4 兼容桥方向 | 旧调用新、新调用旧或双向适配均可行 | 哪种桥最少改变行为且最容易回退 |
| D5 等价证据 | 无现成测试能证明行为一致 | 补单测、集成测试、事件快照还是 artifact 对比 |
| D6 旧实现退役 | 抽离后出现删除旧代码诱惑 | 本阶段禁止删除，退役进入后续重构方案 |
| D7 批次粒度 | 单批次可能跨多个父模块或上千行核心改动 | 继续切片，还是先做只读适配层/壳模块 |
| D8 机械迁移 | 出现大范围移动、重命名、生成或删除 | 是否先建立映射表和回归基线，再进入代码批次 |
| D9 后端/前端先后顺序 | 两条抽离主线都可启动 | 先稳后端接口，还是先稳前端壳层 |
| D10 测试废弃边界 | 某批测试明显会被抛弃但仍覆盖关键行为 | 先登记替代证据，还是接受短期风险窗口 |
| D11 E2E 延后影响 | 抽离批次缺少端到端保障 | 是否补局部契约/集成测试来替代 E2E |

## 候选目标登记方式

本里程碑不直接指定首个抽离目标。候选目标必须按以下格式登记:

| 字段 | 要求 |
| --- | --- |
| 目标名称 | 可对应业务域、运行时域、执行端域或前端工作区域 |
| 父模块 | 必须能落到模块树父级 |
| 现有入口 | 真实文件和真实函数/组件/API |
| 候选模块入口 | 新模块化版本的计划入口 |
| 输入/输出 | 输入、输出、错误、事件、状态写入点 |
| 关键 public 方法 | 已有、待包装、待新增三类分开写 |
| 回归保护 | 单测、集成测试、artifact、事件序列或人工检查；E2E 只作为可选历史证据 |
| 测试汰换 | 旧测试保留、废弃候选、替代证据或风险窗口 |
| 决策点 | 未决事项必须列明，不能隐式推进 |

## 非目标

- 不做整理阶段的命名清理、目录美化或 public 方法收敛。
- 不做重构阶段的主入口切换、旧实现删除或调用拓扑替换。
- 不主动进入发布版本过渡。
- 不提出横向连接、旁路缓存或热路径直连。
- 不把“抽离壳已建立”描述成“模块化改造完成”。
- 不在目标未决时让 AI 单方面选择核心交易逻辑或低风险边界。
- 不创建十万行级单次代码变更。
- 不把多个父模块的抽离混成一次提交。
- 不在 v4.16 整理 E2E。
- 不静默删除旧测试程序；大规模废弃进入后续测试资产汰换方案。

## 验收标准

1. v4.16.0 里程碑文档进入总索引、当前路线图和全量树。
2. 三矩阵路线图明确抽离、整理、重构三步走，且当前只启用抽离。
3. 抽离主线明确拆成后端抽离和前端抽离。
4. E2E 整理明确延后，旧测试程序大规模废弃进入测试资产汰换登记。
5. 抽离工作线包含决策暂停机制。
6. 十万行级重大工程保护栏进入抽离提案默认约束。
7. 候选目标登记格式能覆盖父模块、真实入口、public 方法、状态、测试和回退。
8. 后续任何抽离实现提案都能引用本里程碑作为执行边界。
9. 完成本里程碑不宣称代码重构完成，只宣称抽离动作具备治理入口。
