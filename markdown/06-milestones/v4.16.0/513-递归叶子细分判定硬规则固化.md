# v4.16.0 递归叶子细分判定硬规则固化

> Batch: GOV-LEAF-SPLIT-GATE
> Scope: recursive modularization governance only.
> Movement: no code movement.
> Decision: from the next recursive decision document onward, every single leaf closeout and every parent residual judgment must explicitly run the leaf split decision gate.

---

## 三矩阵影响声明

| 矩阵 | 影响节点 | 变更类型 |
| --- | --- | --- |
| 流程矩阵 | 递归模块化状态机、单叶 closeout、父叶残余判断 | 收紧 |
| 规范矩阵 | 叶子细分判定、父子通信、等价基线、强停止条件 | 升级 |
| 引导矩阵 | 模块树白箱节点、全量树递归入口、后续 milestone 文档 | 门禁化 |

---

## 强制触发点

leaf_split_decision_gate

从本文件落地后，所有新增的递归决策文档只要属于以下任一类型，就必须包含 `leaf_split_decision_gate` 与完整判定结果:

1. 单叶 closeout 文档。
2. 父叶残余判断文档。

不得把该门禁写成口头判断；必须显式列出基础门槛、强拆分触发、强停止条件和最终结果。

---

## 基础门槛

leaf_split_base_gate

继续细分前必须同时满足以下三条。任一不满足，当前叶子不得继续细拆。

| 规则 | 判定问题 | 不满足时的动作 |
| --- | --- | --- |
| white_box_boundary_named | 是否能清楚命名新子叶，并写出输入、输出、调用方、处理范围和不处理范围 | 先整理当前叶，不得拆 |
| parent_child_communication_kept | 新子叶是否仍可由父叶单向调用，且不需要 sibling horizontal link | 停止细拆，回到父叶整理 |
| equivalence_baseline_freezable | 是否能冻结关键输入、默认值、错误分支、状态变化、输出格式和验证命令 | 先补等价基线，不得拆 |

---

## 强拆分触发

leaf_split_positive_trigger

基础门槛全部满足后，至少命中一条强拆分触发，才允许提出下一轮子叶基线。

| 触发 | 判定问题 | 推荐动作 |
| --- | --- | --- |
| public_or_handler_boundary | 是否包含关键 public 方法、route handler、外部 API、命令入口或可复用公共 helper | 优先拆成白箱节点 |
| state_machine_phase | 是否存在 validate / plan / execute / persist / emit event 等阶段，且阶段有独立失败模式或状态变化 | 继续拆 |
| strategy_branch | 是否存在独立策略、指标、意图、算法、协议或运行模式分支 | 继续拆 |
| independent_failure_mode | 是否有独立错误码、诊断、fallback、审计事件或恢复路径 | 继续拆 |
| reuse_pressure | 是否已有多个调用点复用，或明确会被复用 | 可拆，但必须仍由父级统一出口控制 |

---

## 强停止条件

leaf_split_stop_condition

只要命中任一强停止条件，即使存在拆分冲动，也必须停止细拆并 closeout。

| 停止条件 | 判定问题 | 动作 |
| --- | --- | --- |
| micro_leaf_without_owner | 继续拆是否只得到 config decode、format one line、emit one event 等无稳定 owner 的微操作 | `stop_split: true` |
| communication_cost_rises | 拆后是否需要大量父级上下文、参数膨胀或 sibling horizontal link | `stop_split: true` 或回父叶整理 |
| local_proof_missing | 拆后是否无法形成局部等价证明，只能依赖大范围集成测试 | 先补 baseline，不继续拆 |
| line_count_only | 拆分理由是否只有代码行数变大 | 不得拆 |

---

## 每次输出格式

leaf_split_decision_result

后续每个受影响的递归决策文档都必须写出如下五项:

1. `leaf_split_base_gate`: 三条基础门槛逐条结果。
2. `leaf_split_positive_trigger`: 命中的强拆分触发；若无命中必须说明。
3. `leaf_split_stop_condition`: 命中的强停止条件；若无命中必须说明。
4. `leaf_split_decision_result`: 最终为 `continue_split`、`stop_split_true`、`return_parent_residual` 或 `baseline_required`。
5. `next_recursive_step`: 下一步只能指向父叶残余判断、单子叶等价基线、整理当前叶或 closeout，不得跳步。
