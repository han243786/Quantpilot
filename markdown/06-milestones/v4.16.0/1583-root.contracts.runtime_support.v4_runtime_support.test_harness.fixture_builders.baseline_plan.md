## Decision

Freeze `fixture_builders` as a test-only shared fixture child movement.

The next movement may move only shared fixture helper functions out of `qrpc_runtime/src/v4_runtime/test_harness.rs` into `qrpc_runtime/src/v4_runtime/test_harness/fixture_builders.rs`.

## Allowed Movement

Move only these helper functions:

| Helper | Reason |
| --- | --- |
| `sample_core_ir_for_v4_runtime` | Builds the base Core IR used by compat graph fixtures. |
| `sample_compat_graph` | Builds the v4 compatibility graph fixture shared by many tests. |
| `runtime_simulated_market_matrix` | Builds the default runtime-simulated paper capability matrix. |
| `provider_native_market_matrix_for_paper` | Builds provider-native paper-mode capability fixture. |
| `provider_native_market_matrix_for_live_actual` | Builds provider-native live-actual fixture. |
| `runtime_simulated_market_matrix_for_live_actual` | Builds runtime-simulated live-actual rejection fixture. |
| `sample_runtime` | Builds the common paper simulated runtime fixture. |
| `nested_observation_graph` | Builds nested child-machine graph fixture. |

Parent module changes allowed:

- add `mod fixture_builders;`;
- add `use fixture_builders::*;`;
- leave all `#[test]` functions in `qrpc_runtime/src/v4_runtime/test_harness.rs`.

Child module requirements:

- use `use super::*;` to preserve parent-mediated test access;
- expose helpers only as needed inside the test harness parent, preferably `pub(super)`;
- avoid direct production module changes.

## Frozen Surfaces

The movement must not change:

- any `#[test]` body;
- test assertion text or expected event payloads;
- production v4 runtime behavior;
- public API, runtime modes, event schemas, persistence owners, or release-transition behavior.

## Required Gates After Extraction

The extraction closeout must run:

1. `cargo fmt --check`
2. `cargo check -p qrpc-runtime`
3. `cargo test -p qrpc-runtime v4 -- --nocapture`
4. `cargo check -p quantpilot`
5. `git diff --check`
6. UTF-8, full feature tree, and matrix governance checks

## Stop Conditions

Stop before code movement if moving fixture helpers requires:

1. changing test assertions;
2. moving scenario tests in the same step;
3. changing production runtime code;
4. widening helper visibility beyond the test harness parent.
