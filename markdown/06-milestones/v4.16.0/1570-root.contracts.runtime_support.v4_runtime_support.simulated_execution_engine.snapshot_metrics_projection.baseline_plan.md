## Decision

Freeze `snapshot_metrics_projection` as a same-parent child movement candidate.

The next movement may extract asset curve recording, portfolio snapshot projection, and microstructure metric projection while keeping direct-submit orchestration, validation helper families, payload parsing, capability derivation, and tests outside the child.

## Allowed Movement

The actual extraction may add `qrpc_runtime/src/v4_runtime/simulated_execution_engine/snapshot_metrics_projection.rs` and move only these helpers from `qrpc_runtime/src/v4_simulated_execution.rs`:

| Method/helper | Visibility after move | Reason |
| --- | --- | --- |
| `record_asset_point` | `pub(super)` | Same-parent children record asset points after order lifecycle, trigger, and fill mutations. |
| `asset_point` | private | Projection helper used only by the moved snapshot/asset curve owner. |
| `snapshot` | `pub(in crate::v4_runtime)` | `runtime_adapter`, same-parent children, and `v4_runtime` tests/read paths need snapshot access. |
| `microstructure_metrics` | `pub(in crate::v4_runtime)` | `event_replay_orchestration` consumes metrics from the `v4_runtime` parent layer. |
| `round_money` | private | Used only by the moved projection helpers; may move with the projection child if no other caller appears. |

The movement must preserve:

- asset curve append and 256-point trim behavior;
- cash, position market value, and portfolio value rounding;
- snapshot field names and values;
- open order, rejected order, fill, position, asset curve, last order, and last fill projection semantics;
- microstructure order/fill sample construction and reference price fallback;
- no direct child-to-child calls that bypass the simulated execution parent boundary.

## Frozen Parent-Owned Surface

The next movement must leave the following outside `snapshot_metrics_projection`:

- `submit_order` and direct-submit fill orchestration;
- fill execution and ledger mutation already closed in `fill_ledger_accounting`;
- market trigger flow already closed in `market_trigger_flow`;
- order lifecycle internals already closed in `order_lifecycle_flow`;
- runtime adapter behavior already closed in `runtime_adapter`;
- `validate_position_action`, `pre_execution_rejection_reason`, and `non_executable_resting_reason`;
- conditional order helpers and capability derivation helpers;
- payload parsing helpers;
- v4 tests.
