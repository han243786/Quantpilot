## Scope

`source_mapping` freezes the Core IR data binding to runtime source config mapping boundary before movement.

Current parent-owned functions:

- `data_sources_from_core_ir`
- `parse_exchange_hint`
- `parse_symbol_hint`
- `parse_bool_hint`
- `parse_u64_hint`

Inputs:

- `CoreStrategyIr`
- `DataBindingKind`
- source hints: `exchange`, `symbol`, `timeframe`, `ping_enabled`, `request_interval_ms`

Outputs:

- `Vec<DataSourceConfig>`

## Public API Equivalence

The crate-visible function `data_sources_from_core_ir` must remain callable from current in-crate users.

Allowed movement:

- add `qrpc_runtime/src/data_module/source_mapping.rs`
- declare `mod source_mapping;` in `qrpc_runtime/src/data_module.rs`
- re-export or delegate `data_sources_from_core_ir` through the parent module so existing call sites do not change

Forbidden movement:

- do not move provider trait or `BuiltinDataModule`
- do not move collection orchestration
- do not move quality diagnostics
- do not move exchange endpoint or payload parsing
- do not move mock or historical cache logic
- do not move tests in this batch

## Split Decision Gate

The child is expected to stop after actual extraction.

Reasons:

- all helper functions are private source-hint parsers for one public mapping function
- further splitting by hint type would create tiny fragments
- the output construction shares the same `DataSourceConfig` defaults
