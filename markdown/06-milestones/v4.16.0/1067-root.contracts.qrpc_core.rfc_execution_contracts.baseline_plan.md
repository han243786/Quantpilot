## Summary

This baseline freezes the remaining qrpc-core RFC execution contract surface before physical extraction from `qrpc_core/src/lib.rs`.

The next implementation step may move only the RFC-style public contracts from `MarketScope` through `HandoffSnapshot` into a private child module under the qrpc-core crate root. Public names must remain available through the crate facade.

## Frozen Surface

The selected child owns the current RFC execution surface in `qrpc_core/src/lib.rs`:

- `MarketScope`;
- `PrimaryDataType`;
- `SourceType`;
- `Timeframe`;
- `TimeRange`;
- `RoundingMode`;
- `PrecisionPolicy`;
- `UsageTag`;
- `DataRequest`;
- `AllocationMethod`;
- `Allocation`;
- `Allocation::apply_to_targets`;
- `OrderStatus`;
- `OrderStatus::can_transition_to`;
- `Order`;
- `FeedbackKind`;
- `ExecutionFeedback`;
- `HandoffSnapshot`;
- `HandoffSnapshot::validate_completeness`.

## Equivalence Baseline

| Surface | Frozen behavior |
| --- | --- |
| Data request taxonomy | All `MarketScope`, `PrimaryDataType`, `SourceType`, `Timeframe`, `RoundingMode`, and `UsageTag` enum variants remain unchanged. |
| Data request DTOs | `TimeRange`, `PrecisionPolicy`, and `DataRequest` keep field names, field order, types, derives, and serde shape. |
| Allocation DTOs | `AllocationMethod` variants and `Allocation` fields remain unchanged. |
| Allocation helper | `Allocation::apply_to_targets` keeps target iteration, explicit weight fallback to `target_weight`, total-budget multiplication, min/max clamping, and last-write behavior per symbol. |
| Order DTOs | `OrderStatus` variants and `Order` fields remain unchanged. |
| Order transition helper | `OrderStatus::can_transition_to` keeps terminal-state rejection and the exact allowed transition matrix. |
| Feedback DTOs | `FeedbackKind` variants and `ExecutionFeedback` fields remain unchanged. |
| Handoff DTO | `HandoffSnapshot` keeps strategy, positions, open orders, balances, cycle, and timestamp fields unchanged. |
| Handoff validation | `HandoffSnapshot::validate_completeness` keeps empty `snapshot_id`, empty `source_strategy_id`, and missing open-order `order_id` checks and preserves the current message strings. |
| Public facade | Existing crate-root public names remain available through `qrpc_core::*`. |

## Planned Extraction Shape

BE-001SQ-02 may:

- create `qrpc_core/src/rfc_execution_contracts.rs`;
- add `mod rfc_execution_contracts;` to `qrpc_core/src/lib.rs`;
- add `pub use rfc_execution_contracts::*;` to preserve crate-root public surfaces;
- move only the frozen surface listed above;
- keep crate-root tests in `qrpc_core/src/lib.rs`;
- keep closed qrpc-core child modules unchanged.

BE-001SQ-02 should not split the selected surface into smaller child files yet. The first physical extraction should establish the parent owner; BE-001SQ-03 must then judge whether data request, allocation, order/feedback, or handoff families deserve child-level extraction.

## Same-Parent Parallel Wave Judgment

This child remains a single-child extraction for BE-001SQ-02.

`same_parent_parallel_children` is not activated because the selected surface is the only remaining qrpc-core root residual. Internal subfamily parallelism must wait until the new parent file exists and BE-001SQ-03 decides whether to continue splitting.

## Hard Boundaries

BE-001SQ-02 must not:

- change enum variants, struct fields, derives, serde shapes, helper method behavior, validation messages, order transition rules, allocation math, public exports, or tests;
- move crate-root tests;
- reopen closed qrpc-core child modules;
- change `qrpc_core_ir`, `qrpc_compiler`, `qrpc_runtime`, `quantscript`, backend, executor, frontend, physical `plugins/*`, or release transition;
- create direct sibling shortcuts to closed qrpc-core children.

## Split Rule Pre-Check

| Rule | Baseline result |
| --- | --- |
| Physical owner | Worth extracting. The selected slice is the final public qrpc-core contract family still embedded in the crate-root file. |
| Public surface | Continue only at this layer. Public item names remain preserved through the crate facade. |
| Mixed responsibility | Continue after extraction. The slice includes data request, allocation, order/feedback, and handoff subfamilies, but first needs a stable physical owner. |
| State ownership | Guarded. `OrderStatus::can_transition_to` is a pure contract transition helper, not a runtime mutable service state machine. |
| Side effects | Stop at extraction. No IO, persistence, locks, async lifecycle, or external calls are involved. |
| Parent-mediated dependency | Required. Closed primitive/runtime IO names and downstream callers must consume names through the crate-root facade. |
| Future reopen rule | Required after extraction to decide whether data request, allocation, order/feedback, and handoff subfamilies deserve child-level splitting. |
