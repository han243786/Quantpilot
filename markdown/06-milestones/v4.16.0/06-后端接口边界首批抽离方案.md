# v4.16.0 后端接口边界首批抽离方案

> 批次编号: BE-001。
> 执行档位: 重型。
> 决策来源: 开发者明确选择“先走后端接口边界”。
> 范围: router/API/facade 大模块边界；不进入 runtime 内部状态迁移。

---

## 决策

BE-001 作为 v4.16 的第一个真实抽离批次，先走后端接口边界。

抽离粒度采用“先大后小”: 先抽一个后端接口边界大模块，再在这个大模块内部按 capability、strategy config、runtime、graph/compile 等小模块逐步抽离。

本批次目标不是重写后端，也不是迁移 handler，而是先把后端对外接口边界稳定下来:

1. 明确 `build_app_router` 作为父入口。
2. 明确各 `register_*_routes` 的归属模块。
3. 明确 capability、strategy config、runtime、graph compile 的 facade 边界。
4. 保留旧 handler、旧状态所有权和旧 response schema。
5. 为后续真实代码抽离提供可审查的接口地图和兼容桥。

---

## 先大后小抽离策略

| 层级 | 本批次定义 | 后续动作 |
| --- | --- | --- |
| 大模块 | `backend.interface_boundary` | 建立 router/API/facade 父级边界 |
| 小模块 1 | `backend.capability` | 后续从大模块内抽 capability 子边界 |
| 小模块 2 | `backend.strategy_config` | 后续从大模块内抽 strategy config 子边界 |
| 小模块 3 | `backend.runtime` | 后续从大模块内抽 runtime route facade，不迁移 runtime 状态 |
| 小模块 4 | `backend.graph_compile` | 后续从大模块内抽 graph/compile route facade |

所有小模块抽离都必须先通过 `backend.interface_boundary` 父级边界，不允许子模块之间直接横向改 route owner、handler 或 response schema。

## 本批次边界

| 项 | 本批次处理 | 本批次不处理 |
| --- | --- | --- |
| router 父入口 | 明确 `build_app_router` 是后端接口边界父入口 | 不重排全部路由 |
| route registration | 登记大模块 route owner 和 facade 候选 | 不删除旧 `register_*_routes` |
| handler | 保留旧 handler | 不迁移 handler 内部逻辑 |
| 状态 | 保持 AppState、runtime state、executor state 所有权不变 | 不迁移状态、不改锁 |
| response schema | 保持现有 API response schema | 不改错误格式、不改 artifact schema |
| 测试 | 使用后端 API tests 和人工 route 核查作为证据 | 不整理 E2E，不依赖视觉快照 |

## 兼容桥

BE-001 的兼容桥方向为:

```text
build_app_router
  -> register_*_routes
  -> existing handler
  -> existing state owner
```

后续如果进入代码壳，只允许添加 facade 包装层:

```text
build_app_router
  -> backend_interface_boundary facade
  -> register_*_routes
  -> existing handler
```

该 facade 只能做边界登记、route owner 聚合、契约检查或轻量委托，不得改变 handler 行为。

**回退点**: 任一后续代码壳失败时，直接回到 `build_app_router -> register_*_routes -> existing handler -> existing state owner` 的旧路径。

大模块抽离成功后，小模块抽离仍保留相同回退点。任何小模块失败时，回退到 `backend.interface_boundary` 父级边界和旧 handler。

## 首批 route owner

| 接口域 | 父模块 | 真实文件 | public 入口 | 约束 |
| --- | --- | --- | --- | --- |
| capability | `backend.capability` | `src/capability_api.rs` | `get_capabilities`、`/api/capabilities` | capability 是前端能力真源，不得硬编码替代 |
| strategy config | `backend.strategy_config` | `src/strategy_config_api.rs` | `register_strategy_config_routes` | 不改变 preflight 语义，不补 E2E mock |
| runtime | `backend.runtime` | `src/runtime/mod.rs` | `register_runtime_routes` | 不迁移 runtime 状态所有权 |
| graph | `backend.graph_compile` | `src/graph_api.rs` | `register_graph_routes` | 不绕过版本记录 |
| QuantScript graph | `backend.graph_compile` | `src/graph_quantscript_api.rs` | `register_graph_quantscript_routes` | 不允许任意主机代码 |
| compile | `backend.graph_compile` | `src/compile_api.rs` | `register_compile_routes` | runtime compile 仍是真实数据源 |

## 实施顺序

1. BE-001A: 文档与门禁登记，并引用 `11-system抽离经验回填.md`。
2. BE-001B: 建立 `backend.interface_boundary` 大模块边界。
3. BE-001C: route owner 映射表和接口边界核查。
4. BE-001D: 区分 public 入口、兼容 public 入口、关键内部实现和保留外部边界。
5. BE-001E: 如果需要代码壳，先提案讨论 facade 粒度。
6. BE-001F: 使用后端 API tests 验证行为不变。
7. BE-001G: closeout 时只宣告后端接口边界大模块已稳定，不宣告 runtime 子模块抽离完成。

## 必须暂停讨论的点

| 决策点 | 触发条件 |
| --- | --- |
| facade 粒度 | 一个总 facade 还是按 capability/runtime/graph 分 facade |
| route 顺序 | 任何 route registration 顺序变化 |
| response schema | 任何 API response、error code、artifact 字段变化 |
| 状态归属 | 任何 AppState、runtime state、executor state 迁移 |
| E2E 替代 | 后端接口变化需要端到端证据，但 E2E 仍延后 |

---

## 非目标

- 不删除旧 handler。
- 不切换主 API。
- 不迁移状态所有权。
- 不改 response schema。
- 不整理 E2E。
- 不删除旧测试程序。
- 不进入发布版本过渡。

---

## 验收标准

1. BE-001 进入 v4.16 后端抽离登记。
2. 全量树和模块树能定位本批次方案。
3. 治理门禁能发现 BE-001 方案缺失。
4. 后续代码变更必须先引用本方案，再进入实现。
5. 完成本批次后只宣告“后端接口边界抽离方案已落地”，不宣告 runtime、compile 或 storage 已抽离。
