## 落地范围

控制面阶段先落地 v4.16 的抽离治理入口:

1. 建立后端抽离登记。
2. 建立前端抽离登记。
3. 建立测试资产汰换登记。
4. 将 E2E 整理延后写成明确边界。
5. 将十万行级重大工程保护栏纳入治理门禁。

控制面阶段不做真实代码抽离，不搬迁目录，不删除旧实现，不删除测试程序。进入代码试水后，首批真实抽离记录以 `09-system.entry首批抽离记录.md` 为准。

## 当前决策状态

| 决策 | 状态 | 说明 |
| --- | :--: | --- |
| 首个后端抽离目标 | 需讨论 | 候选包括 runtime、graph compile、storage/security；不能由 AI 单方面决定 |
| 首个前端抽离目标 | 需讨论 | 候选包括 strategy hub、runtime panels、capability projection；不能借机做 UX 重构 |
| 后端/前端先后顺序 | 需讨论 | 可先稳后端接口，也可先稳前端壳层，需要开发者拍板 |
| E2E 替代策略 | 需讨论 | 当前 E2E 整理延后，后续需确定契约测试、集成测试和人工验收组合 |
| 测试废弃批次 | 需讨论 | 旧测试程序允许大规模废弃，但每批必须登记替代证据或风险窗口 |
