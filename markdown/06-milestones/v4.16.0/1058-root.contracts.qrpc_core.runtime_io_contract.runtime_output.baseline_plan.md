## Summary

`runtime_output` freezes the runtime event and session output DTO family before physical extraction.

This baseline may only prepare the next extraction of:

- `RuntimeEvent`
- `RuntimeCycleOutput`
- `SessionOutput`

## White Box Boundary

| Item | Owner | Input | Output | Side effects |
| --- | --- | --- | --- | --- |
| `RuntimeEvent` | `runtime_output` | event id, type, trace/source identity, timestamp, payload | runtime event schema | none |
| `RuntimeCycleOutput` | `runtime_output` | closed child DTO families plus portfolio state and fetch counts | single cycle output schema | none |
| `SessionOutput` | `runtime_output` | slow and fast cycle outputs plus final portfolio and fetch counts | session output schema | none |

## Equivalence Baseline

The next extraction must preserve:

- `RuntimeEvent`: `event_id`, `event_type`, `trace_id`, `source_id`, `ts_ms`, and `payload`.
- `RuntimeCycleOutput`: `cycle_name`, `trace_id`, `normalized_data`, `intent_signals`, `agent_decisions`, `risk_decisions`, `execution_plans`, `fill_reports`, `portfolio_state`, `runtime_events`, and `data_fetch_counts`.
- `SessionOutput`: `slow_cycle`, `fast_cycle`, `final_portfolio`, and `data_fetch_counts`.
- `Serialize` / `Deserialize` derives.
- `RuntimeEventType` and `serde_json::Value` type ownership.
- `BTreeMap<String, u32>` fetch-count shapes.
- Existing parent and crate-root facade exports.

## Extraction Plan

BE-001SL-02 may:

- create `qrpc_core/src/runtime_io_contract/runtime_output.rs`;
- add `mod runtime_output;` and `pub use runtime_output::*;` to the runtime IO parent;
- move only `RuntimeEvent`, `RuntimeCycleOutput`, and `SessionOutput`;
- import `RuntimeEventType` from the qrpc-core crate facade;
- import `Value` and `BTreeMap` locally in the child;
- import all closed runtime IO child DTO dependencies through the runtime IO parent facade.

BE-001SL-02 must not:

- move `BacktestEquityPoint`, backtest metrics, `PeriodReturn`, `BacktestSummary`, or `BacktestOutput`;
- reopen closed market data IO, decision flow, execution IO, or portfolio state children;
- add sibling horizontal links;
- change downstream runtime/backend/compiler behavior;
- introduce release-transition optimization.

## Same-Parent Parallel Judgment

`same_parent_parallel_children` remains inactive for this leaf.

Reason: `runtime_output` is an aggregate over several closed sibling children and is also consumed by the queued `backtest_output` residual. Parent-mediated serial extraction keeps the dependency graph readable.
