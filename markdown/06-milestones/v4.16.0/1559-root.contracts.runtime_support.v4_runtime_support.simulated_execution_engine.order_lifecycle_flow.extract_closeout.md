## Decision

Extract `order_lifecycle_flow` as a dedicated simulated execution child.

The extraction moved order lifecycle helper behavior out of the parent include while preserving the public runtime API, event names, payload shapes, order status transitions, order id sequencing, OCO behavior, amend revision semantics, expiry behavior, history trimming, rejection counts, and portfolio changed event emission.

## Code Movement

| Path | Change |
| --- | --- |
| `qrpc_runtime/src/v4_runtime/simulated_execution_engine.rs` | Adds `mod order_lifecycle_flow;` beside the already extracted runtime adapter. |
| `qrpc_runtime/src/v4_runtime/simulated_execution_engine/order_lifecycle_flow.rs` | New child module owning order lifecycle helper methods. |
| `qrpc_runtime/src/v4_simulated_execution.rs` | Removes the moved helper implementations and keeps orchestration, fill/accounting, trigger, snapshot, metrics, validation, and tests outside this child. |

Moved helper methods:

| Method | Final visibility | Reason |
| --- | --- | --- |
| `submit_oco_bracket` | `pub(super)` | Parent submit flow calls OCO registration through the simulated execution parent boundary. |

| `reject_order` | `pub(super)` | Parent submit/adapter rejection flows remain parent-mediated. |
| `expire_orders` | `pub(in crate::v4_runtime)` | `event_replay_orchestration` calls expiry before trigger sweep from a sibling v4 runtime child. |
| `trim_history` | `pub(super)` | Shared retention policy remains internal to the simulated execution parent. |
| `cancel_oco_siblings` | `pub(super)` | Fill completion stays parent-owned and calls lifecycle sibling cancellation through the parent boundary. |
| `reject_existing_order` | `pub(super)` | Amend and fill/trigger flows share existing-order rejection through the parent boundary. |
| `accepted_order` | `pub(super)` | Parent submit flow and OCO registration share accepted-order construction. |

## Preserved Parent-Owned Surface

The following stayed outside `order_lifecycle_flow`:

- `submit_order`;
- market price update, trigger sweep, and trailing stop mechanics;
- fill construction, ledger/accounting mutation, fee charging, asset curve mutation, and portfolio valuation;
- snapshot projection and microstructure metrics;
- request validation, capability derivation, payload parsing, token normalization, and helper families;
- v4 tests.

## Boundary Notes

`amend_order` and `expire_orders` required `pub(in crate::v4_runtime)` rather than the baseline's initial `pub(super)` estimate. This is not a public API expansion: both methods remain restricted to the v4 runtime module tree. The visibility adjustment preserves existing direct test and sibling orchestration access after the helper implementations moved into a nested child.

No release-transition optimization, hot-path sibling horizontal connection, route/schema change, persistence owner change, or runtime mode change was introduced.
