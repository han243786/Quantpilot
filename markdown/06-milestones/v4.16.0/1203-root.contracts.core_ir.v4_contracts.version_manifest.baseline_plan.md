## Summary

`root.contracts.core_ir.v4_contracts.version_manifest` freezes the equivalence baseline for extracting the v4 version
manifest compatibility contract from `qrpc_core_ir/src/v4.rs`.

Frozen public surface:

- `V4VersionManifest`
- `impl Default for V4VersionManifest`
- `V4VersionManifest::validate_static_contract`

Frozen internal child helpers:

- `default_version_manifest_version`
- `default_qs_language_version`
- child-local imports for QS type-system, machine contract, and venue capability matrix version defaults

Frozen behavior:

- default schema version remains `V4_VERSION_MANIFEST_VERSION`
- default QS language, QS type-system, machine contract, and venue capability matrix versions remain unchanged
- additive compatibility flags default to true through the parent `default_true` helper
- validation keeps the current schema version, blank QS language version, type schema version, machine template version,
  capability matrix version, additive type compatibility, additive defaulted field compatibility, type tightening,
  type deletion, and semantic schema bump error strings

Allowed extraction:

- add `mod version_manifest;` to `qrpc_core_ir/src/v4.rs`
- re-export the child through `pub use version_manifest::*;`
- create `qrpc_core_ir/src/v4/version_manifest.rs`
- move `V4VersionManifest`, its `Default` impl, and `validate_static_contract`
- move `default_version_manifest_version` and `default_qs_language_version`
- import `default_true`, schema identity constants, and sibling version default helpers through the v4 surface

Forbidden movement:

- schema identity constants, QS type-system implementation, machine contract implementation, venue capability matrix
  implementation, plugin governance, reproducibility, complexity budget, developer learning pipeline, static bundles,
  compile-time capability reports, compatibility bridge, bridge builders, tests, machine graph contract, QS profile, and
  runtime mode contract
