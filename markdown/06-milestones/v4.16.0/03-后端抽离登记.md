# v4.16.0 后端抽离登记

> 职责: 为后端抽离批次建立候选清单、父模块坐标、兼容桥、回退点和等价验证方式。
> 范围: Rust 后端、运行时、编译链、存储安全、执行端交互边界。
> 非目标: 不切换主 API，不删除旧 handler，不迁移执行端真实状态所有权。

---

## 登记规则

1. 每个候选只能围绕一个父模块或一条兼容桥展开。
2. 抽离阶段默认旧实现保留，新候选模块只作为并存版本或适配层。
3. public 方法新增、移动或包装时，必须同步 `markdown/00-matrix-governance/module-tree.md`。
4. 没有等价性证据或替代证据的候选不得进入代码实现。
5. 涉及状态归属、锁、事务、持久化或执行端边界时，必须先决策暂停。
6. 采用 system 经验回填口径: public 入口、兼容 public 入口、关键内部实现、保留外部边界分开登记。

## 候选细节

### B0 后端接口边界大模块

| 字段 | 内容 |
| --- | --- |
| 目标 | 建立 BE-001 后端接口边界大模块，先稳定 router/API/facade 父级关系 |
| 关键 public 方法 | `build_app_router`、`get_capabilities`、`register_strategy_config_routes`、`register_runtime_routes`、`register_graph_routes`、`register_compile_routes` |
| 关键内部实现 | 后续只允许登记 route owner 聚合、facade 委托和契约检查；handler 业务实现不因此迁移 |
| 保留外部边界 | AppState、runtime state、executor state、response schema、artifact schema |
| 输入/输出 | HTTP request、AppState、route registration -> Axum Router、API response、错误边界 |
| 兼容桥 | 旧 `build_app_router` 继续作为父入口，候选 facade 只登记接口边界和路由归属 |
| 回退点 | 保留原 route registration 顺序、旧 handler、旧 response schema |
| 等价证据 | `cargo test -p quantpilot --test api_run`、`cargo test -p quantpilot --test api_backtest`、`cargo test -p quantpilot --test api_graph_versions`、`cargo test -p quantpilot --test api_evidence_contract`、`cargo test -p quantpilot --test api_ai_proposal` |
| 替代证据 | 当历史 API 脚本废弃时，使用 Rust API tests、OpenAPI/route 人工核查和 response schema 对照替代 |
| 子模块顺序 | 后续在本大模块内依次抽 `backend.capability`、`backend.strategy_config`、`backend.runtime`、`backend.graph_compile` |
| 决策点 | 已决策先抽后端接口边界大模块；仍需讨论 facade 粒度和第一批是否只做文档/契约或进入代码壳 |
| 禁止事项 | 不切换主 API，不删除旧 handler，不迁移状态所有权，不改变 `/api/*` response schema |
| system 经验应用 | 先像 `system.entry.backend_process` 一样稳定父入口和兼容桥，再讨论内部 facade 归位；不得把 handler 或 state owner 顺手搬走 |

### B1 runtime 运行入口适配层

| 字段 | 内容 |
| --- | --- |
| 目标 | 把 runtime run/backtest/mutation 的入口行为包成候选 facade，先不改路由 |
| 关键 public 方法 | `register_runtime_routes`、`/api/runtime/v4/run`、`/api/runtime/backtest`、`/api/runtime/runs/:run_id/events` |
| 输入/输出 | runtime request、v4 graph、backtest request -> run record、artifact、SSE event |
| 兼容桥 | 旧路由调用候选 facade；候选 facade 失败时仍可回到旧处理函数 |
| 回退点 | 保留原 runtime route 和 handler 调用链 |
| 等价证据 | `cargo test -p quantpilot --test api_run`、`cargo test -p quantpilot --test api_backtest`、`cargo test -p quantpilot --test api_evidence_contract` |
| 替代证据 | 当旧测试程序被废弃时，使用 API 契约测试、artifact 对比或事件序列替代 |
| 决策点 | D2 接口粒度、D3 状态归属、D4 兼容桥方向 |

| 字段 | 内容 |

## 暂停条件

出现以下任一情况，停止实现并回到方案讨论:

1. 候选需要跨 `backend.runtime` 和 `executor.runner` 直接通信。
2. 候选要求删除旧 handler 或旧 state owner。
3. 候选无法给出等价性证据。
4. 候选需要一次性移动多个父模块。
5. 候选会改变 API response、artifact schema 或 capability 声明。
6. 候选无法区分 public 入口、关键内部实现和必须保留的外部边界。
