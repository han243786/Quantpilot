## Selection Rationale

`machine_graph_contract` is selected because:

- it is the next graph-level state-machine schema after the closed machine schema;
- it owns independent validation failure modes for graph identity, duplicate machines, edge integrity, DAG acyclicity, event catalog completeness, emitter/consumer permissions, and risk-plane enforcement;
- existing v4 tests already cover graph positive/negative cases;
- it is large enough to require a baseline before code movement.

## Explicit Non-Owners

The selected child does not own:

- machine schema/taxonomy or machine static validation, which are closed under `machine_contract`;
- QS state-machine profile policy and validation;
- complexity budget DTOs and validation;
- compat bridge builder functions;
- default helper bodies unless the baseline explicitly proves movement is required;
- test fixture helpers.
