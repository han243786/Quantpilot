## 目标

### 1. 实时交易接口
- 接入 OKX/Binance 真实交易 API (下单/撤单/查订单/查余额)
- 实现 `LiveExecutionModule` 替代 `BuiltinExecutionModule(Paper)`
- 风险控制: 交易前二次确认、单日最大亏损硬止损、API限流保护

### 2. 多用户认证与数据隔离
- 用户注册/登录 (JWT token)
- 每个用户独立的策略图、回测记录、凭证
- 管理员面板: 用户管理、系统配置

### 3. 插件市场
- 插件签名验证 (Ed25519)
- 远程插件索引下载 + manifest校验
- 插件沙箱: 实际CPU/内存限制 (非声明式)

### 4. 前端UX补全
- t()全量包裹 (~175处剩余)
- 编译/回测进度指示 + 取消按钮
- 响应式暗色主题完善

### 5. 整合包发布
- Windows NSIS安装器
- Docker多阶段镜像
- GitHub Actions CI/CD发布流水线
- SBOM (SPDX) + SHA256签名

### 完成标准

- 可通过OKX测试网完成真实下单→成交→持仓查询全流程
- 两个用户登录后互相看不到对方的策略图
- 插件市场可下载并验证一个签名插件
- 前端无报错，所有硬编码文本已t()包裹
- `gh release create` 可一键发布全平台安装包

## 方案

### 1. 实时交易接口

**新模块**: `qrpc_runtime/src/live_execution.rs`
- 复用 `ExecutionModuleProvider` trait
- OKX API: REST 下单 + WebSocket 订单状态推送
- HMAC-SHA256 签名 (复用test_runner.rs已有实现)
- 下单前风控检查: 资金充足、单笔上限、日累计上限

**文件**: `qrpc_runtime/src/live_execution.rs`, `src/credential_vault.rs` (扩展exchange凭证)

### 2. 多用户认证

**新模块**: `src/auth/`
- JWT token 认证替代单一 API_KEY
- SQLite 用户数据库 (新增依赖 `rusqlite`)
- 中间件注入 `user_id` 到 request extension
- AppState BTreeMap key 加 `{user_id}:` 前缀

**文件**: `src/auth/`, `src/state.rs`, `src/middleware.rs`

### 3. 插件市场

**增强**: `qrpc_runtime/src/plugin_market.rs` + `plugin_runtime_registry.rs`
- Ed25519 签名: 插件开发者签名manifest, 市场公钥验证
- 远程索引: `fetch_index()` → 校验 `index_hash`
- 沙箱: `tokio::time::timeout` 包裹插件调用, 进程级内存限制

**文件**: `qrpc_runtime/src/plugin_market.rs`, `qrpc_core/src/plugin.rs`

### 4. 前端UX补全

- t()包裹: 逐文件完成 (BacktestComparePage → propertyPanelViews → compileGraph → 其余)
- 进度指示: 编译/回测 API 返回 `X-Progress` header, 前端轮询展示
- 取消按钮: 编译/回测操作绑定 AbortController

### 5. 整合包发布

- `packaging/windows/installer.nsi` — NSIS脚本
- `packaging/docker/Dockerfile` — 多阶段(distroless)
- `.github/workflows/release.yml` — tag触发
- `release/release-manifest.yaml`

## 风险

| 风险 | 缓解 |
|------|------|
| 真实交易导致资金损失 | 默认paper模式，live需显式启用+二次确认 |
| SQLite并发写入瓶颈 | 单用户桌面应用，并发低 |
| 插件沙箱逃逸 | tokio::time::timeout + 独立进程(远期) |
| NSIS打包Windows兼容性 | CI用windows-latest runner测试 |
| JWT密钥泄露 | 环境变量注入，不写入代码 |

## 决策纪录

### 决策 1: 实时交易上线策略

**选项**:
- A: 渐进 — OKX测试网先行
- B: 全量 — OKX+Binance同时

**选择**: A

**理由**: 测试网无资金风险，可充分验证签名/下单/状态同步链路。Binance和主网在测试网稳定后追加。

**影响**: v2.0.0仅OKX测试网，v2.1.0加Binance+主网。

### 决策 2: 多用户数据库

**选项**:
- A: SQLite (rusqlite)
- B: 文件系统 (JSON)

**选择**: A

**理由**: SQLite提供ACID事务、索引查询、无额外服务进程。适合单机桌面应用。rusqlite是Rust生态成熟crate。

**影响**: 新增依赖`rusqlite`+`jsonwebtoken`。用户数据从JSON文件迁移到SQLite。

### 决策 3: 插件沙箱

**选项**:
- A: tokio::time::timeout (进程内)
- B: 独立进程 (WASM/子进程)

**选择**: B

**理由**: 进程内超时无法防止死循环或内存泄漏。子进程隔离提供真正的安全边界，崩溃不影响主进程。

**影响**: 插件执行引擎需重构为IPC模式。v2.0.0先实现子进程隔离框架，v2.1.0加WASM支持。

### 决策 4: 整合包发布优先级

**选项**:
- A: Windows优先
- B: 全平台同时

**选择**: A

**理由**: QuantPilot当前为Windows桌面应用(Tauri)，Windows是主战场。Docker镜像作为服务器部署补充。

**影响**: v2.0.0产出 Windows NSIS安装器 + Docker镜像。Linux/macOS包延入v2.1.0。
