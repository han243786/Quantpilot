## V1 — 架构合规（0.5 天）

### V1-1 删除旧编译路径（规则 1.1 / 1.3）

**违规**：`compile_api.rs:49-55` 的 `else` 分支在 `graph_json=None` 时仍走 `map_frontend_runtime_config` 绕过 QS 管道。

**方案**：删除 `else` 分支。当 `graph_json` 缺失时返回错误而非降级。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/compile_api.rs:37-56` | `if let Some(ref graph_json) = request.graph_json` 的 `else` 改为返回 400 错误 |
| 2 | `cargo test --workspace` | 确认无编译路径测试失败 |

**验收**：
```
curl -X POST /api/runtime/compile -d '{"runtime_config": {...}}'  # 不带 graph_json
→ HTTP 400: "graph_json is required for compile"
```

### V2-4 硬编码波动率改为常量（规则 5.1）

**违规**：`data_module.rs:1192` — `get_mock_volatility()` 回退值硬编码 `0.005`。

**方案**：提取为命名常量。

```rust
const DEFAULT_MOCK_VOLATILITY: f64 = 0.005;

fn get_mock_volatility() -> f64 {
    let bits = MOCK_VOLATILITY.load(Ordering::Relaxed);
    if bits == 0 { DEFAULT_MOCK_VOLATILITY } else { f64::from_bits(bits) }
}
```

**验收**：`grep "0.005" qrpc_runtime/src/data_module.rs` 仅匹配到常量定义行。

## V3 — 存储生命周期实现（1 天）

### V3-1 创建 `src/storage_lifecycle.rs` 并接入 main.rs

**方案**：按照 `03-implementation/runtime/implementation-storage-lifecycle.md` §3 实现。

| 步骤 | 内容 |
|------|------|
| 1 | 创建 `src/storage_lifecycle.rs`：`StorageLifecycle` 枚举 + `directory_lifecycle()` 映射 + `startup_storage_cleanup()` |
| 2 | 在 `main.rs` 中注册 `mod storage_lifecycle` |
| 3 | 在 `main.rs` 的启动流程中调用 `storage_lifecycle::startup_storage_cleanup()` |

**验收**：服务器启动日志包含 `[storage]` 清理信息，过期文件被删除。

**验收**：测试结束后 `storage/test-runs/` 为空或仅保留最新 5 个。

### V3-3 暂时数据 TTL 标记

**方案**：为 `backtests/`、`runs/` 等暂时目录中的文件添加写入时间戳记录，供启动清理判断。
