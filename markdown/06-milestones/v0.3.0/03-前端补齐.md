## F0 — 策略花名册 QS 集成（1.5 天）

### F0-1 花名册展示 QS 生成的策略

**现状**：`POST /api/test/scenario/run` 响应包含 `graph_id`，后端已保存 QS 源码到 `storage/graphs/{graph_id}.qs`。前端花名册只显示通过前端编辑器创建的策略。

**方案**：`GraphStore` 加载策略列表时，同时扫描 QS 策略目录（或后端 API 自动合并）。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/store/graphStore.js` 或对应的 hub model | 在 `loadGraphList` 中增加对 QS 策略的获取逻辑 |
| 2 | `frontend/src/pages/StrategyHubRosterRowActions.jsx` | QS 策略行添加 `查看 QS 源码` 操作 |
| 3 | `frontend/src/pages/StrategyHubHeroSection.jsx` | 状态卡片中 `可运行策略` 计数包含 QS 策略 |

**验收**：用 `@compile` 编译 QS 策略后，刷新策略中心页面，花名册中出现该策略（名称来自 `@test { name: "..." }` 或 graph_id）。

### F0-2 QS 源码视图

**现状**：QS 源码保存在 `storage/graphs/{graph_id}.qs`，前端无查看入口。

**方案**：在策略工作区新增 `源码` 标签页（或复用现有 `构建` 标签页），显示原始 QS 代码。代码高亮使用简单的 `<pre>` 即可，不需要引入语法高亮库。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/pages/StrategyWorkspacePage.jsx` | WORKSPACE_TABS 新增 `{ id: "source", label: "源码" }` |
| 2 | 新增 `frontend/src/pages/StrategyWorkspaceSourceTab.jsx` | 通过 `GET /api/graphs/:id/quantscript` 或直读 storage/ 拿到源码，`<pre>` 渲染 |

**验收**：点击花名册中 QS 策略的操作按钮 → 工作区 → 源码标签页 → 展示 QS 代码。

## F1 — 调试与对比可视化（2.5 天）

### F1-1 @debug 调试标签页

**现状**：后端 `@debug(closes, fast, slow)` 已实现，per-bar 数据收集到 `data_snapshot.debug_bars`。前端无可视化。

**方案**：新增 `workspace-tab-debug` 标签页，以表格 + 简易折线图展示调试数据。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/pages/StrategyWorkspacePage.jsx` | WORKSPACE_TABS 新增 `{ id: "debug", label: "调试" }` |
| 2 | 新增 `frontend/src/pages/StrategyWorkspaceDebugTab.jsx` | 从 `data_snapshot.debug_bars` 读取数据，渲染为 `<table>` |
| 3 | 同上 | 使用 SVG 或 Canvas 绘制简易折线图（X=bar index, Y=value） |

**数据格式**：
```json
"debug_bars": [
  { "bar": 0, "closes": null, "fast": null },
  { "bar": 20, "closes": 42100, "fast": 42050 }
]
```

**验收**：运行 `@debug(closes, fast)` 的回测后，切换到调试标签页，看到表格显示每 bar 的值，折线图展示趋势。

### F1-2 @compare 对比面板

**现状**：后端 `@compare_backtests { left: 0, right: 1 }` 已实现，返回指标差异列表（纯文本）。前端无差异化展示。

**方案**：在 TestReport 展示区或回测对比页中，将差异指标以绿色/红色高亮显示。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/components/EventStreamPanel.jsx` 或 `StrategyResearchConsole.jsx` | 检测 `compare:` 前缀消息，解析差异列表 |
| 2 | 同上 | 渲染为两列对比表格，left / right / diff |

**数据格式**：
```
compare: 2 differences — net_profit: -99.93 vs 248.02, sharpe: -4.50 vs 5.23
```

**验收**：运行含 `@compare_backtests` 的场景后，对比面板显示绿红色差异表。

### F1-3 事件类型分布图表

**现状**：后端 `execute_run` 已收集事件类型计数到 `data_snapshot.event_types`。前端未使用。

**方案**：在研究控制台的状态面板中展示事件分布（简易柱状图或列表）。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/components/StrategyResearchConsole.jsx` | 读取 `event_types` 渲染为水平柱状图（CSS bar） |

**验收**：Paper 运行后，在研究标签页看到事件类型分布：`DataUpdated: 2, IntentTriggered: 2, ExecutionPlanned: 3...`

### F1-4 断言失败 actual 值展示

**现状**：后端断言失败消息包含 `(actual: 5.000000)`。前端展示时可能被截断。

**方案**：研究控制台或事件面板中，断言失败行以红色高亮显示 actual 值。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/components/EventStreamPanel.jsx` | 解析 `assert failed:` 消息，提取 actual 值，红色高亮 |
| 2 | `frontend/src/styles.css` | `.assert-actual { color: red; font-weight: bold }` |

**验收**：断言失败时，面板显示 `assert failed: total_fills > 999 (actual: 5)`，其中 `5` 红色加粗。

### F2-3 回测选项增加 volatility 参数

**方案**：回测启动弹窗（或高级选项区）增加 `volatility` 输入框。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/store/graphStoreRuntimeSessionActions.js` | `backtest_options` 结构新增 `volatility: number` |

## F4 — 内联 QS 编辑器 + 一键测试（1.5 天）

### F4-1 内联 QS 编辑器

**现状**：QS 策略只能通过 `.qs` 文件和 `@test` 指令运行。无前端编辑入口。

**方案**：在策略中心或工作区增加一个简易 QS 文本编辑器，直接输入/粘贴 QS 代码并运行。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | 新增 `frontend/src/pages/QuantScriptEditor.jsx` | `<textarea>` + `运行` 按钮 |
| 2 | `frontend/src/router.js` | 新增路由 `/quantscript` |
| 3 | 导航栏 | 新增 `QS` 链接 |

**验收**：导航到 `/quantscript` → 粘贴 QS 代码 → 点击运行 → 调用 `POST /api/test/scenario/run` → 下方展示 TestReport JSON 或可视化步骤列表。

### F4-2 Run Scenario 按钮

**现状**：需要手动调用 API 或命令行工具运行 QS 场景。前端无操作入口。

**方案**：在 QS 工作区（F0-2 的源码视图）增加 `运行测试` 按钮，一键提交到 `/api/test/scenario/run`。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/pages/StrategyWorkspaceSourceTab.jsx` | 新增 `运行测试` 按钮 |
| 2 | 同上 | 调用 API，结果以步骤列表展示 |

**验收**：打开 QS 策略源码页 → 点击 `运行测试` → 下方展示 3 个步骤及通过/失败状态。
