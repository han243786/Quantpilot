## M-A — 后端补齐（1.5 天）

### M-A-1 `win_rate` 接入 BacktestSummary

**现状**：TestRunner 的 `execute_backtest_core` 已计算 `win_rate`（基于 equity_curve），但仅存储在 `TestRunner.last_backtest_metrics`（TestReport 的 data_snapshot 中）。后端回测 API 返回的 `BacktestSummary` 结构体无此字段，前端 `BacktestDetailPage` 无法展示。

**方案**：在 `BacktestSummary` 新增 `win_rate` 字段，由 `FastBacktestSandbox::run_backtest()` 计算并填充。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `qrpc_core/src/lib.rs` | `BacktestSummary` 新增 `pub win_rate: f64` |
| 2 | `qrpc_runtime/src/sandbox.rs:run_backtest()` | 在构建 `BacktestSummary` 时，基于 equity_curve 计算 `win_rate = 盈利步数 / 总步数` |
| 3 | `src/backtest_artifacts.rs:summarize_equity_curve()` | 同步输出 `win_rate` 到工件摘要 |
| 4 | `frontend/src/pages/BacktestDetailPage.jsx` | `summaryItems` 新增 `{ label: "胜率", value: formatPercent(summary?.win_rate) }` |

**验收**：
```
回测完成后 → 详情页 → 胜率: 45.2%
@assert backtest.metrics.win_rate >= 0 → passed
```

### M-A-2 `volatility` 接入 mock 沙箱

**现状**：`@backtest { volatility: 2.0 }` 参数已解析并存储到 `TestActionDef::Backtest.volatility`，但 `execute_backtest_core` 未将其传递给 `mock_raw_klines`。波动率始终硬编码为 `0.005`。

**方案**：通过模块级 `AtomicF64` 在 TestRunner 和 data_module 之间传递波动率值。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `qrpc_runtime/src/data_module.rs` | 新增 `pub static MOCK_VOLATILITY: AtomicF64 = AtomicF64::new(0.005)` |
| 2 | 同上 | `mock_raw_klines()` 中 `noise = pseudo_random(...) * trend_close * MOCK_VOLATILITY` |
| 3 | `src/test_runner.rs:execute_backtest_core()` | `if let Some(vol) = volatility { MOCK_VOLATILITY.store(*vol, Ordering::Relaxed); }` |
| 4 | `frontend/src/components/TopToolbar.jsx` 或回测弹窗 | 新增波动率滑块或输入框 |

**验收**：
```
@backtest { source: "deterministic_mock", volatility: 2.0 }
→ fills 数量或收益与 volatility: 0.5 不同

@backtest { source: "deterministic_mock", volatility: 0.1 }
→ 收益接近 0（波动极小，无交易信号）
```

### M-A-3 QS 源码 API 端点

**现状**：`@compile` 后 QS 源码保存到 `storage/graphs/{graph_id}.qs`，前端通过 `graph_id` 可定位策略，但无 API 端点返回源码内容。

**方案**：利用已有的 `GET /api/graphs/:id/quantscript` 端点（`graph_quantscript_api.rs`），或新增简化端点。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/graph_quantscript_api.rs` 或 `src/test_runner.rs` | 若 graph_id 以 `qs_` 开头，直接从 `storage/graphs/{id}.qs` 读取返回 |
| 2 | `frontend/src/pages/StrategyWorkspacePage.jsx` | WORKSPACE_TABS 新增 `{ id: "source", label: "源码" }` |
| 3 | 新增 `frontend/src/pages/StrategyWorkspaceSourceTab.jsx` | `useEffect` → `fetch("/api/graphs/:id/quantscript")` → `<pre>` 渲染 |

**验收**：
```
打开 QS 生成的策略工作区 → 点击"源码"标签页 → 展示完整 .qs 代码
```

**方案**：在研究控制台新增 `对比` 子标签页或扩展 `EventStreamPanel` 的步骤消息渲染。

|------|------|------|

| 步骤 | 文件 | 改法 |
|------|------|------|

### M-B-3 模拟盘状态指示器

**现状**：Testnet 执行模块已实现（`execute_testnet_run`），但前端无连接状态反馈。用户不知道模拟盘是否在线、余额多少。

**方案**：在 `StrategyWorkspacePage` 的状态栏增加 Testnet 状态 pill。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/pages/StrategyWorkspacePage.jsx` | 状态区新增 `<div className="status-pill testnet">` |
| 2 | 同上 | `runtime.testnet_status` 字段驱动（需要 store 支持） |
| 3 | `frontend/src/store/graphStoreRuntimeSessionActions.js` | `startRuntime` 支持 `mode: "testnet"` → 在 runtime state 中设置 `testnet_status: "connecting"` |
| 4 | 同上 | Testnet 订单确认后 → `testnet_status: { exchange: "OKX", balance: 95857, connected: true }` |

**状态枚举**：

| 状态 | 显示 |
|------|------|
| `idle` | 不显示 pill |
| `connecting` | `模拟盘: 连接中...` (黄色) |
| `connected` | `模拟盘: OKX | 余额 95,857 USDT` (绿色) |
| `error` | `模拟盘: 连接失败` (红色) |

**验收**：
```
点击 [启动模拟 ▼] → [Testnet 模拟盘]
→ 状态栏出现: 🟡 模拟盘: 连接中...
→ 订单成交后: 🟢 模拟盘: OKX | 余额 95,857 USDT
```
