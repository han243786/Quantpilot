## I-1 — @debug per-bar 指标值收集通道（0.5 天）

### 现状问题

用户写 `@debug(rsi_val, fast, slow)` 后，前端调试标签页显示的全是 `null`。

**根因**：数据流有三段断裂——

```
QS 变量名                   Sandbox 内部                   TestRunner 输出
─────────────               ─────────────                 ───────────────
@debug(rsi_val, fast)       evaluate_indicator_signal()    backtest.equity_curve
   ↓                              ↓                         → 只有 equity/cash
last_debug_vars              derived_metrics: {             debug_bars:
  = ["rsi_val","fast"]         "rsi": 30.5                  bar.insert("rsi_val", null)
                             }                              bar.insert("fast", null)
                                ↓
                             每个 bar 都计算了
                             但历史从不保存
```

断裂点 1：`FastBacktestSandbox` 不知道要跟踪哪些变量。  
断裂点 2：`BacktestOutput` 没有 per-bar 指标值字段。  
断裂点 3：`@debug` 中的变量名（`rsi_val`）和 sandbox 内部存储的 key（`"rsi"`）不一致。

### 方案

}

**步骤 2**：构建 debug_bars 时消费 `backtest.debug_values` 而非插入 null（第 943-956 行）

```rust
if let Some(ref debug_vars) = self.last_debug_vars {
    let debug_rows = backtest.debug_values.as_ref();
    let bars: Vec<_> = backtest.equity_curve.iter().enumerate().map(|(i, pt)| {
        let mut bar = serde_json::Map::new();
        bar.insert("bar".to_string(), serde_json::json!(i));
        bar.insert("equity".to_string(), serde_json::json!(pt.equity));
        bar.insert("timestamp_ms".to_string(), serde_json::json!(pt.ts_ms));
        for var in debug_vars {
            let value = debug_rows
                .and_then(|rows| rows.get(i))
                .and_then(|row| row.get(var))
                .copied();
            bar.insert(var.clone(), serde_json::json!(value));
        }
        serde_json::Value::Object(bar)
    }).collect();
    self.last_debug_bars = Some(serde_json::Value::Array(bars));
}
```

**步骤 3**：构建变量名映射表——`@debug(rsi_val, fast)` 中用户用的变量名（`rsi_val`）需要映射到 sandbox 内部的 `derived_metrics` key（`"rsi"`）。映射来源于 QS lowering 的绑定表。

最简单方案：在 `@debug` 处理时，从 `compile_result` 的 indicator params 中提取所有可能的 key，与用户变量名做模糊匹配（包含关系）。

```rust
// 构建指标 key → 用户变量名的反向映射
// 如果 compile_result 有 indicators，遍历其 params keys
let mut var_to_metric: BTreeMap<String, String> = BTreeMap::new();
if let Some(ref compiled) = self.compile_result {
    for indicator in &compiled.core_ir.indicators {
        for param_key in indicator.params.keys() {
            for var in vars {
                if var.contains(param_key) || param_key.contains(var.as_str()) {
                    var_to_metric.insert(var.clone(), param_key.clone());
                }
            }
        }
    }
}
// 然后将 debug_var_names 设置为 metric keys 而非用户变量名
let metric_names: Vec<String> = vars.iter()
    .map(|v| var_to_metric.get(v).cloned().unwrap_or_else(|| v.clone()))
    .collect();
sandbox.debug_var_names = metric_names;
```

**验收**：
```
@debug(closes, fast, slow)
@backtest { source: "deterministic_mock" }
→ 前端调试标签页表格中 closes/fast/slow 列显示实际数值（非 null）
→ SVG 折线图有实际曲线
```

## I-2 — 双编译路径合并（0.5 天）

### 现状问题

两条编译路径产出不同的 intent 类型和参数语义：

```
路径A（Graph）                             路径B（QS）
─────────────                             ──────────
前端拖拽图                                 .qs 源码
  ↓                                         ↓
前端序列化为 FrontendRuntimeConfig         parse_quant_script_module()
  ↓                                         ↓
POST /api/runtime/compile                 lower_script_to_runtime_config()
  ↓                                         ↓
map_frontend_runtime_config()             frontend_runtime_config_from_core_with_template()
  ↓                                         ↓
RuntimeProtocolCoreConfig                 map_frontend_runtime_config()
  ↓                                         ↓
compile_runtime_protocol_config()         compile_runtime_protocol_config()
```

差异来源：`map_frontend_runtime_config` 和 `lower_script_to_runtime_config` 对同一策略可能产出不同的 `RuntimeProtocolCoreConfig`。v0.3.0 规划明确"QS 是唯一策略定义路径"，但 Path A 从未经过 QS 管道。

### 方案

让 Path A 也走 QS 管道：Graph JSON → `generate_quantscript_from_graph_value` → `parse_quant_script_module` → `lower_script_to_runtime_config` → `compile`。

```
路径A（合并后）
──────────────
前端拖拽图
  ↓
前端发送 raw graph JSON + FrontendRuntimeConfig（兼容期两个都发）
  ↓
POST /api/runtime/compile
  ↓
generate_quantscript_from_graph_value(graph_json)
  ↓
parse_quant_script_module(qs_string)
  ↓
lower_script_to_runtime_config(&module)
  ↓
compile_runtime_protocol_config(&config)
  ↓
统一产出 CoreStrategyIr
```

#### I-2b — compile_runtime_request 处理分叉

**文件**：`src/compile_api.rs`，第 14-74 行

```rust
pub(super) async fn compile_runtime_request(
    State(state): State<AppState>,
    Json(request): Json<CompileRuntimeRequest>,
) -> Result<Json<CompileRuntimeResponse>, (StatusCode, String)> {
    // ... 能力验证保持不变 ...

    let compiled = if let Some(ref graph_json) = request.graph_json {
        // 新路径：Graph JSON → QS → lower → compile
        let qs_source = generate_quantscript_from_graph_value(graph_json)
            .map_err(|e| (StatusCode::BAD_REQUEST, format!("graph-to-qs conversion failed: {e}")))?;
        let module = quantscript::parse_quant_script_module(&qs_source)
            .map_err(|e| (StatusCode::BAD_REQUEST, format!("qs parse failed: {e}")))?;
        let runtime_protocol = quantscript::lower_script_to_runtime_config(&module)
            .map_err(|e| (StatusCode::BAD_REQUEST, format!("qs lowering failed: {e}")))?;
        qrpc_compiler::compile_runtime_protocol_config(&runtime_protocol)
            .map_err(|e| (StatusCode::BAD_REQUEST, format!("compile failed: {e}")))?
    } else {
        // 旧路径（兼容期保留，前端未升级时回退）
        let mapped = map_frontend_runtime_config(&request.runtime_config)
            .map_err(|e| (StatusCode::BAD_REQUEST, format!("mapping failed: {e}")))?;
        qrpc_compiler::compile_runtime_protocol_config(&mapped.runtime_protocol)
            .map_err(|e| (StatusCode::BAD_REQUEST, format!("compile failed: {e}")))?
    };

    // ... artifact bundle 构建 + 响应保持不变 ...
}
```

**验收**：
- 旧前端（不传 `graph_json`）→ 走原路径，功能不受影响
- 新前端（传 `graph_json`）→ 走 QS 路径，编译结果一致
- TestRunner 的 Path B 编译也走同样的 QS 路径（验证等效性）
