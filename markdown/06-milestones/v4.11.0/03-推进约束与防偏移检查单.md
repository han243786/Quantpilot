# v4.11.0 推进约束与防偏移检查单

> 目的：确保 v4 策略配置系统从开始到彻底达成设计指标期间，不偏移为页面优化、账户系统、策略搜索、实盘宣称或泛化功能扩张。
> 硬规则：遇到分歧点必须当场和用户讨论，解决后才能继续推进。

## 3. 分歧点处理协议

### 3.1 必须暂停的分歧点

遇到以下任一情况，必须暂停受影响内容的继续推进，并向用户说明分歧：

- 本地代码、支持矩阵、总览文档、里程碑文档对同一能力给出不同状态。
- 某个能力可能从 `unsupported` 被写成 `planned` 或 `supported`。
- 命名可能让用户误解为真实资金、实盘、云账户、研究级回测或第三方市场。
- 新增依赖、路由、数据模型或能力状态需要改变既有边界。
- 设计指标与现有实现冲突，无法通过文档澄清解决。
- 发现文档路径漂移、文件命名冲突或索引指向不存在文件。
- 需要在 `PaperSimulated`、`PaperActual`、demo/testnet、provider_native、runtime_simulated 之间重新定义边界。

### 3.2 暂停时输出格式

暂停时只输出以下内容，不继续改受影响文件：

```text
发现分歧点：
1. 分歧对象：
2. A 口径：
3. B 口径：
4. 风险：
5. 我的建议：
6. 需要你确认：
```

### 3.3 解决后处理

用户确认后，必须：

- 把决策写入本文件“已拍板决策”或对应里程碑设计文档。
- 同步支持矩阵、用户功能切面或规划方案中的相关口径。
- 若涉及能力扩展，补功能演进登记和回归保护矩阵。

## 4. 设计指标闸门

每个工作线开始前、实现中、closeout 前都要检查以下指标。

| 指标 | 开始前 | 实现中 | closeout |
| --- | --- | --- | --- |
| `SC-1` 配置域完整 | 明确影响哪些配置域 | 不新增无归属 UI | 每个配置域有状态与证据 |
| `SC-2` 契约可导出 | 明确 artifact 字段 | 不绕过 QS/compile | digest 和导出测试通过 |
| `SC-3` 能力不漂移 | 明确后端真源 | 前端不硬编码能力 | capability stack clean |
| `SC-4` 运行前可解释 | 明确 runtime boundary | PaperActual demo 文案一致 | 无 live/实盘误导 |
| `SC-5` 证据闭环 | 明确 evidence anchors | run/backtest/proposal/snapshot 关联 | 证据可追踪到 artifact |
| `SC-6` 用户不误解 | unsupported 列表确认 | 不新增账号/搜索/实盘 CTA | 文案门禁和人工审计通过 |

任一 P0 指标未满足，不得进入 closeout。

## 5. 阶段推进检查单

### Phase 0：立项与边界

- [ ] `01-规划方案.md` 已列出目标、非目标、工作线。
- [ ] 功能演进登记包含每个新增能力 ID。
- [ ] unsupported 项没有进入 planned/supported。
- [ ] 运行模式命名只使用 `PaperSimulated` / `PaperActual`。
- [ ] 如发现分歧点，已按第 3 节暂停并解决。

### Phase 1：契约设计

- [ ] artifact 不产生第二编译路径。
- [ ] 所有 digest 使用 canonical JSON SHA-256。
- [ ] artifact 不包含密钥、secret、refresh token、账户资料。
- [ ] `ConfigDomainStatus` 同时表达生命周期和运行 readiness，但不混用。
- [ ] OpenAPI 路由草案已登记。

### Phase 2：后端聚合

- [ ] 后端仍是 capability 真源。
- [ ] preflight 覆盖 missing、restricted、stale、unsupported。
- [ ] `unsupported` required capability fail-closed。
- [ ] Risk Plane 缺失或被绕过时拒绝。
- [ ] PaperActual 只表示 OKX demo 边界。

### Phase 3：前端策略配置台

- [ ] 新 UI 文案全部 `t()` 包裹。
- [ ] safe_fallback 只读或禁用，不恢复完整操作。
- [ ] 配置域按 v4 策略配置系统组织，不按页面清单组织。
- [ ] 不展示账户、搜索筛选、实盘、研究级回测 CTA。
- [ ] 组件使用现有设计系统，不新建一套视觉语言。

### Phase 4：AI proposal 绑定

- [ ] proposal 必须绑定配置域。
- [ ] proposal 必须有 before/after digest 或等价结构。
- [ ] sandbox 未通过不得激活。
- [ ] AI 不直接改 QS，不直接执行。

### Phase 5：执行端 preflight

- [ ] 执行端不自行推断能力。
- [ ] 启动前展示 runtime boundary。
- [ ] 不显示 `live` 作为用户侧模式。
- [ ] unsupported 或 digest mismatch 禁止启动。

### Phase 6：文档与矩阵同步

- [ ] 支持矩阵与本地代码模块键一致。
- [ ] 用户功能切面总览继续以 v4 策略配置为第一切面。
- [ ] README/索引新增文档路径后必须能打开。
- [ ] 文档路径必须稳定；发现命名漂移需单独登记解决。

### Phase 7：验证与 closeout

- [ ] UTF-8、用户文案、i18n、capability、feature evolution 门禁通过。
- [ ] Rust 和前端相关测试通过。
- [ ] 三角色手动验证完成。
- [ ] 至少一轮自由维度诱错审计完成。
- [ ] `02-策略配置系统端到端设计.md` 实现回填表已更新。

## 6. 禁止漂移清单

| 漂移 | 禁止原因 |
| --- | --- |
| 把 v4.11 做成策略中心搜索/筛选 | 已明确不做，且不提升策略配置水准。 |
| 把 PaperActual 写成 live/testnet live | 会误导真实资金能力。 |
| 把 `live.okx` 内部键直接展示给用户 | 内部 ID 不等于用户能力命名。 |
| 新增账户设置、用户资料、注销按钮 | 已明确 unsupported。 |
| 引入 Monaco/CodeMirror/zod/ajv/schemars 而不评审 | 违反依赖治理与最小实现原则。 |
| 前端用静态数组决定能力支持 | 违反 capability 真源。 |
| artifact 直接生成 runtime config 并绕过 QS | 违反 QS 唯一路径。 |
| AI proposal 自动写入并启动 | 违反 proposal_only。 |
| 把基础回放宣传成研究级回测 | 违反支持矩阵声明。 |

## 7. 文档路径稳定规则

当前仓库已有部分里程碑文件存在后缀漂移现象，例如 `01-规划方案0.md`、`01-规划方案1.md`、`01-规划方案2.md`。v4.11 不在本线顺手整理历史路径，避免扩大范围。

后续规则：

- 新增文档必须使用稳定路径。
- README 或索引引用的路径必须实际存在。
- 发现历史命名漂移时，单独登记为文档治理项。
- 未经用户确认，不在策略配置系统里程碑中批量重命名历史文件。
