## A1 — API 错误修复（1.5 天）

### A1-1 `internal_error` 返回 400 而非 500

**严重度**：🔴 高  
**文件**：`src/api_errors.rs:58-59`

```rust
// 当前：所有内部错误伪装成 400
pub(super) fn internal_error(error: anyhow::Error) -> (StatusCode, String) {
    json_bad_request("bad_request", error.to_string())
}
```

**影响**：监控系统无法区分 4xx（用户错误）和 5xx（服务器错误）。编译失败、IO 失败、反序列化失败全部返回 400。

**方案**：`internal_error` 返回 500。新增 `user_error` 返回 400 用于区分。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/api_errors.rs:58-59` | `internal_error` 改为 `(StatusCode::INTERNAL_SERVER_ERROR, "内部服务器错误".to_string())` |
| 2 | `src/compile_api.rs` 多处 | 将用户输入校验的 `.map_err(internal_error)` 改为 `.map_err(user_error)` |
| 3 | `src/runtime_api.rs` 多处 | 同上 |
| 4 | `cargo test --bin quantpilot` | 确认无断言检查 400 状态码的通过性 |

**约束**：§2.1 要求中文错误消息。§5.5 要求 E2E 验证。

**验收**：`curl -X POST /api/runtime/compile -d '{}` → HTTP 500，非 400。

### A1-2 两种错误响应格式统一

**严重度**：🔴 高  
**文件**：`src/api_errors.rs:4-56`（旧格式）vs `:76-133`（RFC 9457 格式）

**现状**：旧格式 `{"error":"...","message":"...","details":[...]}` 调用 ~30 次，新格式 `{"type":"...","title":"...","status":400}` 调用 <5 次。

**方案**：统一为旧格式（所有现有客户端依赖它）。将 RFC 9457 格式的函数标记为 `#[deprecated]`，新功能统一用旧格式。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/api_errors.rs` | 将 `problem_*` 系列函数标记 `#[deprecated]` |
| 2 | `src/runtime_api.rs` | 将 5 处 `problem_response` 调用改为 `json_bad_request` |

**验收**：`grep -r "problem_response\|problem_bad_request" src/` 返回 0（或全部 deprecated）。

### A1-3 全局 JSON 解析错误处理

**严重度**：🟡 中  
**文件**：`src/main.rs` 路由注册处

**现状**：当客户端发送无效 JSON 时，Axum 返回英文纯文本：`Failed to deserialize the JSON body into the target type: missing field 'runtime_config'`。

**方案**：添加 Axum 全局 `JsonRejection` handler。

```rust
fn json_rejection_handler(rejection: axum::extract::rejection::JsonRejection) -> impl IntoResponse {
    (StatusCode::BAD_REQUEST, Json(json!({
        "error": "bad_request",
        "message": format!("请求格式错误: {}", rejection)
    })))
}
```

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/main.rs` | 在 router 上添加 `.route_layer(from_fn(json_rejection_handler))` |

**验收**：`curl -X POST /api/runtime/compile -d 'not json'` → 返回中文 JSON 错误。

## A3 — 状态一致性修复（0.5 天）

### A3-1 编译失败后清除 pending_modifications

**严重度**：🔴 高  
**文件**：`src/test_runner.rs:274` vs `:300-308`

**根因**：`self.pending_modifications.clear()` 只在编译成功路径执行（第 274 行）。编译失败时修改残留，下次编译被重复应用。

**方案**：将 clear 移到 `compile_strategy()` 开头，无论成败都清除。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/test_runner.rs:274` | 删除 `self.pending_modifications.clear()` |
| 2 | `src/test_runner.rs:191` (compile_strategy 开头) | 新增 `self.pending_modifications.clear()` |

**验收**：`@modify` → `@compile`（失败）→ `@compile`（成功），修改只应用一次。

---

### A3-2 回测失败时清空 last_backtest_metrics

**严重度**：🟡 中  
**文件**：`src/test_runner.rs:975-978`

**根因**：`execute_backtest_core()` 返回 Err 时，`last_backtest_metrics` 保持上次成功的值。后续 `@assert backtest.metrics.*` 检查的是旧值。

**方案**：在 execute_backtest_with_range 的 Err 分支前设置 `self.last_backtest_metrics.clear()`。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/test_runner.rs` | 回测 Err 返回前 `self.last_backtest_metrics.clear()` |

**验收**：成功回测→失败回测→`@assert backtest.metrics.*` → 报"未知回测指标"而非用旧值。

---

### A3-3 testnet 循环复用 HTTP Agent

**严重度**：🟡 中  
**文件**：`src/test_runner.rs:681-687`

**根因**：`okx_request()` 每次调用都新建 `ureq::Agent`。testnet 60 分钟循环中创建数千个 Agent。

**方案**：用 `LazyLock` 或 `OnceLock` 静态持有 Agent。

**验收**：testnet 长时间运行不会持续增长 HTTP Agent 对象。

---

### A3-4 storage_lifecycle 错误日志

**严重度**：🟡 中  
**文件**：`src/storage_lifecycle.rs:54-57`

**根因**：`read_dir` 失败时静默 return，无日志。

**方案**：添加 `safe_eprintln!("[storage] 无法读取目录: {e}")`。

**验收**：权限不足时日志输出诊断信息。
