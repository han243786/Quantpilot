## W1 — UI 简洁化（2.5 天）

### 设计原则

```
当前问题:
  大量字段和 UI 堆在前端界面里
  EventStreamPanel ~1300 行，BacktestDetailPage 一页塞 6 个面板
  TopToolbar 双行按钮密集排列

目标:
  信息密度降低 40%，视觉层次清晰
  默认折叠次要信息，用户按需展开
  单体仪表盘风格，操作流程一眼可见
```

### W1-1 字段裁剪——减少可见字段数

**现状**：回测摘要显示 7 个指标项，运行摘要显示全部事件字段，账户面板展开全部指标。

**方案**：每个面板默认只显示 3-4 个核心字段，其余通过"展开详情"按钮访问。

| 面板 | 当前可见 | 简化后默认 | 折叠项 |
|------|:--:|:--:|------|
| 回测摘要 | 7 项 | 4 项（收益、回撤、胜率、成交数） | 协议、哈希、权益 |
| 运行摘要 | 全部事件字段 | 3 项（状态、事件数、权益） | 事件类型分布、单条事件详情 |
| 账户面板 | 全部指标 | 3 项（总权益、可用现金、持仓） | 手续费、冻结仓位 |
| 策略图节点 | 标题+副标题+摘要+快速字段 4 行 | 2 行（标题+核心参数） | 模块 key、运行时状态 |

**约束**：§2.5 要求前端字符串使用 `t()` 包裹，新增的"展开详情"按钮必须用 `{t("展开详情")}`。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/components/EventStreamPanel.jsx` | 每个面板区默认折叠次要字段 |
| 2 | `frontend/src/pages/BacktestDetailPage.jsx` | summaryItems 从 7 项裁到 4 项，其余入折叠区 |
| 3 | `frontend/src/nodes/BaseNodeCard.jsx` | 简化模式下只显示 title + 1 行 summary |

**验收**：默认视图每面板 ≤4 个字段，折叠区点击后展开。

### W1-2 面板重整——合并重叠面板

**现状**：`StrategyResearchConsole` 同时展示回测、运行、事件三个面板，`EventStreamPanel` 也有回测/运行历史，功能重叠。

**方案**：研究控制台只保留主视图切换（回测 | 运行），每个视图内嵌精简的事件流。删除 `EventStreamPanel` 中与研究控制台重复的历史列表区块。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/components/StrategyResearchConsole.jsx` | 事件面板从独立区块变为主视图侧栏 |
| 2 | `frontend/src/components/EventStreamPanel.jsx` | 删除 ResearchConsole 已覆盖的回测/运行历史区块 |

**验收**：用户在研究控制台不需要在两个地方看到相同的回测列表。

### W1-3 布局重设——从多面板平铺到仪表盘

**现状**：StrategyWorkspacePage 6 个标签页平铺，每个标签页内又是自己的子面板。用户需要在多个标签页间切换才能完成一个操作流程。

**方案**：工作区改为仪表盘布局：

```
┌────────────────────────────────────────────┐
│  编译状态 │ 运行状态 │ 最近回测 │ 快速操作  │   ← 仪表盘
├────────────────────────────────────────────┤
│  策略图编辑器（构建标签页）                   │   ← 主工作区
│                                            │
├────────────────────────────────────────────┤
│  诊断（折叠条，仅有问题时展开）               │   ← 问题区
└────────────────────────────────────────────┘
```

"研究"和"调试"标签页合并到仪表盘中的状态卡片和快速操作入口。保留"构建"作为主工作区，"诊断"作为底部折叠条。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/pages/StrategyWorkspacePage.jsx` | 默认 tab 改为新增的 dashboard 视图 |
| 2 | 新增 `frontend/src/pages/StrategyWorkspaceDashboard.jsx` | 集成编译状态、运行状态、最近回测、快速操作四个卡片 |
| 3 | `frontend/src/pages/strategy-workspace.css` | 仪表盘四列网格布局 |

**验收**：打开策略工作区后，第一个看到的不是 6 个标签页而是仪表盘。

```css
  --qp-warning: #f59e0b;
  --qp-danger: #ef4444;
  --qp-text: #e2e8f0;
  --qp-text-muted: #64748b;
  --qp-radius: 6px;
  --qp-gap: 8px;
}
```

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/styles.css` | 新增 `:root` CSS 变量块 |
| 2 | `frontend/src/components/`、`frontend/src/pages/` | 硬编码色值替换为 CSS 变量引用 |
| 3 | `frontend/src/nodes/nodeCardPresentation.js` | 节点颜色改用 CSS 变量 |

**验收**：全局主色值只在一处定义，修改一处即可影响全局。

## W3 — 凭证安全（2.5 天）

### 设计原则

```
范围: 单体本地应用。不引入微服务、API 网关、外部证明服务。
目标: 用户向系统安全提交 api_key / password / passphrase 等敏感字段
      保护覆盖: 输入 → 传输 → 存储 → 内存 → 日志
约束: 不降低使用体验（不要求重复输入，不增加额外操作步骤）
      所有安全机制对用户透明
```

### 安全边界定义

```
┌─ 浏览器进程 ──────────────────────────────────┐
│  输入框 (type=password, 不缓存)                 │
│  ↓ XHR POST (HTTPS 加密)                       │
├─ Rust 后端 ───────────────────────────────────┤
│  ↓ 接收 → 立即消费（签名/下单）                  │
│  ↓ 使用后 Zeroize 内存中的明文字符串              │
│  ↓ 不写入 storage/ 目录                         │
│  ↓ 不写入日志 (eprintln!/tracing 替换为 ***)      │
│  ↓ 不写入 API 响应                              │
│  长期存储: 环境变量 或 加密的本地凭证文件          │
└──────────────────────────────────────────────┘
```

### W3-1 传输安全——前端输入保护

**现状**：前端 `TopToolbar` 中的 testnet 启动直接将 api_key 拼接在 HTTP 请求中发送。OKX 凭证目前要求用户写入环境变量，但用户可能通过前端界面提交。

**方案**：
- 所有敏感字段的 `<input>` 使用 `type="password"` 且设置 `autocomplete="off"`
- 敏感字段不在 `localStorage` / `sessionStorage` 中缓存
- POST 请求体中敏感字段单独标记，后端日志自动替换

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/components/TopToolbar.jsx` | testnet 凭证输入框设为 `type="password" autocomplete="off"` |
| 2 | `frontend/src/store/graphStoreRuntimeSessionActions.js` | 凭证不在前端 store 中持久化 |
| 3 | 新增凭证输入组件 `frontend/src/components/CredentialInput.jsx` | 统一的敏感字段输入框，内置安全属性 |

**验收**：浏览器密码管理器不会提示保存 api_key，刷新页面后凭证输入框为空。

---

### W3-2 存储安全——加密本地凭证文件

**现状**：OKX api_key / secret / passphrase 通过环境变量 `QUANTPILOT_EXCHANGE_KEY` 等传入（§P3-2）。`execute_testnet_run` 中 `load_exchange_credentials()` 从 `std::env::var` 读取后直接使用。环境变量设置对普通用户门槛高。

**方案**：新增本地凭证文件 `storage/.credentials`（AES-256-GCM 加密），密钥从系统机器标识派生。提供简单的 CLI 命令管理凭证：

```bash
quantpilot credential set okx --key=xxx --secret=xxx --passphrase=xxx
quantpilot credential list
quantpilot credential delete okx
```

凭证文件 `.credentials` 加入 `.gitignore`，不入版本控制。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | 新增 `src/credential_vault.rs` | `CredentialVault` 结构体: `set(id, key, value)` / `get(id)` / `delete(id)` / `list_ids()` |
| 2 | 同上 | `encrypt(plaintext) → Vec<u8>` 使用 `ring::aead` AES-256-GCM，密钥从主机名+SID 派生 |
| 3 | 同上 | `decrypt(ciphertext) → String` |
| 4 | `src/test_runner.rs:load_exchange_credentials()` | 优先读环境变量，未设置时从 `CredentialVault` 读取 |
| 5 | `.gitignore` | 新增 `storage/.credentials` |

**约束**：§7.1 要求 `storage/.credentials` 属于长期（Permanent）数据，不被启动清理删除。

**验收**：
```
quantpilot credential set okx --key=xxx --secret=yyy --passphrase=zzz
→ Credentials stored.
@run { mode: "testnet" } → 无需设置环境变量, 自动从 vault 读取
quantpilot credential delete okx → Credentials removed.
```

### W3-3 内存安全——使用后立即清零

**现状**：`load_exchange_credentials()` 返回 `(String, String)`，调用者用完即弃，但 Rust String 的释放时机不确定，内存中可能长期残留明文。

**方案**：引入 `zeroize` crate，凭证读取后立即包装为 `Zeroizing<String>`，使用完毕后强制清零。

```rust
use zeroize::Zeroizing;

fn load_exchange_credentials() -> Result<(Zeroizing<String>, Zeroizing<String>), String> {
    let key = Zeroizing::new(std::env::var("QUANTPILOT_EXCHANGE_KEY")?);
    let secret = Zeroizing::new(std::env::var("QUANTPILOT_EXCHANGE_SECRET")?);
    Ok((key, secret))
}
```

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `Cargo.toml` | 新增依赖 `zeroize = { version = "1", features = ["zeroize_derive"] }` |
| 2 | `src/test_runner.rs:load_exchange_credentials()` | 返回类型改为 `Zeroizing<String>` |
| 3 | `src/test_runner.rs:execute_testnet_run()` | 签名后用 `zeroize()` 主动清零 |
| 4 | `src/credential_vault.rs` | `get()` 返回 `Zeroizing<String>` |

**验证方法**：`cargo test --bin quantpilot` 全通过。

### W3-4 日志脱敏——防止凭证泄露到日志

**现状**：`eprintln!` 在多处打印状态信息，虽然当前未打印凭证值，但无系统化防护。一旦未来有人添加调试日志打印请求体，凭证就可能泄露。

**方案**：新增 `safe_log!` 宏，自动将 `api_key`、`secret`、`password`、`passphrase` 等敏感字段替换为 `***`。

```rust
macro_rules! safe_log {
    ($($arg:tt)*) => {
        eprintln!($($arg)*) // 在宏内部做字符串替换
    };
}
```

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | 新增 `src/safe_log.rs` | `sanitize_secrets(&str) -> String` 函数：正则替换敏感字段值 |
| 2 | `src/test_runner.rs` | 所有 `eprintln!` 替换为 `safe_log!` |
| 3 | `src/main.rs` | 全局注册 `safe_log`，启动日志不打印凭证 |

**验收**：任何位置的 `safe_log!("body: {}", request_body)` 都不会输出明文 secret。
