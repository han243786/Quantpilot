# v4.7.0 规划方案 — v4 AI 提案 + 性能优化

> 版本类型: MINOR | 基准: v4.6.0 | 终稿确认: 2026-05-25
> 来源: v4.x 能力自然延伸 + v3.7.1 AI proposal/sandbox verification 的 v4 路径

---

## 目标

v4.7.0 把 v3.7.1 已有的 AI 提案和沙箱验证能力接入 v4 状态机运行时，并对 v4 runtime 做性能优化。

1. **v4 AI 策略提案** — AI 可分析 v4 machine trajectory 并生成参数/结构优化提案
2. **v4 沙箱验证** — AI 提案在 v4 回测沙箱中独立回放验证
3. **v4 runtime 性能优化** — event batching、memory pooling、大回测 (>500 bar) 性能

核心变化:

- v4 策略也能触发 AI 提案和沙箱验证，不再只有 v3 路径
- v4 回测 >500 bar 场景可用 (性能从 ~30s 降至 ~5s)

## 非目标

- 不在 v4.7.0 实现 AI 自动修改 v4 QS 源码
- 不改变 v3 AI 提案路径
- 不开放 v5.0.0 架构变更

## W1 — v4 AI 提案 (2 天)

### W1-1 v4 machine trajectory 分析

**文件**: `src/runtime/mutation.rs`

**方案**: AI 提案系统消费 v4 回测工件的 `machine_trajectory`，分析：
- 状态驻留时间分布 (哪个 state 耗时最多)
- transition 频率 (哪些事件最频繁触发)
- Risk Plane 拒绝率 (风控是否过严/过松)
- Execution fill rate (成交率是否偏低)

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/runtime/mutation.rs` | `generate_ai_proposals` 增加 v4 trajectory 输入 |
| 2 | 同上 | proposal target 支持 v4 machine 参数 (state timeout、transition guard、memory threshold) |

**约束**: GP §9.1 (沙箱验证), GP §9.4 (审批工作流)
**验收**: 完成 v4 回测 → 系统生成 AI 提案 → 提案引用 machine trajectory 数据

### W1-2 v4 提案审批集成

**方案**: v4 AI 提案复用现有 L1/L2/L3 审批工作流。提案类型新增 `v4_machine_param_tune`、`v4_transition_guard_adjust`。

**验收**: v4 AI 提案 → 提交审批 → Approve → 提案状态联动 → Activated

## W2 — v4 沙箱验证 (1.5 天)

### W2-1 v4 提案沙箱回放

**文件**: `src/sandbox_verification.rs`

**方案**: sandbox verification 对 v4 提案执行独立 v4 回测。对比原策略与提案策略的 machine trajectory，验证提案不劣化。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/sandbox_verification.rs` | 增加 v4 提案沙箱回放入口 |
| 2 | 同上 | v4 trajectory 对比逻辑 (状态覆盖率/transition 时效性/Risk Plane 决策一致性) |

**约束**: GP §9.1 (CandidateUnderperforms 阻断)
**验收**: v4 AI 提案 → sandbox 回放 → CandidateUnderperforms → 提案拒绝合并

### W2-2 提案审批联动

**方案**: v4 提案审批状态与 AI 提案状态联动 (Accept→Activated, Expired→Expired)，锁顺序同 v3 规范。

**验收**: Approve v4 提案 → 提案自动 Activated → 策略参数热更新

## W3 — 性能优化 (1.5 天)

### W3-1 Event Batching

**文件**: `qrpc_runtime/src/v4_runtime.rs`

**方案**: `run_until_idle` 的逐事件循环改为批量处理。同一 `advance_time` 窗口内的同类型 Market 事件合并为一批，减少 transition 匹配开销。

**验收**: 500 bar 回测 → 耗时降低 >50%

### W3-2 Memory Pooling

**方案**: `V4RuntimeMemorySnapshot` 的序列化/克隆改为增量更新。只序列化变化部分，减少大回测 (>500 bar) 的 memory 开销。

**验收**: 500 bar 回测 → memory 峰值降低 >30%

## 兼容性与迁移

- v4.7.0 不改变 v3 AI 提案、v3 沙箱验证和现有审批流的 API 语义；v4 能力仅在 `source_kind = backtest` 且目标为 `v4.*` 时增加额外静态约束。
- v4.7.0 不改变 `V4BacktestArtifact` v1 schema 的必填字段；新增的 tick replay 与 microstructure 字段保持可选，旧工件仍可读取。
- v4.7.0 性能优化以确定性不变为前提；event batching/memory pooling 的深度指标如未达到外部验收阈值，必须在 closeout 遗留项中登记，不得伪造成已完成。
