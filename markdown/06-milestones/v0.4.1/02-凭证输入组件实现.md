# W4-2 凭证输入组件实现

> 基于 v0.4.1 审计修复补丁 W4-2 | 设计文档: api安全方案.md §本地凭证存储设计

---

## 目标

将交易所 API 凭证的存储模型从「逐字段存取」升级为「按标签整体存取」，并在前端集成 `CredentialInput` 组件提供统一的凭证管理入口。

## 设计原则

1. **原子性** — 同一交易所的全部字段（key + secret + passphrase + ...）作为整体加解密和增删
2. **字段无关性** — 存储层不关心字段名叫 `api_key` 还是 `API-KEY`，完全由用户定义
3. **标签引用** — 调用方按标签（如 `"okx_testnet"`）一键获取全部字段
4. **遵守 General_Policy** — 错误消息全中文 (§2.1)、前端 `t()` 包裹 (§2.5)、storage 声明生命周期 (§7.1)

## 改动清单

### 后端 (Rust)

| 文件 | 改动 |
|------|------|
| `src/credential_vault.rs` | API 重构: 删除 `set(key,val)` / `get(key)`，统一为 `set_service(label, fields)` / `get_service(label)` → `BTreeMap<String, String>` |
| `src/cli_support.rs` | CLI 适配新 API: `credential set <label> --key=X --secret=Y --passphrase=Z` 收集为 field_map 整体提交 |
| `src/test_runner.rs` | `load_exchange_credentials()` 改为从 `get_service("okx")` 获取完整字段 Map |
| `src/graph_api.rs` 等 | 搜索 `credential_vault` 旧 API 调用点，统一迁移 |

### 前端 (React)

| 文件 | 改动 |
|------|------|
| `frontend/src/components/CredentialInput.jsx` | 接收 `fields: [{name, label, required}]` 列表，动态渲染输入框，`type="password" autocomplete="off"` |
| `frontend/src/components/TopToolbar.jsx` | 新增「凭证」按钮 → 弹出框内嵌 `CredentialInput`，支持新增/编辑/删除标签 |

## 存储生命周期

| 文件 | 分类 | TTL | 依据 |
|------|------|-----|------|
| `storage/.credentials` | 长期 (Permanent) | 无上限 | 用户显式创建，仅主动删除 (§7.1) |
| `storage/.machine_key` | 长期 (Permanent) | 无上限 | 随 .credentials 共存亡，首次生成后永存 |

已在 `.gitignore` 中忽略 `storage/.credentials`（现有），需追加 `storage/.machine_key`。

## 验收条件

| # | 条件 | 验证方式 |
|---|------|---------|
| 1 | `set_service("okx", {key, secret, passphrase})` → 加密写入成功 | Rust 单元测试 |
| 2 | `get_service("okx")` → 解密返回完整字段 Map | Rust 单元测试 |
| 3 | `delete_service("okx")` → 文件更新，标签消失 | Rust 单元测试 |

| 6 | 凭证文件损坏时返回中文错误「凭证文件损坏或密钥不匹配」 | Rust 单元测试 |
| 7 | 前端 CredentialInput 三个输入框均为 `type=password autocomplete=off` | 浏览器审查 |
| 8 | 前端按钮文案用 `t()` 包裹 | 代码审查 |
