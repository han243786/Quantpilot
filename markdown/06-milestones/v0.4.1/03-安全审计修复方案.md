# v0.4.1 安全审计修复方案

> 基于 2026-05-08 网络安全工程师视角全量审查 | 12 项发现 | 估时 3 天

## 一、发现清单与修复方案

### S0-1 CLI 命令行参数泄露凭证

**问题**：`quantpilot credential set okx --key=abc123 --secret=xyz789` 将凭证以命令行参数传递，操作系统进程列表和 shell 历史可直接读取明文。

**修复方案**：

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `cli_support.rs` | `set` 子命令不再从 `--key=` 读取，改为交互式 stdin 输入 |
| 2 | 同上 | 新增 `--stdin` 标志，支持 `echo "$SECRET" \| quantpilot credential set okx --stdin` |
| 3 | 同上 | 保留 `--key=` 用于非敏感元数据（如 `--label=testnet`），敏感字段只能通过交互输入 |

**交互体验**：
```
$ quantpilot credential set okx
  请输入 api_key: [隐匿输入]
  请输入 secret: [隐匿输入]
  请输入 passphrase (可选): [隐匿输入]
  凭证已存储。标签: okx
```

**验收**：`ps aux` 不显示 secret 明文。shell history 不包含 `--secret=`。

### S0-2 密钥派生失败时静默降级为零密钥

**问题**：`derive_key()` 中 `get_or_create_machine_key().unwrap_or_default()` 失败时产生全零密钥，AES 加密退化为仅由 hostname 派生。

**修复方案**：

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `credential_vault.rs:derive_key()` | 删除 `unwrap_or_default()`，改为 `?` 传播错误 |
| 2 | 同上 `load()` | `derive_key` 失败时返回 `Err("无法派生加密密钥: 机器密钥不可用")` |

**验收**：删除 `storage/.machine_key` 并设为只读目录后，`CredentialVault::load()` 返回中文错误而非静默用零密钥解密。

---

### S0-3 前端凭证管理 API 路由不存在

**问题**：TopToolbar 的 CredentialPanel 调用 `/api/credentials` 但 `app_router.rs` 无此路由，UI 静默失败。

**修复方案**：

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `app_router.rs` | 新增三条路由：`GET /api/credentials`、`POST /api/credentials`、`DELETE /api/credentials/:service` |
| 2 | `main.rs` 或新建 `src/credential_api.rs` | 实现 handler：`list_credentials` / `set_credential` / `delete_credential` |
| 3 | `main.rs` `AppState` | 新增 `credential_vault: Arc<CredentialVault>` 字段，启动时初始化 |

**API 契约**：
```
GET  /api/credentials           → { "services": ["okx", "binance"] }
POST /api/credentials           ← { "service": "okx", "fields": {"key":"...","secret":"..."} }
DELETE /api/credentials/:service → { "deleted": "okx" }
```

**验收**：点击 TopToolbar「凭证」→ 显示已存储标签列表 → 新增/删除生效。

### S1-1 get_service() 返回明文 BTreeMap

**问题**：`get_service()` 返回 `BTreeMap<String, String>`，其中 `String` 值不实现 Zeroize，drop 后堆内存残留明文。

**修复方案**：

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `credential_vault.rs` | 新增 `SecretString(String)` wrapper，`Drop` 时调用 `zeroize::Zeroize::zeroize(&mut self.0)` |
| 2 | 同上 `VaultData` | `BTreeMap<String, String>` → `BTreeMap<String, SecretString>` |
| 3 | 同上 `get_service()` | 返回值改为 `CredentialFields`（其中 value 是 String，在返回前从 SecretString 转换），原始 SecretString 在锁内 drop |

注意：这个修复需要在"调用便利性"和"内存安全"之间取平衡。`get_service()` 返回给调用方的 value 仍然是 `String`（否则每个调用方都要处理 SecretString 类型），但 vault 内部持有的数据应该用 `SecretString`，确保锁释放后内部副本被清零。调用方拿到的是 `clone` 出来的 String，用完后的清理责任在调用方。

**验收**：代码审查确认 VaultData 内字段值在离开 Mutex lock 后被清零。

### S1-2 机器密钥生成 TOCTOU 竞态

**问题**：两个并发调用同时检查 `path.exists()` → 同时生成密钥 → 互相覆盖。

**修复方案**：

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `credential_vault.rs` | 使用 `std::sync::OnceLock` 保护 `get_or_create_machine_key()`，确保只执行一次 |
| 2 | 同上 | 生成密钥时先写 `.tmp` 再 `rename`，防止写入中断导致空文件 |

**验收**：并发调用 `CredentialVault::load()` 不会产生密钥文件竞争。

---

### S1-3 凭证文件非原子写入

**问题**：`save_inner()` 使用 `fs::write` 直接覆盖，崩溃导致文件截断。

**修复方案**：

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `credential_vault.rs:save_inner()` | 参照 `graph_api.rs:atomic_write()`：写 `.tmp` → `fs::rename` 替换 |
| 2 | 同上 | 写入前将旧文件 rename 为 `.bak`，写入成功后删除 `.bak`，失败则从 `.bak` 恢复 |

**验收**：写入中途强制杀进程后，`.credentials` 保持完整（或从 `.bak` 自动恢复）。

---

### S1-4 passphrase 在 HTTP 头明文传输

**问题**：OKX API 要求 `OK-ACCESS-PASSPHRASE` 头携带明文 passphrase，通过 HTTPS 传输但无证书 pinning。

**这是 API 协议约束，不可消除，只能文档化并采取缓解措施。**

**缓解方案**：

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `api安全方案.md` | 新增「OKX API 凭证传输风险说明」章节 |
| 2 | `test_runner.rs` | 在 `okx_request()` 上方添加文档注释，说明 passphrase 通过 HTTPS 传输，建议使用 IP 白名单 + 子账户 API key |
| 3 | `README.md` | beta 限制说明中加入「testnet 模式使用 OKX API，passphrase 经 HTTPS 明文传输」 |

**验收**：文档中有明确的传输风险说明。

### S2-1 全局环境变量副作用

**问题**：`std::env::set_var("HTTPS_PROXY", ...)` 修改全局进程状态。

**修复方案**：

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `test_runner.rs:execute_testnet_run()` | 删除 `std::env::set_var("HTTPS_PROXY", &proxy)`，Agent 已通过 `AgentBuilder::proxy()` 独立配置 |
| 2 | 同上 | 删除不再需要的 `proxy` 变量读取（`testnet_agent()` 内部已读取 `QUANTPILOT_PROXY`） |

**验收**：删除后 `cargo test` 通过，testnet 功能正常。

---

### S2-2 日志脱敏无法覆盖自定义字段名

**问题**：`safe_log.rs` 的 pattern 列表是硬编码的，用户自定义字段名（如 `"k"`, `"s"`）不会被脱敏。

**修复方案**：

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `safe_log.rs` | `sanitize_secrets()` 新增可选参数 `extra_patterns: &[String]` |
| 2 | `credential_vault.rs:load()` | 加载 vault 后提取所有字段值，注册到脱敏模块 |
| 3 | `main.rs` | 启动时调用 `safe_log::register_credential_patterns(&vault)` |

**验收**：存储在 vault 中的任意字段值在 `safe_eprintln!` 输出中被替换为 `***`。

---

### S2-3 凭证文件无 AAD 绑定

**问题**：`Aad::empty()` 不绑定密文上下文，旧版本密文替换检测不到。

**修复方案**：

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `credential_vault.rs:encrypt()` | `Aad::empty()` → `Aad::from(CREDENTIALS_FILE.as_bytes())` |
| 2 | `credential_vault.rs:decrypt()` | 同上同步修改 |

**验收**：将旧的 `.credentials` 文件重命名后移回 → 解密失败（AAD 不匹配）。

---

### S2-4 sanitize_secrets 只替换首次匹配

**问题**：每个 pattern 的 `find` 只匹配一次，同一行出现多次敏感值只脱敏第一次。

**修复方案**：

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `safe_log.rs:sanitize_secrets()` | `if let Some(pos) = ...` → `while let Some(pos) = ...`，循环替换直到无匹配 |

**验收**：日志中包含多个 secret 值全部被替换。

---

### S2-5 凭证面板关闭后 React state 不清除

**问题**：关闭 CredentialPanel 后，`useState` 中的凭证明文字符串保留在内存。

**修复方案**：

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `TopToolbar.jsx` (CredentialPanel) | 关闭面板时调用 `setValues({})`，将 state 重置为空对象 |
| 2 | `CredentialInput.jsx` | 新增 `onClose` prop，组件卸载时清空内部 state |

**验收**：关闭凭证面板后，React DevTools 中看不到残留的凭证值。
