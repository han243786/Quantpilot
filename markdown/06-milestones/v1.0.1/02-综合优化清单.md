## S0 — 阻断

### S0-1 validate_dag() 接入编译管道

**严重度**: 🔴 | **来源**: R3 集成链路+状态机

**问题**: `CoreStrategyIr::validate_dag()` 已实现但**从未在编译管道中被调用**。含分支/环的策略图通过 QS 编译时不会触发 DAG 环检测。

**方案**: 在 `compile_runtime_protocol_via_qs()` 中 lower 完成后、compile 前调用 `qs_protocol.validate_dag()`。

**验收**: 构造含环的 graph JSON, 编译返回 DAG 环检测失败错误。

## P1 — 高优

### P1-1 全库补 `#[serde(alias)]`

**严重度**: 🟠 | **来源**: R3 序列化

**问题**: 全库 0 处 `#[serde(alias)]`。未来任何字段重命名都会导致旧持久化数据反序列化失败。

**方案**: 对 `storage/` 中持久化的核心 struct (RunRecord, BacktestRecord, VaultData 等) 的现有字段补 `#[serde(alias)]`。

**验收**: 用旧字段名的 JSON 反序列化成功。

### P1-2 后台任务 JoinHandle 保存

**严重度**: 🟠 | **来源**: R3 资源清理

**问题**: `main.rs:709` `tokio::spawn` 的后台循环任务 JoinHandle 未保存，进程退出时无法 abort。

**方案**: 保存 JoinHandle 到 AppState, 在 shutdown 时 abort。

**验收**: 后台任务在进程退出时被取消。

### P1-3 SSE EventSource 卸载清理

**严重度**: 🟠 | **来源**: R3 资源清理

**问题**: 非 `stopRuntime()` 路径 (如用户导航离开) 时 EventSource 未 close。

**方案**: 在 `runtimeController` 的 close 回调中加组件卸载时的 useEffect cleanup。

**验收**: 策略运行中导航到其他页面, 浏览器 Network 标签无残留 SSE 连接。

### P1-4 PluginLifecycleState 转移警卫

**严重度**: 🟠 | **来源**: R3 状态机

**问题**: `activate()`/`deactivate()`/`mark_faulted()` 无条件设置状态，允许非法转移 (Registered→Stopped, Faulted→Stopped)。

**方案**: 在三个方法中加入当前状态检查:
- activate: 只允许 Registered/Stopped → Active
- deactivate: 只允许 Active → Stopped
- mark_faulted: 只允许 Active → Faulted

**验收**: 对已 Active 的插件调 activate 返回 Ok(()) (幂等); 对 Faulted 调 deactivate 返回 Err。

### P1-5 credential_vault 数据降级告警

**严重度**: 🟠 | **来源**: R3 序列化

**问题**: `credential_vault.rs` `serde_json::from_str(&decrypted).unwrap_or_default()` 静默退化空保险库。

**方案**: 改为 `match from_str { Ok(d) => d, Err(e) => { safe_eprintln!("凭证数据损坏"); return Err(...) } }`。

**验收**: 损坏的凭证文件返回错误, 不清空已有数据。

### P1-6 OrderStatus 状态机基础警卫

**严重度**: 🟠 | **来源**: R3 状态机

**问题**: `OrderStatus` 是纯数据字段，无状态转移校验。非法跳转不被阻止。

**方案**: 在 `SimOrder` 上添加 `transition(new_status)` 方法, 校验合法转移:
- Created → Submitted
- Submitted → Accepted/Rejected
- Accepted → PartiallyFilled/Cancelled/Expired
- PartiallyFilled → Filled/Cancelled/Expired

**验收**: 尝试 Created→Filled 返回 Err。

## P2 — 中优

### P2-1 嵌套写锁标注

**问题**: `main.rs` `process_expired_approvals` 嵌套获取 `approval_records.write()` + `ai_proposals.write()` — 脆弱模式。

**方案**: 添加注释标注获取顺序，防止未来反向获取导致死锁。

### P2-2 localStorage schema_version

**问题**: 前端 `quantpilot_frontend_graph` 和 `capabilities_cache` 无 schema_version。

**方案**: 在 JSON 体中加入 `_schema: 1`，加载时校验。

### P2-3 读锁长持优化

**问题**: `runtime_api.rs:2932` 遍历全部 runs 时长时间持有读锁。

**方案**: clone 需要的 keys 后在锁外执行遍历。

### P2-4 expect 前置条件文档化

**问题**: `runtime_api.rs:294` expect 有逻辑保障但无注释说明。

**方案**: 加注释 `// SAFETY: build_backtest_artifact_views 成功才会进入此分支`。

### P2-5 前端 "reconnecting" 状态

**问题**: `RuntimeState` 无 "reconnecting" 状态, SSE 断开后无 UI 反馈。

**方案**: 在 SSE onerror 触发重连时设 status 为 "reconnecting"。

### P2-6 t() 包裹硬编码中文 (优先前 10 文件)

**问题**: 30+ 文件硬编码中文未用 `t()`。全量改造工作量大。

**方案**: v1.0.1 优先处理 TopToolbar/StrategyWorkspacePage/LeftSidebar/App/CommandPalette 共 5 个核心文件。

### P2-7 Vec::with_capacity 预分配

**问题**: 10 处热路径 `Vec::new()` + `push()` 缺少预分配。

**方案**: 根据已知上界 (如 `agent_policies.len()`) 加 `with_capacity()`。

### P2-8 测试辅助函数去重

**问题**: `assert_complete_event_envelopes` 和 `field_names` 在两个测试文件中完全重复。

**方案**: 提取到 `tests/common/mod.rs`。

### P2-9 frontend_runtime_mapping 重复模式提取

**问题**: `template_node.find + unwrap_or` 模式重复 4 次。

**方案**: 提取 `fn resolve_node_name(template_nodes, node_id) -> String`。

### P2-10 并发 Atomic ordering 优化

**问题**: 部分 `AtomicBool` 使用 `SeqCst` 过度保守。

**方案**: 降级为 `AcqRel` (写) / `Acquire` (读)。

### P2-11 workspace sha2 统一

**问题**: 根 Cargo.toml 和子 crate 各自声明 `sha2 = "0.10"`。

**方案**: 移到 `[workspace.dependencies]`。

### P2-12 前端 localStorage normalizeGraphShape 升级机制

**问题**: 旧格式数据每次加载都 normalize 但不写回升级。

**方案**: 加载旧格式成功后写回新格式。

### P2-13 credential_vault get_service Zeroizing 包装

**问题**: `get_service()` 返回未包装 Zeroizing 的克隆 String。

**方案**: 返回 `BTreeMap<String, Zeroizing<String>>`。
