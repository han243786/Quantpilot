# v4.3.0 规划方案 — v4 回测 + 多交易对策略

> 版本类型: MINOR | 基准: v4.2.0 | 终稿确认: 2026-05-25
> 来源: v4.0.0 规划文档 非目标延期 + v4.2.0 非目标 + 回测能力自然扩展

---

## 目标

v4.3.0 把 v4 状态机运行时从"实时 Paper 运行"扩展到"历史回测"，并支持多交易对策略。

1. **v4 回测引擎** — 历史 K 线数据驱动状态机回放，产出完整的 v4 回测工件
2. **多交易对 v4 策略** — 单份 v4 QS 同时运行在 BTCUSDT/ETHUSDT/SOLUSDT 上
3. **v4 策略模板库** — 3-5 个常用 v4 策略模板，覆盖 Observation/Decision/Execution 组合

核心变化:

- 回测不再是 v3.7.1 独有功能，v4 策略也可以回测
- 回测工件包含 v4 特有的证据：machine 状态轨迹、Risk Plane 决策历史、Execution 能力来源记录
- 前端回测详情/对比页面兼容 v4 工件

## 非目标

- 不在 v4.3.0 开放嵌套状态机 (流向 v4.4.0)
- 不实现 tick 级回放 (仍为后续增强)
- 不改变 v3 回测语义
- 不新增交易所/交易对

## W1 — v4 回测引擎 (3 天)

### W1-1 确定性回放适配 v4 状态机

**文件**: `qrpc_runtime/src/v4_runtime.rs`, `qrpc_runtime/src/sandbox/replay.rs`

**方案**: v4 runtime 支持 `ReplayMode`，用历史 K 线数据替代实时行情事件。`advance_time()` 改为由回放数据驱动的时间推进。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `qrpc_runtime/src/v4_runtime.rs` | V4PaperSimulatedRuntime 增加 `new_for_backtest()` 构造器 |
| 2 | `qrpc_runtime/src/sandbox/replay.rs` | 历史 K 线 → v4 `bar_closed` 事件序列 |
| 3 | `qrpc_runtime/src/v4_runtime.rs` | 确定性回放: 相同输入 → 相同 machine 状态轨迹 |

**约束**: GP §1.2 (跨三层验证), GP §10.3 (回测 12 项指标)
**验收**: 同一 v4 策略 + 同一历史数据 → 两次回测产生相同 machine 状态轨迹和成交

### W1-2 v4 回测工件

**文件**: `src/backtest_artifacts.rs`, `qrpc_core_ir/src/v4.rs`

**方案**: v4 回测工件扩展 `BacktestArtifact`：
- `machine_trajectory`: 每个 bar 时刻的全部 machine 状态快照
- `risk_plane_decisions`: Risk Plane 批准/拒绝历史
- `execution_capability_sources`: Execution 能力来源记录
- 保留现有 12 项回测指标

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `qrpc_core_ir/src/v4.rs` | 定义 `V4BacktestArtifact` 类型 |
| 2 | `src/backtest_artifacts.rs` | 工件持久化兼容 v4 扩展字段 |

**验收**: v4 回测完成 → 工件文件包含 machine_trajectory + risk_plane_decisions

### W1-3 v4 回测前端展示

**文件**: `frontend/src/pages/BacktestDetailPage.jsx`

**方案**: 回测详情页增加 v4 专属视图：
- 状态机轨迹时间线（每台 machine 的状态变化）
- Risk Plane 决策瀑布图
- Execution 能力来源标签

复用 `V4RuntimeEvidencePanel` 组件渲染回测证据。

**验收**: 打开 v4 回测详情 → 看到 machine 状态轨迹 + Risk Plane 决策历史

## W2 — 多交易对 v4 策略 (1.5 天)

### W2-1 universe 展开为独立 machine 实例

**文件**: `quantscript/src/lowering/universe.rs`, `qrpc_runtime/src/v4_runtime.rs`

**方案**: v4 QS 声明 `symbols: [BTCUSDT, ETHUSDT, SOLUSDT]` 时，每个交易对展开为独立的 ObservationMachine/ExecutionMachine 实例。DecisionMachine 共享（跨交易对决策）。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `quantscript/src/lowering/universe.rs` | v4 machine graph 支持 universe 展开 |
| 2 | `qrpc_runtime/src/v4_runtime.rs` | 多实例 machine 管理: `machine_id` → `{symbol}_{machine_id}` |

**约束**: GP §1.6 (顶层 DAG 保留，复杂度下沉到状态机)
**验收**: 部署含 `symbols: [BTCUSDT, ETHUSDT]` 的 v4 策略 → 创建 2 套 ObservationMachine + ExecutionMachine 实例

### W2-2 跨交易对 Risk Plane 聚合

**方案**: 多交易对场景下，Risk Plane 汇总全部交易对的风险敞口做全局判断。

**验收**: 一个交易对超风险限制 → Risk Plane 拒绝该交易对的 Execution 事件

## 兼容性与迁移

| 兼容对象 | 迁移策略 | 保护方式 |
|---------|---------|---------|
| v3 回测 | v3 请求默认仍走既有 backtest 路径；只有 `runtime_kind=v4`、v4 MachineGraph metadata 或 v4 formal source 才进入 v4 回测 | `cargo test backtest` 与前端回测详情测试继续覆盖 v3 artifact 展示 |
| 既有回测工件 | `v4_backtest_artifact.json` 是可选扩展；旧工件没有该文件时仍从原 `backtest` 记录加载 | `src/backtest_artifacts.rs` 维持 optional 读取和 manifest digest 校验 |
| v4 实时运行 | `new_for_backtest()` 与 deterministic bar replay 不改变 PaperSimulated 实时入口、执行端 RunnerPool 或 `/api/runtime/v4/run` | `cargo test -p qrpc-runtime v4_` 同时覆盖实时与回放相关 v4 行为 |
| 策略模板 | v3 模板 ID、图结构和加载逻辑不迁移；v4 模板通过 `template_runtime_version` 与 `metadata.artifacts.v4_machine_graph` 明确分流 | `graphStore.templates` 与模板库页面测试验证 v3/v4 模板并存 |
| OpenAPI 客户端 | `runtime_kind` 和 `symbols` 是 backtest options 的新增可选字段；未传时保持既有默认行为 | `tools/check-version-consistency.ps1` 和 OpenAPI 文档同步纳入 closeout |
