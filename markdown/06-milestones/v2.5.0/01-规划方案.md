# v2.5.0 规划方案

> 版本类型: MINOR | 基准: v2.4.0 | 目标: 消化剩余 P2 + 全部 P3

---

## 目标

- 消化审计发现剩余 ~58 条 P2 项
- 消化全部 ~50 条 P3 项
- 性能覆盖: 启动优化, 编译缓存, 数据库升级
- 文档完成全量中文化
- GP 合规持续保持 28/28

## 非目标

- 不新增功能模块
- 不改变协议定义
- 不做架构级重构

## 核心优化方向

### 一、性能深化 (15项 P2)

| # | 优化项 | 预期效果 |
|---|--------|---------|
| 1 | 启动流程并行化 (目录创建/状态预热) | 启动时间 -50% |
| 2 | SQLite → 连接池替代单 Mutex | 认证QPS +3x |
| 3 | 编译产物缓存 (同图同参数跳过编译) | 重复编译 <100ms |
| 4 | data_module 缓存 LRU 淘汰 | 内存占用可控 |
| 5 | K线数据懒加载 (按需拉取) | 启动内存 -30% |
| 6 | 历史缓存文件索引 (避免遍历目录) | 列表操作 O(1) |
| 7 | SSE 事件压缩 (gzip) | 带宽 -70% |
| 8 | Service Worker 离线缓存 | 二次加载 <1s |
| 9 | CSS 代码拆分 (styles.css 31000 tokens) | 首屏 CSS -60% |
| 10 | 图片/图标懒加载 | 首屏渲染 -200ms |

### 二、安全加固 (10项 P2)

| # | 加固项 |
|---|--------|
| 1 | 请求体限制按端点差异化 (compile=1MB, upload=10MB) |
| 2 | 前端 CSP nonce 支持 (移除 unsafe-inline) |
| 3 | Permissions-Policy 头添加 |
| 4 | 前端路由路径规范化 (防路径混淆) |
| 5 | API 响应统一包裹 (避免信息泄露) |
| 6 | 凭证 vault 脱敏模式优化 (长度阈值 8→4) |
| 7 | sanitize_secrets 大小写一致性修复 |
| 8 | trace_id 改用 UUID v4 |
| 9 | 存储错误消息去路径化 |
| 10 | 分页参数校验统一 |

### 三、健壮性提升 (10项 P2)

| # | 提升项 |
|---|--------|
| 1 | 后台任务 panic 恢复状态标记 (复位 run_in_progress) |
| 2 | config_generation_history 双 Mutex 实例统一 |
| 3 | RateLimiter 桶清理改后台任务 |
| 4 | 文件操作 TOCTOU 窗口文档化 |
| 5 | snapshot_service 签名输入抽取共享函数 |
| 6 | PortfolioState debug_assertions 不变性检查 |
| 7 | 确定性问题: 所有回测场景显式设置 seed |
| 8 | 热插拔测试改用 FastBacktestSandbox |
| 9 | #[ignore] 测试补充文档注释 |
| 10 | 前端 schema 版本比较 `!==` → `>=` |

### 四、P3 低优先级 (50条, 分批消化)

**代码质量类 (15条)**:
- 魔法数值提取为常量 (多处)
- 无用的 `let _ = window` 删除
- BTreeMap → HashMap 替换 (热点路径)
- merge truncate 排序优先
- MACD 双 EMA 合并
- QS AST 遍历统一
- 目录创建并行化
- 序列化/反序列化减少 (编译链)
- rusqlite bundled 评估替代方案

**前端类 (20条)**:
- 搜索输入清洗
- 事件数组环形缓冲区
- 对比页骨架屏
- 中间宽度布局测试
- prefers-reduced-motion 验证
- CSS 变量空值检查自动化
- @keyframes 跨文件去重
- 模块锁定标记 tooltip
- 编译诊断严重度 aria-label
- HTTP 状态码前端隐藏

**文档类 (15条)**:
- 英文指南豁免记录
- check-i18n.ps1 加入门禁矩阵
- 术语表创建
- 文档中英文段落全面审查
- 模板文件更新
- 过时架构文档归档

## 验收总闸

| # | 验收项 | 标准 |
|---|--------|------|
| 1 | GP 合规矩阵 | 28/28 |
| 2 | 全部门禁 | 10/10 通过 |
| 3 | 启动时间 | < 3s (冷启动) |
| 4 | 测试覆盖 | src/ 全部模块有测试 |
| 5 | 前端首屏 | Lighthouse ≥ 90 |
| 6 | 内存基线 | 空闲 < 200MB |
| 7 | P2 消化率 | ≥ 80% |
| 8 | P3 消化率 | ≥ 60% |

## 风险

| 风险 | 缓解 |
|------|------|
| P3数量大 (50条), 时间不足 | 按影响/修复成本排序, 低成本项优先消化 |
| 性能优化引入回归 | 每项优化前后跑 benchmark 对比 |
| SQLite 连接池迁移 | 灰度: 先加 feature flag, 验证后再默认启用 |
