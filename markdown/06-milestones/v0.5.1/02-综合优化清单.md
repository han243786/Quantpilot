## P0 — 架构排雷（2.5 天）

### P0-1 编译路径统一：删除 `map_frontend_runtime_config` 直接编译路径

**严重度**: 🔴 阻断 | **来源**: 审计 §1.1, §1.3, §5.4 | **策略**: 架构铁律 #1, #3 + 禁止事项 #4

**问题**:

当前存在两条编译路径，QS 管道仅作为"补充验证"运行，实际编译走旧路径。这直接违反 §1.1 和 §1.3，正是策略要防止的 bug 根源。

| 位置 | 问题 |
|------|------|
| `src/compile_api.rs:44-78` | `generate_quantscript_from_graph_value` 结果仅用作诊断警告 `QPCONVOK`，编译本身走 `map_frontend_runtime_config` |
| `src/compile_api.rs:70-73` | `graph_json=None` 时完全跳过 QS，注释标注"将在 v0.4.0 移除"但仍未移除 |
| `src/runtime_api.rs:220` | `/api/runtime/run` 直接调用 `map_frontend_runtime_config` |
| `src/runtime_api.rs:316` | `/api/runtime/replay` 直接调用 `map_frontend_runtime_config` |
| `src/runtime_api.rs:504` | `/api/runtime/experiment/variants` 直接调用 `map_frontend_runtime_config` |
| `src/runtime_api.rs:572` | `/api/runtime/experiment/execute` 直接调用 `map_frontend_runtime_config` |

**方案**:

将 QS 管道作为唯一编译入口，`map_frontend_runtime_config` 降级为 QS 管道内部步骤或直接删除。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/compile_api.rs` | 删除第 51-63 行诊断警告逻辑，将第 46-49 行 QS 管道输出 (`lower_script_to_runtime_config`) 作为实际编译输入 |
| 2 | `src/compile_api.rs` | 删除第 70-73 行 `graph_json=None` 回退分支，改为返回 400 错误: `"编译请求必须包含 graph_json"` |
| 3 | `src/runtime_api.rs` | 4 个路由中 `map_frontend_runtime_config(&request.runtime_config)` → 调用 `compile_runtime_request` (走 QS 管道) |
| 4 | `src/frontend_runtime_mapping.rs` | `map_frontend_runtime_config` 标记 `#[deprecated]` 或改为 QS 管道内部辅助函数 |
| 5 | `src/graph_quantscript_api.rs` | 确保 `generate_quantscript_from_graph_value` 输出可作为编译入口 (验证已存在) |
| 6 | 全部 | 搜索 `map_frontend_runtime_config` 调用点，逐一迁移或删除 |
| 7 | `tests/` | 更新所有集成测试，确保编译请求携带 `graph_json` |

**验收**:
- `grep -rn "map_frontend_runtime_config" src/ --include="*.rs"` 返回 0（除 `#[deprecated]` 声明本身）
- `grep -rn "未收到 graph_json" src/ --include="*.rs"` 返回 0
- `cargo test --workspace` 全量通过
- 同一策略图经 graph 编辑器编译 vs 直接 API 调用，编译结果完全一致

### P0-3 存储配额强制执行

**严重度**: 🔴 阻断 | **来源**: 审计 §7.2 | **策略**: 存储生命周期 #2

**问题**:

`GLOBAL_MAX_BYTES` 被 `#[allow(dead_code)]` 标记，450MB/475MB 阈值不存在，每目录配额不存在。存储可以无限增长。

| 策略要求 | 当前状态 |
|---------|---------|
| 全局 500MB 上限 | 常量定义但未被调用 (`#[allow(dead_code)]`) |
| 80% (400MB) 告警 | `WARN_AT_BYTES` 已设置，`startup_storage_cleanup` 中检查 |
| 90% (450MB) 强制清理 | **未实现** |
| 95% (475MB) 拒绝非长期写入 | **未实现** |
| 暂时目录 ≤200MB | **未实现** |
| 瞬间目录 ≤50MB | **未实现** |

**方案**:

在 `storage_lifecycle.rs` 中实现完整的配额执行链，在所有写入路径之前调用。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/storage_lifecycle.rs` | 删除 `#[allow(dead_code)]`，实现 `check_storage_quota()` 函数：计算 storage/ 总大小 → 80% 告警 / 90% 强制清理过期 / 95% 返回 Err |
| 2 | `src/storage_lifecycle.rs` | 实现 `check_directory_quota(dir, lifecycle)` 函数：暂时 ≤200MB / 瞬间 ≤50MB |
| 3 | `src/storage_lifecycle.rs` | `startup_storage_cleanup()` 中集成 90% 强制清理过期暂时/瞬间数据的逻辑 |
| 4 | `src/runtime_persistence.rs` | 6 个 persist 函数在写入前调用 `check_storage_quota()` |
| 5 | `src/snapshot_service.rs` | `persist_snapshot` 写入前调用配额检查 |
| 6 | `src/alert_engine.rs` | `persist_alert_firing` 写入前调用配额检查 |
| 7 | `src/chaos_experiment.rs` | `persist_chaos_report` 写入前调用配额检查 |
| 8 | `src/sandbox_verification.rs` | `persist_json` 写入前调用配额检查 |
| 9 | `src/graph_api.rs` | `persist_graph_version` 写入前调用配额检查 |
| 10 | `src/storage_lifecycle.rs` | 添加单元测试：配额满时拒绝写入 / 清理后恢复写入 |

**验收**:
- `storage/` 总大小超过 475MB 时，非长期写入返回中文错误
- `storage/backtests` 超过 200MB 时写入被拒
- `storage/snapshots` 超过 50MB 时写入被拒
- `cargo test --workspace` 全量通过
