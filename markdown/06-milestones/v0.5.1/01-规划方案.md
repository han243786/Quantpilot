# v0.5.1 全量审计收口排雷

> 基于 2026-05-10 全量审计报告 | 无新功能 / 无新架构 / 只收口 | 15 项 | 估 5.5 天
> 审计基准: `General_Policy.md` §1-§7（排除 §8 前端设计规范，已由 v0.5.0 覆盖）

---

## 背景

v0.5.0 完成了 Adobe 风格前端全量重构和 38 项 General_Policy 合规审计。2026-05-10 进行的独立全量审计发现 **10 通过 / 7 部分 / 8 违规**，其中最严重的三个问题：

1. **编译双路径**: QS 管道仅在 `compile_api.rs` 中作为补充验证运行，实际编译仍走 `map_frontend_runtime_config` 旧路径。`runtime_api.rs` 中 4 个路由完全绕过 QS。这违反了 §1.1 和 §1.3，正是策略要防止的 bug 根源（"双路径曾导致同一策略产出不同的 intent 类型"）
2. **53 处英文错误消息**: 分布在 11 个文件中，违反 §2.1 全中文错误消息规定
3. **存储配额系统残缺**: `GLOBAL_MAX_BYTES` 是死代码，`persist_with_ttl` 不存在，11 个写入路径零生命周期声明，违反 §7.2/7.4

## 原则

```
排雷: 修复会导致系统出错、策略不一致或违反架构铁律的缺陷
收口: 将已定义在 General_Policy 中但未落实的规范拉通到可验证状态
优化: 消除用户可感知的质量不一致

不纳入: 新功能 / 新指标 / 新架构思想 / 新依赖 / 重设计 / 前端 UI 变更
```

## 与 v0.5.0 的关系

v0.5.0 解决了前端设计系统和 18 项 S0/P1/P2 优化。v0.5.1 是它的延续——针对独立审计发现的后端架构和代码规范问题进行收口，不引入新功能。
