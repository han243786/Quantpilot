> 承接 v1.0.7 质量收口 | 全新功能 | **状态: ✅ 已完成 (16/16, 100%)**
>
> **执行基调**: [General_Policy](../../General_Policy.md) + [超级规范化](../../01-principles/principles-super-standardization.md)
>
> 本里程碑所有设计、开发、检查、审计活动均以 GP 八章条款和超级规范化五条流水线为唯一执行标准。

## 背景

v1.0.7 完成了 9 项体验收口，五维度审计加权 9.6/10，GP 矩阵 28/28 ✅。当前版本的回测系统已具备基础能力：K 线回放、四种订单类型、权益曲线、五文件输出包。

但产品边界文档明确将"研究级回测语义"列为非宣称能力。当前缺失的核心能力包括：

1. **风险调整收益指标**：仅有总收益率和最大回撤，无夏普/索提诺/卡尔玛等业界标准指标
2. **市场微观结构模型**：滑点仅固定 bps，无买卖价差成本、无市场冲击、无排队概率
3. **多标的复杂策略**：统一时间轴缺失、信号路由仅单标的、跨标的约束不存在
4. **基准对比**：无买入持有基准、无 Alpha/Beta

此外，`WeightedSignals` agent（最常用的 agent 类型）将所有标的信号混为一个 net score，使得同时交易 BTC 和 ETH 的策略无法正确执行。

---

## 原则

1. **QS 路径唯一**（GP §1.1）：所有新能力必须通过 QS 管道，不新建独立编译路径
2. **跨三层验证**（GP §1.2）：每个功能在 QS 解析 / Core IR / 运行时三层均有对应实现
3. **零 stub**（GP §5.3）：新增指标/模型的 evaluator 必须有完整计算实现
4. **全中文错误**（GP §2.1）：新增 API 错误消息使用中文
5. **门禁全量通过**：不降低现有门禁标准

## 目标

### 目标 A：研究级回测指标（BacktestSummary 增强）

将 `BacktestSummary` 从 10 个字段（其中 3 个始终为 0）扩展为包含业界标准风险调整收益指标的完整摘要。

**做到什么算完成**：
- 后端 `BacktestSummary` 新增 12 个指标字段并全部填充真实计算值
- 前端 `BacktestDetailPage` 和 `BacktestComparePage` 展示新增指标
- `.qs` 测试场景中 `@backtest` step 可对新增指标做 `@assert` 验证

### 目标 B：成交模型增强（FillEngine 升级）

将 FillEngine 从固定滑点 + 无限流动性模型升级为包含买卖价差、波动率缩放滑点、市场冲击的三层成交模型。

**做到什么算完成**：
- 滑点模型支持三种模式：固定 bps / 波动率缩放 / 订单簿深度
- 成交价格基于 bid/ask（而非 mid price）
- 新增 `SlippageModel` 和 `MarketImpactModel` 可配置
- 回测对比页面可 diff 不同成交假设

### 目标 C：多标的策略支持（时间轴 + 信号路由）

实现统一时间轴回放引擎和按标的分组的信号路由，使多标的、多频率复杂策略的回测结果正确。

**做到什么算完成**：
- `UnifiedTimelineReplay` 替代当前的 `ReplayDataModule`（按 index 步进）
- `WeightedSignals` agent 按 symbol 分组输出独立决策
- 回测对比结果与单标的场景一致（无回归）

### 目标 D：基准对比

为每个回测自动生成买入持有基准，计算 Alpha/Beta/Information Ratio。

**做到什么算完成**：
- 回测输出包含 `benchmark_equity_curve`
- 前端叠加权益曲线图可切换显示基准线
- 对比指标表展示超额收益

---

## 非目标

以下能力明确不在 v1.1.0 范围内：

- **实盘交易** — 刻意的产品边界（GP §架构铁律明确纸面/测试网）
- **限价单排队概率模型** — 需要完整订单簿快照数据，当前仅 OKX v5 REST API 不提供深度数据
- **蒙特卡洛随机化** — 计算密集，v1.2.0 再考虑
- **市场状态分区分析** — 依赖更长时间序列数据，延期
- **VaR/CVaR/偏度/峰度** — 加分项，P2 延后
- **多标的原子化执行批次** — 仅在同时多标的调仓时触发，v1.2.0
- **插件市场 / SaaS** — 与项目定位冲突

#### A2 — 指标计算器

新文件：`qrpc_runtime/src/backtest_metrics.rs`

```
BacktestMetrics::compute(sessions, equity_curve, trade_ledger, benchmark_prices)
  → BacktestSummary（所有字段填充）
```

计算逻辑：
- **年化收益率**：`(1 + total_return)^(365 / days) - 1`
- **年化波动率**：日收益率标准差 × √365（或 √252 交易天数）
- **夏普**：年化收益率 / 年化波动率
- **索提诺**：年化收益率 / 下行波动率（仅负收益率参与标准差计算）
- **卡尔玛**：年化收益率 / max_drawdown_ratio
- **盈亏比**：从 TradeLedger 按 `realized_pnl` 分组求和
- **连续盈亏**：遍历成交序列
- **回撤持续**：从 equity_curve 计算峰值-恢复区间
- **Alpha/Beta**：策略日收益率 vs 基准日收益率的线性回归

```rust
pub enum SlippageModel {
    FixedBps { bps: f64 },              // 现有行为
    VolatilityScaled { base_bps: f64, vol_coefficient: f64 },  // 滑点 ∝ 波动率

    pub latency_distribution: LatencyModel,
}

    Fixed { delay_ms: u64 },
    Normal { mean_ms: u64, std_ms: u64 },
    PerExchange { binance_ms: u64, okx_ms: u64 },
```

#### B2 — FillEngine 集成

文件：`qrpc_runtime/src/fill_engine.rs`

改动 `build_fill_report()` 函数：

```rust
// 现有:
let fill_price = match order.order_type {
    OrderType::Market => market_price * (1.0 + direction * slippage_bps / 10_000.0),
    OrderType::Limit => base_price,
};

// 改为:
```

#### C2 — 多标的信号路由

文件：`qrpc_runtime/src/agent_module.rs`

`build_weighted_agent_decision()` 改为按 symbol 分组：

```rust
// 现有: signals → single net score → single AgentDecision (pick first symbol)
// 改为: signals → group_by(symbol) → per-symbol scores → Vec<AgentDecision>

fn build_weighted_agent_decisions(
    agent: &AgentPolicy,
    signals: &[IntentSignal],
    ...
) -> Vec<AgentDecision> {
    let mut decisions = Vec::new();
    let grouped = group_signals_by_symbol(signals);

    for (symbol, symbol_signals) in grouped {
        let weighted_score = compute_weighted_score(&symbol_signals);
        if weighted_score.abs() < agent.decision_threshold.unwrap_or(0.05) {
            continue;
        }
        decisions.push(build_single_decision(agent, symbol, &symbol_signals, weighted_score));
    }
    decisions
}
```

### S0 实现顺序（依赖关系）

S0-4 和 S0-1 无代码依赖，可并行启动。其余按依赖链顺序：

```
第一步（并行）:
  S0-4 买卖价差        ← 仅改 fill_engine.rs，独立
  S0-1 统一时间轴       ← 仅改 sandbox/ + 新增 replay_timeline.rs，独立

第二步:
  S0-5 基准生成         ← 依赖 S0-1: 基准价格序列对齐统一时间轴

第三步（并行）:
  S0-2 多标的信号路由    ← 依赖 S0-1: 时间轴变化后数据到达方式改变
  S0-3 指标计算器        ← 依赖 S0-1: 需从 session/equity_curve 计算
                        ← 依赖 S0-2: 多标的 trade_ledger 产生正确的逐笔 PnL
```

## 决策纪录

### 决策 1: 夏普比率无风险利率假设

**选项**:
- A: 使用 0% 无风险利率（简化）
- B: 支持配置无风险利率参数

**选择**: A

**理由**: QuantPilot 定位为加密货币策略沙箱，传统无风险利率（国债收益率）不适用。稳定币借贷利率波动大且不可靠。0% 简化是业界加密货币回测的惯例（TradingView / Backtrader 默认行为）。

**影响**: `BacktestSummary::sharpe_ratio` 计算使用 `R_f = 0`。

### 决策 2: 统一时间轴的慢/快周期触发策略

**选项**:
- A: 严格按 K 线收盘时间触发慢周期（现有的 `close_time_ms`）
- B: 统一时间轴的每个时间点都同时触发慢周期和快周期

**选择**: A

**理由**: 慢周期使用 K 线收盘价，在任何时间点都用最新收盘价会导致前视偏差（look-ahead bias）。GP §5.3 禁止 stub evaluator，同样禁止前视偏差。快周期（报价）可以在每个时间点触发。

**影响**: `UnifiedTimeline` 维护两类触发器，慢周期仅在 `close_time_ms` 匹配时触发。

### 决策 3: 买卖价差数据源

**选项**:
- A: 回测中从 K 线波动率估算 bid/ask spread（保守，不会高估）
- B: 要求用户提供历史报价数据才启用价差模型
- ~~C: K 线 OHLC 极值作为 bid/ask（low = bid, high = ask）~~ — 弃用

**选择**: A（默认）+ B（可选）

**理由**: 
- 弃用 C 的原因：low 和 high 是时间段内的极端成交价，不是买卖报价。在剧烈波动期（恐慌买入推高 high、恐慌卖出砸低 low），价差会被系统性高估数倍。
- A 方案使用波动率缩放的基础价差估计：`half_spread = mid * base_bps * vol_adjustment / 20000`，其中 base_bps 按时间框架分档（分钟线 0.5bp / 小时线 1bp / 日线 2bp），vol_adjustment 限制在 0.5x-3x 范围内，防止极端值。
- 当真实报价数据可用时（`DataBindingKind::Quote`），自动切换到真实 bid/ask。

**影响**: 
- 新增 `SpreadEstimateSource` 枚举（`VolatilityBased` / `RealQuote`），写入 `DataQualitySnapshot`，回测报告透明标注价差估算方法
- `SlippageModel` 的 `use_bid_ask` 在报价数据不可用时默认 false
- 价差估算函数 `estimate_spread(mid_price, volatility, timeframe_minutes) → SpreadEstimate` 独立可测试

### 决策 4: `turnover_ratio` 等三个始终为 0 字段的处理

**选项**:
- A: 直接删除 + serde 自动忽略旧 JSON 中多余字段
- B: 保留为 `#[serde(default)]`，标记 `#[deprecated]`
- ~~C: 保留并开始填充真实值~~ — 不选

**选择**: A

**理由**:
- 这三个字段在 v1.0.7 中始终为 0.0，前端代码搜索证实无任何读取引用
- B 方案在同一 crate 内构造 `BacktestSummary` 时会触发 deprecation warning，而 clippy 配置 `-D warnings` 会因此拒绝编译——门禁直接红
- A 方案中 serde 的默认行为是忽略未知字段（`#[serde(default)]` 在结构体级别），旧回测 JSON 中多余字段不会导致 panic
- 不违反 GP §4.2，因为这不是错误消息变更，且无测试断言引用这三个字段

**影响**: 三个字段直接删除。旧回测数据加载无影响。`contracts/openapi/root.yaml` 中 `BacktestSummary` schema 同步移除这三个字段（OpenAPI 合约变动属于能力边界变更，走 §4.1 流程）。
