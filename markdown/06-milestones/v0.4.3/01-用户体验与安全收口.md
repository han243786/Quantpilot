## 发现清单

### U1 — Content-Type 缺失时的 JSON 错误返回英文

**严重度**：🟡 中 | **类型**：易用性

**现象**：不带 `Content-Type: application/json` 头 POST 到 API 时，Axum 返回英文纯文本：
```
Expected request with `Content-Type: application/json`
```

`json_rejection_middleware` 只拦截了 422（JSON 解析失败），未覆盖 Content-Type 头缺失导致的 400/415。

**改法**：扩展 `json_rejection_middleware` 覆盖范围，或添加 Content-Type 校验中间件。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `main.rs` | `json_rejection_middleware` 增加 400/415 状态码拦截 |

**验收**：`curl -X POST /api/runtime/compile -d '{}'` → 中文 JSON 错误。

---

### U2 — 编译 API 请求体格式对用户不透明

**严重度**：🟡 中 | **类型**：易用性

**现象**：`POST /api/runtime/compile` 要求嵌套的 `runtime_config` 结构，但无 API 文档说明。用户手动构造 JSON 请求时极易因字段名/嵌套层级不匹配而收到 `请求格式错误`。

**改法**：在 `api安全方案.md` 或新建 `api参考.md` 中提供核心 API 的请求/响应示例。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `markdown/04-guides/` | 新增 `guide-api-reference.md`，列核心端点的 curl 示例 |

**验收**：文档中有至少 5 个端点的 curl 示例（health / capabilities / graphs/save / compile / backtest）。

---

### U3 — 凭证 CLI get 无二次确认直接打印明文

**严重度**：🟡 中 | **类型**：安全性/易用性边界

**现象**：`quantpilot credential get okx` 直接将 `key`、`secret`、`passphrase` 明文输出到终端。用户虽然主动请求，但缺少二次确认。屏幕共享或终端录制时可能导致凭证泄露。

**改法**：`get` 命令增加确认提示，默认只显示标签名和字段名（不显示值），`--reveal` 标志才输出值。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `cli_support.rs` | `get` 默认只列字段名，`--reveal` 才显示值 |

**验收**：`credential get okx` → `标签 'okx' 包含字段: key, secret, passphrase (使用 --reveal 查看值)`。

---

### S1 — auth_middleware 全放行

**严重度**：🟠 高 | **类型**：安全性

**现象**：`QUANTPILOT_API_KEY` 未设置时，所有 API 请求无条件放行。同一台机器上任意进程可向 `localhost:3000` 发送请求并触发 testnet 运行。

**改法**：默认生成随机 API key 并打印到启动日志，所有 API 请求（除 `/api/health`）要求 `X-API-Key` 头匹配。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `auth_middleware.rs` | 未设置环境变量时自动生成随机 key，打印到 safe_eprintln |
| 2 | 同上 | `/api/health` 加入白名单，其余路由要求认证 |
| 3 | `main.rs` | 启动时打印 `API Key: <random>` |

**验收**：不带 `X-API-Key` 头调用 `/api/graphs` → 401 Unauthorized（中文错误）。

---

### S2 — 凭证 API 懒初始化

**严重度**：🟢 低 | **类型**：易用性

**现象**：首次启动时 `storage/.machine_key` 不存在，vault 初始化失败（因为 `CredentialVault::load()` 在 `app_runtime_helpers.rs` 中被调用但 vault 加载需要一个空的 `.credentials` 文件才能成功）。用户需先通过 CLI `credential set` 创建 vault 文件，API 才能使用。

**改法**：`CredentialVault::load()` 中，文件不存在时创建空 vault 并初始化。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `credential_vault.rs:load()` | `.credentials` 不存在时创建空 VaultData 并 save |

**验收**：全新安装启动后 `GET /api/credentials` → `{"services":[]}` 而非 503。
