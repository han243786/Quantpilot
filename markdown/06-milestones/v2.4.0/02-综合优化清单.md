## P1 高优先级 (53条)

### 一、代码安全 (12条)

#### P1-C1 risk_checker 空头策略绝对值求和
**严重度**: 高
**来源**: 维度C 边界扫描
**策略**: GP §5.1 (禁止硬编码逻辑错误)
**问题**: `clamp_portfolio_target_portfolio_net_exposure` 对 `target_weight.abs()` 求和, 空头仓位被高估导致过度限制
**方案**: 分别计算多头敞口和空头敞口, 按净方向 clamp
**验收**: `cargo test risk_checker` 新增空头策略测试通过

#### P1-C2 backtest_metrics curr 有限性检查缺失
**严重度**: 高
**来源**: 维度C 边界扫描
**策略**: GP §5.2 (禁止静默忽略)
**问题**: `compute_step_returns` 中 `curr` 为 NaN/Inf 时毒化所有下游指标
**方案**: 循环中添加 `if !curr.is_finite() { return Vec::new() }`
**验收**: 注入 NaN 权益点 → 夏普/索提诺返回 0 而非 NaN

#### P1-C3 get_mock_volatility 无上限
**严重度**: 高
**来源**: 维度C 边界扫描
**策略**: GP §5.1 (禁止硬编码)
**问题**: `MOCK_VOLATILITY` 可注入 INF 导致全 OHLC 为 INF
**方案**: 添加 `vol.clamp(1e-6, 1.0)`
**验收**: 设置 `MOCK_VOLATILITY=Inf` → 回退到默认值

#### P1-C4 agent_module 硬编码默认 50.0
**严重度**: 高
**来源**: 维度A GP扫描
**策略**: GP §5.1 (禁止硬编码)
**问题**: `agent.spread_trigger_bps.unwrap_or(50.0)` 魔法数值
**方案**: 提取为 `const DEFAULT_SPREAD_TRIGGER_BPS: f64 = 50.0;`
**验收**: `grep "unwrap_or(50.0)" qrpc_runtime/src/agent_module.rs` 返回0

#### P1-B1 写锁内执行文件 I/O
**严重度**: 高
**来源**: 维度B 并发扫描
**策略**: GP §5.2
**问题**: `process_expired_approvals` 持锁执行 `fs::write` + `fs::rename`
**方案**: v2.3.3 已通过 spawn 后台 I/O 修复, 验证无遗留
**验收**: `grep -A10 "write().await" src/main.rs` 确认锁内无 I/O

#### P1-B2 沙箱验证 spawn 无 catch_unwind
**严重度**: 高
**来源**: 维度B 并发扫描
**策略**: 后台任务可靠性
**问题**: `run_sandbox_verification` panic 后不重启
**方案**: spawn 闭包内添加 `catch_unwind` + 3次退避重试
**验收**: 注入 panic → 日志显示重试 + 最终降级

#### P1-B3 block_on_http 每次创建新 Runtime
**严重度**: 高
**来源**: 维度B 并发扫描
**策略**: 资源管理
**问题**: fallback 路径每次创建新 tokio Runtime (完整线程池)
**方案**: 使用 `LazyLock<Runtime>` 全局单例
**验收**: 并发调用100次 → Runtime 创建仅1次

#### P1-E1 SSE 流无超时清理
**严重度**: 高
**来源**: 维度E API扫描
**策略**: 资源管理
**问题**: SSE 长连接无超时, 僵尸连接可堆积
**方案**: `Sse::new(stream).max_age(Duration::from_secs(300))`
**验收**: 断开客户端 → 300s后服务端释放连接

#### P1-E2 max_rps=0 导致拒绝服务
**严重度**: 高
**来源**: 维度E API扫描
**策略**: 配置防御
**问题**: `QUANTPILOT_RATE_LIMIT_RPS=0` 导致所有请求429
**方案**: 构造时校验 `max_rps >= 1`, 拒绝0值
**验收**: 设置 RPS=0 → 启动报错或回退到默认100

#### P1-E3 运行时记录列表无用户隔离
**严重度**: 高
**来源**: 维度E API扫描
**策略**: 多用户安全
**问题**: `list_runs/list_backtests` 不按 user_id 过滤
**方案**: 持久化时用 `scoped_key(user_id, record_id)`, 列表时按前缀过滤
**验收**: 不同用户登录 → 仅看到自己的运行记录

#### P1-E4 auth 速率限制器无代理检测
**严重度**: 高
**来源**: 维度E API扫描
**策略**: 安全
**问题**: 反向代理后所有请求共享同一 IP 令牌桶
**方案**: 与全局速率限制器一致的代理 IP 检测
**验收**: 设置 `QUANTPILOT_TRUSTED_PROXY` → 正确解析 `X-Forwarded-For`

#### P1-F1 CSP 策略优化
**严重度**: 高
**来源**: 维度E API扫描
**策略**: 安全头
**问题**: `style-src 'unsafe-inline'`, 缺 `base-uri` 指令
**方案**: 如前端框架支持, 改用 nonce; 至少添加 `base-uri 'self'`
**验收**: `curl -I http://127.0.0.1:3000` 响应头含 `base-uri 'self'`

### 三、前端性能 (10条)

#### P1-J1 EventStreamPanel 虚拟列表
**严重度**: 高
**来源**: 维度J 性能扫描
**问题**: 千级事件直接渲染全部DOM
**方案**: 接入 `react-window` FixedSizeList, 仅渲染可视行
**验收**: 1000条事件 → 渲染时间 < 200ms

#### P1-J2 零 React.memo → 关键组件包裹
**严重度**: 高
**来源**: 维度J 性能扫描
**问题**: 全部组件裸函数, 父渲染→子全量重渲染
**方案**: EventStreamPanel/PropertyPanel/ModuleSidebar/StrategyCanvas/BaseNodeCard 包裹 React.memo
**验收**: `grep -c "React.memo\|memo(" frontend/src/components/*.jsx` ≥ 5

#### P1-J3 StrategyCanvas 节点上限
**严重度**: 高
**来源**: 维度F 前端扫描
**问题**: 无 MAX_NODES 保护, 恶意图可导致浏览器卡死
**方案**: 添加 `MAX_NODES=1000`, 超限阻止渲染 + 提示
**验收**: 导入1001节点图 → 显示"节点过多"错误

#### P1-J4 QS 源码文本区 maxLength
**严重度**: 高
**来源**: 维度F 前端扫描
**问题**: QuantScriptEditor 文本区无限长度
**方案**: `maxLength={50000}`
**验收**: 粘贴60000字符 → 截断或阻止

#### P1-J5 事件搜索防抖
**严重度**: 高
**来源**: 维度J 性能扫描
**问题**: 每按键触发全量过滤
**方案**: useMemo 缓存 + onChange debounce 200ms
**验收**: 快速输入10字符 → 仅触发1次过滤

#### P2-J1 SMA 滑动窗口优化
**严重度**: 中
**来源**: 维度J 性能扫描
**问题**: O(N*period) 性能
**方案**: 滑动窗口求和 O(N)
**验收**: 10万K线 SMA(200) 从 ~500ms → ~50ms

#### P2-J2 fill_engine positions 索引
**严重度**: 中
**来源**: 维度J 性能扫描
**问题**: Vec 线性搜索 O(P)
**方案**: BTreeMap<(Exchange, Symbol), Position>
**验收**: 50标的订单提交 从 O(P) → O(log P)

#### P2-J3 signal_kind_for_intent 重复扫描
**严重度**: 中
**来源**: 维度J 性能扫描
**问题**: 每个signal重复遍历全部 signal_rules
**方案**: 预索引 HashMap<String, SignalKind>
**验收**: 循环内 `grep "signal_rules.iter()"` 仅出现于索引构建

#### P2-J4 权益曲线多次遍历
**严重度**: 中
**来源**: 维度J 性能扫描
**问题**: 5次全量遍历
**方案**: 单次遍历流式计算 (Welford's algorithm)
**验收**: 10万点权益曲线 → metrics 计算时间减半

#### P2-J5 大回测内存溢出保护
**严重度**: 中
**来源**: 维度J 性能扫描
**问题**: BacktestOutput 全量内存, 百万点 OOM
**方案**: 超阈值 (50万点) 溢出到文件, 内存仅保留摘要
**验收**: 100万点回测 → 内存 < 500MB
