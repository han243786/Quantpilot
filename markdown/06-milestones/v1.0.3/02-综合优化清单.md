# v1.0.3 综合优化清单

> 第四轮审计 | 15 项 | S0:3 / P1:6 / P2:6

## S0 — 阻断

### S0-1 parse_date_range_ms 时间倒流校验

**问题**: `test_runner.rs:1373` 只返回 end_ms, 不比较 start 和 end。传入 `2025..2024` 静默通过。

**方案**: 解析后增加 `if end_ms <= start_ms { bail!("结束时间必须大于开始时间") }`。

**验收**: 传入 end < start 返回错误。

### S0-2 NaN/Inf 输入校验

**问题**: 全库 0 处 `is_finite()` / `is_nan()` 检查。f64 比较 `> 0.0` 对 NaN 永远 false, 导致分类错误。

**方案**: 在 `payload_number` (backtest_artifacts.rs) 和 K 线数据入口 (data_module.rs) 加 `is_finite()` 守卫。

**验收**: 构造含 NaN 的 K 线 JSON → 解析拒绝或替换为 0。

### S0-3 编译并发 Semaphore

**问题**: 100 并发编译请求全部放行 (rate_limiter 前 100 个), CPU 密集操作可撑爆线程池。

**方案**: `compile_api.rs` 添加 `tokio::sync::Semaphore::new(4)` 限制同时编译数为 4。

**验收**: 同时发起 10 个编译请求, 仅 4 个并发执行, 其余排队。

## P1 — 高优

### P1-1 Paper 运行互斥锁

**问题**: 双标签可同时启动 Paper 运行, 无 run_id 互斥。

**方案**: 后端 `start_test_run` 检查 `state.runs` 中是否已有 running 状态的 run, 有则拒绝。

**验收**: 标签 A 运行中 → 标签 B 启动运行 → 返回 409 "已有运行在进行中"。

### P1-2 删除策略后优雅降级

**问题**: 标签 B 打开已被标签 A 删除的策略, 报未处理异常。

**方案**: `loadGraphById` 返回 404 时, `resolveLoadedGraphWithRegistry` 显示 "此策略已被删除, 请返回策略中心"。

**验收**: 删除策略后另一标签加载 → 友好中文提示而非异常。

### P1-3 端口冲突中文错误

**问题**: `main.rs:733` bind 失败透传 OS 英文错误 "Address already in use"。

**方案**: `.map_err(|e| anyhow!("端口 {} 已被占用，请检查是否有其他 QuantPilot 实例在运行: {}", port, e))?`。

**验收**: 端口被占用 → "端口 3000 已被占用, 请检查是否有其他 QuantPilot 实例在运行"。

### P1-4 data_module 429 退避重试

**问题**: 429 限流直接降级 mock 数据, 无重试。

**方案**: 参考 `test_runner.rs:752` 的退避重试模式, 加 1s/2s/3s 三次重试后降级。

**验收**: 模拟 429 → 重试 3 次 → 仍 429 则降级 mock。

### P1-5 插件市场 HTTP 状态码检查

**问题**: `fetch_manifest` 不检查状态码, 404 返回 "JSON 解析失败"。

**方案**: 在 `response.text()` 前加 `response.status().is_success()` 检查, 404 → "插件不存在"。

**验收**: 访问不存在的插件 → "插件 xxx 不存在 (404)"。

### P1-6 核心持久化 struct 加 deny_unknown_fields

**问题**: 全库 0 处 `#[serde(deny_unknown_fields)]`, 字段名拼错静默丢弃。

**方案**: 对 `VaultData`, `RunRecord`, `BacktestRecord` 三个核心持久化 struct 加此标注。

**验收**: 含未知字段的 JSON 反序列化失败。

## P2 — 中优

### P2-1 跨标签 storage 事件监听

**问题**: 0 处 `window.addEventListener("storage", ...)`, 跨标签完全盲。

**方案**: 在 `graphStore` 初始化时监听 storage 事件, 检测到 `capabilities_cache` 变更时刷新能力快照。

**验收**: 标签 A 更新 capabilities → 标签 B 自动刷新。

### P2-2 配额阈值 >= 修正

**问题**: `> 450MB` 而非 `>= 450MB`, 450MB 恰好不触发清理。

**方案**: `> FORCE_CLEAN_AT_BYTES` → `>= FORCE_CLEAN_AT_BYTES`。

**验收**: 450MB 恰好触发强制清理。

### P2-3 QUANTPILOT_PORT=0 拒绝

**问题**: bind(0) 分配随机端口, 0 是保留端口。

**方案**: parse 成功后检查 `port == 0`, 拒绝并提示使用有效端口。

**验收**: `QUANTPILOT_PORT=0` → "端口 0 是保留端口, 请使用 1-65535"。

### P2-4 回测 K 线数量上限

**问题**: 无 bars 数量上限, 100 万条可 OOM。

**方案**: 在回测入口加 `MAX_BACKTEST_BARS = 500_000`, 超出拒绝。

**验收**: 超过 50 万条的 K 线数据 → 拒绝并提示上限。

### P2-5 网络 5xx/4xx 分类

**问题**: `error_for_status` 不区分临时/永久错误。

**方案**: 区分 status >= 500 (临时) 和 >= 400 (永久), 在诊断中携带分类。

**验收**: 500 响应 → "临时服务端错误"; 404 → "数据不存在"。

### P2-6 Tauri wait_for_backend 进程归属校验

**问题**: 端口可达即认为后端已就绪, 不验证是否为当前进程。

**方案**: 在 `wait_for_backend` 中增加 `/api/health` 的响应校验 (检查版本号或进程 ID)。

**验收**: 已有进程占端口 → wait 不误判为当前进程就绪。
