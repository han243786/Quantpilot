## 目标

### 1. 架构根基重构
- **RuntimeCoordinator 拆分**: 22字段 god object → CycleOrchestrator + RuntimeState + MergeCoordinator + ConfigTracker

- **async 化**: std::sync::Mutex → tokio::sync::Mutex (data_module, execution_module)
- **ExecutionModuleProvider ISP 拆分**: 4方法 → ExecutionPlanner + ExecutionSubmitter

### 2. i18n 完整化
- **en-US 全量审核**: 318 处 `// TODO: translate` → 审核确认或修正
- **后端错误消息编码化**: 260+ Rust 硬编码中文 → 语言中立错误码 + 前端 t() 映射
- **前端状态标签 i18n**: runtimeStatus + EventStreamPanel + nodeCardPresentation
- **日期/数字格式化**: 替换所有硬编码 `"zh-CN"` 和手动格式化 → Intl API

### 3. 可观测性
- **tracing 引入**: 替换 safe_eprintln! → tracing + tracing-subscriber
- **日志轮转**: 文件日志 + JSON 结构化输出
- **健康检查丰富化**: /api/health 返回组件状态 (凭证/存储/数据库/告警)
- **Metrics 面板**: 交易量/P&L/延迟百分位 → 前端展示

### 4. 安全根基
- **TLS 终止**: axum-server + rustls 或 nginx sidecar
- **JWT 刷新机制**: /api/auth/refresh 端点
- **Windows 凭证权限**: ACL 限制 storage/.credentials
- **登录速率限制**: 独立 5次/分钟/IP 限制

### 5. 测试补全
- **backup E2E**: 完整备份-恢复循环测试
- **snapshot 集成**: snapshot_service API 端点测试
- **E2E waitForTimeout 替换**: 79 处 → waitForSelector/waitForResponse
- **request_json 去重**: 4 文件重复 → tests/common

## 方案

### 1. RuntimeCoordinator 拆分

**文件**: `qrpc_runtime/src/lib.rs` → `coordinator/` 子模块

```
RuntimeCoordinator (原有)
  → CycleOrchestrator    — 纯管道编排 (run_cycle, 无内部状态变更)
  → RuntimeState         — portfolio + data_fetch_counts + last_action_at_ms
  → MergeCoordinator     — merge_engine + merge_policy + merge_records
  → ConfigTracker        — config_generation + applied_deployment_revisions + history
```

### 2. 错误类型系统

**新文件**: `qrpc_core/src/error.rs`

```rust
#[derive(Debug, thiserror::Error)]
pub enum QuantPilotError {
    #[error("验证失败: {0}")]
    Validation(String),
    #[error("运行时错误: {0}")]
    Runtime(String),
    #[error("IO错误: {0}")]
    Io(#[from] std::io::Error),
    #[error("序列化错误: {0}")]
    Serialization(String),
}
```

### 3. 前端 i18n

逐文件完成 en-US 翻译审核, 后端错误消息编码化为 `error_code` + 前端 `t()` 映射。

### 4. 可观测性

替换 `safe_eprintln!` → `tracing::info!/warn!/error!`, 引入 `tracing-subscriber` 配置 JSON 格式输出到文件。

## 风险

| 风险 | 缓解 |
|------|------|
| RuntimeCoordinator 拆分引入回归 | 渐进拆分 (每步 cargo test 验证), 保留原有 API |
| thiserror 迁移破坏 trait 签名 | 先添加 QuantPilotError, 再用兼容层过渡 |
| tracing 引入编译时间增加 | 仅引入必要 feature (fmt, json), 不引入 OpenTelemetry |
| TLS 配置复杂度 | 第一阶段仅 Docker sidecar, 第二阶段 rustls |

## 决策纪录

### 决策: 错误类型方案

**选项**:
- A: thiserror 自定义枚举 (类型安全, IDE 友好)
- B: anyhow 保持现状 (零迁移成本)

**选择**: A

**理由**: 当前 `anyhow` 无法区分错误类型 (调用者不能 match 错误变体)。thiserror 提供类型化错误, axum `IntoResponse` 可统一 HTTP 映射。迁移成本可控 (渐进式, 新代码用新类型, 旧代码用兼容层)。

**影响**: 新增 `qrpc_core/src/error.rs`, 所有 provider trait 返回类型变更为 `Result<T, QuantPilotError>`。

### 决策: tracing vs env_logger

**选项**:
- A: tracing (生态最强, 异步原生支持, 结构化)
- B: env_logger (轻量, 零依赖)

**选择**: A

**理由**: tracing 是 Rust 生态标准, 原生支持 async/await span 追踪, JSON 输出适配 Loki/ES, 未来可扩展 OpenTelemetry。env_logger 只能文本输出。

**影响**: 新增 `tracing` + `tracing-subscriber` 依赖, 替换 safe_eprintln! 宏。
