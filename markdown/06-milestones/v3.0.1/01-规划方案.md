# v3.0.1 规划方案

> 版本类型: PATCH | 基准: v3.0.0 | 目标: 安全与数据完整性紧急修复

---

## 目标

- 修复凭证保险库缺少 .bak 回滚机制 (数据丢失风险)
- 审计日志修复: fsync + Mutex守卫生命周期 + 文件句柄复用
- RingBuffer Vec→VecDeque 性能修复 (O(N) → O(1))
- 前端静默 catch 块 → 错误状态 UI
- 签名机制从纯SHA-256升级为HMAC-SHA256
- 执行端关键路径浮点 NaN/Inf 过滤

## 非目标

- 不新增功能
- 不改变API接口
- 不处理P2/P3项

## 方案

### 安全修复 (5项)

| # | 文件 | 问题 | 修复 |
|---|------|------|------|
| D-1 | `credential_vault_v2.rs` | save() 无 .bak 回滚, 写入失败数据丢失 | 对照测试端 save_inner(): 先建 .bak→写tmp→失败从bak恢复→清理bak |
| D-2 | `audit_log.rs` | `let _guard = self.writer.lock()` 守卫立即丢弃, Mutex不生效 | 修复为 `let _guard = self.writer.lock().unwrap()` |
| D-3 | `audit_log.rs` | 追加写入无 fsync/flush, 崩溃丢日志 | write后加 file.sync_all() |
| G-1 | `migration_sender.rs` | 签名为纯SHA-256校验和(可重放) | 改用 session_crypto::sign/verify (HMAC-SHA256) |
| G-2 | `migration_sender.rs` | HTTP传输未加密, session_crypto已就绪但未用 | send_to_executor中加密body |

### 数据完整性 (3项)

| # | 文件 | 问题 | 修复 |
|---|------|------|------|
| C-1 | `executor_state.rs` | RingBuffer.push remove(0) O(N) | 改用 VecDeque, pop_front O(1) |
| C-2 | `ws_client.rs` | reconnect_backoff_secs * 2 溢出 | saturating_mul |
| C-3 | `kline_buffer.rs` + `ws_client.rs` | f64 NaN/Inf 无过滤直接入缓冲 | 入口处 is_finite() 校验 |

### 前端错误处理 (3项)

| # | 文件 | 问题 | 修复 |
|---|------|------|------|
| F-1 | `ExecutorApp.jsx` | catch {} 静默, execStatus 从未设为 error | 添加 setExecStatus("error") + 重试按钮 |
| F-2 | `KlineChart.jsx` | catch {} 静默, 图表空白 | 添加 error 状态 + 重试覆盖层 |
| F-3 | `StrategyGraphPanel.jsx` | EventSource 无 onerror 处理 | 添加 onerror 处理器 + 连接状态指示 |
