## 🔴 阻塞项 — P0 阶段（1.5 天）

### D1 — 40 处原始 eprintln!/println! 迁移到 safe_eprintln!

**问题**：10 个文件中存在 40 处 `eprintln!` / `println!` 调用，未经过 `safe_log::sanitize_secrets` 脱敏。若日志消息中包含 OKX API 签名参数或请求体片段，凭证明文会写入 stderr。

**涉及文件**：

| 文件 | 数量 | 风险等级 |
|------|:--:|:--:|
| `main.rs` | 8 | 高 — 启动日志 / 错误报告 |
| `cli_support.rs` | 18 | 高 — 命令行交互 |
| `auth_middleware.rs` | 1 | 中 |
| `compile_api.rs` | 2 | 中 |
| `graph_api.rs` | 1 | 低 |
| `storage_lifecycle.rs` | 4 | 低 |
| `test_runner.rs` | 3 | 高 — testnet 请求上下文 |
| 其他 | 3 | 低 |

**改法**：逐文件审计，所有 `eprintln!(...)` → `crate::safe_eprintln!(...)`。CLI 帮助文本（`cli_support.rs`）和 `main.rs` 中的纯状态输出可以保留，但任何可能包含动态数据的调用点必须迁移。

**验收**：`grep -rn "eprintln!\|println!(" src/ --include="*.rs" | grep -v safe_eprintln | grep -v "用法\|帮助\|usage\|help"` 返回 ≤5（只保留纯文本输出）。

### D3 — problem_* 废弃调用点迁移

**问题**：`api_errors.rs` 中 `problem_not_found`、`problem_conflict`、`problem_bad_request`、`problem_internal` 已标注 `#[deprecated]`，但 10+ 处调用点未迁移。当前代码以 deprecated 状态编译无报错（仅 warning），但长期保留会导致错误响应格式分裂。

**残留调用点**：

| 文件 | 行 | 函数 |
|------|-----|------|
| `alert_engine.rs` | 148 | `problem_not_found` |
| `chaos_experiment.rs` | 247 | `problem_not_found` |
| `chaos_experiment.rs` | 253 | `problem_internal` |
| `runbook.rs` | 312 | `problem_not_found` |
| `runtime_api.rs` | 827, 3272 | `problem_not_found` |
| `runtime_api.rs` | 3099, 3172 | `problem_bad_request` |
| `runtime_api.rs` | 3295, 3301 | `problem_internal` |
| `sandbox_verification.rs` | 31, 267 | `problem_not_found` |
| `sandbox_verification.rs` | 55 | `problem_bad_request` |
| `sandbox_verification.rs` | 273 | `problem_internal` |
| `snapshot_service.rs` | 145 | `problem_conflict` |
| `snapshot_service.rs` | 191 | `problem_not_found` |
| `snapshot_service.rs` | 197 | `problem_internal` |

**改法**：`problem_not_found(msg)` → `json_bad_request("not_found", msg)`，类推。同步更新测试断言中引用旧错误格式的期望值。

**验收**：`grep -rn "problem_not_found\|problem_conflict\|problem_bad_request\|problem_internal" src/ --include="*.rs"` 返回 0（`#[deprecated]` 声明本身除外）。

### D8 — not_found_fallback 汉化

**问题**：`app_router.rs:29-36` 的 404 fallback 返回全英文 JSON，违反 General_Policy §2.1。

```rust
// 当前
"title": "Not Found",
"detail": "The requested endpoint does not exist."

// 应为
"title": "未找到",
"detail": "请求的资源不存在"
```

**改法**：`app_router.rs:not_found_fallback()` 消息改为中文。

**验收**：`curl /api/nonexistent` 返回中文 404。

### D6 — vault 内存安全残余文档化

**问题**：`get_service()` 返回 `CredentialFields`（`BTreeMap<String, String>`），值不包 `Zeroizing`。调用方拿到 `String::clone()` 副本，原始 `SecretString` 在锁内 drop 时已清零。但 clone 副本的生命周期由调用方管理，调用方若忘记 `Zeroizing::new()` 包裹则残留明文。

此项已在 `api安全方案.md` 的"安全边界与已知限制"中声明。本轮在代码中追加 `/// # 安全` 文档注释标注此行为。

**改法**：`credential_vault.rs:get_service()` 上方添加文档注释，说明调用方应尽快 wrap Zeroizing。

**验收**：代码审查确认注释存在。
