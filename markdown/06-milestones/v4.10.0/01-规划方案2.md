# v4.10.0 规划方案 — UX 收口与产品边界固化

> 版本类型: MINOR | 基准: v4.9.0 closeout
> 来源: 2026-05-26 全量审计残留项 + 用户产品决策
> 约束: 全量树 + GP 矩阵 + 超级规范化文档

---

## 目标

v4.10.0 处理 v4.9.0 未覆盖的 UX 收口项, 同时固化若干产品边界决策: 明确裁剪账户系统、策略中心不做搜索、补充 OpenAPI 路由完整性。

1. **亮色主题**: 基于现有 `--ad-*` 令牌体系新增 `prefers-color-scheme: light` 媒体查询和用户手动切换。
2. **执行端 i18n 补完**: StrategyGraphPanel 接入 `useI18n`, 消灭执行端最后一个硬编码中文组件。
3. **styles.css 瘦身**: 消除重复选择器, 合并 `.ad-btn` / `.ghost-btn` / `.primary-btn` 两套按钮系统。
4. **Tutorial 自动触发**: 首次访问检测 (`localStorage` 标志), 策略中心增加可见的"新手指引"入口。
5. **工作区 Tab keep-alive**: Tab 切换从条件渲染改为 CSS `display` 控制, 避免 Suspense 闪烁和状态丢失。
6. **产品边界固化**: 明确记录账户系统裁剪、策略中心无搜索/筛选、单机工具定位。

## 非目标

- **不新增账户功能**: 不实现登录、注销、密码找回、会话撤销、refresh token 语义变更。
- **不新增策略搜索/筛选**: 策略中心维持当前列表展示, 不做搜索框、排序、分页。
- **不新增 provider**: 不接入非 OKX provider。
- **不开放真实资金**: `LiveActual` / `LiveSimulated` 保持 deferred。
- **不新增 Machine 模板**: 不扩展 v4 状态机模板。
- **不修改 V1 QS 语法面**。

## 产品边界决策 (v4.10.0 固化)

### 决策 1: 裁剪账户系统

**结论**: QuantPilot 定位为**单机交易工具**, 不做多用户账户系统。

**理由**:
- 本产品运行在用户本地机器, 通过 Tauri 桌面壳或 localhost 访问。
- 多用户账户、权限模型、RBAC 适用于 SaaS/团队场景, 与本产品定位不符。
- 当前 `register` / `login` / `refresh` 端点保留用于本地加密和会话管理, 但不扩展为完整账户系统。

**明确不做**:
- 注销端点 (`POST /api/auth/logout`)
- 密码找回/重置流程
- 2FA / TOTP / WebAuthn
- 管理员角色和权限模型
- 用户管理 UI

**保留面**:
- 当前 auth 端点保持不变, 用于本地 JWT 会话和凭证隔离。
- 若未来产品定位变化 (SaaS/团队版), 账户系统作为独立 MAJOR 版本重新评估。

### 决策 2: 策略中心不做搜索/筛选

**结论**: 策略中心维持当前全量列表展示。

**理由**:
- 单机交易工具的典型策略数量在可滚动范围内 (<50)。
- 搜索/筛选增加 UI 复杂度, 与"专业工作区外壳"设计原则冲突 (§8.10)。
- 若未来策略数量成为实际问题, 作为独立 MINOR 版本添加。

### 决策 3: 单机工具定位

**结论**: QuantPilot 的产品定位正式固化为"专业量化策略研究桌面工具"。

**含义**:
- 所有功能设计以单人本地使用为默认上下文。
- 不优化多用户场景、团队协作、云端同步。
- 协作 (`collaboration.rs`) 保持现有实现, 不扩展。
- 部署和运维以 `start.bat` / Tauri 桌面壳为主要路径。

## W0 — 亮色主题

**严重度**: P2
**约束**: GP §8.1-§8.6, 超级规范化 §5

### 问题

当前设计系统仅暗色模式。`prefers-color-scheme: light` 无响应, 用户无法切换。

### 方案

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/design-system.css` | 新增 `:root.light` 或 `@media (prefers-color-scheme: light)` 令牌覆盖 |
| 2 | `frontend/src/styles.css` | 关键组件适配亮色背景/文字/边框 |
| 3 | `frontend-executor/src/design-system.css` | 执行端同步亮色令牌 |
| 4 | 设置页 (v4.9.0 W3) | 增加 `auto / dark / light` 三态切换 |

### 设计约束

- 亮色令牌基于同一 `--ad-*` 变量体系, 仅覆盖色值, 不改变间距/字号/圆角。
- 亮色背景: `#f5f5f5`, 卡片: `#ffffff`, 主文字: `#1a1a1a`, 辅助文字: `#6b6b6b`。
- 图表和热力图区域保持暗色 (数据可视化可读性)。

### 验收

- 系统偏好为 light 时自动切换; 手动切换覆盖系统偏好。
- 策略中心、工作区、执行端三区域亮色均可读。
- `prefers-reduced-motion` 不受影响。

## W4 — 工作区 Tab keep-alive

**严重度**: P3
**约束**: GP §8.10

### 问题

工作区 Tab 使用条件渲染 (`{activeTab === "code" && <StrategyWorkspaceCodeTab />}`), 导致每次切换触发完整 unmount/remount, Suspense fallback 闪烁, 滚动位置和表单状态丢失。

### 方案

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `frontend/src/pages/StrategyWorkspacePage.jsx` | 条件渲染改为 `style={{ display: activeTab === id ? "block" : "none" }}` |
| 2 | 各 Tab 组件 | 确认 `useEffect` 依赖不因 `display:none` 产生副作用 |
| 3 | `frontend/src/pages/StrategyWorkspacePageSections.jsx` | 同步调整 |

### 验收

- Tab 切换无 Suspense fallback 闪烁。
- 切换后表单输入和滚动位置保留。
- 不可见 Tab 不触发 API 轮询。
