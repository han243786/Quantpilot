## 解决方案与验收标准

### P1-01 — ChaosPage API 路径错误

**方案**: 修改 `ChaosPage.jsx:31` `chaos-experiments` → `chaos/experiments`; 第47行 `chaos-experiments/create` → `chaos/experiments`
**验收**: `grep -rn "chaos-experiments" src/` 返回 0; ChaosPage 创建/刷新功能正常

### P1-02 — API_BASE 双源冲突

**方案**: 统一为单一 `resolveApiBase()` 函数。`utils/api.js` 改为从 `graphStorePersistenceHelpers.js` 导入 `API_BASE`; 组件层统一使用 `/api` 相对路径
**验收**: 设置 `VITE_API_BASE_URL=http://localhost:9000/api` → store 和组件请求同时正确路由; 不设置时默认行为不变

### P1-03 — SSE 事件无批处理

**方案**: 在 `graphStoreRuntimeSessionActions.js` 的 `_onMessage` 中引入微批处理——累计 50ms 窗口内的事件、合并为单次 `set()`。使用 `requestAnimationFrame` 或 `setTimeout(fn, 0)` 合并同一帧内的多次 set
**验收**: 高频率模拟下(30+事件/秒)，React DevTools 显示每帧 ≤3 次渲染(当前为每事件1次); 事件无丢失

### P1-04 — EventStreamPanel 无虚拟列表

**方案**: 方案A(最小)——将渲染上限从500降至100，添加"显示更多"按钮; 方案B(完整)——引入 `react-window` FixedSizeList。推荐A(零新依赖)
**验收**: 500条事件时 DOM 节点数 ≤120; 滚动性能无明显卡顿

### P1-05 — Recharts 未独立分包

**方案**: `vite.config.js` manualChunks 添加: `if (id.includes("recharts")) return "chart-vendor"`
**验收**: 构建产物中出现独立 `chart-vendor-*.js`; vendor chunk 从465KB降至 ≤280KB; 非对比页面的初始加载不包含 recharts

### P1-06 — SSE JSON.parse 无 try-catch

**方案**: 在 `_onMessage` 和 `_onAccount` 处理器中包裹 `JSON.parse(message.data)`:
```js
try { const event = JSON.parse(message.data); ... } catch(e) { console.warn("[sse] JSON解析失败", e); }
```
**验收**: 构造 `data: {broken` 的 SSE 事件 → 控制台 warn 输出、后续事件正常处理、连接不中断

### P1-07 — 初始化 30s 无取消按钮

**方案**: `AppShellFallback` 组件添加"取消等待"按钮 → 调用 `AbortController.abort()` 中断初始化 → 使用缓存/降级数据渲染 UI; `initialize()` 接受外部 AbortSignal
**验收**: 点击"取消等待"后3秒内 UI 渲染为降级模式(使用 localStorage 缓存或空图); 操作不阻塞

### P2-01 — O(N) 双 pass .map() 合并

**方案**: `graphStoreRuntimeSessionState.js:60-104` 将两次 `.map()` 合并为一次遍历; 添加 `node.type !== "runtime"` 快速路径跳过非运行时节点
**验收**: 50节点30事件/秒场景下对象分配减少 ≥40%; `npx vitest run` 全量通过

### P2-02 — initialize() 并行化独立请求

**方案**: `graphStore.js:186-187` 将 `refreshCapabilities()` 和 `refreshGraphIndex()` 改为 `Promise.all`:
```js
const [, graphIndex] = await Promise.all([get().refreshCapabilities(), get().refreshGraphIndex()]);
```
**验收**: 正常网络下初始化时间减少 ~40%; 错误处理路径不变

### P2-03 — 凭证 CRUD 静默错误

**方案**: `TopToolbar.jsx:409-415` catch 块中设置 `loadError` 状态并在 UI 显示; `handleDelete` 相似处理
**验收**: 凭证 API 500错误 → 面板内显示红色错误消息; 凭证 API 无数据 → 显示"暂无已存储凭证"(现状)

### P2-04 — ChaosPage/SnapshotsPage mutation 静默错误

**方案**: `ChaosPage.jsx:53` `catch (_) {}` → `catch (e) { setCreateError(e.message) }`; SnapshotsPage 同理
**验收**: 创建/恢复操作失败 → 内联错误消息显示(不通过页面级 error banner)

### P2-05 — fetchJson 不设 error.status

**方案**: `graphStorePersistenceHelpers.js:236-243` 中 `throw new Error(message)` 前设置 `error.status = response.status`(与 postJson 一致)
**验收**: `fetchJson` 抛出的 Error 对象包含 `.status` 属性; 调用方可区分 4xx/5xx

### P2-06 — 页面仅显示 HTTP 状态码

**方案**: `AlertsPage.jsx:20` 等 `throw new Error(\`HTTP ${res.status}\`)` → 改为 `res.text().then(t => { throw new Error(t.slice(0,200)) })` 读取响应体
**验收**: 后端返回 `{"error":"数据库连接失败"}` → 用户看到此消息而非仅 "HTTP 500"

### P2-07 — 验证 O(n*e) edges.filter

**方案**: `validation.js` 入口处预建 `edgesByTarget` / `edgesBySource` Map(O(e)一次), 节点循环内使用 Map.get(O(1))
**验收**: 1000节点2000边 graph 验证 <100ms (当前估500ms); `npx vitest run` 全量通过

### P2-08 — 无 visibilitychange 处理器

**方案**: `graphStoreRuntimeSessionActions.js` 添加:
```js
document.addEventListener("visibilitychange", () => {
  if (document.hidden) { /* 标记后台状态 */ }
  else { /* 恢复可见时执行一次同步刷新 */ }
});
```
**验收**: 切换标签页5分钟 → 切回时3秒内恢复最新状态; 后台期间不触发 React 重渲染

### P2-09 — 无 IndexedDB 回退

**方案**: localStorage QuotaExceededError 时降级写 IndexedDB; 读取时优先 localStorage、回退 IndexedDB。使用 `idb-keyval` 或原生 IndexedDB API
**验收**: >5MB 策略图 → 写入 IndexedDB、刷新后可恢复; console 无配额错误; 小图仍用 localStorage

### P2-10 — 缺少分页参数

**方案**: 后端确认支持分页后, 前端添加 `?limit=200&offset=0`; 超出200条时显示"加载更多"
**验收**: 200+条回测记录时仅请求前200条; 滚动加载后续记录

### P2-11~P2-15 — OpenAPI spec / save body / 恢复重试 / normalizer registry

**方案**: 这些是文档/架构改进:
- P2-11: `root.yaml` 补充 POST 端点 requestBody schema
- P2-12: save 端点确认 body schema 后前端对齐
- P2-13: `recoverLatestRunnableGraph` 重试间隔从 1500ms 增至 5000ms、最大重试从 10 降至 3
- P2-14: `normalizeGraphShape` 接受 registry 参数而非硬编码 defaultRegistry
