## 第一阶段: 统一 API 客户端 (2天, 解决 8 项)

### 问题
代码库存在 **4 个互不兼容的 API_BASE 来源**:
- `utils/api.js` — 不含 /api 后缀
- `graphStorePersistenceHelpers.js` — 含 /api 后缀
- `runtimeApproval.js` — 第三个 env 变量 VITE_BACKEND_ORIGIN
- 页面组件手动拼接 — 各写各的

### 方案
创建 `src/api/client.js` 统一出口:

```
src/api/
  client.js       # 统一 fetch 包装器 (含 AbortController + auth 扩展点)
  sseClient.js    # SSE EventSource 包装器 (为 Web Worker 预留接口)
  pagination.js   # 分页参数构建
```

| 改动 | 影响 |
|------|------|
| 所有 fetch 调用改为 `apiClient.get/post/delete` | 消除 4 个 API_BASE 来源 |
| SSE 连接统一走 `sseClient` | 为 visibilitychange/Worker 预留 |
| 列表端点统一加 `?limit=&offset=` | C4 分页问题直接解决 |
| OpenAPI spec 可作为 client 的类型来源 | A1-A5 spec 缺口间接解决 |

### 解决项
C8 (API_BASE), A6 (版本前缀), C4 (分页), A1-A5 (spec 可补全), D4 (重连注释)
