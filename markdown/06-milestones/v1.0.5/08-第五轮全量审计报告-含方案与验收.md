## 解决方案与验收标准

### S0-01 — SSE transport 零回归测试

**方案**: 新增 `graphStoreRuntimeTransport.test.js`:
1. 使用 `vi.useFakeTimers()` 控制时间
2. 构造 mock EventSource (全局 mock)
3. 测试: 正常连接→断开→重连→事件处理器转移 (_onMessage/_onAccount/_onComplete/_onError)
4. 测试: 5次重试后 onRetryExhausted 触发
5. 测试: _manualClose→跳过重连
6. 测试: 指数退避 (1s→2s→4s→8s→16s)
**验收**: 6个测试通过, `npx vitest run` 不变

### S0-02 — runtimeActionLock 零回归测试

**方案**: `graphStoreRuntimeSessionActions.test.js` 中新增:
1. Mock fetch 延迟 100ms 模拟 POST
2. 同时调用 startRuntime() 两次
3. 验证仅 1 个 POST 发送
4. 验证锁在 finally 释放
**验收**: 2个测试通过

### P1-01 — 30 store action 零覆盖

**方案**: 新增 `graphStore.editorActions.test.js`:
1. createNode→验证 nodes 长度+1
2. addEdge→验证 edges 长度+1
3. removeSelected→选中节点+删除→验证 nodes 长度-1
4. updateNodeConfig→修改参数→验证 graph 更新
5. updateNodeName→重命名→验证 name 变化
**验收**: 5+个核心编辑器操作有测试; vitest run 通过

### P1-02 — EditorPage/LeftSidebar 零测试

**方案**: 新增 `LeftSidebar.test.jsx`: 验证 7 个导航项渲染、active 项高亮、点击触发导航
**验收**: 组件渲染测试通过

### P1-03 — saveGraph 回滚零测试

**方案**: `graphStore.versionHistory.test.js` 中新增: mock POST 返回 500→验证 state 回滚到 prevGraph
**验收**: 测试验证回滚路径执行

### P1-04 — ghost backendError

**方案**: `buildRuntimeCompletionState` 中添加 `backendError: null`
**验收**: SSE 断开→run_completed 后 `runtime.backendError === null`

### P1-05 — compileResult 陈旧

**方案**: 7 个编辑器 action (`createNode`, `updateNodeConfig`, `addEdge`, `removeSelected` 等) 的 set() 中追加 `compileResult: get().compileResult` (保留不覆盖) 或 所有编辑器 action 追加设置 `compileResult: null` 表明 "已重新验证,未重新编译"
**决策点**: 保留 compileResult 还是置 null？保留让 P2-22 缓存逻辑生效但数据陈旧; 置 null 强制重编译

### P1-06 — compileResult 跨图持久化

**方案**: `loadLatestGraph` 和 `loadGraphById` 的 set() 中添加 `compileResult: null`
**验收**: 加载图后 `get().compileResult === null`

### P1-07 — 回测 events 未绑定

**方案**: `buildBacktestCompletionState` 中添加 `.slice(0, 200)` 限制
**验收**: 回测完成 1000 事件→仅 200 存入

### P1-08 — formalQuantScriptOverride 跨重置泄露

**方案**: `resetGraph()` 的 set() 中添加 `formalQuantScriptOverride: null`
**验收**: 设置覆盖→重置→compileCurrentGraph 不读取旧覆盖

### P1-09 — null byte URL 注入

**方案**: `router.js` parseRoute 中对 decoded param 调用 `sanitizeText` 过滤控制字符
**验收**: `/strategies/%00` 导航→重定向到 hub 或显示 "无效策略ID"
