## 一、S0 阻断级 — 11 项

### S0-1 — SSE 重连处理器转移完全失效

**来源**: 第三轮 / Agent 7 (状态管理)
**文件**: `graphStoreRuntimeTransport.js:39-41`

**问题**:
```js
if (es._onMessage) next.addEventListener("runtime_event", es._onMessage);
if (es._onComplete) next.addEventListener("run_completed", es._onComplete);
if (es._onError) next.onerror = es._onError;
```
`_onMessage` / `_onComplete` / `_onError` 从未被设置，重连后所有事件静默丢失。

**优化方案**:
1. 在 `graphStoreRuntimeSessionActions.js` 中注册监听器时，将处理器引用存储到 EventSource 实例的自定义属性
2. 在 `_reconnect()` 中读取并转移
3. 添加 `Last-Event-ID` 跟踪以便从断点恢复

**验收标准**:
- 启动模拟 → 断开网络 → 恢复网络 → 事件流继续接收且无丢失
- `onRetryExhausted` 回调在 5 次重试失败后触发
- `cargo test --workspace` 编译通过

**估时**: 2h

### S0-2 — 未保存策略图刷新后全部丢失

**来源**: 第三轮 / Agent 9 (工作流)
**文件**: `graphStore.js:190-196` + `graphStorePersistenceHelpers.js:512-516`

**问题**:
`graphExistsInIndex()` 检查 graph_id 是否在后端索引中。`openBlankWorkspace()` 生成客户端 `graph_${Date.now()}` ID，从未持久化到后端。刷新后 localStorage 中的完整策略图被跳过。

**优化方案**:
1. 修改 `graphExistsInIndex()` 逻辑：当后端索引为空时（新用户/离线），允许 localStorage graph 通过
2. 在 `initialize()` 中增加第三个回退：如果前两步失败但 localStorage 存在可用 graph，使用它
3. 前端生成 graph_id 时添加 `local_` 前缀以区分客户端/服务端 graph

**验收标准**:
- 打开空白工作区 → 添加节点 → 不点保存 → 刷新浏览器 → 策略图保留
- 已有后端索引的策略图行为不变
- `npx vitest run` 全量通过

**估时**: 1h

### S0-3 — 运行时清理 effect 过期闭包

**来源**: 第三轮 / Agent 9 (工作流)
**文件**: `StrategyWorkspacePage.jsx:66-72`

**问题**:
```js
useEffect(() => {
  return () => { if (runtime?.status === "running") stopRuntime(); };
}, []); // ← 空数组导致闭包永远看到初始 "idle" 状态
```

**优化方案**:
1. 将 `runtime.status` 加入依赖数组
2. 或者用 `useRef` 保存最新 runtime 引用，cleanup 中读取 ref

**验收标准**:
- 启动模拟 → 导航到其他页面 → 后端 POST `/runtime/stop` 被调用
- 刷新页面时 SSE 连接正常关闭
- 无 React 18 StrictMode 警告

**估时**: 30min

### S0-4 — 跨标签删除策略导致状态损坏

**来源**: 第三轮 / Agent 9 (工作流)
**文件**: `graphStore.js:160-171`

**问题**:
Storage 监听器盲目接受 localStorage graph，不验证与当前 route 的一致性。Tab B 删除后 Tab A 被替换为空白图，URL/状态失步。

**优化方案**:
1. 在 storage 监听器中检查 `event.newValue` 是否为 `null`（被删除）
2. 如果是删除，比较 `event.key` 中的 graph_id 与当前 `get().graph.metadata.graph_id`
3. 匹配时显示 toast 提示 "此策略已被删除" 并重定向到 Hub
4. 如果是更新而非删除，调用 `resolveLoadedGraphWithRegistry()` 验证后再应用

**验收标准**:
- Tab A 编辑策略 → Tab B 删除同一策略 → Tab A 显示 "此策略已被删除" + 返回按钮
- Tab B 保存不同策略 → Tab A 不受影响
- 正常跨标签保存同步不受影响

**估时**: 1h

### S0-5 — 无运行互斥锁 (可同时启动两个模拟)

**来源**: 第三轮 / Agent 7 (状态管理)
**文件**: `graphStoreRuntimeSessionActions.js:71-82`

**问题**:
`startRuntime()` 的 POST 期间无互斥。快速双击发起两个并行 POST、两个 SSE 连接，第一个泄漏。

**优化方案**:
1. 添加 `runtimeActionLock` 状态字段
2. `startRuntime()` / `startBacktest()` 开头检查锁
3. POST 完成后（成功或失败）释放锁
4. 锁定时 UI 显示 "启动中..." 并禁用按钮

**验收标准**:
- 双击 "启动模拟" → 仅一个 POST 发送
- 模拟运行中 → "启动模拟" 按钮 disabled
- `startBacktest` 同理

**估时**: 45min
