## S0-1: Safe fallback E2E 阻断

**严重度**: S0  
**来源**: `npm run test:e2e`  
**现状**: 已修复，2026-05-24 本地复验 21/21 通过  
**失败用例**: `editor enters safe fallback mode when capability fetch fails without cache`

### 问题

测试 helper `enterCurrentWorkspace` 进入工作区后固定点击 `workspace-tab-research`。在 capability 服务 503 且无本地缓存时，前端进入 safe fallback，所有 workspace surface 被投影为 `declared_only`：可见但禁用。Playwright 等待禁用按钮变为可点击直到 30s 超时。

### 根因

测试预期和产品安全语义不一致：

- 测试预期：safe fallback 下仍能点击研究页 tab。
- 产品现状：safe fallback 下 tab 可见但禁用，只保留默认 dashboard 和工具栏安全提示。

### 推荐方案

保留产品 strict safe fallback，不放宽交互语义；修改 E2E：

1. 将 `enterCurrentWorkspace` 拆成两个 helper：
   - `enterCurrentWorkspace(page)`：只进入默认 dashboard 并验证工具栏。
   - `enterWorkspaceResearch(page)`：只在健康/缓存能力快照下点击 research。
2. safe fallback 用例验证：
   - `toolbar-capability-alert` 包含“安全回退模式”。
   - `toolbar-compile-action` / `toolbar-start-runtime-action` / `toolbar-start-backtest-action` 禁用。
   - `workspace-tab-research`、`workspace-tab-code`、`workspace-tab-monitor` 禁用且 title 含能力不可用原因。
   - 工具菜单可打开，导出运行配置禁用。

### 验收

- `cd frontend && npm run test:e2e` 21/21 通过。
- `tools/run-closeout-gates.bat` 不再在 E2E 阶段失败。
- safe fallback 不暴露编译、运行、回测、导出 runtime_config 等风险动作。

### 涉及文件

- `frontend/tests/e2e/editor-capabilities-smoke.spec.js`
- 可能追加: `frontend/src/pages/StrategyWorkspacePage.codeMode.test.jsx`

## P2-2: Clippy 门禁语义不清

**严重度**: P2  
**现状**: `tools/check-clippy-warning-budget.ps1 -MaxWarnings 58` 通过，当前 workspace clippy warning budget 为 58/58。  
**冲突**: 超级规范化表格写 `Clippy` 为阻断，但当前只阻断 clippy error，不阻断 warning。

### 可选方案

| 方案 | 内容 | 优点 | 风险 |
|------|------|------|------|
| A | 明确 clippy 为 error gate，warning 进入债务预算 | 低风险，适合 PATCH | 仍保留 warning 债务 |
| B | 直接升级为 `cargo clippy -- -D warnings` | 质量最高 | 本轮需一次性清 68 条 warning，改动面大 |
| C | 按 crate 分预算，先 executor 0，其它 crate 递减 | 可持续 | 需要新增统计脚本 |

### 推荐方案

采用 C：保留 executor warning budget=0，同时新增 workspace clippy warning budget 的只降不升门禁。v3.7.2 可先登记现状预算，后续 PATCH 逐步递减；若你要求更强约束，再切 B。

### 验收

- 文档明确当前 clippy 语义。
- 若采用预算化，新增脚本可输出 `workspace clippy warning budget: current/max`。
- 不再出现“clippy 通过”等同于“warning-free”的表述。
