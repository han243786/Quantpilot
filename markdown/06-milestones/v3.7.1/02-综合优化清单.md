## S0: 正确密码登录挂起 (阻塞所有项)

**严重度**: S0
**来源**: GP §10.3 回归检查
**策略**: GP §5.1 (认证与授权)
**预估时间**: 15 分钟

### 问题

`login_handler` 中，Step 3 (`generate_jwt` + `create_refresh_token`) 在正确密码验证通过后挂起约 120 秒。错误密码路径（不进入 Step 3）~555ms 正常返回。

### 根因

`generate_refresh_token()` 每次调用创建新的 `ring::rand::SystemRandom` 实例。在 Windows 上，`SystemRandom::new()` 调用 `BCryptOpenAlgorithmProvider(BCRYPT_RNG_ALGORITHM)` 打开 CSPRNG 句柄，开销不可预测且无法保证快速返回。

`create_refresh_token` 在 `std::sync::Mutex<Connection>` 锁范围内调用 `generate_refresh_token()` 两次（一次用于 token，一次用于 family_id 前缀），锁持有期间阻塞所有其他数据库操作。两个因素叠加导致 120s 级挂起。

### 方案

1. **缓存 `SystemRandom`** — 使用 `OnceLock` 全局缓存 `ring::rand::SystemRandom` 实例，与 `jwt_secret_bytes()` 的缓存模式一致。消除每次 `generate_refresh_token()` 调用的 CSPRNG 句柄创建开销。
2. **Token 生成移出锁范围** — 在 `login_handler` Step 3 中，将 `generate_refresh_token()` 调用移至 `db.lock()` 之前执行，仅在锁范围内执行 SQL INSERT。

### 验收

- 正确密码登录返回 JWT 时间 < 2s
- 错误密码返回时间 < 1s（回归不变）
- `cargo check --workspace` 通过

### 涉及文件

- `src/auth/mod.rs` — `generate_refresh_token()` 函数，`create_refresh_token()` 函数，`login_handler` 函数

## P1: DELETE 凭证路由 405 (依赖 S0 完成)

**严重度**: P1
**来源**: GP §10.3 回归检查
**策略**: GP §4.1 (API 一致性)
**预估时间**: 5 分钟

### 问题

`DELETE /api/credentials/{service}` 返回 HTTP 405 Method Not Allowed。

### 根因

`Cargo.toml` 声明 `axum = "0.7"`（实际锁定 0.7.9），但 `credential_api.rs` 使用 `{service}` 路径参数语法。Axum 0.7 使用 `:param` 语法，`{param}` 被当作字面路径段处理。`/api/credentials/{service}` 仅匹配字面路径 `/api/credentials/{service}`（含花括号），不匹配 `/api/credentials/okx`。

### 方案

将路由定义从 `{service}` 改为 `:service`：

```rust
// 修改前
.route("/api/credentials/{service}", delete(delete_credential))
// 修改后
.route("/api/credentials/:service", delete(delete_credential))
```

### 验收

- `curl -X DELETE http://127.0.0.1:3000/api/credentials/test123` → 200 或 404，非 405
- `cargo check --workspace` 通过

### 涉及文件

- `src/credential_api.rs` — 第 13 行路由定义

## P2: 测试编译文件锁阻塞 (依赖 P1 完成)

**严重度**: P2
**来源**: GP §10.3 回归检查
**策略**: 测试基础设施
**预估时间**: 10 分钟

### 问题

运行中的 QuantPilot 服务器 (`target/debug/quantpilot.exe`) 持有二进制文件锁，`cargo test` 编译测试目标时因无法覆盖写入而阻塞。

### 根因

Cargo 编译测试二进制时需要写入 `target/debug/` 目录。Windows 上运行中的 `.exe` 文件持有写入锁，阻止 Cargo 更新 `quantpilot.exe`。

### 方案

提供测试辅助脚本 / Makefile 目标，在运行测试前自动停止服务器进程：

1. 在项目根目录创建 `scripts/test.sh` / `scripts/test.ps1`：
   - 先查找并终止运行中的 `quantpilot.exe` 进程
   - 然后执行 `cargo test --bin quantpilot`
2. 或提供单行命令：
   ```bash
   # PowerShell: 先杀进程再测试
   Get-Process quantpilot -ErrorAction SilentlyContinue | Stop-Process -Force; cargo test --bin quantpilot
   ```

### 验收

- 服务器运行时执行测试命令，自动停止服务器后测试正常编译运行
- `cargo check --workspace` 通过

### 涉及文件

- （新建）`scripts/test.sh`
- （新建）`scripts/test.ps1`
