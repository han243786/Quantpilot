# v4.8.0 规划方案 — 双模拟盘切面 + P2 质量收敛

> 版本类型: MINOR | 基准: v4.7.0 closeout | 终稿确认: 2026-05-25
> 来源: 两轮自由维度诱错审计 (第1轮 A-E, 第2轮 F-H) 剩余 P2 = 21 项
> 修复基线: S0/S1/P1 已清零, P2-1(无界集合)/P2-13(全量树计数) 已先行修复
> 执行模式策略: 先完成 `PaperSimulated` 与 `PaperActual` 两个模拟盘切面; `LiveSimulated` 与 `LiveActual` 延后

---

## 目标

v4.8.0 先把实盘交易四模式中风险最低、最有教学价值的两个模拟盘切面做实，再消化两轮 8 维诱错审计的全部剩余 P2 发现，把 v4 从"功能完整"推进到"可验证模拟执行 + 测试覆盖充分 + API 格式一致 + 运行时数值安全 + 代码可维护"。

1. **双模拟盘切面** — 完成 `PaperSimulated` 实时模拟盘与 `PaperActual` OKX 模拟盘 API 切面
2. **测试补全** — 补上 v4 runtime / QS 审计 / E2E 的关键测试缺口
3. **API 一致性** — 统一错误响应格式、SSE 格式、路由文档
4. **运行时加固** — 数值安全、输入验证、边界防御
5. **代码质量** — 性能热点、模块拆分、文件安全

## 非目标

- 不接入真实资金执行端
- 不开放 `LiveActual` 真实下单
- 不开放 `LiveSimulated` 真实账户上下文读取
- 不新增 Machine 模板类型
- 不改变 V1 QS 保留面
- 不开放深度 ≥3 嵌套
- P3 项不纳入本版本 (流向持续回归)

## 四模式取舍

| 模式 | v4.8.0 决策 | 数据/成交来源 | 风险说明 |
|------|-------------|---------------|----------|
| `PaperSimulated` | 先完成 | 实时行情 + 本地模拟撮合、余额、手续费、资产曲线 | 不接触 provider 下单接口 |
| `PaperActual` | 先完成 | OKX 模拟盘 API (`x-simulated-trading: 1`, demo flag=1) + provider 回执 | 只允许 OKX 模拟环境, 不允许生产实盘 endpoint / production flag=0 |
| `LiveSimulated` | 延后 | 真实账户上下文 + 本地假设成交 | 需要读取真实账户与仓位, 存在凭证和账户暴露风险 |
| `LiveActual` | 延后 | 真实账户 + provider 真实下单/成交 | 存在真实资金风险, 不进入 v4.8.0 执行端切面 |

执行端命名必须避免把 OKX 模拟盘误写成"实盘"。v4.8.0 中 `live.okx` 只可作为 OKX 模拟盘 provider 通道登记, UI 与日志必须显示"OKX 模拟盘 / 非真实资金"。

OKX 环境标记必须集中在 provider profile 中: production flag=0 只属于延后的真实资金切面; v4.8.0 的 `PaperActual` 固定使用 demo flag=1, REST 固定带 `x-simulated-trading: 1`。

## W0 — 双模拟盘执行切面 (2 天)

### W0-1: PaperSimulated 实时模拟盘

**目标**: 让 v4 `PaperSimulated` 可以消费实时 OKX 行情事件, 在本地 runtime 中完成模拟撮合、订单状态、手续费、持仓和资产曲线。

**边界**:
- 使用 `src-executor/ws_client.rs` 的 OKX testnet / paper 行情事件或现有 OKX paper feed。
- 下单、撤单、改单全部停留在 `qrpc_runtime/src/v4_runtime.rs` 的 `runtime_simulated` 执行能力中。
- `provider_order_submission_attached` 必须保持 `false`。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src-executor/live_runner.rs` | RunnerPool 为 v4 `PaperSimulated` 注入 OKX 实时行情事件 |
| 2 | `qrpc_runtime/src/v4_runtime.rs` | 复用本地模拟撮合, 记录实时行情驱动的 memory snapshot |
| 3 | `frontend-executor/src/components/V4EvidencePanel.jsx` | 明确展示"实时模拟盘 / 本地撮合 / 无 provider 下单" |

**验收**: 执行端启动 v4 `PaperSimulated` → 收到 OKX 行情 → 本地模拟订单进入 acknowledged/filled/rejected 事件流 → evidence 中 `provider_order_submission_attached=false`。

**W0-1 落地状态 (2026-05-25)**:
- 已完成实时行情 -> v4 `PaperSimulated` -> 本地撮合 -> evidence 广播闭环。
- 中间层统一使用 `market.data` 与图元数据 `default_venue_id`; `paper-simulated` 是通用模拟盘 venue, 不再把 OKX 名称写进 runtime/template 中间层。
- OKX 特定逻辑仅保留在数据获取端 `src-executor/ws_client.rs` 与后续执行适配端 `src-executor/okx_rest.rs`。
- 回归覆盖: executor W0-1 闭环测试、qrpc-runtime market tick source 测试、quantscript 图元数据测试、frontend v4 模板边界测试、双前端 build。

### W0-2: PaperActual OKX 模拟盘 API

**目标**: 在无真实资金风险的前提下, 利用现有 OKX 模拟盘 API 完成 provider 回执型模拟盘切面。

**边界**:
- 仅允许 OKX 模拟盘 REST/WS: REST 请求必须带 `x-simulated-trading: 1`。
- OKX SDK/API 环境 flag 必须固定为 demo flag=1; production flag=0 不进入 v4.8.0 执行路径。
- 仅使用模拟盘凭证, UI、日志、审计记录必须标注"OKX 模拟盘 / 非真实资金"。
- 禁止生产实盘 endpoint、禁止真实账户余额/仓位读取、禁止真实资金下单。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src-executor/okx_rest.rs` | 固化模拟盘 header 与环境标识, 暴露订单提交/撤单/查询回执 |
| 2 | `src-executor/main.rs` | 增加 `PaperActual` 模式路由/模式切换, 与现有 `paper/live` 文案解耦 |
| 3 | `src-executor/audit_log.rs` | provider 请求摘要写入审计, 敏感字段脱敏 |
| 4 | `contracts/openapi/root.yaml` | 登记 `PaperActual` 模式、OKX 模拟盘限制和响应结构 |

**验收**: `PaperActual` 模式提交最小限价单 → OKX 模拟盘返回 order id → 查询/撤单成功 → 审计日志记录模拟盘标识 → 不出现生产实盘 endpoint。

### W3-5: V4RuntimeInputEvent.payload serde deny_unknown

**严重度**: P2 | **来源**: 第1轮 A-P2-3 | **文件**: `qrpc_runtime/src/v4_runtime.rs:47-48`

**现状**: `#[serde(default)] pub payload: Value` — 缺失时默认为 Null，不触发反序列化错误。

**方案**: 去掉 `#[serde(default)]`，缺失 payload 时反序列化直接失败。

**受影响的调用方** (必须同步传 `"payload": {}`):
- `src/runtime/run.rs`: `start_v4_runtime_run` → `submit_event` 调用链
- `src-executor/main.rs`: executor SSE 行情转换 → `V4RuntimeInputEvent` 构造
- `qrpc_runtime/src/v4_runtime.rs`: `enqueue_graph_event()` 内部事件构造
- 所有 v4 runtime 测试中构造 `V4RuntimeInputEvent` 的位置

**验收**: 反序列化 `{"event_type":"test","source":"test","ts_ms":0}` → Err; 4 个调用方均已显式传 payload

**方案**: 改为两阶段提交: 先将 5 个文件写入临时目录，全部 `sync_all` 后，原子 rename 临时目录到最终位置。失败时回滚整个临时目录。

**验收**: 模拟崩溃测试 — 不会出现部分更新的图版本

### W4-5: LiveActual 延后切面的构造期安全门禁

**严重度**: P2 | **来源**: 第1轮 A-P2-1 | **文件**: `qrpc_runtime/src/v4_runtime.rs:828-903`

**现状**: `new_for_mode(LiveActual)` 未要求 `venue_matrix` 或 `capability_policy`。v4.8.0 不开放 `LiveActual` 执行端切面, 但必须先把构造期门禁补齐, 防止后续误接真实资金路径。

**方案**: LiveActual 构造时 `capability_policy.is_some()` 为硬要求，缺失时返回 Err。

**验收**: 无 capability_policy 创建 LiveActual runtime → Err

### W4-6: SSE broadcast 慢客户端告警

**严重度**: P2 | **来源**: 第1轮 B-P2-4 | **文件**: `src-executor/main.rs:898`

**现状**: `Err(Lagged(_)) => continue` 静默吞掉。

**方案**: Lagged 时 `eprintln` 告警日志 + 计数器递增，在 v4 evidence 面板展示丢弃事件数。

**验收**: 慢客户端连接 → 日志出现 `[executor] SSE client lagged`

### W4-7: spawn_blocking 加 30s 超时

**严重度**: P2 | **来源**: 第1轮 B-P2-5 | **文件**: `src/auth/mod.rs:385,485`

**现状**: bcrypt spawn_blocking 缺超时。v3.5.0 已规划但未实现。

**方案**: `tokio::time::timeout(Duration::from_secs(30), spawn_blocking(...)).await`。

**验收**: `cargo test auth::tests` — 仍通过
