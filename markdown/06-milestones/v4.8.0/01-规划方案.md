# v4.8.0 规划方案 — P2 全量消化 + v4 质量收敛

> 版本类型: MINOR | 基准: v4.7.0 closeout | 终稿确认: 2026-05-25
> 来源: 两轮自由维度诱错审计 (第1轮 A-E, 第2轮 F-H) 剩余 P2 = 21 项
> 修复基线: S0/S1/P1 已清零, P2-1(无界集合)/P2-13(全量树计数) 已先行修复

---

## 目标

v4.8.0 消化两轮 8 维诱错审计的全部剩余 P2 发现，把 v4 代码质量从"功能完整"提升到"测试覆盖充分 + API 格式一致 + 运行时数值安全 + 代码可维护"。

1. **测试补全** — 补上 v4 runtime / QS 审计 / E2E 的关键测试缺口
2. **API 一致性** — 统一错误响应格式、SSE 格式、路由文档
3. **运行时加固** — 数值安全、输入验证、边界防御
4. **代码质量** — 性能热点、模块拆分、文件安全

## 非目标

- 不新增功能能力 (纯质量收敛)
- 不新增 Machine 模板类型
- 不改变 V1 QS 保留面
- 不开放深度 ≥3 嵌套
- P3 项不纳入本版本 (流向持续回归)

## W3 — 运行时数值安全 (1.5 天)

### W3-1: compute_step_returns prev 有限性检查

**严重度**: P2 | **来源**: 第1轮 C-P2-6 | **文件**: `qrpc_runtime/src/backtest_metrics.rs:311-317`

**现状**: 仅检查 `curr.is_finite()`，不检查 `prev`。INFINITY 作为 prev 时产生 NaN。

**方案**: 增加 `prev.is_finite()` guard，与 `curr.is_finite()` 并列。

**验收**: `cargo test backtest_metrics` — 仍通过；新增 INFINITY prev 测试

### W3-2: Sharpe/Sortino/Calmar 加 annualized_return guard

**严重度**: P2 | **来源**: 第1轮 C-P2-7 | **文件**: `qrpc_runtime/src/backtest_metrics.rs:130,145,153`

**现状**: 三个比率仅检查分母，不检查 `annualized_return` 是否有限。

**方案**: guard 条件增加 `annualized_return.is_finite()`。

**验收**: `cargo test backtest_metrics` — 仍通过

### W3-3: slippage_bps/fee_bps 有限性验证

**严重度**: P2 | **来源**: 第1轮 C-P2-8 | **文件**: `qrpc_runtime/src/v4_runtime.rs:3682-3712`

**现状**: `validate_simulated_order_request` 验证了 price/quantity/limit 等字段，未验证 `slippage_bps` 和 `fee_bps`。

**方案**: 增加 `!is_finite() || < 0.0` 检查。

**验收**: `cargo test -p qrpc-runtime v4_` — 新增 INFINITY slippage 拒绝测试

### W3-4: v4 回测 win_rate 计算

**严重度**: P2 | **来源**: 第1轮 C-P2-9 | **文件**: `src/runtime/backtest.rs:549`, `src/backtest_artifacts.rs:1417`

**现状**: v4 回测 win_rate 硬编码 0.0。v3 从 `wins / total_steps` 计算。

**方案**: 从 v4 资产曲线计算 win_rate = `equity 上升的 bar 数 / 总 bar 数`。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/runtime/backtest.rs` | `build_v4_backtest_output` 中计算 win_rate |
| 2 | `src/backtest_artifacts.rs` | `summarize_equity_curve` 不再覆盖 |

**验收**: v4 回测 → win_rate ≠ 0.0 (有成交时)

### W3-5: V4RuntimeInputEvent.payload serde deny_unknown

**严重度**: P2 | **来源**: 第1轮 A-P2-3 | **文件**: `qrpc_runtime/src/v4_runtime.rs:47-48`

**现状**: `#[serde(default)] pub payload: Value` — 缺失时默认为 Null，不触发反序列化错误。

**方案**: 去掉 `#[serde(default)]`，缺失 payload 时反序列化直接失败。调用方如需可选 payload 显式传 `{}`。

**验收**: 反序列化缺 payload 的 JSON → Err

## W4 — 代码质量与收口 (1 天)

### W4-1: Clone() 热点消除 — machine_spec 借用

**严重度**: P2 | **来源**: 第2轮 H-P2-7 | **文件**: `qrpc_runtime/src/v4_runtime.rs:1600`

**现状**: `machine_spec(&machine_id).cloned()` 在 process_event 内循环中克隆整个 V4MachineContract。

**方案**: 改为返回 `&V4MachineContract` 引用。数据源 `self.graph.machines` 在运行时不可变，借用安全。

**验收**: `cargo test -p qrpc-runtime v4_` — 仍通过；`grep "machine_spec.*cloned" qrpc_runtime/src/v4_runtime.rs` → 0

### W4-2: 大文件读取加大小检查

**严重度**: P2 | **来源**: 第2轮 H-P2-8 | **文件**: `src/backtest_artifacts.rs:1967`, `src/runtime_persistence.rs:380+`

**现状**: 多处 `fs::read_to_string` 直接加载，无大小上限。

**方案**: 读取前 `tokio::fs::metadata` 检查文件大小，拒绝 >100MB 文件，返回 `ERR_FILE_TOO_LARGE`。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src/runtime_persistence.rs` | 新增 `read_file_bounded(path, max_bytes)` |
| 2 | `src/backtest_artifacts.rs` 等 | 替换 `fs::read_to_string` 为 `read_file_bounded` |

**验收**: 尝试加载 >100MB 工件 → 400 + ERR_FILE_TOO_LARGE

### W4-3: v4_runtime.rs 模块拆分

**严重度**: P2 | **来源**: 第2轮 H-P2-10 | **文件**: `qrpc_runtime/src/v4_runtime.rs` (5258行)

**方案**: 拆分为 4 个文件:
- `v4_runtime_types.rs` — 所有 struct/enum 定义
- `v4_runtime.rs` — 核心运行时 (构造/事件循环/transition/snapshot)
- `v4_simulated_execution.rs` — 模拟撮合引擎 (订单/成交/持仓/资产曲线)
- `v4_runtime_tests.rs` — 测试模块

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `qrpc_runtime/src/v4_runtime_types.rs` | 新建，移动类型定义 |
| 2 | `qrpc_runtime/src/v4_runtime.rs` | 保留核心运行时逻辑 |
| 3 | `qrpc_runtime/src/v4_simulated_execution.rs` | 新建，移动模拟执行逻辑 |
| 4 | `qrpc_runtime/src/lib.rs` | 更新 mod 声明 |

**验收**: `cargo test -p qrpc-runtime v4_` — 全部通过；每个文件 <2000 行

### W4-4: 图保存跨文件原子性

**严重度**: P2 | **来源**: 第1轮 D-P2-10 | **文件**: `src/graph_api.rs:414-449`

**现状**: `persist_graph_version` 分阶段提交 5 个文件，非组级原子。

**方案**: 改为两阶段提交: 先将 5 个文件写入临时目录，全部 `sync_all` 后，原子 rename 临时目录到最终位置。失败时回滚整个临时目录。

**验收**: 模拟崩溃测试 — 不会出现部分更新的图版本

### W4-5: LiveActual 构造函数强制 capability policy

**严重度**: P2 | **来源**: 第1轮 A-P2-1 | **文件**: `qrpc_runtime/src/v4_runtime.rs:828-903`

**现状**: `new_for_mode(LiveActual)` 未要求 `venue_matrix` 或 `capability_policy`。

**方案**: LiveActual 构造时 `capability_policy.is_some()` 为硬要求，缺失时返回 Err。

**验收**: 无 capability_policy 创建 LiveActual runtime → Err

### W4-6: SSE broadcast 慢客户端告警

**严重度**: P2 | **来源**: 第1轮 B-P2-4 | **文件**: `src-executor/main.rs:898`

**现状**: `Err(Lagged(_)) => continue` 静默吞掉。

**方案**: Lagged 时 `eprintln` 告警日志 + 计数器递增，在 v4 evidence 面板展示丢弃事件数。

**验收**: 慢客户端连接 → 日志出现 `[executor] SSE client lagged`

### W4-7: spawn_blocking 加 30s 超时

**严重度**: P2 | **来源**: 第1轮 B-P2-5 | **文件**: `src/auth/mod.rs:385,485`

**现状**: bcrypt spawn_blocking 缺超时。v3.5.0 已规划但未实现。

**方案**: `tokio::time::timeout(Duration::from_secs(30), spawn_blocking(...)).await`。

**验收**: `cargo test auth::tests` — 仍通过
