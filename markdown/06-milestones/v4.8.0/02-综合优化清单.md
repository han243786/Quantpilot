## 四模式实施顺序

| 模式 | v4.8.0 状态 | 说明 |
|------|-------------|------|
| `PaperSimulated` | 先完成 | 实时行情进入本地模拟撮合, 不提交 provider 订单 |
| `PaperActual` | 先完成 | 只接 OKX 模拟盘 API, demo flag=1, REST 请求固定 `x-simulated-trading: 1` |
| `LiveSimulated` | 延后 | 需要读取真实账户上下文, 涉及凭证和账户暴露风险 |
| `LiveActual` | 延后 | 真实资金下单风险最高, 不进入 v4.8.0 执行端切面 |

统一命名: 文档、UI、日志、OpenAPI 中不得把 OKX 模拟盘称为真实实盘; 使用"OKX 模拟盘 / 非真实资金"。
统一环境标记: production flag=0 只属于延后的真实资金切面; v4.8.0 `PaperActual` 固定 demo flag=1。

## W3 — 运行时数值安全 (5 项, 1.5 天)

### W3-1: compute_step_returns 未检查 prev 有限性

**严重度**: P2
**来源**: 第1轮审计, 维度C (边界/数值)
**策略**: GP §10.3 (回测指标 — NaN/Inf 不可污染下游)
**问题**: `qrpc_runtime/src/backtest_metrics.rs:311-317` 仅检查 `curr.is_finite()`, 不检查 `prev`。`f64::INFINITY.max(f64::MIN_POSITIVE)` 仍为 INFINITY, 后续除法 `(curr - INFINITY) / INFINITY` 产生 NaN, 传播到所有下游指标。
**方案**:
1. 增加 `prev.is_finite()` guard, 与 `curr.is_finite()` 并列
2. 新增测试: INFINITY prev 输入 → 空 returns vec
**验收**: `cargo test backtest_metrics` — 新增 INFINITY prev 测试通过
**依赖**: W1-2 (QSV 诊断码测试提供回归安全网)
**工时**: 0.2 人日

### W3-2: Sharpe/Sortino/Calmar 未 guard annualized_return

**严重度**: P2
**来源**: 第1轮审计, 维度C (边界/数值)

**方案**: 三个 guard 条件各增加 `&& annualized_return.is_finite()`
**验收**: `cargo test backtest_metrics` — 仍通过; 新增 NaN annualized_return 测试

**策略**: GP §7.2 (存储配额 — 单文件也应受大小限制以防护 OOM)
**问题**: `src/backtest_artifacts.rs:1967`, `src/runtime_persistence.rs:380+`, `src/graph_api.rs:851` 等处 `fs::read_to_string` 直接加载, 无大小上限。恶意工件可致 OOM。

**验收**: 尝试加载 >100MB 工件 → 400 + ERR_FILE_TOO_LARGE
**依赖**: 无

### W4-4: 图保存跨文件原子性不保证

**严重度**: P2
**来源**: 第1轮审计, 维度D (持久化)
**策略**: GP §2.6 (凭证保险库安全 — 原子写入模式应扩展到所有关键写入)
**问题**: `src/graph_api.rs:414-449` 的 `persist_graph_version` 分 5 次顺序 `replace_graph_artifact`, 单文件原子但组不原子。崩溃可能留下部分更新状态。

**验收**: 模拟 kill -9 在写入中 → 无部分更新; 崩溃恢复后 latest.json 指向完整版本
**依赖**: 无
**工时**: 0.2 人日

### W4-5: LiveActual 延后切面缺少构造期安全门禁

**严重度**: P2
**来源**: 第1轮审计, 维度A (逻辑/契约)
**策略**: GP §1.9 (Risk Plane 不可绕过), §1.10 (Execution 能力来源标记)
**问题**: `V4Runtime::new_for_mode(LiveActual)` 仅检查 `risk_plane.required`, 未要求 `venue_matrix` 或 `capability_policy`。v4.8.0 不开放 `LiveActual` 执行端切面, 但构造期门禁必须先 fail-closed, 防止后续误接真实资金路径。
**方案**: LiveActual 构造时增加 `capability_policy.is_some()` 硬检查, 缺失返回 `Err("v4 LiveActual requires capability_policy")`
**验收**: 无 capability_policy 创建 LiveActual → Err
**依赖**: W1-1 (v4 run 测试)
**工时**: 0.1 人日

### W4-6: SSE broadcast 慢客户端静默丢事件

**严重度**: P2
**来源**: 第1轮审计, 维度B (并发)
**策略**: GP §5.2 (禁止静默忽略 — 数据丢失应有告警)
**问题**: `src-executor/main.rs:898` — `Err(Lagged(_)) => continue` 静默吞掉。慢客户端导致的事件丢失对运维不可见。
**方案**:
1. Lagged 时 `eprintln!("[executor] SSE client lagged, {} events dropped", n)` 日志
2. 在 v4 evidence 面板或 executor state 中增加 `sse_lagged_count` 计数器
3. executor health endpoint 暴露计数器
**验收**: 慢客户端连接 → 日志出现 `[executor] SSE client lagged`; health endpoint 含 lagged 计数
**依赖**: W2-2 (SSE 统一)
**工时**: 0.1 人日
