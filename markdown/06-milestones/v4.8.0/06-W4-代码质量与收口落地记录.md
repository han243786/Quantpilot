# W4 代码质量与收口落地记录

## 范围

本轮收口覆盖 v4.8.0 W4 的 7 个 P2 项，目标是把运行时、存档、执行端可观测性和认证阻塞边界固化为可测试行为。

## 已完成

| 项 | 落地内容 |
| --- | --- |
| W4-1 | `v4_runtime` 事件循环不再克隆整份 `machine_spec`，改为借用态预检 execution/cache/memory 写入边界。 |
| W4-2 | 图存档、运行记录、回测工件、历史行情缓存读取加入 100MB 上限，API 面返回 `ERR_FILE_TOO_LARGE`。 |
| W4-3 | `v4_runtime.rs` 拆为主运行时、类型/初始化、模拟执行、测试四个源文件，单文件均低于 2000 行。 |
| W4-4 | 图保存替换路径收拢为 bundle commit，提交前验证 staging 文件齐全，失败时统一逆序回滚已替换文件。 |
| W4-5 | `LiveActual` 构造必须通过显式 execution capability policy，裸 `new_for_mode(..., LiveActual)` fail-closed。 |
| W4-6 | SSE broadcast lag 不再静默吞掉，执行端记录告警并在 health 输出 `sse_lagged_event_count`。 |
| W4-7 | auth 注册、登录、刷新中的 `spawn_blocking` 全部包 30s timeout，超时返回结构化内部错误。 |
