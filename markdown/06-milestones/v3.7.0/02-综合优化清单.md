# v3.7.0 综合优化清单

## P2 — 高优先级 (6项)

### S1: 执行端 vault Zeroizing 对齐测试端

**严重度**: P2
**来源**: R1 S0-4 + R4 #9
**策略**: GP §2.6 (凭证保险库安全)
**问题**: `credential_vault_v2.rs` 的 `CredentialEntry` 使用普通 `String`，进程内存残留明文凭证
**方案**:
1. `CredentialEntry(pub BTreeMap<String, String>)` → `CredentialEntry(pub BTreeMap<String, Zeroizing<String>>)`
2. `ExecutorCredentialVault.key: [u8; 32]` → 实现 `Drop` trait 调用 `zeroize`
3. `get_service()` 返回值改为 `Zeroizing<BTreeMap<String, String>>`
**验收**: `grep -r "Zeroizing" src-executor/credential_vault_v2.rs` 确认使用

### S2: api_guard 从 opt-in 升级为强制验证

**严重度**: P2
**来源**: R1 S0-7 + R4 #8
**策略**: GP §2.7 (实时执行安全边界)
**问题**: `api_guard_middleware` 无签名头时透传，任何本地进程可调用执行端 API
**方案**:
1. 移除透传分支: 无签名头 → `401 Unauthorized`
2. 健康检查 `/api/executor/health` 永久豁免
3. 添加环境变量 `QUANTPILOT_EXECUTOR_INSECURE=true` 用于临时降级(开发/调试)
**验收**: 无签名头 curl POST → 401; `QUANTPILOT_EXECUTOR_INSECURE=true` → 透传

### S3: 执行端策略状态持久化基础框架

**严重度**: P2
**来源**: R1 S0-3 + R4 #7
**策略**: GP §7.1 (存储生命周期)
**问题**: 执行端重启后所有已部署策略丢失
**方案**:
1. `ExecutorState` 新增 `persist(path)` — 将 `strategies` 序列化为 JSON 写入 `storage/.executor-state.json`
2. `ExecutorState::new()` → `load(path)` — 启动时从磁盘恢复
3. 原子写入: tmp + fsync + rename
4. 仅在 `register()`/`start_strategy()`/`stop_strategy()` 时触发持久化
**验收**: 部署策略→重启执行端→GET /strategies 仍返回策略

### S4: audit_log 写入/sync 错误日志化

**严重度**: P2
**来源**: R2 P2-3 + R4 #6
**策略**: GP §5.2 (禁止静默忽略)
**问题**: `let _ = writeln!(...)` 和 `let _ = file.sync_all()` 完全静默
**方案**:
1. write 失败 → `eprintln!("[audit] 写入失败: {}", e)`
2. sync 失败 → `eprintln!("[audit] sync失败: {}", e)`
3. `recent()` 读取失败 → 返回空 `Vec` (已有逻辑, 无需改动)
**验收**: 模拟磁盘满→stderr 可见错误输出

### S5: migration_api 尊重传入执行模式

**严重度**: P2
**来源**: R3 N5
**策略**: 功能完整性
**问题**: `load_strategy` 第97行硬编码 `execution_mode: ExecutionMode::Paper`
**方案**: 从 `pkg.execution_mode` (新增可选字段, 默认 Paper) 读取
```rust
execution_mode: pkg.execution_mode.unwrap_or(ExecutionMode::Paper),
```
**验收**: Live模式策略→部署后 `GET /strategies` 显示 mode=Live

### S6: 执行端 5 处裸 .unwrap() → map_err

**严重度**: P2
**来源**: R4 #5
**策略**: GP §5.2 (禁止静默忽略)
**问题**: list_strategies/get_strategy_detail/get_klines/strategy_events_sse 使用裸 `.unwrap()`
**方案**: 统一改为 `.map_err(|e| (StatusCode::INTERNAL_SERVER_ERROR, format!("锁异常: {}", e)))?`
**验收**: `grep "\.unwrap()" src-executor/main.rs` 返回0 (仅测试/初始化除外)
