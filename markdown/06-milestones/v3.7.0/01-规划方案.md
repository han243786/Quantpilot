# v3.7.0 规划方案 — 五轮诱错遗留消化

> 版本类型: MINOR | 基准: v3.6.0 + 五轮诱错修复 | 目标: 关闭所有 P2/P3 遗留项
> 来源: Round1~5 自由维度诱错 (164→0 S0, 26→0 P1)

---

## 目标

- 消化五轮诱错发现的全部 P2 遗留 (6项)
- 消化全部 P3 遗留 (8项)
- 执行端凭证保险库 Zeroizing 对齐测试端
- api_guard 从 opt-in 升级为强制验证
- 执行端策略状态持久化基础框架

## 非目标

- 不新增功能
- 不改变 API 接口

## 方案

### P2 — 高优先级 (6项)

| # | 来源 | 问题 | 方案 |
|---|------|------|------|
| S1 | R1 S0-4 | 执行端 vault 无 Zeroizing | credential_vault_v2.rs: CredentialEntry 改用 `Zeroizing<String>`, 实现 `Drop` 零化 key 字段 |
| S2 | R1 S0-7 | api_guard Phase 5 未强制 | 移除透传路径: 无签名头时返回 401; health 端点豁免; 添加 `QUANTPILOT_EXECUTOR_INSECURE` 环境变量作为临时降级开关 |
| S3 | R1 S0-3 | 执行端策略状态无持久化 | ExecutorState 新增 `persist()`/`load()`: 策略注册表 → `storage/.executor-state.json`, 原子写入 |
| S4 | R2 P2-2 | audit_log 写入/sync 静默失败 | `append()`: write 失败 → eprintln!; sync 失败 → eprintln!。`recent()` 失败 → 返回空 Vec |
| S5 | R3 N5 | migration_api 所有策略强制 Paper 模式 | load_strategy: 尊重传入的 execution_mode 字段, 不再硬编码 `ExecutionMode::Paper` |
| S6 | R4 #5 | 执行端 5 处裸 `.unwrap()` | list_strategies/get_strategy_detail/get_klines/strategy_events_sse 改用 `.map_err()` |

| # | 验收项 | 标准 |
