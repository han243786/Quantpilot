# v4.2.0 规划方案 — 执行端 v4 集成 + P3 消化

> 版本类型: MINOR | 基准: v4.1.0 | 终稿确认: 2026-05-25
> 来源: v4.0.0 V9 审计 P3 遗留 (3 项) + v4.0.0 规划文档 非目标延期 + 架构自然演进

---

## 目标

v4.2.0 把 v4 运行时从"本地独立沙盒"升级为"可接入真实行情和部署管道的执行端子系统"。

1. **执行端集成 v4 runtime** — v4 策略可通过执行端 :3001 部署/启动/停止，接收 OKX 行情驱动
2. **消化 v4.0.0 V9 审计 P3** — 锁内 I/O 消除、执行端版本横幅修正
3. **v4 执行端监控 UI** — 执行端前端展示 v4 状态机证据

核心变化:

- `V4PaperSimulatedRuntime` 不再只能通过 `/api/runtime/v4/run` 本地启动，通过执行端的 `RunnerPool` 管理生命周期
- v4 ObservationMachine 可消费 OKX WebSocket 行情事件
- 执行端前端新增 v4 证据面板，与主前端 `V4RuntimeEvidencePanel` 对应

## 非目标

- 不在 v4.2.0 开放嵌套状态机
- 不实现 v4 回测 (流向 v4.3.0)
- 不改变 OKX testnet 下单路径 (仍经过 Risk Plane)
- 不新增订单能力类型
- 不把 v4 runtime 设为默认运行时 (v3.7.1 路径仍为主路径)

## W1 — 执行端 v4 集成 (3 天)

### W1-1 RunnerPool 支持 v4 runtime

**文件**: `src-executor/live_runner.rs`, `qrpc_runtime/src/v4_runtime.rs`

**方案**: `RunnerPool` 新增 `V4Runner` 变体，封装 `V4PaperSimulatedRuntime`。策略部署时根据编译产物的 `runtime_kind` 选择 v3 或 v4 runner。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src-executor/live_runner.rs` | RunnerPool 增加 `spawn_v4_runner()` |
| 2 | `qrpc_runtime/src/v4_runtime.rs` | V4PaperSimulatedRuntime 实现 `Runner` trait |
| 3 | `src-executor/executor_state.rs` | ExecutorState 增加 v4 runtime kind 标识 |

**约束**: GP §1.6 (顶层 DAG 保留), GP §10.3 回归 (v3 runner 不受影响)
**验收**: 部署 v4 QS 策略到执行端 → RunnerPool 创建 v4 runner → 状态为 Active

### W1-2 OKX 行情驱动 v4 ObservationMachine

**文件**: `src-executor/ws_client.rs`, `qrpc_runtime/src/v4_runtime.rs`

**方案**: OKX WebSocket 行情事件转换为 v4 `Market` 事件域 (price_tick/bar_closed/orderbook_updated)，通过 `submit_event()` 注入 v4 runtime。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src-executor/ws_client.rs` | 行情数据 → `V4RuntimeInputEvent` 转换 |
| 2 | `qrpc_runtime/src/v4_runtime.rs` | `submit_event()` 支持 Market 事件域 |

**约束**: GP §1.8 (事件驱动迁移), GP §2.7 (实时执行安全)
**验收**: 执行端连接 OKX testnet → v4 ObservationMachine 收到 price_tick → 触发 transition

### W1-3 执行端 v4 策略部署 API

**文件**: `src-executor/main.rs`

**方案**: 执行端现有 deploy/start/stop 端点兼容 v4 策略。

| 步骤 | 文件 | 改法 |
|------|------|------|
| 1 | `src-executor/main.rs` | deploy 端点接收 v4 graph/QS source |
| 2 | `src-executor/executor_state.rs` | 策略元数据增加 `runtime_version: "v3" | "v4"` |

**约束**: GP §4.4 (API 路由变更)
**验收**: `POST /api/executor/strategies` 部署 v4 QS → `POST /api/executor/strategies/:id/start` → 策略运行

### W1-4 v4 executor evidence 投影

**文件**: `qrpc_runtime/src/v4_runtime.rs`

**方案**: v4 runtime 通过执行端 SSE 推送 `memory_snapshot` 事件，结构兼容主前端 `v4RuntimeEvidence.js`。

**验收**: 执行端 SSE 事件流包含 `v4RuntimeMemorySnapshot` → 前端可渲染

## 兼容性与迁移

- **v3 执行端兼容**: `RuntimeKind::V3` 仍为默认值；既有迁移包不携带 `runtime_kind` 时继续走 v3 `LiveRunner`，deploy/start/stop API 语义不变。
- **v4 执行端 opt-in**: 只有请求声明 `runtime_kind/runtime_version = "v4"`、或显式携带 v4 `graph/source` 时，执行端才创建 v4 runner。
- **持久化兼容**: executor 状态文件新增 `runtime_kind` 字段；旧状态文件缺字段时按 v3 读取，避免旧部署无法恢复。
- **行情兼容**: OKX Paper `WsEvent` 仍先服务 v3 runner；v4 runner 只订阅匹配 symbol 或空订阅策略，不改变 v3 行情分发。
- **SSE 兼容**: 既有 trigger 事件保持原格式；v4 策略额外收到 `v4RuntimeMemorySnapshot` 事件，旧前端可忽略未知事件。
- **真实下单边界**: v4.2.0 仅接入 PaperSimulated runner 和 runtime_simulated evidence，不改变 OKX testnet provider-native 下单路径。
