# QuantPilot 测试体系优化清单

> 基于 P0~P3 全链路实施 + 极限压力测试 + 回测成交调参过程中暴露的全部问题

---

## P0 — 阻塞性缺陷（必须修）

### P0-1 QS 编译路径回测不产生成交

**现象**：TestRunner 使用 `lower_script_to_runtime_config()` 内部编译，产出的 `CompiledRuntimeProtocol` 送入 `FastBacktestSandbox` 后 `total_fills = 0`。而 Graph 路径（`POST /api/runtime/compile` → `POST /api/runtime/backtest`）使用相同沙箱却有 5 fills。

**根因**：QS lowering 产出的 intent 类型（`IntentKind::LongTermBuy`）与 Graph 模块（`builtin.intent.double_ma`）的信号链路不同，执行层过滤行为有差异。

**影响**：所有 .qs 场景文件回测步骤的 `total_fills`、`trade_count` 恒为 0，`total_return_pct` 恒为 0%，参数修改前后结果完全一致。

**修复方向**：让 TestRunner 走 `POST /api/quantscript/formal/compile` → `POST /api/runtime/backtest` 完整 API 链路，复用已验证可产生成交的 Graph 后端路径。

| 文件 | 改法 |
|------|------|
| `src/test_runner.rs` | `compile_strategy()` 改为调用 `compile_formal_quantscript_request` 的内部逻辑，产出 `FrontendRuntimeConfig` 后再走 `execute_backtest_request` |
| `src/test_runner.rs` | `execute_run()` 同样改为使用 `FrontendRuntimeConfig`→`map`→`compile`→`RealTimeSandbox` 路径 |

---

### P0-2 `market_state_for()` fallback 零流动性

**现象**：当 exchange/symbol 在 `MarketState` map 中不存在时，返回 `buy_liquidity: 0.0, sell_liquidity: 0.0`。

**根因**：硬编码的 fallback。P0 中已修复的 `quote_price_map()` Kline 盲视问题掩盖了这一缺陷——只要 quote_map 被填充，订单就是 MARKET 类型，绕过了流动性检查。但如果未来有人使用纯 LIMIT 订单策略或引入新的订单类型，这个 fallback 会再次导致零成交。

**影响**：任何依赖 LIMIT 订单的策略在无 Quote 数据时全部失败。

**修复方向**：

| 文件 | 改法 |
|------|------|
| `qrpc_runtime/src/fill_engine.rs:403-417` | `market_state_for()` 的 fallback 从 `liquidity: 0.0` 改为使用 `fallback_price * days * 0.1` 或类似的合理默认值 |
| 或 | 当 liquidity 为 0 时，`executable_qty()` 对所有订单类型返回 `order.quantity`（等同于 MARKET） |

## P1 — 数据质量（修复后回测才具备分析价值）

### P1-1 Mock 数据无真实波动率

**现象**：`mock_raw_klines()` 生成完全线性价格序列，前 100 天 +20/天，后 100 天 +250/天，无跳空、震荡、盘整。

**影响**：所有参数组合产生完全一致的 5 次成交、-0.0999% 收益。参数扫描完全无区分度。

**修复方向**：

| 子项 | 文件 | 改法 |
|------|------|------|
| P1-1a 随机波动 | `qrpc_runtime/src/data_module.rs:mock_raw_klines()` | 在价格中加入基于 seed 的随机波动（±2%） |
| P1-1b 多阶段行情 | 同上 | 生成 3~5 段不同趋势（上涨/下跌/震荡/跳空）的行情拼接 |
| P1-1c 可配置 volatility | 同上 | 接受 `volatility: f64` 参数控制波动幅度 |

### P1-2 Mock 不产出 Quote 数据

**现象**：确定性回放只注入 `NormalizedMarketData::KlineSeries`，从不产生 `Quote`。

**影响**：执行模块 `quote_price_map()` 在 P0 修复前完全空。P0 修复后从 Kline close 提取价格作为回退，但这只提供了 mid_price，缺少 bid/ask spread。

**修复方向**：

| 文件 | 改法 |
|------|------|
| `qrpc_runtime/src/data_module.rs` | `mock_kline_bars_for_backtest()` 额外产出 `NormalizedMarketData::Quote`，包含基于 Kline OHLC 推算的 bid/ask |

## P2 — 指标完整性（让回测报告有分析价值）

### P2-1 `sharpe` / `turnover_ratio` / `fee_drag_ratio` 永远为 0

**现象**：`FastBacktestSandbox::run_backtest()` 中 `BacktestSummary` 的 `turnover_ratio`、`average_trade_notional`、`fee_drag_ratio` 被硬编码为 `0.0`。这些值需通过 `backtest_artifacts.rs` 的 `summarize_equity_curve()` 后处理才填充，但 TestRunner 读取的是原始 `BacktestOutput.summary`。

**影响**：回测报告中缺失夏普比率、换手率、手续费占比等关键绩效指标。

**修复方向**：

| 文件 | 改法 |
|------|------|
| `src/test_runner.rs:execute_backtest()` | 在 `run_backtest()` 之后调用 `backtest_artifacts` 层的 `summarize_equity_curve` 等价逻辑，或遍历 sessions 手动计算 turnover/fee_drag |
| 或 `qrpc_runtime/src/sandbox.rs:run_backtest()` | 将 `turnover_ratio` / `fee_drag_ratio` 的计算前移到沙箱内部 |

### P2-2 `net_profit` 未扣减手续费

当前 `summary.net_profit = final_equity - initial_equity`，已隐含手续费影响（因为 `final_equity` 来自 `cash_balance + net_notional`，cash_balance 已扣除手续费）。但缺少显式的 `total_fees_paid` 指标。

**修复方向**：在 TestRunner 的 `execute_backtest()` 中遍历 `sessions[].fill_reports`，累加 `fee_paid` 字段。

## P3 — 断言能力增强（让 @test 能表达复杂验证）

### P3-1 不支持跨指标比较

当前 `@assert` 语法只支持 `backtest.metrics.<name> <op> <literal>`，无法表达：
- `backtest.metrics.initial_equity == backtest.metrics.final_equity`
- `backtest.metrics.net_profit > backtest.metrics.total_fees_paid`

**修复方向**：

| 文件 | 改法 |
|------|------|
| `src/test_runner.rs:evaluate_assert()` | 支持 `<name> <op> <name>` 双指标比较语法 |
| `quantscript/src/test_plan.rs` | `TestActionDef::Assert` 从 `String` 升级为结构化 `AssertExpr` |

### P3-2 不支持组合断言

无法表达 AND/OR 组合条件：
```
@assert run.equity > 0 && run.events.length > 0
```

**修复方向**：`evaluate_assert()` 增加 `&&` / `||` 解析和短路求值。

### P3-3 不支持浮点容差

`==` 比较使用 `f64::EPSILON` 容差，但金融场景需要可配置的小数精度。

**修复方向**：支持 `==(0.001)` 语法指定容差。

## P4 — TestRunner 功能缺口

### P4-1 缺少 `@wait` 实际实现

`@wait { condition: "run.status == completed", timeout: 120s }` 目前直接跳过。需要实现异步轮询等待。

**修复方向**：

| 文件 | 改法 |
|------|------|
| `src/test_runner.rs:execute_step()` | `TestActionDef::Wait` 分支实现轮询循环，调用 `tokio::time::sleep` + 条件检查 |
| 需要 | 将 `execute` 从同步改为真正的 async，或使用 `tokio::spawn` |

### P4-2 缺少回测比较

`@compare` / `@backtest_compare` 指令不存在。无法在单场景内"运行两次回测并比较指标"。

**修复方向**：新增 `TestActionDef::CompareBacktests { left: String, right: String }`，在 TestRunner 中保存多次回测结果并按索引比较。

### P4-3 缺少 historical_replay 支持

`@backtest` 的 `source` 参数接受 `"historical_replay"` 但 TestRunner 未处理该路径。且缺少本地数据文件引导（需先执行 `fetch` 缓存历史数据）。

**修复方向**：实现 `BacktestSource::HistoricalReplay` 分支，并增加数据准备步骤。

### P4-4 缺少可配置回测参数

`@backtest` 的 `start`/`end`/`seed` 参数接受但不传递给沙箱。seed 始终为硬编码的 `BACKTEST_TEST_SEED = 7`。

**修复方向**：将 `@backtest { seed: 42 }` 中的 seed 值覆盖 `BACKTEST_TEST_SEED`。

## P5 — 前端测试增强

### P5-1 模块面板搜索不支持 data-testid 精确匹配

当前 `dragModuleToCanvas(page, "klines")` 查找 `getByTestId("module-card-klines")`，但实际模块 key 可能不匹配（如 `data_kline` vs `klines`）。

**修复方向**：在 Playwright 测试中先通过 test bridge 获取实际模块 key 列表，动态匹配。

### P5-2 缺少前端视觉回归测试

当前截图仅用于人工检查，无像素级回归检测（pixelmatch）。

**修复方向**：新增 `tests/e2e/visual-regression.spec.js`，在 CI 中使用 `expect(page).toHaveScreenshot()` 进行基线对比。

### P5-3 缺少性能基准测试

无首屏加载时间、画布渲染帧率、事件流处理延迟的基准和断言。

**修复方向**：利用已有的 `playwright.perf.config.js` 和 `perf-*.spec.js`，添加 CI 中的性能回归阈值断言。

---

## P6 — CI / 运营

### P6-1 CI workflow 未经真实验证

`scenario-test.yml` 已编写但从未在 GitHub Actions 上实际运行过。

**修复方向**：将 workflow 推送到 `main` 分支，触发首次运行，修复所有环境差异问题。

### P6-2 缺少夜间回归趋势图

每日定时运行的测试结果未被收集为时间序列，无法检测性能或通过率的渐变退化。

**修复方向**：在 CI 中将 TestReport JSON 上传到 artifact store，附加日期标签，用简单的 CSV 或 JSON Lines 累积。

### P6-3 后端重启后状态丢失

当前测试依赖后端运行时的内存状态（之前测试的 graph/runs 等）。后端重启后首次测试需要预热步骤。

**修复方向**：在 `run-all-scenarios.sh` 中添加预热步骤（调用 `POST /api/graphs/save` 创建基础策略图）。

---

## P7 — 文档与可发现性

### P7-1 `.qs` 文件语法无校验提示

用户编写 .qs 文件时只能通过提交到 API 看错误信息。无本地 lint/check 工具。

**修复方向**：新增 `tools/check-qs.js`，调用 `POST /api/test/scenario/run` 但仅做解析+编译验证（dry-run）。

### P7-2 测试指南与脚本化场景未同步

`实机场景化测试指南.md` 中 118 个步骤与 `tests/scenarios/*.qs` 文件之间的映射未写入文档，用户不知道哪些步骤已自动化。

**修复方向**：在测试指南的覆盖率比对表中新增"自动化状态"列，标注每行是 QS / Playwright / 人工。
