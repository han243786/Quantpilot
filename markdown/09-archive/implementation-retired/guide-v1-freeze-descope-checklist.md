# V1 冻结 / 范围排除检查清单

本文档定义了保留的 `V1` 面和显式的范围排除边界。如果某个任务未在下方显式保留，则将其视为延迟而非当前阶段中的未完成工作。

## V1 目标

以诚实、狭窄、有测试保护的产品面收尾当前阶段：

- 正式 QuantScript 主干保持显式且有界
- 稳定的共享核心切片在各入口点间保持对齐
- 结构化诊断替换明显的纯字符串失败路径
- `risk.profile(...)` 和 `execution.profile(...)` 将复杂性保持在主策略语法之外
- 第一个可执行 `P4` 切片可通过工件、详情视图、列表摘要和比较/报告工作流进行查看和比较

## V1 中保留

### 1. QuantScript 主干和共享核心

- 仅保留正式 QuantScript 稳定主干
- 已落地的共享核心切片：
  - 直接 MA 比较
  - 单侧 `RSI`
  - 单侧 `momentum`
  - 单侧 `zscore`
  - 第一个窄价差切片
- 已落地切片的跨入口等价护栏
- 解析器接受但不受支持的构造的显式早期失败行为

### 2. 结构化诊断

- 已落地的稳定辅助函数/输入合约的 `QPQSLOW` 结构化失败
- 代表性编译侧和降级侧失败的 golden-like API 响应形态覆盖
- 被接纳窄切片的正式价差拒绝 golden-like 覆盖

### 3. 向外移动的 profile 复杂性

- `risk.profile("global")`
- `execution.profile("paper")`
- 保持两个合约狭窄；在 `V1` 期间不要将它们扩展为通用 DSL

### 4. 第一个可执行 P4 切片

- 回测假设：
  - `fee_bps`
  - `slippage_bps`
  - `latency_ms`
- 覆盖优先级：
  - `请求覆盖 > profile 默认值 > 后端回退`
- 假设模块的工件/详情/列表可见性
- 比较/报告工作流支持：
  - `execution_assumptions`
  - `metrics`
  - `trade_ledger`
  - `equity_curve`
- 当前更丰富的指标切片：
  - `net_profit`
  - `turnover_ratio`
  - `average_trade_notional`
  - `fee_drag_ratio`

## V1 后延迟

这些项目被显式延迟。除非新的合约审查重新打开它们，否则不要让它们重新进入活跃收尾说明。

### 1. 共享核心和语言扩展

- `MACD` 共享核心扩展
- 更广泛的价差合约：`ratio`、`absolute`、双侧价差、线对线价差
- 任意用户定义指标 DSL
- 任意比较器 DSL
- 当前主干之外的通用语言特性

### 2. 风险和执行扩展

- 通用风险 DSL
- 通用执行 DSL
- `broker.profile(...)` 扩展超出单独批准的最小合约
- 策略本地延迟脚本
- 交易所特定费用表系统

### 3. 回测和报告扩展

- 逐交易比较
- 成交时间线比较
- 完整时间线比较 UI
- 概率滑点
- 市场冲击模拟
- 订单簿模拟
- 需要新合约审查的更广泛交易结果分析：
  - `winning_trade_count`
  - `losing_trade_count`
  - `average_trade_return`
- 更广泛的比较/报告 DSL 行为

## 阶段收尾前删除或压缩

### 1. 删除重复的真实数据源

- 移除重复工件真实数据的旧比较/报告形态
- 移除从已统一模块重新推导假设、指标、交易台账或权益曲线摘要的辅助逻辑
- 在新的统一模块成为权威后，移除保留过时比较/报告期望的测试
- 在 `V1` 之后，从保留的双重 `report_narrative` / `compare_report` 面迁移到 `compare_report` 作为唯一外部报告真实数据；有序清理见 [Compare Report V1 后迁移检查清单](./guide-compare-report-v1-post-migration-checklist.md)

### 2. 压缩活跃规划文档

- 将已完成的任务移出活跃收尾文档
- 将阶段完成的切片压缩为简短的声明性状态要点
- 停止将已落地的工作列示为仍然是下一步任务

### 3. 保持一个权威措辞路径

- 比较/报告措辞应来自统一的比较/报告模块
- 文档应区分当前实现事实与延迟工作
- 提示和产品措辞不应将延迟的能力提及其为近期工作

## V1 退出检查清单

仅在以下所有条件满足时，才将 `V1` 视为阶段收尾：

1. 活跃文档不再将延迟工作呈现为当前实现。
2. 活跃收尾文档已压缩，仅包含未完成的工作。
3. 工件、详情、列表和比较/报告视图都指向相同的假设/指标/交易台账/权益曲线真实数据模块。
4. 比较/报告合约有稳定的 API 或工件护栏覆盖。
5. 没有延迟的能力静默暴露在文档、提示或 UI 措辞中。
6. UTF-8 检查在定义保留的 `V1` 面的活跃文档上通过。

## 冻结后操作规则

`V1` 冻结后：

- 在保留面内进行优化和清理
- 在没有新的书面合约审查的情况下，不要扩大保留的合约
- 将延迟项目视为后续阶段的开始，而非遗留的待办事项
