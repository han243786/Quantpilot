# 价差最小合约

本文档定义了 `spread(...)` 的第一个诚实产品合约。

它不定义通用的套利 DSL。它不授权广泛的多元指标增长。它仅冻结值得推进到共享核心设计中的最窄价差语义。

## 目的

当前代码库已有部分价差相关机制：

- 前端/运行时模块锚点：`builtin.intent.spread_observer`
- 编译时字段，如 `max_time_diff_ms`、`align_direction_code`、`field_code` 和 `spread_output_code`
- 运行时降级已经可以构建双输入 `SpreadSpec`

仍然缺少的是显式的产品边界。本文档就是那个边界。

## 最小产品目标

第一个价差合约有意保持狭窄：

- 恰好两个输入
- 显式的 as-of 时间对齐
- 一个单一的可观察价差输出
- 一个单一的阈值风格共享核心条件形态

任何更广泛的内容在以下入口点间稳定之前保持范围外：

- 正式 QuantScript
- 图/运行时编译
- Strategy IR

## 第一个被接纳的切片

值得作为共享核心候选的第一个价差切片是：

- `以 bps 为单位的双输入对齐价差输出`
- 以 `单侧阈值` 形式使用

规范示例：

```text
spread(
  align_asof(left, direction="backward", tolerance_ms=1000),
  align_asof(right, direction="backward", tolerance_ms=1000),
  output="bps"
) > 5
```

为什么此切片优先：

- 它已匹配当前面向运行时的 `SpreadSpec` 形态
- 对于第一个产品化的合约，`bps` 比任意比率数学更容易解释
- 单侧阈值条件适合当前单侧 `RSI`、`momentum` 和 `zscore` 使用的相同共享核心方向

以下不是第一个切片：

- 直方图风格的价差变换
- 任意价差算术
- 双侧合并价差规则
- 三腿或 N 腿套利表达式
- 在价差表达式本身中编码的场地路由策略

## 时间对齐策略

价差语义仅在对齐策略显式且有界时才是可接纳的。

最小对齐策略是：

- 连接模式：`asof`
- 必需方向：`backward`、`forward` 或 `nearest` 之一
- 必需容差：`max_time_diff_ms`
- 如果在容差内不存在对应观测值，价差样本缺失

产品规则：

- 不要静默将不匹配的时间戳视为零
- 不要静默将观测值向前结转到声明的容差之外
- 在描述产品合约时，不要将对齐方向隐藏在辅助函数默认值后面

当前建议的第一个策略：

- 默认方向：`backward`
- 产品示例和测试中需要显式容差

这使第一个合约保持诚实，并匹配当前面向运行时的 `AlignAsofSpec` 形态。

## 输出策略

运行时降级路径已识别多个输出编码，但产品合约不应在第一天平等暴露所有编码。

当前输出词汇表：

- `absolute`
- `ratio`
- `bps`

第一个被接纳的共享核心切片是：

- `bps`

其他输出保持实现辅助性质，但还不是第一类共享核心承诺。

理由：

- `bps` 是跨市场或跨来源分歧的最简单第一单位
- 它避免了在合约冻结之前过度承诺比率规范化语义

## 跨入口合约

仅当相同语义形态可以在所有三个入口点间诚实地表达时，第一个价差切片才被视为真正的产品能力。

### 正式 QuantScript

正式 QuantScript 现在为第一个切片接纳相同的窄辅助函数形式：

```qs
if spread(
    align_asof(left, direction="backward", tolerance_ms=1000),
    align_asof(right, direction="backward", tolerance_ms=1000),
    output="bps"
) > 5 {
    emit Intent("BUY", instrument="BTCUSDT", quantity=1.0)
}
```

### 图/运行时编译

图/运行时编译是当前价差合约的锚点，因为它已携带：

- 两个显式输入
- `align_direction_code`
- `max_time_diff_ms`
- `spread_output_code`

对于第一个切片，图/运行时编译应保持可执行形态的真实数据源。

### Strategy IR

Strategy IR 应仅接纳相同的窄价差切片。

在产品合约稳定之前，它不应为价差发明更广泛的条件语言。

## 价差共享核心接纳规则

价差仅在以下所有条件成立时，才应移动到与直接 MA 比较或单侧 `RSI` / `momentum` / `zscore` 相同的共享核心通道：

1. 相同的双输入对齐 `bps` 价差可以在正式 QuantScript、图/运行时编译和 Strategy IR 间表达。
2. 由此产生的条件降级到一个稳定的 Core IR 形态。
3. 合约不再依赖临时匹配器恢复作为其主要快乐路径。
4. 对齐策略已固定并有测试覆盖。
5. 跨入口等价测试可以锁定相同的语义条件形态。

在此之前，价差仍然是受保护的中期项目，而非近期的共享核心承诺。

## 明确范围外

第一个价差合约不包括：

- 动态场地选择
- 跨超过两个来源的最优腿搜索
- 跨交易所路由策略
- 通用套利策略 DSL
- 自定义价差数学函数
- 用户定义的价差比较器
- 多窗口价差状态机
- 对类似 `MACD` 的价差衍生品的隐含支持

## 当前实现事实

当前代码状态应诚实描述：

- 图/运行时编译已具有具体的双输入价差运行时形态
- 第一个仅图/运行时切片现已针对 `bps` 加单侧阈值落地，并降级到结构化比较，而非停留在原始条件文本
- 该图/运行时切片现在也以显式编译合约失败的方式拒绝非 `bps` 输出、非正容差和非单侧阈值元数据
- 编译器/运行时代码已经可以构建 `SpreadSpec`
- Strategy IR 现在也接纳相同的窄双输入 `bps` 单侧阈值切片，并将其降级为带有显式拒绝护栏的结构化比较
- 图/运行时和 Strategy IR 现在也有针对相同窄切片的跨入口等价护栏，因此两个落地入口点必须保持降级到相同的 Core IR 条件形态
- 正式 QuantScript 现在是相同窄价差切片的第三个落地采纳者
- 正式 QuantScript 现在将该被接纳的辅助函数形式降级到图/运行时和 Strategy IR 使用的相同结构化价差比较
- 图/运行时、Strategy IR 和正式 QuantScript 现在有针对相同窄切片的三入口等价护栏
- 格式错误的价差辅助函数形态已作为结构化 `QPQSLOW001` 浮出，而非泄漏通用辅助函数错误
- 正式 QuantScript 价差拒绝路径现在也有针对非 `bps`、缺少 `align_asof(...)`、非正 `tolerance_ms` 和非单侧阈值形态的 golden-like API 响应形态覆盖

这意味着第一个窄价差通道现已跨所有三个入口点落地，但价差仍然不是通用的套利 DSL 或广泛的多元共享核心特性。

对于当前路线图，`P3` 现在可被视为此第一个窄价差切片的阶段完成。

## 下一个实现顺序

当价差工作恢复时，顺序应为：

1. 保持此合约狭窄
2. 仅实现双输入 `bps` 单侧阈值切片
3. 使图/运行时编译成为该切片的可执行真实数据源
4. 在 Strategy IR 中添加匹配的窄入口支持
5. 保持图/运行时与 Strategy IR 等价测试到位
6. 只有在那之后才评估 `ratio` 或 `线对线` 风格价差条件是否值得扩展

## 使用规则

不要将价差描述为通用的套利语言特性。

在第一个窄切片在所有三个入口点间稳定之前，不要在 UI、提示或文档中暴露更广泛的价差声明。
