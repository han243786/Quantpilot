# 自由维度诱错审计 — v4.4.0 第 1 轮

> 执行日期: 2026-05-25  
> 审计对象: 嵌套状态机第一波  
> 审计方式: Codex 主线程 5 维并行诱错  
> 结论: **无 S0**。发现项均已在本轮实现中消化或由既有门禁覆盖。

## 一、审计范围

| 维度 | 主题 | 重点问题 | 结论 |
|---|---|---|---|
| A | 类型契约 | `MachineState.child_machine` 是否破坏旧扁平 graph、是否允许三级嵌套 | 无 S0；深度 >2 拒绝，旧字段缺省兼容 |
| B | QS 静态审计 | state 内嵌套 machine 是否被接受，state 外嵌套是否继续拒绝 | 无 S0；新增 `QSV4118` 深度超限诊断 |
| C | runtime 路由 | 父/子 machine 同事件匹配时是否存在不确定优先级 | 无 S0；父 transition 优先，子 machine 仅在父未匹配时处理 |
| D | 证据与回放 | memory snapshot / backtest trajectory 是否保留子 machine 证据 | 无 S0；snapshot 层级化，trajectory 扁平展开 active child |
| E | UI / 治理 | evidence 面板、复杂度预算、OpenAPI、全量树和版本门禁是否同步 | 无 S0；新增复杂度预算面板并更新同步文档 |

## 二、已消化风险

| 风险 | 处理 |
|---|---|
| 子 machine 与父 machine 复用 id 导致 runtime state 覆盖 | Core IR 静态契约拒绝父子重复 id，并在全图范围检查 top-level / nested 重复 |
| 子 machine 模板与父模板不一致导致事件源边界漂移 | Core IR 与 QS audit 均要求 child machine template 与 parent template 一致 |
| 嵌套后事件目录漏收 child transition event | `validate_event_catalog` 与 QS catalog 推导遍历 machine family |
| runtime 同事件父子同时触发导致行为不稳定 | `transition_candidate_for_machine` 先匹配父 transition，再进入 active child |
| 前端只展示顶层 machine，用户看不到实际运行状态 | evidence projection 递归 normalize `children`，UI 递归展示层级 |
| 复杂度预算不可见 | runtime snapshot 输出 `complexity_metrics`，前端显示预算使用率和状态 |

## 四、结论

本轮未发现阻断 v4.4.0 继续 closeout 的 S0。嵌套状态机保持 beta 能力边界：最大深度 2、同模板子 machine、无跨父通信、无默认模板暴露。
