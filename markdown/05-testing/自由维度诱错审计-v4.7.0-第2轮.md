## P1 高 (已修复)

### P1-1: 速率限制器未安装 ConnectInfo — 全局共享桶

**严重度**: P1
**来源**: G — 安全深潜
**文件**: `src/rate_limiter.rs:99-119` + `src/lib.rs:971`
**违反条款**: GP §2.8

**问题**: `axum::serve(listener, app)` 未调用 `into_make_service_with_connect_info::<SocketAddr>()`。`request.extensions().get::<ConnectInfo<SocketAddr>>()` 始终返回 `None`，所有请求共享 `"unknown"` 单一令牌桶。100 RPS 限制作用于全局而非每 IP。认证 6次/分钟的限流也共享同一桶——6 次失败后整个系统登录被阻塞。

**修复建议**: 改为 `axum::serve(listener, app.into_make_service_with_connect_info::<SocketAddr>())`。

## P2 中 (v4.8.0 前修复)

### P2-1: v4 runtime event_log/orders/fills 无界增长

**来源**: H | **文件**: `qrpc_runtime/src/v4_runtime.rs:816,567-568`
**问题**: `event_log.push()` 永不裁剪。大回测 (10000 bar) 可累积百万条事件。`orders` 和 `fills` 同样无限制。对比: `asset_curve` 已正确 cap 在 256 条。
**修复**: 增加 event_log/orders/fills 上限 (如 10万/1万/1万)，或回测完成后清理。

### P2-2: start_v4_runtime_run 零功能测试

**来源**: F | **文件**: `src/runtime/run.rs:43-87`
**问题**: v4 runtime 启动端点有 6 个错误路径 (冲突/静态契约失败/handoff拒绝/缺graph/缺source/缺event catalog)，无一有测试。tests/api_run.rs 仅测试 v3 路径。
**修复**: 新增 `tests/api_run.rs` v4 测试覆盖全部错误路径 + 一条成功路径。

### P2-3: QS 静态审计诊断码覆盖率仅 11%

**来源**: F | **文件**: `quantscript/src/v4_static_audit.rs`
**问题**: ~35 个 QSV4xxx 诊断码，仅 4 个有显式测试 (QSV4105, QSV4117, QSV4118, QSV4300)。其余 31 个仅在 SAMPLE_V4_QS 解析中附带触发，无人为构造的针对性测试。
**修复**: 每个诊断码至少一个测试用例，故意构造无效输入触发特定码。

### P2-4: E2E 缺 auth/v4策略/v4回测 用户旅程

**来源**: F | **文件**: `frontend/tests/e2e/`
**问题**: 无登录/注册/令牌刷新 E2E；无 v4 QS 策略编写→编译→运行 E2E；无 v4 回测 E2E。所有 API E2E 使用 Mock，无真实后端集成。10 个 spec 中 3 个 test.skip。
**修复**: 补 auth flow、v4 策略 authoring、v4 回测 E2E。至少一个 spec 对接真实后端。

### P2-5: API 错误响应格式不一致 — auth 缺少 error_code

**来源**: H | **文件**: `src/auth/mod.rs:341-433` vs `src/api_errors.rs:1-116`
**问题**: register/login/refresh 的错误响应缺少 `error_code` 和 `details` 字段，而 runtime/compile/v4-run 均使用标准格式 `{"error","error_code","message","details"}`。
**修复**: auth handler 改用 `json_bad_request_with_code`。

### P2-6: SSE 格式不一致 — event: 字段 vs payload type 字段

**来源**: H | **文件**: `src/runtime/run.rs:478-498` vs `src-executor/main.rs:824-923`
**问题**: 主后端 SSE 用 `Event::default().event(name)` 设 SSE event 字段；执行端 SSE 用 `Event::default().data(json)` 把类型嵌入 payload 的 `"type"` 字段。前端需处理两种格式。
**修复**: 统一为一种格式。

### P2-7: Clone() 热点 — process_event 中 machine_spec 全量克隆

**来源**: H | **文件**: `qrpc_runtime/src/v4_runtime.rs:1600`
**问题**: `process_event` 内循环对每个候选 transition 执行 `machine_spec(&machine_id).cloned()` 克隆整个 V4MachineContract (含全部 states/transitions/memory)。154 处 `.clone()` 调用遍布 v4_runtime.rs。
**修复**: 替换为借用引用；V4MachineContract 存储在 `self.graph.machines` 中无需克隆。

### P2-8: 大文件读取无大小检查

**来源**: H | **文件**: `src/backtest_artifacts.rs:1967`, `src/runtime_persistence.rs:380+`
**问题**: 多处 `fs::read_to_string` 直接加载文件到内存，无大小上限。恶意构造的回测工件或运行记录可导致 OOM。
**修复**: 读取前检查 `tokio::fs::metadata`，拒绝 >100MB 文件。

### P2-9: 前端组件测试覆盖率不均

**来源**: F | **文件**: `frontend/src/components/`
**问题**: 39/72 组件无测试文件。StrategyCanvas.jsx (806行) 仅 1 个部分测试。EventStreamPanel 有 10 个测试但 StrategyCanvas 几乎没有。
**修复**: StrategyCanvas.jsx 增加交互测试 (拖拽/连线/配置)。

### P2-10: 模块文件过大

**来源**: H | **文件**: `v4_runtime.rs` (5258行), `core_ir_evaluator.rs` (2610行), `mutation.rs` (2158行)
**问题**: v4_runtime.rs 混合了类型定义、运行时逻辑、模拟执行引擎、回测和测试。拆分可改善可维护性。
**修复**: `v4_runtime_types.rs` + `v4_runtime.rs` + `v4_simulated_execution.rs` + `v4_runtime_tests.rs`。
