## 待确认项决策

| # | 事项 | 决策 | 理由 |
|---|------|------|------|
| 1 | @test 块放 .qs 文件内还是独立文件 | **同一文件**，策略定义在上，测试指令在下，`// ═══ 测试指令 ═══` 分隔 | 策略+测试共存一目了然；一个文件即可复现完整场景；不增加文件管理负担 |
| 2 | Phase 1 先做哪些 @assert 表达式 | `compile.compilable`, `run.events.length`, `run.equity`, `run.has_event(name)`, `backtest.metrics.sharpe`, `backtest.metrics.max_drawdown` | 覆盖编译、运行、回测三大核心路径的最关键断言，后续按需扩展 |
| 3 | `window.__QUANTPILOT_TEST__` 是否暴露到生产 | **仅 DEV 模式** (`import.meta.env.DEV` 守卫) | 避免泄露内部状态到生产环境；减小生产 bundle；安全最佳实践 |
| 4 | 是否需要 QUANTPILOT_TEST_MODE 环境变量 | **是**，设置后：跳过 API Key 认证、超时降到 10s、storage 使用隔离目录 `storage-test/` | 防止测试污染生产数据；加速测试执行；CI 中无需配置认证密钥 |

## P0 — Quantscript 测试指令 + 后端 TestRunner [基础]

**目标**：一个 `.qs` 文件可以从策略定义到编译→运行→断言全程自动执行。

### P0.1 扩展 Quantscript AST

**涉及文件**：`quantscript/src/script.rs`, `quantscript/src/hir.rs`

```
新增 AST 节点
├── Item::TestBlock        → { name, cover, steps }
├── Item::StepBlock        → { name, actions }
├── Stmt::TestAssert       → { expression: String }
├── Stmt::TestCompile      → { }
├── Stmt::TestRun          → { mode, duration_secs, save }
├── Stmt::TestBacktest     → { source, start, end, seed, save }
├── Stmt::TestModify       → { node, param, value }
├── Stmt::TestSaveRun      → { }
└── Stmt::TestWait         → { condition, timeout_secs }
```

**对应 HIR**：`HirTestBlock`, `HirStepBlock`, `HirTestAction`

### P0.2 解析器识别 @ 标注

**涉及文件**：`quantscript/src/lib.rs` (tokenizer + parser)

- tokenizer 新增识别：`@test`, `@step`, `@assert`, `@compile`, `@run`, `@backtest`, `@save_run`, `@modify`, `@wait`
- parser 新增 `parse_test_block()`, `parse_step_block()`, `parse_test_action()`
- 解析后 strategy 部分和 test 部分共存于 `ScriptModule.items`

### P0.3 TestPlan 提取器

**新增文件**：`quantscript/src/test_plan.rs`

```rust
pub struct TestPlan {
    pub scenario_name: String,
    pub cover: Vec<String>,
    pub steps: Vec<TestStep>,
}

pub enum TestStep {
    Compile { assertions: Vec<String> },
    Run { mode: RunMode, duration_secs: u64, save: bool, assertions: Vec<String> },
    Backtest { source: BacktestSource, assertions: Vec<String> },
    Modify { node: String, param: String, value: f64 },
    SaveRun,
    Wait { condition: String, timeout_secs: u64 },
}

pub fn extract_test_plan(module: &ScriptModule) -> Option<TestPlan>
```

### P0.4 后端 TestRunner 引擎

**新增文件**：`src/test_runner.rs`

核心执行循环：

```
fn execute(plan: TestPlan, strategy_source: &str) -> TestReport {
    // 1. 编译策略部分
    let module = parse_quant_script_module(strategy_source)?;
    let runtime_config = lower_script_to_runtime_config(&module)?;
    let compiled = compile_runtime_protocol_config(&runtime_config)?;

    // 2. 逐步执行
    for step in plan.steps {
        match step {
            TestStep::Compile { assertions } => {
                // 求值 assert 表达式：compile.compilable == true 等
            }
            TestStep::Run { mode, duration_secs, assertions } => {
                // 启动 RealTimeSandbox，收集事件流
                // 求值 assert 表达式：run.equity > 0 等
            }
            TestStep::Backtest { source, assertions } => {
                // 启动 FastBacktestSandbox + deterministic_mock
                // 求值 assert 表达式：backtest.metrics.sharpe > 0 等
            }
            // ...
        }
    }
}
```

### P0.5 API 端点

**新增文件**：`src/api_test_scenario.rs`

```
POST /api/test/scenario/run
  Request:  { source: "<quantscript content>" }
  Response: TestReport { scenario_name, steps[], passed_count, failed_count }

POST /api/test/scenario/run-file
  Request:  { file_path: "tests/scenarios/scenario_01.qs" }
  Response: TestReport { ... }

GET  /api/test/scenario/list
  Response: ["tests/scenarios/scenario_01.qs", ...]
```

### P0.6 单元测试

**涉及文件**：`quantscript/src/lib.rs` (tests), `tests/api_test_scenario.rs`

- 解析含 @test 标注的 .qs 字符串
- 验证 extract_test_plan 输出正确
- 端到端：提交 .qs → 编译 → run → 断言 → 拿到 TestReport

### P0 验收标准

```
curl -X POST http://127.0.0.1:3000/api/test/scenario/run \
  -d '{"source": "....包含策略+@test的完整.qs内容..."}'

→ 返回 TestReport，passed_count > 0，duration_ms 合理
→ 所有 @assert 求值正确
```

## P3 — CI 集成 + 闭环 [生产]

**目标**：每次提交自动运行全量测试，生成可追溯的报告。

### P3.1 CI 工作流

**新增文件**：`.github/workflows/scenario-test.yml`

```yaml
jobs:
  backend-scenarios:
    steps:
      - build backend (release)
      - start with QUANTPILOT_TEST_MODE=true
      - run all .qs scenarios
      - upload TestReport artifacts

  frontend-e2e:
    steps:
      - build frontend
      - start vite dev server
      - npx playwright test --config=playwright.ci.config.js
      - upload screenshots + trace

  report:
    needs: [backend-scenarios, frontend-e2e]
    steps:
      - merge TestReport JSONs
      - generate markdown summary
      - comment on PR with pass/fail table
```

### P3.2 测试报告生成

**新增工具**：`tools/generate-test-report.js`

```
输入：多个 TestReport JSON + Playwright test-results/
输出：markdown/测试/测试报告-{date}.md
      ├── 后端场景通过率：12/12
      ├── 前端场景通过率：15/15
      ├── 失败详情表
      └── 截图索引
```

### P3.3 回归监控

- 每次 PR 自动运行 P0+P1 测试（轻量，<5 分钟）
- 每日午夜运行 P2+P3 全量（<30 分钟）
- 失败自动在 PR 上评论 `@test-fail-bot`

### P3 验收标准

```bash
# CI 一键运行
gh workflow run scenario-test.yml

# 查看最新报告
cat markdown/测试/测试报告-2026-05-04.md

# PR 自动评论
gh pr view 123 --comments
# → "## Test Results: 27/27 passed ✅"
```

## 风险矩阵

| 风险 | 级别 | 缓解 | 里程碑 |
|------|:----:|------|:------:|
| @test 语法与现有 quantscript 冲突 | 低 | `@` 前缀隔离，不影响 fn/import 语法 | P0 |
| TestRunner 断言求值逻辑错误 | 中 | 每个 @assert 算子独立单元测试 | P0 |
| react-flow 内部 API 变动导致 testid 失效 | 低 | data-testid 是框架无关的公共接口 | P1 |
| deterministic_mock 数据不符合回测断言预期 | 中 | 先用已知 seed 调试断言阈值 | P2 |
| CI 环境 Rust/Node 版本不一致 | 低 | 使用 rust-toolchain.toml + .nvmrc 锁定版本 | P3 |
