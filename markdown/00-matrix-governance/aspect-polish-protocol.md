# 切面打磨模式协议

> Protocol: aspect_polish_mode
> Version: aspect-polish-mode-v1.2
> Scope: v4.16+ 横向质量优化、体验优化、性能优化、安全优化、测试体系优化、文档和治理资产优化。
> Owner: 三矩阵治理层。

切面打磨模式用于在不污染旧系统的前提下升级一个横向切面。它不仅作用于代码，也同步作用于模块树、全量树、接口契约、测试、文档、里程碑和状态游标。

固定流程:

```text
隔离 -> 分叉 -> 优化 -> 裁剪
```

---

## 1. 隔离

隔离阶段只允许识别范围，不允许修改旧实现。

必须标记:

| 类别 | 必须标记内容 |
| --- | --- |
| 代码范围 | 入口、出口、调用方、状态读写点、持久化点、锁、错误分支、测试入口 |
| 接口范围 | route、command、event、schema、capability action、OpenAPI / AsyncAPI |
| 治理范围 | 模块树节点、全量树条目、流程矩阵、规范矩阵、引导矩阵、里程碑、状态游标 |
| 旧基线 | 旧代码行为、旧契约、旧测试、旧文档当前态 |
| 外溢边界 | 本轮明确不得触碰的模块、文件、接口和文档 |

隔离输出物固定为 `aspect_isolation_manifest`。

---

## 2. 分叉

分叉阶段完全不动旧代码的行为路径。必须复制或新建受影响区的镜像。

镜像对象包括:

| 对象 | 说明 |
| --- | --- |
| 代码镜像 | 新模块、新目录、新实现文件、新 adapter 或新 frontend 副本 |
| 模块树镜像 | 新白箱节点或候选节点，标记为 mirror / candidate，不提前替代旧节点 |
| 全量树镜像 | 新文件、新目录、新契约草案和测试入口登记为镜像态 |
| 契约镜像 | 新 route/schema/action/event 先作为 candidate 或 parallel surface |
| 测试镜像 | 新测试可验证镜像路径，但不得删除旧测试基线 |
| 文档镜像 | 新说明只描述镜像态，不得宣称已经是当前主干态 |

分叉输出物固定为 `aspect_fork_manifest`。

---

## 3. 优化

优化只允许发生在镜像区。旧代码仍作为稳定基线存在。

优化阶段必须持续证明:

1. 镜像区没有反向依赖旧实现的关键行为。
2. 镜像接口能覆盖隔离阶段标记的受影响端口。
3. 新模块树和全量树镜像与真实文件一致。
4. 新测试覆盖镜像路径的主要成功、失败和边界场景。
5. 没有绕过父子通信规则或引入未登记横向连接。

优化输出物固定为 `aspect_optimization_evidence`。

---

## 4. 裁剪

只有当新代码和新治理资产可以完全独立运行时，才允许裁剪旧代码和旧治理当前态。

裁剪前必须满足:

| 门禁 | 要求 |
| --- | --- |
| 独立运行 | 新代码不依赖旧实现完成主流程 |
| 端口切换 | 隔离阶段标记的入口、出口、调用方全部切到新镜像 |
| 契约切换 | 当前 OpenAPI / AsyncAPI / capability catalog / event schema 不再暴露旧入口 |
| 测试切换 | 主测试和 E2E 不再依赖旧路径；旧测试删除或归档有说明 |
| 治理切换 | 模块树、全量树、状态游标、里程碑索引同步提升新镜像为当前态 |
| 旧路径清理 | 旧代码、旧入口、旧契约、旧当前态文档引用被删除或转入历史归档 |

裁剪输出物固定为 `aspect_cutover_closeout`。

裁剪阶段必须同步填写 `aspect-cutover-record.md`。该记录是运行层事实，不替代本文协议；当 `shared_state`、`migration_needed`、`dual_run_required`、`feature_flag`、`rollback_plan` 或 `cutover_gate` 为空时，不得把裁剪结果写成完成。

---

## 5. 三矩阵硬规则

| 矩阵 | 切面打磨要求 |
| --- | --- |
| 流程矩阵 | 必须按隔离、分叉、优化、裁剪推进；裁剪前不得跳过独立运行证明 |
| 规范矩阵 | 旧代码不可直接污染；镜像区不得横向直连 sibling；发布过渡必须由开发者明确声明 |
| 引导矩阵 | 代码、模块树、全量树、契约、测试、文档和游标必须同步分叉、同步优化、同步裁剪 |

---

## 6. 禁止事项

1. 未隔离就修改旧实现。
2. 未分叉就把旧代码原地重写。
3. 镜像未独立运行就删除旧代码。
4. 代码切换了，但模块树、全量树或当前接口契约仍指向旧路径。
5. 把历史文档当作当前架构说明。
6. 用“测试通过”替代端口切换清单。
7. 用切面打磨绕过重构模式的 public owner、route/schema、持久化、锁或状态机门禁。

## 8. 三档执行

切面打磨不得默认按重型治理执行。每轮开始时必须先判定执行档位，并把档位写入记录。

| 档位 | 触发条件 | 必需产物 | 允许省略 |
| --- | --- | --- | --- |
| 轻量切面 | 只影响单一 UI/文案/样式/局部开发体验；不改变接口、状态、持久化、模块 owner、测试契约 | `aspect_light_card`、最小验证结果、rollback 一句话 | 完整四段式长文档、模块树候选节点、全量树候选节点 |
| 标准切面 | 影响一个明确切面下的多个文件或一个可复用组件；可能需要新镜像组件/工具/样式入口；不删除旧主路径 | `aspect_isolation_manifest`、`aspect_fork_manifest`、`aspect_optimization_evidence`、rollback 一句话 | 裁剪 closeout，除非本轮实际切换主入口 |
| 重型切面 | 跨模块、跨接口、跨状态机、跨治理资产，或需要抛弃旧代码/旧文档当前态 | 完整四段式产物，含 `aspect_cutover_closeout` | 无 |

升档规则:

1. 轻量切面一旦触碰接口、状态、持久化、锁、模块 owner、全量树当前态或删除旧路径，必须升为标准或重型。
2. 标准切面一旦进入旧路径裁剪，必须补齐重型裁剪 closeout。
3. 任何档位都不得跳过验证；只是验证粒度不同。

轻量卡硬升档触发器:

| 触发器 | 结果 |
| --- | --- |
| 改接口、route、schema、event 或 capability | 升为标准或重型 |
| 改状态、锁、持久化、事务、权限或安全边界 | 升为标准或重型 |
| 删除旧代码、旧入口、旧契约、旧测试或旧当前态文档 | 升为重型 |
| 改模块边界、public owner、模块树当前态或父子通信规则 | 升为重型 |
| 影响多个父级模块 | 升为标准或重型 |
| 改变测试语义，而不是只补测试或修测试描述 | 升为标准或重型 |
| 无法一句话写清 rollback | 禁止轻量卡 |
| 实际改动超出 `allowed_files` 或 `allowed_scope` | 暂停并重新判定档位 |

## 9. 轻量执行卡

轻量切面只需要固定 6 行，避免治理成本吞掉优化速度:

```text
aspect:
tier: lightweight
allowed_files:
old_entry:
new_entry:
acceptance:
rollback:
```

字段要求:

| 字段 | 要求 |
| --- | --- |
| `aspect` | 写清切面坐标，例如 `frontend.main.sidebar` |
| `allowed_files` | 明确本轮允许触碰的文件；超出即升档或暂停 |
| `old_entry` | 旧入口或旧基线 |
| `new_entry` | 新镜像、新入口或新样式承载点 |
| `acceptance` | 至少包含构建/测试/视觉/焦点/移动端中与本切面相关的项 |
| `rollback` | 一句话说明如何撤回本切面 |

## 10. 临时产物规则

预览日志、截图、临时报告、调试输出默认进入系统临时目录或既有 ignored 目录，不得落在仓库根目录。只有当这些文件本身是交付物时，才允许进入版本控制。

若临时产物意外进入工作区，本轮 closeout 前必须清理；无法清理时必须说明占用进程和残留路径。

## 11. 回退句硬规则

每轮切面打磨 closeout 必须包含 `rollback`。回退句不需要长，但必须能让下一位执行者知道:

1. 恢复哪个旧入口。
2. 删除或停用哪个新镜像。
3. 是否需要回滚样式 token、测试或治理记录。

示例:

```text
rollback: restore LeftSidebar inline implementation, remove SidebarRail, and revert ad-sidebar token/style changes.
```
