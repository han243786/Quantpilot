# 流程矩阵

> 继承对象: `markdown/01-principles/principles-super-standardization.md`
> 职责: 管变更如何提出、校验、优化、实现、验证和收口。

---

## 1. 流程状态机

任何变更进入状态机前，必须先通过 `work-mode-routing.md` 判定工作模式。

| 工作模式 | 流程主线 | 收口条件 |
| --- | --- | --- |
| 重构模式 | 等价基线 -> 抽离/整理 -> closeout -> 父级残余判断 | 结构变化可验证且旧路径处理清楚 |
| 推进模式 | 开辟 -> 落实 -> 测试 -> 跳转 -> 返回 -> 写入 | 新能力符合技术指标并已并入主代码库 |
| 切面打磨模式 | 隔离 -> 分叉 -> 优化 -> 裁剪 | 新镜像独立运行，旧代码与旧当前态治理资产已裁剪 |

所有变更进入实现前必须经过以下状态机。轻量档可压缩记录，但不得跳过状态声明。

```text
Draft 提案
  -> FitCheck 适配性校验
  -> Refine 方案优化
  -> FitCheck 再校验
  -> DesignLocked 设计方案落定
  -> Implementing 实现中
  -> Verifying 验证中
  -> Closed 收口
```

| 状态 | 输出物 | 不合格表现 |
| --- | --- | --- |
| Draft | 问题、目标、执行档位、影响矩阵声明 | 未说明影响哪些矩阵节点 |
| FitCheck | 产品边界、模块边界、旧能力、冲突、锁和幻觉风险校验 | 提案直接进入实现 |
| Refine | 至少一轮方案优化记录 | 没有解释为什么当前方案优于原方案 |
| FitCheck 再校验 | 优化后方案再次过适配性校验 | 优化后新增风险未复核 |
| DesignLocked | 落定方案、测试、文档、回退策略 | 边做边改设计且无记录 |
| Implementing | 按落定方案修改代码或文档 | 超出方案范围 |
| Verifying | 门禁、测试、人工检查或审计证据 | 用“看起来可以”替代证据 |
| Closed | 收口记录、剩余风险、后续项 | 未记录未完成项 |

---

## 2. 三档执行入口

流程矩阵只负责推进，不负责偷懒。执行档位由 `proposal-flow.md` 判定:

- 轻量档: 只改变表达，不改变系统。
- 标准档: 改变实现，但不改变模块边界。
- 重型档: 改变边界、契约、能力、拓扑或长期治理规则。

命中更高档以更高档为准。不确定时升一档。

---

## 3. 每次变更的最低记录

| 执行档 | 最低记录 |
| --- | --- |
| 轻量 | 执行档位、三矩阵无影响声明、为什么不是更高档、验证方式 |
| 标准 | 影响矩阵、模块树节点、适配性校验、方案优化记录、局部回归命令 |
| 重型 | 完整状态机、模块树白箱节点、旧路径/兼容桥/退役、冲突锁检查、回归保护矩阵 |

---

## 4. 与旧流程的关系

`principles-super-standardization.md` 仍是门禁和 closeout 的历史主干。流程矩阵不复制旧文全文，只在变更入口处新增强状态机和三档执行判定。

当两者出现冲突时:

1. 不继续实现受影响内容。
2. 记录冲突对象、两种口径、风险和建议。
3. 经用户确认后同步三矩阵或旧主干文件。

---

## 5. 切面打磨流程钩子

切面打磨模式不得直接套用重构模式的递归四段式。它必须使用 `aspect-polish-protocol.md`:

1. `aspect_isolation_manifest`: 只划范围，不动旧实现。
2. `aspect_fork_manifest`: 复制代码与治理资产镜像，不提前替换当前态。
3. `aspect_optimization_evidence`: 只在镜像区优化，并持续证明端口覆盖。
4. `aspect_cutover_closeout`: 新代码独立运行后，裁剪旧代码和旧当前态治理资产。

裁剪阶段如涉及删除旧模块、旧 route、旧契约或旧测试，可临时借用重构模式的旧路径清理门禁。

---

## 6. 推进模式流程钩子

推进模式不得直接套用重构模式的递归四段式，也不得被切面打磨模式替代。它必须使用 `advance-mode-protocol.md`:

1. `advance_opening_manifest`: 确定会接入哪些已有代码端口，以及需要新增哪些端口。
2. `advance_implementation_record`: 按开辟清单落下新增代码、契约、测试和文档。
3. `advance_test_evidence`: 对新增代码和受影响端口执行技术指标验证。
4. `advance_jump_record`: 遇到结构阻塞或横向质量阻塞时，允许局部跳至重构模式或切面打磨模式。
5. `advance_return_record`: 局部模式完成后必须回到推进模式，继续能力验收。
6. `advance_write_in_closeout`: 新代码完全符合技术指标后并入主代码库和当前治理资产。

如果新增能力不满足指标，可以回到开辟、落实或测试中的任意合理阶段继续循环；不得跳过写入门禁。
