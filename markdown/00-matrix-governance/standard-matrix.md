# 规范矩阵

> 继承对象: `markdown/General_Policy.md`
> 职责: 管硬规则、禁止项、父子通信、回退、冲突、并发锁和 AI 幻觉发现。

---

## 1. 父子通信硬规则

开发态默认结构为白箱树:

```text
父模块
  -> 子模块 A
  -> 子模块 B
  -> 子模块 C
```

硬规则:

1. 父模块是对外协调层。
2. 子模块默认不得横向直连兄弟模块。
3. 跨模块通信必须经过父模块、登记接口、事件、adapter 或契约层。
4. 即使横向直连更快，开发态仍优先保持父子通信。
5. 例外只能进入 `release-transition-protocol.md` 的发布过渡协议。

---

## 2. 发布过渡限制

允许为了发布版本性能优化提出横向连接，但必须满足:

- 开发者明确声明本轮进入发布版本过渡，或允许评估发布性能优化横向连接。
- AI 不得主动提出进入发布过渡。
- 横向连接只能作为发布态性能边存在，不能反向修改开发态模块边界。
- 每条横向连接必须有可撤销证明。

---

## 3. 新旧冲突规则

任何变更必须检查:

| 冲突类型 | 检查问题 |
| --- | --- |
| 旧能力回退 | 是否影响既有 supported / restricted 能力 |
| 旧数据兼容 | 旧图、旧 QS、旧运行记录、旧快照是否还能读取或明确拒绝 |
| 旧路径残留 | 新路径跑通后旧路径是否需要 adapter、兼容桥或退役清单 |
| 文档口径冲突 | README、支持矩阵、总览、三矩阵是否给出不同状态 |
| 测试冲突 | 是否删除或弱化旧测试而未说明 retired / migration |

无法回答时必须升为重型档。

切面打磨模式额外要求:

1. 旧代码在分叉前不得被原地改写。
2. 镜像代码未完全独立运行前，不得删除旧代码。
3. 旧当前态治理资产不得提前改成新当前态，只能标记 mirror / candidate。
4. 裁剪时必须同时删除或归档旧代码、旧入口、旧契约、旧测试和旧当前态文档引用。

推进模式额外要求:

1. 开辟阶段必须同时声明既有接入端口和新增端口。
2. 技术指标未声明或未验证时，不得进入写入阶段。
3. 局部跳转到重构模式或切面打磨模式时，必须记录 `return_condition`，不得让局部模式吞并推进目标。
4. 新能力写入主代码库前，契约、测试、模块树、全量树和回退说明必须同步。

---

## 4. 并发锁与状态规则

涉及事务、锁、缓存、事件回放、审批、沙箱、执行端或持久化时，必须记录:

- 状态拥有者。
- 锁顺序。
- 是否跨 await / I/O 持有锁。
- 失败时是否 fail-closed。
- 是否可重放、可回滚、可审计。

任何锁顺序变化、事务边界变化或并发读写路径变化一律重型档。

---

## 5. AI 幻觉发现规则

AI 或 vibecoding 辅助提出事实时，必须能指向:

- 真实文件。
- 真实模块树节点。
- 真实 public 方法或接口。
- 真实测试、门禁或人工检查项。

以下情况视为未证实:

- 提到不存在的模块、文件、能力 ID、接口或测试。
- 只凭命名推断支持能力。
- 只凭代码存在性宣称产品支持。
- 说不清父模块、调用方或能力真源。

未证实内容不得进入 DesignLocked。

---

## 6. 工作模式硬规则

| 模式 | 禁止事项 |
| --- | --- |
| 重构模式 | 不得借重构名义新增未验收产品能力 |
| 推进模式 | 不得借推进名义顺手大规模改结构，不得绕过开辟端口清单、技术指标验证或写入门禁 |
| 切面打磨模式 | 不得跳过隔离和分叉，不得只分叉代码而不分叉模块树、全量树、契约、测试和文档 |

工作模式冲突时必须暂停并重新 FitCheck。

---

## 7. 质量与速率护栏

所有模式共同遵守 `governance-quality-speed-guard.md`:

| 护栏 | 硬规则 |
| --- | --- |
| 旧路径文档债 | 历史旧债进入 debt ledger，单独分批清理；新增文件漏登记或误登记必须当前任务内修复 |
| 工作模式入口 | 每次任务先判定工作模式；用户只说“继续”时不得默认递归重构 |
| 轻量卡防滥用 | 命中接口、状态、持久化、模块边界、旧路径删除、多父级影响、测试语义改变或无法一句话回退时必须升档 |

任何一项不成立，本轮 closeout 必须写明新债、实际模式和补救计划。
